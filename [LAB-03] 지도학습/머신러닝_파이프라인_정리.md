## 1. 통계 모형과의 차이점

### 학습/검증 데이터로 분할 후 학습 데이터에 대해서만 학습을 수행

**모델링용 데이터 전처리 → 모델 구축 → 모델 평가 및 개선** 흐름 안에서, 머신러닝 기법 활용 항목:

| 단계 | 내용 |
|---|---|
| 파생변수 생성 | 파생변수 기술 격차 확인 필요 |
| 로그 변환 | |
| 공간특성 변환 | |
| 명목형 변환 | |
| **학습·검증용 데이터 분할** (단순 모델 비교) | 결측치, 이상치 대체 / 더미변수 인코딩 / 다중공선성 확인 / 스케일링 / 차원축소 / 베이스 모델 구축 |
| 최적 모델 선정 | 교차검증 및 하이퍼파라미터 튜닝 / 과적합 점검 |

> **결측치·이상치 처리, 더미변수 인코딩, 다중공선성 확인 및 스케일링, 차원 축소 등의 전처리는 데이터 분할 후 학습·검증용 데이터에 대해 각각 수행해야 함**
>
> 통계 모형에는 없던 **"학습·검증용 데이터 분할"** 과정이 머신러닝에는 추가됨

## 2. 머신러닝 데이터 분할 전후에 따른 데이터 전처리 시점

### 데이터 누수 방지를 위한 전처리 순서

**왜 분할 전/후를 나눠야 하나?** — 핵심 위협: **Data Leakage(데이터 누수)**
- 검증(Validation) 데이터의 정보가 모델 훈련 시 노출되어 '미래의 데이터' 역할을 해야 하는 전체 데이터에 대해 통계량(평균, 분산, 분위수 등)을 활용하는 전처리를 하면 오답지를 미리 참조하는 것과 같음

#### 분할 전 (전체 데이터) — 통계량을 사용하지 않는 안전한 작업만 수행
- **도메인 기반 파생변수**: BMI 산출, 요일 추출 등 단순 계산
- **단순 함수 적용**: 로그 변환
- **명목형 범주 매핑**: 텍스트 카테고리 대체
- **명백한 오류값**: 나이 200살 등 명백한 데이터 기입 오류 처리

#### 분할 후 (학습셋 한정) — 데이터의 분포/통계량을 사용하는 작업은 주의 ⚠️ (중요)
- **결측치 대체**: 평균, 중앙값, 최빈값 계산해 채움
- **이상치 경계값**: IQR 이상치 경계값 계산
- **스케일링**: StandardScaler 등
- **다중공선성 처리**: VIF 계산 및 변수 선택
- **차원 축소**: PCA (주성분 분석 공분산 활용)

#### 우선 조건
- 동형변수(평균, 분산, 분위수 등)를 활용하는 전처리는 학습(Train)셋 기준 산출
- 검증(테스트) 데이터셋은 학습셋에서 산출된 통계량으로 크게 그대로 재사용 유지해야 함

#### 올바른 파이프라인 흐름
전체 데이터(안전한 변환) → 분할(Train/Val) → 모델 학습(fit) → 튜닝 및 평가

#### 가장 흔한 실수
- 스케일링 후 데이터 분할 → 테스트 성능이 비정상적으로 과대평가되는 심해 실수
- 전체 평균으로 결측치 채우기 → 판다지도 누수가 반드시 Train 파이프라인 사용 필요

## 3. scikit-learn의 Pipeline을 통한 파이프라인 구축

### (1) End-to-End 자동화 아키텍처

데이터 정제부터 최적 모델 배포까지의 흐름을 하나로 묶어 일괄 처리
- 데이터 분할 후 수행되는 전처리와 모델 학습을 하나의 흐름으로 묶어 일괄 처리
- 통계량 산출 과정을 학습셋에서 국한시켜, 검증/평가셋에 미래 정보가 오염되는 것을 방지

| 단계 | 내용 |
|---|---|
| 1. 데이터 정제 | 결측치·이상치 처리 / 파생변수 생성 / 수치형 로그변환 |
| 2. Train/Test 분할 | 정답 비율 유지 / 컨텍 확인 / 통계량 산출은 학습셋에서 수행 (sklearn `train_test_split` 활용, 범주형 균형이 문제 시 `stratify=종속변수` 옵션으로 층화 추출 사용) |
| 3. 변수 전처리 | 결측치 처리 / 이상치 처리 / 다중공선성 처리 / 스케일링(Std) / One-Hot 인코딩 |
| 4. 변수 차원 정리 | PCA 차원축소 (필요한 경우만 수행) — scikit-learn Pipeline 결합의 영역 (검증 데이터 오염 방지) |
| 5. 모델 학습/튜닝 | 12개 알고리즘 / 하이퍼파라미터 튜닝 / 5-Fold 교차 검증 |
| 6. 평가 및 저장 | 다각적 성능 지표 / Best Params 요약 / .pkl 파일 저장 |

### 알고리즘 수학적 특성별 전처리 분기 전략

| 알고리즘 군 | 스케일링 | 다중공선성 | One-Hot 인코딩 | PCA | 전략적 비고 |
|---|---|---|---|---|---|
| 선형 계열 | 필수✅ | 필수✅ | 필수(drop='first') | 선택🟡 | 스케일링이 성능에 영향 없음 |
| 규제 모델·비선형 | 필수✅ | 필수✅ | 필수(Standard) | 선택🟡 | 변수 스케일 차이에 의한 왜곡 방지 |
| 트리·부스팅 계열 | 선택🟡 | 불필요 | 선택(전체 유지) | 선택🟡 | 다중공선성 영향이 적어 결과 해석 용이성을 위해 처리하기도 함 |

### (2) `my_ml` 모듈의 `fit_pipeline` 함수 구조

**모델 객체 + 입력 데이터(DataFrame)** → `my_ml.fit_pipeline()`

전처리부터 모델 학습까지의 단계를 순차적으로 엮는 핵심 함수. 사용하는 모델 객체 유형에 따라 자동 구성

- **ColumnTransformer**
  - 수치형 데이터 처리: `SimpleImputer`(결측치 중앙값 대체) → `OutlierClipper`(IQR 클리핑) → `VIFSelector`(다중공선성 처리) → `StandardScaler` → `PCA`
  - 범주형 데이터 처리: `SimpleImputer`(결측치 최빈값 대체) → `OneHotEncoder`(drop='first' 옵션)
- **ColumnTransformer**: 변수 타입별 병렬 처리 — 수치형·범주형 컬럼에 서로 다른 변환을 동시에 적용, 모델별 num/cat 파이프라인을 별도 구성해 결과를 결합
- Estimator → `.fit(X, y)` → `.predict(X)`

파이프라인 구축 모듈 사용하기: 제공되는 모듈은 workspace의 `/helpers` 패키지(폴더)에 위치

## 4. 모델 저장과 재사용: pkl 파일

### pkl 파일이란?
파이썬 객체를 그대로 담는 파일

### 저장과 불러오기
- `joblib.dump` / `joblib.load` 권장
- 표준 pickle 모듈로도 저장 가능
- 전처리+모델은 Pipeline으로 저장

### 사용 시 주의점 ⚠️
- 저장·로드 환경의 버전 일치 필요
- 신뢰할 수 없는 pkl은 로드 금지
- 용량이 크면 compress 옵션 활용

```python
import joblib
from sklearn.pipeline import make_pipeline
from sklearn.ensemble import RandomForestClassifier

# 전처리 + 모델을 하나의 파이프라인으로 학습
model = make_pipeline(StandardScaler(), RandomForestClassifier())
model.fit(X_train, y_train)

# 저장: 학습 결과를 pkl 파일로 직렬화
joblib.dump(model, "rf_model.pkl", compress=3)

# 불러오기: 재학습 없이 바로 예측
loaded = joblib.load("rf_model.pkl")
y_pred = loaded.predict(X_test)
```

## 5. 선형회귀 (Linear Regression)

### 머신러닝 관점에서의 선형회귀
- 입력 변수 X와 출력값 y의 관계를 회귀식 ŷ = β₀ + β₁x₁ + ... + βₚxₚ 로 표현
- **목표**: 학습 데이터에서 손실(loss)을 최소화하는 회귀계수 β를 찾는 것
- **손실함수(Loss Function)**: MSE(평균제곱오차)를 최소화 → 최소제곱법(OLS)

L(θ) = (1/n) Σ(yᵢ - ŷᵢ)² → min

### 머신러닝 워크플로우
[STEP 1] 데이터 분할(Train/Test 분리) → [STEP 2] 모델 학습(Train 데이터로 β 추정) → [STEP 3] 예측(Test 데이터에 대해 ŷ 산출) → [STEP 4] 성능 평가(예측값 ŷ와 실제값 y 비교)

### 선형회귀 장단점

| 장점 | 단점 |
|---|---|
| 학습/예측 속도가 빠름 | 비선형 관계 학습 한계 |
| 모델 구조가 단순함 | 다중공선성에 매우 취약 |
| 결과 해석 직관적 | 이상치(Outlier)에 민감 |
| 베이스라인 모델로 적합 | 변수 스케일/분포 영향 큼 |

## 6. 정규화 회귀 - Ridge / Lasso / ElasticNet

선형회귀의 한계를 보완하는 알고리즘: 선형회귀는 **다중공선성, 과한 변수, 변수별 영향력 편차**에 취약함 → 회귀계수 β에 패널티(penalty)를 부여하여 모델을 단순화하고 안정성을 높이는 방법

### 세 가지 정규화 회귀 비교

| 정규화 | 페널티 항 | 특징 |
|---|---|---|
| **Ridge (L2 정규화)** | λΣβᵢ² | 회귀계수의 크기를 가볍게 억제(0으로 안 만듦), 다중공선성 완화에 효과적, 모든 변수를 유지하며 영향력만 완화 (다중공선성 완화 효과) |
| **Lasso (L1 정규화)** | λΣ\|βᵢ\| | 일부 회귀계수를 정확히 0으로 만듦(Feature Selection 내장), 변수가 많거나 최소한 데이터에 유리 (자원 축소 효과) |
| **ElasticNet (L1+L2 혼합)** | λ₁Σ\|βᵢ\| + λ₂Σβᵢ² | Ridge와 Lasso의 장점을 결합, 다중공선성 완화 + 변수 선택 동시, 상관관계 높은 그룹 변수 선정 (Lasso + Ridge 절충) |

> 단, α, λ 절정된 알파값으로 정규화 대상서에 제한함(**람다값 = 1이면 원 손실함수와 동일**)

| 모델 | 패널티 | 계수 축소 | 변수 선택 | 관련 상황 |
|---|---|---|---|---|
| 선형회귀 | 없음 | X | X | 변수 적고 다중공선성 없음 |
| Ridge | L2 | O (0에 근접) | X | 다중공선성 존재 |
| Lasso | L1 | O (정확히 0) | O | 변수 많고 선택 필요 |
| ElasticNet | L1+L2 | O | O | 변수 많음 + 다중공선성 |

## 7. `/helpers/my_ml.py`에 구현된 `fit_pipeline` 함수

### 학습 알고리즘 유형에 따른 파이프라인 생성 방법

| 모델 | VIF | 스케일링 | drop_first |
|---|---|---|---|
| **LinearRegression** | 다중공선성 점검 필요 (vif=True) | 필요 (scale=True) | True |
| **Ridge** | 선택(Ridge가 완화, vif=False 가능) | 필요(Standard, scale=True) | True |
| **Lasso** | 불필요(자동 처리, vif=False) | 필요(L1 페널티, scale=True) | True |
| **ElasticNet** | 불필요(vif=False) | 필요(L1+L2, scale=True) | True |

```python
# LinearRegression
fit_pipeline(model=LinearRegression(), vif=True, scale=False, drop_first=True)

# Ridge
fit_pipeline(model=Ridge(alpha=1.0), vif=False, scale=True, drop_first=True)

# Lasso
fit_pipeline(model=Lasso(alpha=0.01), vif=False, scale=True, drop_first=True)

# ElasticNet
fit_pipeline(model=ElasticNet(), vif=False, scale=True, drop_first=True)
```

## 8. LinearRegressor → 파이프라인 박스 확장 시 확인 가능한 전처리 구조

```
Pipeline
├─ preprocessor: ColumnTransformer
│   ├─ num
│   │   └─ VIFSelector
│   │       Parameters: threshold=10.0, check_cols=None
│   │       (다중공선성을 기준값 10으로 걸러냄, 연쇄적 전처리 단계)
│   ├─ cat: ['is_age_capped', 'is_income_capped', 'ocean_area', 'special_cluster']
│   │   └─ OneHotEncoder
│   │       Parameters:
│   │         categories='auto'
│   │         drop='first'   ← drop_first=True가 적용됨
│   │         sparse_output=False
│   │         dtype=<class 'numpy.float64'>
│   │         handle_unknown='ignore'
│   │         min_frequency=None
│   │         max_categories=None
│   │         feature_name_combiner='concat'
│   │       (OneHotEncoder는 더미변수 처리용 sklearn 버전)
│   └─ remainder: passthrough
└─ LinearRegression (전처리 완료 후 선형회귀 모델 학습)
```

## 9. 대표적인 비선형 모델: KNN, SVM, Decision Tree

| 모델 | 유형 | 설명 | 키워드 |
|---|---|---|---|
| **KNN** | 거리 기반·국소 모형 | 가까운 이웃의 값을 평균낸다 | 거리 \| 이웃 \| 평균 |
| **SVR (SVM 계열 회귀 모형)** | 커널 기반·전역 모형 | 허용 오차 안은 봐주고, 밖의 오차만 줄인다 | 마진 \| 커널 \| 일반화 |
| **Decision Tree** | 트리 기반·규칙 모형 | 스무고개 방식으로 데이터를 나눈다 | 분할 \| 규칙 \| 해석 |

### K-최근접 이웃 (KNN) (1)

**기본 아이디어** → 비슷한 입력은 비슷한 결과를 가질 것이다
- 새 데이터와 가장 가까운 K개 이웃을 보고, 그들의 다수 클래스(또는 평균)로 예측
- 새로운 데이터가 주어질 때마다 가장 가까운 이웃 데이터만 참고하여 예측을 수행하는 국소 모형(Local Model)
- 전체 데이터를 아우르는 공통 수식을 학습하는 것이 아님에 유의

**작동 순서**: 새 데이터 입력 → 거리 계산(기존 데이터 간) → 가까운 K개 선택(이웃 수 결정) → 이웃 값 집계(결과값(y) 수집) → 평균으로 예측(최종 도출)

**유의 사항**: ⚠️ 스케일링(Scaling)은 필수 — KNN은 '거리'를 기반으로 작동하므로 변수들의 단위 차이(스케일)에 매우 민감. 안정적인 예측 성능을 위해 파이프라인 구성 시 스케일링을 반드시 적용해야 하며, 이상치(Outlier)의 영향도 크게 받음

### K-최근접 이웃 (KNN) (2)

**KNN이 사용하는 거리 척도 (Distance Metric)**: 두 데이터 사이의 "가까움"을 정의하는 함수 — 선택에 따라 이웃 후보가 달라짐 (하이퍼파라미터 튜닝 시 적용)

| 척도 | 공식 | 특징 |
|---|---|---|
| **Euclidean (L2) - 기본값** | d = √Σ(xᵢ-yᵢ)² | 직선 거리 개념에 해당, 연속형 변수에 가장 널리 사용, 큰 값 차이에 민감하여 이상치의 영향 큼, 변수 단위가 다를 경우 왜곡 발생 가능, 스케일링 적용된 데이터에 최적 |
| **Manhattan (L1) - 이상치 영향이 걱정될 때** | d = Σ\|xᵢ-yᵢ\| | 축을 따라 이동하는 거리의 합 개념, 각 변수의 차이를 선형적으로 합산, 유클리드 대비 이상치 영향이 상대적으로 적음, 고차원 데이터에 비교적 안정적 |
| **Minkowski (Lp) - p값을 조절하며 실험** | d = (Σ\|xᵢ-yᵢ\|ᵖ)^(1/p) | p값의 변화에 따라 다른 거리 계산법, p=1: Manhattan, p=2: Euclidean, p=3: 또 다른 Minkowski, p=∞: Chebyshev와 연결(변수 별 차이 중 최댓값을 거리로 사용) |

**KNN의 특징**

| 장점 | 단점 |
|---|---|
| 예측 비용이 데이터 크기에 비례 | 학습 단계가 없어 단순함 |
| 고차원에서 거리 의미가 약해짐 | 직관적이고 구현이 쉬움 |
| 학습 데이터를 메모리에 유지해야 함 | 비선형 결정 경계 자연스럽게 |
| | 지역적 패턴 포착에 강함 |
| | 스케일 차이·이상치에 민감 |

### K-최근접 이웃 (KNN) (3) — 파이프라인 구성

| 항목 | 설정 |
|---|---|
| 모델 성격 | 거리 기반·국소 모형 |
| 학습량 | 거의 없음 |
| 이상치 영향 | 큼 |
| 스케일링 | 필수 ✅ |
| 다중 공선성 | 영향 있음 |

| 해석 | 어려움 |

```python

    model=KNeighborsRegressor(n_jobs=-1),
```

## 10. SVR (SVM 계열 회귀모형) (1)

> 참고: SVC 또는 SVM Classifier: 분류, 범주 예측 / One-Class SVM: 이상치 탐지, 정상·비정상 구분

**기본 아이디어** → 조금 틀리는 건 괜찮다
- 예측선 양옆의 ε-튜브 안의 오차는 무시하는 전역 모형
- 일정 오차를 허용함으로써 노이즈에 둔감하고 더 안정적인 일반화 성능 제공

**커널 트릭 (하이퍼파라미터 튜닝 대상)**: 고차원으로 직접 변환하지 않고, 유사도만 계산

**유의사항** ⚠️: 스케일링(Scaling)은 필수, 복잡한 데이터는 차원 축소 권장 — 거리(내적)를 계산하므로 스케일링이 반드시 필요하며, 변수가 많을 경우 PCA 적용을 권장. 여러 파라미터(C, gamma 등)에 민감하기 때문에 하이퍼파라미터 튜닝시 유의해야 함

## 11. Decision Tree (1)

**핵심 아이디어** → 스무고개 방식의 규칙 기반 모델
- 가장 잘 나누는 질문을 반복하여 점점 순수한 그룹을 만드는 규칙 기반 예측 모형
- 'Yes or No' 방식의 명확한 규칙을 형성하기 때문에 결과에 대한 해석이 매우 쉬움

**진행 절차**
1. 질문을 하나씩 던지며 데이터를 나눈다 (if~else 규칙을 반복적으로 적용)
2. 가장 잘 구분되는 질문을 선택한다 (분산도(MSE) 감소가 가장 큰 분할점 탐색)
3. 데이터를 더 "순수한 그룹"으로 만든다 (각 잎(leaf)이 비슷한 값끼리로 모이도록 분류)
4. 멈출 시점을 정하지 않으면 과적합함 (깊이 제한·최소 샘플 수·가지치기 필요)

트리 구조의 규칙 집합은 if~else 형태로 해석 가능 (예: "온도가 영하입니까?" → "습도가 70% 이상입니까?" 순으로 분기)

### Decision Tree (2)

**주요 용어**

| 용어 | 설명 |
|---|---|
| 노드 (Node) | 데이터를 분할하는 질문/조건 |
| 가지 (Branch) | 노드의 분기 — 참/거짓 결과 |
| 깊이 (Depth) | 루트에서 리프까지의 레벨 수 |
| 루트 노드 (Root) | 트리의 최상단 시작 노드 |
| 리프 노드 (Leaf) | 더 이상 분할하지 않는 최종 노드 |

**트리의 깊이** ⚠️: 과소, 과대적합 개념은 추후 소개합니다. 지금은 학습 모델이 연습에는 잘 하지만 실전에서는 못하는 것으로 이해합니다. (연습=훈련 데이터, 실전=검증 데이터)

트리의 깊이(depth)가 깊어질수록 분할 횟수가 늘어나 결정 경계는 더 세밀해진다.
- 너무 얕으면 과소적합, 너무 깊으면 과대적합으로 일반화 성능이 떨어진다.
- **적절한 깊이 = 너무 얕지도, 너무 깊지도 않은 지점**
- 깊이는 트리 모델의 가장 핵심적인 복잡도 하이퍼파라미터

(예시 4단계: 한 번 분할 → 너무 단순(과소적합) / 두 번 분할 → 경계가 약간 세밀해짐 / 충분히 깊음 → 훈련 데이터에 과대적합)

## 12. 앙상블 기법 개요

여러 개의 추정기(estimator)를 결합하여 더 강력한 예측 모델을 만드는 기법

| Bagging (병렬 구조) | Boosting (순차 구조) |
|---|---|
| 복원 추출로 여러 샘플 생성 | 이전 모델의 잔차(residual) 학습 |
| 독립적 학습 후 예측값 평균 | 순차적으로 모델을 추가하며 개선 |
| **분산(Variance) 감소 효과** | **편향(Bias) 감소 효과** |
| 대표: RandomForest | 대표: XGB / LGBM / CatBoost |

- Bagging: 학습 데이터 → Model 1, Model 2, Model 3 (병렬) → 평균 결합 → ŷ
- Boosting: 학습 데이터 → Model 1 → (잔차 전달) → Model 2 → (잔차 전달) → Model 3 → 가중 결합

### Random Forest (1)

Decision Tree의 Bagging 기반 앙상블 모델
- 여러 개의 결정트리(Decision Tree)를 독립적으로 학습 후 예측값을 평균(Average)내어 최종 예측
- 단일 트리의 **과적합 문제를 완화**하는 것이 핵심 목표

**Random Forest의 특징**

| 장점 (Pros) | 단점 (Cons) |
|---|---|
| ✅ 과적합(Overfitting) 방지에 강력 | ✗ 다수 트리 생성으로 인한 메모리 사용량 증가 |
| ✅ 결측치 및 이상치에 비교적 견고함 | ✗ 단일 의사결정트리 대비 예측 속도가 상대적으로 느림 |
| ✅ 피처 중요도(Feature Importance) 제공 | |

Random Forest 예측 흐름: 학습 데이터(Bootstrapped Samples) → Tree 1, Tree 2, ..., Tree N(각 분기마다 일부 변수를 랜덤 선택) → 평균(Average) Σ(ŷ)/N → 최종 예측 ŷ

## 15. 베이스모델 구축 이후의 프로세스

### 베이스 모델 학습이 완료된 상태에서 시작하는 5단계 평가 흐름

| STEP | 내용 | 무엇을 잘 하는 모델을 볼 것인가 / 방법 예시 |
|---|---|---|
| 01. 성능지표 선정 | 평가지표 검토 후 문제 유형에 맞는 평가 기준 결정 | 예: 회귀 RMSE, MAE, R² / 분류 Accuracy, F1, ROC-AUC 등 |
| 02. 베이스 모델 비교 | 여러 알고리즘 동일 조건 하 성능 비교 후 최종 후보 모델 선정 | 예: Linear Regression, Random Forest, XGBoost, LightGBM → 유망한 알고리즘은 무엇인가? |
| 03. 튜닝 및 교차검증 | 최적 하이퍼파라미터 탐색 / 일반화 성능 추정 | 방법: Grid Search, Random Search, K-Fold CV. 최적의 설정값을 탐색해 보자!(미래 데이터셋 성능 추정) |
| 04. 최종 성능평가 | Test Set 1회 평가 / 튜닝 전·후 비교 | 주의: Test Set은 여기서 처음 사용, 튜닝 과정에는 사용 없어야 함. Test Set으로 실제 성능을 확인해 보자.(미래 데이터 성능 확인) |
| 05. 과적합 진단 | 학습 성능과 검증 성능 비교 / 과적합 여부 확인 | 방법: Learning Curve, Train/Test Gap, CV Score 편차, Gap Ratio. 새로운 데이터에서도 잘 작동할지 확인해 보자.(일반화 가능성 점검) |

**전제 조건 (INPUT)**: 데이터 분할 완료(Train/Validation/Test) · 다수 베이스 모델 학습 완료(기본 하이퍼파라미터)

**최종 산출 (OUTPUT)**: 최적 모델 선정(하이퍼파라미터 확정) · Test Set 최종 성능 보고(정량 지표 기반) · 과적합 진단 결과(일반화 가능성 검토)

### 성능평가지표의 종류 — 예측(Regression) 모델의 대표 성능 평가 지표

| 지표 | 공식 | 설명 |
|---|---|---|
| **R² (결정계수, Coefficient of Determination)** | R² = 1 - Σ(yᵢ-ŷᵢ)²/Σ(yᵢ-ȳ)² | 모델의 설명력(0~1, 음수 가능), 종속변수 분산 중 모델이 설명하는 비율, 높을수록 설명력이 높음(다른 지표와 병행 사용), 설명변수를 추가하면 감소하지 않음 |
| **MAE (평균 절대 오차, Mean Absolute Error)** | MAE = (1/n)Σ\|yᵢ-ŷᵢ\| | 예측 오차의 평균 크기, 이상치에 덜 민감, 원본 단위 → 해석 용이 |
| **MSE (평균 제곱 오차, Mean Squared Error)** | MSE = (1/n)Σ(yᵢ-ŷᵢ)² | 오차 제곱의 평균 측정, 제곱 단위이므로 해석 어려움, MSE가 미분 가능하여 수학적 최적화 및 경사하강법 활용에 유리 |
| **RMSE (평균 제곱근 오차, Root Mean Squared Error)** | RMSE = √((1/n)Σ(yᵢ-ŷᵢ)²) | MSE의 제곱근 → 원본 단위 복원, 이상치 민감도 유지 + 해석 용이, 예측 모델을 사용하는 경우 가장 일반적으로 사용됨 |
| **RMSLE (평균 제곱 로그 오차, Root Mean Squared Log Error)** | RMSLE = √((1/n)Σ(log(yᵢ+1)-log(ŷᵢ+1))²) | 큰 값의 영향력을 완화 → 상대적 오차 해석, 비율적 오차가 중요한 경우에 활용(가격, 수요량 등) |
| **MAPE (평균 절대 백분율 오차, Mean Absolute Percentage Error)** | MAPE = (100/n)Σ\|(yᵢ-ŷᵢ)/yᵢ\| | 실제값 대비 오차의 비율(%) 측정, 스케일(단위)와 무관한 데이터 비교 유용, 상대 오차를(%)로 표현, 실제값이 0에 가까우면 계산이 불안정 |
| **MPE (평균 비율 오차, Mean Percentage Error)** | MPE = (100/n)Σ(yᵢ-ŷᵢ)/yᵢ | 절대값이 부여 오차의 방향(+/-) → 편향(bias) 확인, 과대/과소 예측 경향에 사용(양수: 평균적 과소예측 / 음수: 평균적 과소예측) |

## 16. `my_ml`의 `reg_score()` 함수

머신러닝 학습 모델의 성능평가 지표를 도출하여 반환한다.

1. **INPUT(입력 받기)**: 학습된 회귀 모델과 테스트 설명변수·실제값을 함수의 인자로 전달받는다.
2. **PREPROCESS(형식 정리)**: 파이프라인 여부에 따라 모델 이름을 추출하고, 실제값을 1차원 배열로 변환한다.
3. **PREDICT(예측 수행)**: 모델에 테스트 데이터를 투입하여 예측값을 생성한다.
4. **7개 성능 지표 계산**
   - A. 기본 표: R²(결정계수), MAE(절대 오차), MSE(제곱 오차), RMSE(제곱근 오차) — 별도 조건이 모든 경우에 적용되는 표준 회귀 평가 지표
   - B. 로그 기반 지표: MSLE(로그 제곱 오차), RMSLE(로그 제곱근 오차) — 값에 음수가 포함되면 NaN 반환, 로그 함수의 정의역 오류를 방지
   - C. 비율 지표: MAPE(절대 백분율 오차), MPE(평균 백분율 오차) — 실제값이 0이 포함되면 NaN 반환, 0으로 나눗셈 오류를 방지, 백분율(%)로 표현
5. **OUTPUT(결과 데이터프레임 반환)**: 모델 이름을 인덱스로, 7개 평가 지표를 컬럼으로 갖는 1×7 데이터프레임

## 17. 성능평가지표 기반 모델 성능 비교 원칙

### 모델 비교에 앞서 "무엇으로 비교할 것인가"를 먼저 정의
지표는 모델을 평가하는 도구이자 최적화의 방향성이다. 잘못된 지표는 잘못된 모델을 "최적"으로 선택하게 만든다.

| 원칙 | 설명 |
|---|---|
| **01. 문제 맥락과 정합** | 예측 오차의 비용 구조에 맞춰 지표를 선택한다. 설명력을 보고 싶은가? → R² / 큰 오차에 강한 페널티가 필요한가? → RMSE / 모든 오차를 동등하게 볼 것인가? → MAE / 타깃 범위가 넓고 과소예측에 민감한가? → RMSLE / 상대오차(%)가 중요한가? → MAPE / 과대·과소 예측 경향을 알고 싶은가? → MPE |
| **02. 주 지표 + 보조 지표** | 의사결정용 단일 지표를 정하고, 보조 지표로 결과를 해석한다. 주 지표: 모델 선정의 최종 기준 / 보조 지표: 오차 특성과 설명력 보완. 예) 주=RMSE, 보조=MAE+R² |
| **03. 일관성 유지** | 전 과정 동일 주 지표 사용. 베이스모델 비교 지표=튜닝 목적함수=최종 성능 평가 지표. 평가 중 지표를 변경하면 모델 선택 기준이 달라지고 결과 해석의 일관성이 저하됨 |

### 성능평가지표 선택 기준 (1) — 이상치 민감도·스케일·해석성·적합 상황을 한눈에 비교

| 지표 | 이상치 민감도 | 단위/스케일 | 해석 용이성 | 적합한 상황 |
|---|---|---|---|---|
| R² | 중간(제곱 기반) | 0~1(음수 가능) | 높음(설명력) | 모델 설명력 보고, 도메인·스케일이 다른 데이터셋 간 성능 비교 |
| MAE | 낮음(선형) | 원본 단위 | 매우 높음 | 이상치가 많거나, 오차를 평균적 차이로 해석할 때 |
| MSE | 매우 높음(제곱) | 제곱 단위 | 낮음 | 모델 학습용 손실함수 — 보고용 지표로는 비권장 |
| RMSE | 높음(제곱) | 원본 단위 | 높음 | 큰 오차를 피하는 게 중요한 일반적 회귀 — 표준 선택 |
| RMSLE | 낮음(로그) | 로그 단위(상대 오차) | 중간 | 타깃 범위가 넓거나 지수 분포(가격·수요), 과소예측에 더 민감 |
| MAPE | 낮음(선형, 상대) | %(무차원) | 매우 높음 | 스케일 다른 데이터 간 비교, 실제값이 0에 가까운 값이 적을 때 |
| MPE | 낮음(부호 유지) | %(부호 ±) | 중간(편향 진단) | 예측의 체계적 편향 점검(과대/과소예측 경향) — MAPE의 보조 |

### 성능평가지표 선택 기준 (2) — 도메인별 성능 평가 지표 조합

| 도메인 | 주 지표 | 보조 지표 | 이유 |
|---|---|---|---|
| 부동산 가격 예측 | RMSE 혹은 RMSLE | MAE, R² | 가격 범위 넓음 + 비율 오차 관점 / RMSE(좁은 가격대) / RMSLE(넓은 가격대) |
| 수요·재고 예측 | RMSE 혹은 RMSLE | MAPE, MPE | 과소예측 회피 + 편향 진단 / RMSLE(과소예측 회피) / RMSE(대칭 비용) |
| 금융(주가·환율) | RMSE | MAPE | 큰 오차 회피 + 스케일 무관 비교 |
| 배달·물류 시간 | MAE | RMSE | 일반적 오차 + 최악 케이스 관리 |
| 에너지 수요 | RMSE | MAE, R² | 큰 오차 비용 큼 + 설명력 보고 |
| 마케팅 KPI 예측 | MAPE | MPE, MAE | % 보고 친화적 + 편향 확인 |
| 학술 연구·논문 | R² 또는 RMSE | MAE | 설명력 + 절대 오차 함께 보고 |

## 18. 성능평가지표 채택 전략 (1) — 주 지표 + 보조 지표 모델 비교 절차

주 지표로 모델을 정렬하고, 보조 지표는 그 순위를 **기각할 근거**가 있는지만 확인한다.

| STEP | 방법 |
|---|---|
| STEP 1. 주 지표로 정렬 | Validation 점수 1회 측정값 사용(교차검증은 다음 단계) |
| STEP 2. 근소 격차 그룹 묶기 | (실습)기준: 1등과의 점수 차이가 5% 이내인 모델까지 한 그룹으로 묶음 — 예시: 1등 A=4.21(허용폭 4.21~4.42) → B(4.35)포함, C(4.48)제외 → A·B 근소 격차, C 탈락 |
| STEP 3. 보조 지표로 추가 검토 | 그룹에 1등만 남아 있으면 STEP 4로 직행. 분기: MAE 한쪽만 큼(이상치 과잉), R² 낮음(설명력 부족), MAPE 한쪽만 큼(작은 값을 못 맞춤), MPE 한쪽으로 치우침(체계적 편향 — 꾸준한 과대 또는 과소예측) |
| STEP 4. 최종 선정 | 선정 규칙: ① 1등이 압도적 → 1등 채택 / ② 보조 지표에서도 큰 문제 없음 → 1등 채택 / ③ 1등에서 보조 지표 결함 발견 → 차순위 채택 / ④ 보조 지표가 엇갈림 → 사전 정의한 도메인 우선순위로 판단 |

### 성능평가지표 채택 전략 (2) — 베이스 모델 비교 예시

| 모델 | RMSE(주) | MAE | R² | MPE | 판정 |
|---|---|---|---|---|---|
| A | 4.21 | 3.08 | 0.857 | +0.5% | 모순 없음 — 채택 |
| B | 4.35 | 3.05 | 0.852 | −4.2% | 체계적 과대예측 편향 |
| C | 4.28 | **3.45** | 0.860 | +0.3% | MAE만 유독 큼 — 이상치 과민 |

- Step 1·2: 1등 A=4.21 → 허용폭 4.21~4.42 → B(4.35)·C(4.28) 모두 포함 → 3개 모두 근소 격차
- Step 3: B는 MPE가 한쪽으로 치우쳐 편향, C는 MAE만 유독 큼 — A만 모든 보조 지표에서 모순 없음
- Step 4: A 채택(규칙②: 보조 지표에서도 1등 유지)

**우선순위 지침**: 도메인별 보조 지표 우선순위는 비교 사전 정의해야 하며, 결과를 보고 정할 경우 자기에게 유리한 지표를 고르는 셈이 됨

| 도메인 | 우선순위 |
|---|---|
| 수요·재고 예측(과소예측 회피) | MAE / MPE |
| 금융 보고(% 단위 해석) | MAPE / MAE |
| 학술 보고(설명력 강조) | R² / MAE |
| 이상치 강건성 중시 | MAE / RMSE |

**금지해야 할 다지표 비교 방식** ✗
- 명확한 근거 없는 종합점수 생성
- 보조 지표 1등을 근거로 주 지표 2등 모델 선정
- 결과를 본 뒤 보조 지표 우선순위를 결정
- 과도한 순위의 보조지표 동시 비교
- 도중에 주 지표 변경 — 비교 결과를 재현할 수 없게 됨

참고문헌: James et al.(2021), Hastie et al.(2009), Bishop(2006)

### `my_ml.reg_compare_models()` 처리 흐름

학습된 모델로부터 7개 성능 평가 지표를 산출하는 모듈 (모영아, 2025)

주 지표 정렬 → 근소 격차 그룹 → 결함 점검 → 최종 선정

1. **개별 모델 성능평가**: 모델 리스트·딕셔너리를 받아 각 모델에 `reg_score()` 적용 후 하나의 비교 테이블로 결합
2. **주 지표·보조 지표 사양 확인**: R²(1등−값 1등 임계 0.05), MAE·MSE·RMSE(값>1등×(1+임계) 10%), MAPE·RMSLE(값>1등×(1+임계) 10%), MPE(|값|>1등+5.0)
3. **주 지표로 정렬**: 모든 후보 모델을 주 지표 기준으로 정렬
4. **근소 격차 그룹 묶기**: 1등 점수의 5% 이내 모델까지 한 그룹으로 묶음. 분기 처리: 그룹에 1등만 남을 경우 (6)으로 직행
5. **보조 지표로 모순 점검**: 동일 그룹 내부에서만 결함 체크 — MAE 큼→평균오차 큼, R² 낮음→설명력 부족, MAPE 큼→상대오차 큼, MPE 치우침→체계적 편향
6. **최종 선정(Rank 부여)**: 그룹 내: 주 지표가 높고 결함이 적은 순 / 그룹 외: 주 지표 순
