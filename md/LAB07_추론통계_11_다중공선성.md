## 1. 핵심 개념 완전 풀어쓰기 (면접 답변용)

### 1-1. 다중공선성(Multicollinearity)이란

- **정의**: 회귀분석에서 쓰려는 **독립변수(설명변수)들끼리 서로 강하게 상관되어 있는 현상**. 극단적으로는 한 변수가 다른 변수(들)의 거의 완벽한 1차 함수인 경우도 있다.
  - 오늘 예시(`vif_housing`): `면적_m2`와 `면적_평`은 사실 **같은 정보를 다른 단위로 적어놓은 것**뿐이라 상관계수가 0.999에 가깝게 나옴 → 이게 다중공선성의 극단적 예.
- **왜 문제가 되는가**: 회귀분석은 "이 변수 하나가 달라질 때 결과가 얼마나 달라지는가"를 각 변수별로 분리해서 추정하는 작업인데, 변수들끼리 너무 겹쳐 있으면 **어느 변수의 효과인지 통계적으로 구분이 안 됨.**
  - 회귀계수의 표준오차가 커진다 → 계수가 통계적으로 유의하지 않게 나올 수 있다 (실제로는 의미 있는 변수인데도).
  - 계수의 부호나 크기가 표본이 조금만 바뀌어도 요동친다 (불안정함).
  - **예측력 자체는 크게 나빠지지 않을 수도 있지만, "각 변수가 얼마나 영향을 주는지"를 해석하는 건 신뢰할 수 없어진다.** → 이게 다중공선성이 특히 문제되는 이유 (예측이 목적이면 덜 치명적, 해석/설명이 목적이면 치명적).

### 1-2. 왜 상관분석(2변수)만으로는 부족한가

- 상관분석은 **딱 두 변수 사이의 관계**만 본다.
- 다중공선성은 **세 개 이상의 변수가 얽혀서 만드는 문제**일 수도 있다. 예를 들어 A, B, C 세 변수가 있을 때 A와 B의 상관, A와 C의 상관, B와 C의 상관이 각각은 그리 높지 않아도, **"A ≈ B + C"** 처럼 A가 B와 C의 조합으로 거의 설명되는 경우가 있다. 이런 건 2변수 상관계수 표만 봐서는 못 잡아낸다.
- 그래서 "이 변수를 나머지 모든 변수들로 설명하려고 하면 얼마나 잘 설명되는가"를 재는 **VIF**가 따로 필요함. (그래서 오늘 실습도 상관분석 → 상관행렬 확인부터 시작해서, 그걸로 부족하니까 VIF로 넘어가는 흐름으로 짜여 있음)

### 1-3. VIF (Variance Inflation Factor, 분산팽창계수)

- **계산 원리 (말로 풀어서)**:
  1. 대상 변수 하나(예: `면적_m2`)를 **종속변수**로 놓고, 나머지 변수들(`면적_평`, `방_개수`, `지하철_거리_m`, `건물_연식_년`)을 **독립변수**로 하는 회귀식을 하나 만든다.
  2. 이 회귀식의 결정계수 **R²ᵢ** (그 변수가 나머지 변수들로 얼마나 잘 설명되는지, 0~1 사이 값)를 구한다.
  3. VIF는 다음 식으로 계산된다:

     **VIFᵢ = 1 / (1 − R²ᵢ)**

  - R²ᵢ가 0 (다른 변수들과 전혀 상관이 없음) → VIF = 1/(1-0) = **1** (다중공선성 없음, 이상적)
  - R²ᵢ가 0.9 (다른 변수들로 90% 설명됨) → VIF = 1/(1-0.9) = **10**
  - R²ᵢ가 1에 가까울수록 → VIF는 **무한대로 발산**
  - → 이래서 오늘 실습에서 `면적_m2`의 VIF가 546까지 나온 것. 거의 `면적_평`만으로 100% 설명되기 때문.

- **판정 기준 (관례)**: 오늘 코드에서 쓴 threshold는 **10**.
  - VIF < 10 → 다중공선성 문제 없다고 판단
  - VIF ≥ 10 → 다중공선성이 심각하다고 판단 (더 엄격한 기준에선 5를 쓰기도 함, 분야/책마다 다름)

- **왜 상수항(const)을 추가하는가** (`add_constant`):
  - VIF 계산도 결국 내부적으로 회귀분석(R² 계산)을 하는 거라서, 절편(상수항)이 없는 회귀식은 R²가 왜곡되게 계산된다. 그래서 `variance_inflation_factor()`를 쓸 때는 항상 `add_constant()`로 상수항 열을 하나 추가해준 뒤, **상수항 자기 자신의 VIF는 결과에서 제외(drop)** 한다. (상수항의 VIF는 해석 대상이 아니라서 버림)

```python
X = add_constant(target)                      # 상수항 열 추가
for i in range(X.shape[1]):
    vif_i = variance_inflation_factor(X.values, i)   # i번째 변수의 VIF
vif = vif.drop('const')                        # 상수항 행은 제외
```

### 1-4. VIF ↔ 상관계수(r)의 관계 (2변수일 때만 성립하는 특수 케이스)

- 변수가 딱 2개일 때는 VIF와 피어슨 상관계수 r 사이에 **VIF = 1 / (1 − r²)** 관계가 그대로 성립한다 (R²ᵢ가 곧 단순회귀의 r²이기 때문).
- 하지만 변수가 3개 이상이면 VIF는 "그 변수 하나 vs 나머지 전부"를 보는 거라서 **단순한 2변수 상관계수로는 절대 대체할 수 없다.** → 이게 "왜 상관분석과 VIF를 둘 다 봐야 하는가"에 대한 가장 정확한 답.

## 2. 분석 파이프라인 (처음부터 끝까지 순서)

새로운 데이터셋으로 다중공선성을 점검한다면 아래 순서:

```
1. 데이터 로드
        ↓
2. (독립변수 후보들에 대해) 변수 조합 쌍 생성 → 쌍별 상관분석 (my_stats.correlation 반복 or multi_correlation)
        ↓
3. 상관행렬(coolwarm 히트맵) + 산점도 행렬(pairplot)로 "얼핏 봐도 겹치는 변수" 눈으로 확인
        ↓
4. compute_vif()로 각 변수의 VIF 계산
        ↓
5. VIF가 가장 큰 변수 1개를 제거
        ↓
6. 남은 변수들로 VIF 다시 계산 (3~4번 반복)
        ↓
7. 모든 변수의 VIF < threshold(보통 10) 가 될 때까지 5~6 반복
        ↓
8. 최종 변수셋 확정 → 이후 회귀분석 등에 사용
```

**11차시 실습코드**는 이 중 2~4단계까지는 손코딩, 5~7단계(반복 제거 루프)도 처음엔 `while True` 손코딩으로 짜본 뒤, 마지막에 `my_prep.reduce_vif()` 함수 하나로 압축한 것. 상관분석 때와 똑같은 학습 설계(손코딩 → 모듈화) 패턴이 그대로 반복되고 있음.

### 손코딩 vs 모듈화 비교

```python
# [손코딩 버전] - 반복 제거를 while문으로 직접 작성
threshold = 10.0
work = df.copy()
while True:
    vif = compute_vif(work)
    max_vif = vif['VIF'].max()
    if max_vif < threshold or len(work.columns) <= 1:
        break
    worst = vif['VIF'].idxmax()
    work = work.drop(columns=[worst])

# [모듈화 버전] - 위 로직을 함수 하나로
df_final = my_prep.reduce_vif(df, threshold=10.0)
```
→ `reduce_vif()` 내부를 열어보면 위 while 루프와 사실상 동일한 코드가 들어있음 (컬럼 순서 정렬, 원본 보존을 위한 예외처리 정도만 추가됨). **"직접 짠 코드 = 함수 내부 그대로"라는 감각을 다시 한번 확인하는 게 이번 실습의 핵심 포인트.**

## 3. 모듈 구조 & import 사고방식 (심화편 — 순환 참조)

이번 실습에서 중요한 새 포인트: **모듈끼리 서로를 가져다 쓰는 순환 구조**가 실제로 나옴.

```python
# my_stats.py 상단
from . import my_plot
from . import my_prep      # my_stats가 my_prep을 가져다 씀

# my_prep.py 상단
from . import my_stats      # my_prep도 my_stats를 가져다 씀!
```

- `my_stats.py` 안의 `anova_oneway`, `anova_twoway` 등은 데이터를 long → wide로 펼치는 `my_prep.long2wide()`를 가져다 쓰고,
- `my_prep.py` 안의 `reduce_vif()`는 VIF를 계산하는 `my_stats.compute_vif()`를 가져다 씀.

```python
# my_prep.py의 reduce_vif() 내부
while True:
    vif = my_stats.compute_vif(work)   # ← my_stats의 함수를 가져다 씀
    ...
```

- **사고방식**: `my_stats`(통계 계산)와 `my_prep`(데이터 전처리/변형)는 역할이 다르지만, **서로의 결과물이 필요할 때는 주저 없이 가져다 쓴다**는 설계 철학. "내 모듈이니까 내 안에서 다 해결해야 한다"가 아니라 **"이미 있는 걸 왜 또 짜냐, 가져다 쓰면 되지"** 라는 재사용 마인드가 이 코드베이스 전체에 깔려 있음.
- 실무 관점 참고: 이렇게 양방향으로 import하는 걸 "순환 참조(circular import)"라고 부르는데, 보통은 지양하는 패턴임. 다만 두 모듈이 **함수 단위로만** 서로를 참조하고 모듈이 로드되는 시점에 서로를 즉시 실행하지 않기 때문에 지금 구조에서는 문제없이 동작함. (나중에 직접 헬퍼 모듈을 설계할 때는 "가능하면 순환 없이, 공통 로직은 별도의 third 모듈로 뺀다"는 것도 알아두면 좋음 — 지금 당장 고칠 필요는 없고, "이런 구조가 있다"는 것만 인지)

### `multi_correlation()` 함수도 같은 패턴

```python
def multi_correlation(data, columns=None, ...):
    columns_pairs = list(combinations(columns, 2))   # 모든 변수 조합 쌍 생성
    for col1, col2 in columns_pairs:
        corr = correlation(data, col1, col2, alpha=alpha, plot=False)  # ← 같은 파일의 correlation()을 재사용
        corr_df = concat([corr_df, corr])
    ...
    my_plot.pairplot(...)   # 시각화는 my_plot에 위임
```
→ 지난 시간 배운 `correlation()`(2변수용)을 `combinations()`로 만든 모든 쌍에 대해 반복 호출해서 **다변수 버전으로 확장**한 것. "이미 만든 함수를 여러 번 호출해서 더 큰 기능을 만든다"는 **재사용의 전형적인 예**.

### 4-3. `mtcars` (자동차 32종, 연습문제)

- `mpg`(연료효율성) vs `wt`(무게): **Spearman -0.886, Strong** — 정규성은 만족하지만 **선형성 불만족(linearity=False)** → Spearman 선택 (여기서 지난 시간 배운 `correlation()`의 가정 선택 로직이 다시 그대로 적용됨)
- `mpg` vs `hp`: **Pearson -0.776, Strong** — 정규성·선형성 모두 만족 → Pearson
- `mpg` vs `disp`(배기량): **Spearman -0.909, Strong** — 가장 강한 상관관계
- VIF 확인 결과 `wt`만 VIF 10.368로 기준 초과 → 1단계 제거로 완료 (남은 변수: mpg, disp, hp, drat, qsec + 범주형 변수 그대로 유지)
- **범주형 변수(`cyl`, `vs`, `am`, `gear`, `carb`)는 VIF 계산 대상에서 자동 제외됨** (`compute_vif`가 `select_dtypes(include='number')`로 수치형만 걸러내기 때문). `my_qtcheck.set_type()`으로 미리 범주형 지정해두는 이유가 여기서 드러남 — 안 해두면 숫자로 된 범주형 변수(0/1 코드값 등)까지 VIF 계산에 잘못 섞여 들어갈 수 있음.

## 5. `reduce_vif()` 함수 뜯어보기 (재사용 템플릿)

```python
def reduce_vif(df, columns=None, threshold=10.0, verbose=True):
    # 1) 처리 대상 컬럼 결정 (지정 없으면 수치형 전체, 있으면 존재 여부 검증)
    # 2) 대상이 아닌 컬럼(keep)은 따로 보존해두고, 대상 컬럼(targets)만 복사본으로 작업
    # 3) while True 루프: VIF 계산 → 최댓값이 threshold 미만이거나 컬럼 1개 남으면 종료
    #                      → 아니면 VIF 최댓값 컬럼 제거하고 반복
    # 4) 보존해뒀던 컬럼 + 살아남은 컬럼을 원래 순서대로 합쳐서 반환
```
- **눈여겨볼 설계 포인트**:
  - `columns=None`이면 수치형 컬럼만 자동으로 대상이 되고, 문자열/범주형 컬럼(`keep`)은 건드리지 않고 그대로 최종 결과에 포함시켜줌 → **"수치형만 VIF 대상, 나머지는 원본 그대로 보존"** 이라는 일관된 원칙.
  - 원본 `df`를 직접 수정하지 않고 **복사본(`work`)** 으로 작업 → pandas 원칙("원본 비파괴") 그대로 적용됨.
  - 종료 조건이 **"VIF < threshold" 이거나 "변수가 1개만 남음"** 두 가지라서, 아무리 심각한 다중공선성이어도 무한루프에 빠지지 않고 최소 1개는 남기고 끝나도록 안전장치가 있음.

## 7. 면접 예상 답변 스크립트 (짧은 버전)

**Q. 다중공선성이 무엇이고 어떻게 진단/해결하나요?**

> "다중공선성은 회귀분석에서 독립변수들끼리 서로 강하게 상관되어 있어서, 각 변수가 종속변수에 미치는 개별적인 영향을 통계적으로 구분하기 어려워지는 현상입니다. 단순한 상관계수는 두 변수 사이의 관계만 보여주기 때문에, 세 개 이상의 변수가 얽힌 다중공선성은 VIF(분산팽창계수)로 진단합니다. VIF는 한 변수를 나머지 변수들로 회귀했을 때의 결정계수 R²를 이용해서 1/(1-R²)로 계산하고, 보통 10 이상이면 심각한 다중공선성으로 판단합니다. 해결은 VIF가 가장 큰 변수부터 하나씩 제거하고 남은 변수들로 다시 VIF를 계산하는 과정을 모든 변수의 VIF가 기준 미만이 될 때까지 반복하는 방식으로 진행했습니다."

**Q. VIF가 높다고 무조건 변수를 지워야 하나요?**

> (심화 포인트, 알아두면 좋음) "VIF가 높다는 건 그 변수가 다른 변수들로 잘 설명된다는 뜻이지, 그 변수 자체가 종속변수와 무관하다는 뜻은 아닙니다. 예측이 주 목적이라면 다중공선성이 있어도 모델의 예측 성능 자체는 크게 나빠지지 않을 수 있어서, '어떤 변수의 영향력을 해석해야 하는 상황인지, 순수 예측이 목적인지'에 따라 제거 여부를 판단하는 게 맞습니다. 다만 이번 실습에서는 해석 가능한 회귀모델을 만드는 걸 전제로 VIF 10 기준의 반복 제거를 적용했습니다."
