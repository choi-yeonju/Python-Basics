# LAB-07. 추론통계 개요 — 신뢰구간(CI) 완전 정리

> 이 문서는 "왜 이렇게 계산하는지 → 어떻게 모듈로 재사용하는지 → 새 데이터셋에 어떻게 적용하는지"를 순서대로 볼 수 있게 만든 기본기 참고 문서입니다. 나중에 다른 프로젝트(Olist 등)에서 신뢰구간이 필요할 때 이 문서로 돌아와서 바로 복붙/응용하면 됩니다.

---

## 0. 오늘 배운 것 한 줄 요약

**"표본(일부 데이터)만 보고, 모집단(전체)의 평균이 대략 어느 범위에 있을지 확률적으로 추정하는 것"** = 신뢰구간(Confidence Interval, CI)

그리고 이 계산을 **직접 8단계로 손으로 짜본 뒤 → 내가 만든 `my_stats.ci()` 함수로 한 줄로 축약 → 그 결과를 `my_plot.kdeplot()`으로 시각화**까지 연결하는 실습이었습니다.

---

## 1. 개념부터: 왜 신뢰구간이 필요한가

| 용어                       | 의미                                                                                 | 이번 실습 예시                         |
| -------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------- |
| 모집단(population)         | 알고 싶은 대상 전체                                                                  | 대한민국 사람 전체의 키                |
| 표본(sample)               | 실제로 손에 쥔 데이터                                                                | `origin['키']` (일부 사람 키 데이터) |
| 표본평균                   | 표본의 평균값                                                                        | `sample_mean = data.mean()`          |
| 표본표준편차               | 표본이 평균에서 얼마나 퍼져있는가                                                    | `sample_std = data.std()`            |
| 표준오차(SE)               | "표본평균"이라는 값 자체가 얼마나 흔들릴 수 있는가 (표준편차를 표본크기로 나눠 보정) | `sample_std / sqrt(n)`               |
| 자유도(dof)                | t분포 모양을 결정하는 값. 표본 크기 n에서 추정한 파라미터 수만큼 뺀 값               | `n - 1`                              |
| 신뢰수준(confidence level) | "이 방식으로 구간을 100번 만들면 그 중 몇 번은 진짜 모평균을 포함할까"의 확률        | `clevel = 0.95` (95%)                |
| 신뢰구간(CI)               | 신뢰수준을 만족하는 [하한, 상한] 구간                                                | `(cmin, cmax)`                       |

**핵심 논리 흐름**: 표본평균 하나만 딱 찍어서 "모평균은 이거다"라고 말하는 건 위험합니다. 대신 "표준오차 × t분포의 임계값" 만큼의 폭을 표본평균 좌우로 잡아서 "이 구간 안에 모평균이 있을 가능성이 95%다"라고 말하는 것이 신뢰구간입니다.

- t분포를 쓰는 이유: 모집단의 표준편차를 모르고 표본으로 추정했기 때문에, 정규분포보다 꼬리가 두꺼운 t분포를 사용 (표본이 작을수록 더 넓게 퍼짐 → 표본이 작을 때 불확실성을 더 크게 반영).
- 자유도(dof = n-1)가 커질수록(표본이 커질수록) t분포는 정규분포에 가까워짐.

## 2. 분석 순서 (직접 계산 버전) — "손으로 한 번은 짜봐야 하는 이유"

노트북에서 실제로 진행된 순서 그대로 정리합니다. **이 순서를 외우기보다, 순서 자체가 "신뢰구간 계산 공식을 코드로 분해한 것"임을 이해하는 게 중요**합니다.

```python
from jussam import load_data
from helpers import *
from math import sqrt
from scipy.stats import t

# 1) 데이터 가져오기
origin = load_data('height')

# 2) 신뢰구간을 구할 대상 컬럼 추출
data = origin['키']

# 3) 신뢰수준 정의
clevel = 0.95

# 4) 표본 크기
n = len(data)

# 5) 자유도
dof = n - 1

# 6) 표본평균
sample_mean = data.mean()

# 7) 표본표준편차
sample_std = data.std()

# 8) 표준오차
sample_std_error = sample_std / sqrt(n)

# 9) 신뢰구간 계산 (t분포 활용)
cmin, cmax = t.interval(clevel, dof, loc=sample_mean, scale=sample_std_error)
```

### 이 순서가 갖는 의미

1,2단계는 **"무엇을 분석할지" 대상 확정** (전체 데이터 → 분석할 컬럼)
3단계는 **"어느 정도 확신이 필요한지" 기준 설정** (분석 목적에 따라 0.90/0.95/0.99 등 결정)
4~8단계는 **재료 준비** (n, 자유도, 평균, 표준편차, 표준오차 — 이 재료들은 "신뢰구간 공식"에 들어가는 부품)
9단계는 **공식에 부품을 넣어 최종 결과 도출**

> 💡 새로운 데이터셋을 만나도 이 9단계 순서는 그대로 재사용 가능합니다. 바뀌는 건 `load_data(...)`와 컬럼명뿐입니다.

## 3. 모듈로 감싸기 — `my_stats.ci()`가 하는 일

직접 짠 9단계 코드를 함수 하나로 캡슐화한 것이 `my_stats.py`의 `ci()` 함수입니다.

```python
def ci(data, column=None, clevel=0.95):
    if column is not None:
        data = data[column]        # DataFrame + 컬럼명으로 받은 경우 컬럼만 추출

    n = len(data)
    dof = n - 1
    sample_mean = data.mean()
    sample_std = data.std()
    sample_std_error = sample_std / sqrt(n)

    return t.interval(clevel, dof, loc=sample_mean, scale=sample_std_error)
```

### 호출하는 두 가지 방식 (같은 결과, 입력 형태만 다름)

```python
# 방식 A: 이미 뽑아놓은 Series(연속형 데이터)를 바로 전달
my_stats.ci(data, clevel=0.95)

# 방식 B: DataFrame과 컬럼명을 같이 전달 (내부에서 컬럼 추출을 대신 해줌)
my_stats.ci(origin, column='키', clevel=0.95)
```

**왜 두 가지를 다 지원하게 만들었는가?**

- 이미 `data = origin['키']`처럼 컬럼을 뽑아둔 상태라면 방식 A가 편함
- 아직 원본 DataFrame만 있는 상태라면 매번 `origin['키']`를 따로 안 써도 되게 방식 B를 지원 → **호출하는 사람 입장에서 번거로움을 줄여주는 것이 "재사용 가능한 함수 설계"의 핵심**

## 4. "직접 코드 vs 모듈 호출" — 두 버전 비교

이번 랩의 진짜 포인트는 **동일한 계산을 두 가지 방식으로 할 수 있다는 것을 눈으로 확인**한 것입니다.

| 구분                    | 소스에 직접 코딩                                                   | 모듈 함수 호출                                                               |
| ----------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 코드량                  | 9줄 이상                                                           | 1줄                                                                          |
| 언제 쓰나               | 처음 배울 때, 원리를 이해할 때, 함수를 새로 만들 때(디버깅 기준점) | 원리를 이해한 후, 실전 분석/여러 컬럼 반복 처리할 때                         |
| 장점                    | 각 단계가 눈에 보여서 이해·디버깅이 쉬움                          | 빠르고, 실수(오타, 순서 누락) 가능성이 줄어듦                                |
| 단점                    | 매번 반복 작성해야 하고 길다                                       | 내부 로직을 모르면 블랙박스처럼 느껴질 수 있음                               |
| 이번 실습에서 확인한 것 | `cmin, cmax` (직접 계산)                                         | `my_stats.ci(data, clevel=0.95)` → **완전히 같은 값** 나오는지 검증 |

```python
# 직접 계산한 결과
cmin, cmax = t.interval(clevel, dof, loc=sample_mean, scale=sample_std_error)

# 모듈로 계산한 결과 — 두 결과가 같아야 모듈이 "제대로 작동"하는 것
my_stats.ci(data, clevel=0.95)
my_stats.ci(origin, column='키', clevel=0.95)
```

> ✅ **검증 습관**: 새 함수를 모듈에 추가했으면, 반드시 "직접 계산 버전"과 결과를 나란히 비교해서 같은 값이 나오는지 확인하고 넘어가기. 이번 노트북의 `#03. 모듈 기능 확인` 섹션이 정확히 이 역할을 합니다.

## 5. 모듈을 불러와서 쓴다는 것 — 사고방식 정리

지금 구조는 이렇게 되어 있습니다.

```
helpers/ (패키지)
├── __init__.py     → my_qtcheck, my_plot, my_stats를 한번에 import 되게 연결 + 한글 폰트/그래프 기본값 설정
├── my_qtcheck.py   → 데이터 품질 점검 함수들
├── my_plot.py      → 시각화 함수들 (init, kdeplot, histplot, boxplot, heatmap, barplot, countplot, scatterplot, pairplot ...)
└── my_stats.py     → 통계 분석 함수들 (지금은 ci() 하나, 앞으로 t검정/카이제곱 등 추가될 자리)
```

`from helpers import *` 한 줄이면 `my_plot.kdeplot(...)`, `my_stats.ci(...)`처럼 함수 이름 앞에 모듈명을 붙여서 바로 쓸 수 있는 이유는, `__init__.py`가 `from . import my_plot`, `from . import my_stats` 형태로 **패키지를 열 때 하위 모듈들을 미리 다 불러다 놓기 때문**입니다.

### 왜 이렇게 구조를 나누는가 (확장을 염두에 둔 사고)

1. **관심사 분리(Separation of Concerns)**: "그래프 그리는 코드"와 "통계 계산 코드"를 섞지 않는다 → `my_plot.py`는 그리기만, `my_stats.py`는 계산만 담당
2. **재사용성**: 오늘 만든 `ci()`는 키 데이터뿐 아니라, 광고비/매출액(연습문제)에도, 앞으로 Olist 프로젝트의 배송일/재구매율에도 그대로 쓸 수 있음 — **함수가 특정 데이터셋에 종속되지 않도록 일반화되어 있기 때문**
3. **모듈 간 협업**: `my_plot.kdeplot()` 내부에서 `my_stats.ci()`를 직접 호출해서 신뢰구간 선을 그림 (아래 6번 참고) → 시각화 모듈이 통계 모듈에 "의존"하는 구조. 이렇게 계층을 나눠두면 통계 계산 로직을 한 곳(`my_stats.py`)에서만 고치면 그래프에도 자동 반영됨

### 앞으로 확장할 때 체크리스트

- [ ] 새 통계 함수를 추가할 계획이 있다면 → `my_stats.py`에 함수만 추가하면 됨 (다른 파일 손댈 필요 없음)
- [ ] 그 함수를 그래프에도 반영하고 싶다면 → `my_plot.py`의 관련 함수(`kdeplot` 등)에서 `my_stats.새함수(...)` 형태로 호출 코드 추가
- [ ] 함수를 추가/수정했으면 항상 **"직접 계산 vs 모듈 호출" 비교로 검증** 후 커밋
- [ ] `__init__.py`는 새 파일(`.py`)을 만들었을 때만 `from . import 새파일명` 한 줄 추가해주면 됨 (자주 안 건드림)

## 6. 신뢰구간을 시각화에 연결하기 — `my_plot.kdeplot()`

### (1) 직접 ax를 열어서 신뢰구간 선을 수동으로 그리는 버전

```python
fig, ax = my_plot.init()                                  # 그래프 캔버스 직접 초기화
my_plot.kdeplot(origin, '키', meanline=True, ax=ax)        # KDE(밀도) 그래프만 그림
cmin, cmax = my_stats.ci(origin, column='키', clevel=0.95) # 신뢰구간 계산
ax.axvline(cmin, linestyle=':', color='#0066ff', linewidth=0.5)  # 하한선 직접 그리기
ax.axvline(cmax, linestyle=':', color='#0066ff', linewidth=0.5)  # 상한선 직접 그리기
```

→ `ax=ax`를 넘겼기 때문에 `kdeplot` 함수는 새 캔버스를 만들지 않고 **내가 만든 ax 위에 그림만 얹음**. 이후 `ax.axvline(...)`으로 같은 캔버스에 선을 추가할 수 있음.

### (2) `kdeplot()`이 `clevel`을 받아서 신뢰구간까지 알아서 그려주는 버전 (권장)

```python
my_plot.kdeplot(origin, '키', meanline=True, clevel=0.95)                 # 단일 그룹
my_plot.kdeplot(origin, '키', hue='성별', meanline=True, clevel=0.95)      # 성별로 나눠서
```

`kdeplot()` 내부를 보면:

- `clevel`이 0이 아니면 → `hue`가 없을 땐 전체 데이터로 `my_stats.ci()` 한 번 호출, `hue`가 있으면 **범주(카테고리)별로 각각 `my_stats.ci()`를 호출**해서 그룹마다 다른 색으로 신뢰구간을 표시
- `meanline=True`면 평균선(빨간 점선 혹은 그룹별 색)까지 같이 표시

> 💡 **(1)번을 먼저 손으로 해보고 → (2)번(모듈이 다 해주는 버전)으로 넘어가는 흐름 자체가, 위 4번의 "직접 코드 vs 모듈 호출" 원칙을 시각화에도 그대로 적용한 것**입니다. 함수 안에서 무슨 일이 벌어지는지 안 뒤에 축약형을 쓰는 것과, 모르고 축약형만 쓰는 것은 완전히 다릅니다.

### 주의: `hue`를 쓸 때

- `meanline`은 `kdeplot` 자체 옵션 설명에는 "hue가 설정된 경우 지원하지 않는다"고 docstring에 적혀 있지만, 실제 구현에는 hue별 평균선도 처리하는 분기가 있음 → **docstring과 실제 동작이 다를 수 있으니, 문서만 믿지 말고 실제로 hue를 넣어 실행해서 결과를 눈으로 확인하는 습관**이 필요합니다.

## 7. 연습문제에서 얻은 추가 교훈 (광고비/매출액 데이터)

```python
origin = load_data('ad_sales')
my_plot.kdeplot(origin, '광고비(백만원)', meanline=True, clevel=0.95)
my_plot.kdeplot(origin, '매출액(억원)', meanline=True, clevel=0.95)
```

### melt를 잘못 쓰면 생기는 실수

```python
df = pd.melt(origin, id_vars='월', var_name='구분', value_name='금액')
```

- `id_vars='월'`은 "월" 컬럼은 그대로 유지, 나머지 컬럼(광고비, 매출액)들을 세로로 길게 풀어헤치는 것 (wide → long)
- 이때 생기는 컬럼은 기본적으로 `variable`(원래 컬럼명이 값으로 들어감, 예: '광고비(백만원)')과 `value`(실제 숫자값) → `var_name`, `value_name`으로 이름을 바꿔준 것이 `구분`, `금액`

**실수 포인트**: `variable`(=`구분`) 컬럼은 "광고비"/"매출액" 같은 **범주형(카테고리) 값**이라서 `kdeplot`의 x축(연속형 숫자)으로 쓸 수 없습니다.

```python
# ❌ 잘못된 사용 (범주형 컬럼을 x로 넣음)
my_plot.kdeplot(df, 'variable', hue='월', meanline=True, clevel=0.95)

# ✅ 올바른 사용 (실제 숫자값 컬럼을 x로, 카테고리는 hue로)
my_plot.kdeplot(df, '금액', hue='구분', meanline=True, clevel=0.95)
```

> 📌 **일반 규칙**: `kdeplot`, `histplot` 등 분포를 그리는 함수의 `x`는 반드시 **연속형(숫자) 컬럼**이어야 하고, 그룹을 나누는 기준(카테고리)은 `hue`로 넘긴다. `melt` 이후에는 항상 "어떤 컬럼이 숫자값이고 어떤 컬럼이 카테고리인지" 먼저 확인하고 나서 그래프 함수에 넣기.

## 8. 새로운 데이터셋에 적용할 때 — 초보자용 실전 체크리스트

처음부터 끝까지 한 번에 다 짜지 말고, **작은 단위로 실행 → 결과 확인 → 다음 단계**로 진행하세요.

### Step 1. 데이터 확인 (제일 먼저, 절대 생략 금지)

```python
origin = load_data('데이터셋이름')   # 또는 pd.read_csv(...)
origin.head()
origin.info()          # 컬럼 타입 확인 (숫자형인지 문자형인지)
origin.describe()      # 대략적인 분포 확인
```

- 신뢰구간을 구하려는 컬럼이 **연속형(숫자)**인지 반드시 확인 (범주형이면 애초에 평균/신뢰구간 개념 자체가 안 맞음)

### Step 2. 신뢰구간, 직접 vs 모듈로 둘 다 한번 찍어보기

```python
data = origin['대상컬럼']
# 방식 A
my_stats.ci(data, clevel=0.95)
# 방식 B
my_stats.ci(origin, column='대상컬럼', clevel=0.95)
```

→ 둘이 같은 값 나오면 이 함수는 이 데이터셋에도 문제없이 작동하는 것.

### Step 3. 단일 분포 + 신뢰구간 시각화

```python
my_plot.kdeplot(origin, '대상컬럼', meanline=True, clevel=0.95)
```

→ 이 그래프가 정상적으로 나오는지 먼저 확인. (여기서 에러 나면 컬럼명 오타, NaN 존재, 데이터 타입 문제 등을 먼저 의심)

### Step 4. 그룹별 비교가 필요하면 hue 추가

```python
my_plot.kdeplot(origin, '대상컬럼', hue='그룹컬럼', meanline=True, clevel=0.95)
```

→ `그룹컬럼`은 반드시 카테고리(성별, 지역, 등급 등)여야 함. 연속형 컬럼을 hue로 넣으면 안 됨.

### Step 5. 여러 컬럼을 한 번에 비교해야 한다면 (연습문제처럼)

```python
df = pd.melt(origin, id_vars='기준컬럼', var_name='구분', value_name='값')
my_plot.kdeplot(df, '값', hue='구분', meanline=True, clevel=0.95)
```

→ melt 후에는 `df.head()`로 결과 모양을 눈으로 한 번 확인하고 나서 그래프 함수에 넣기.

### Step 6. 결과 해석

- 신뢰구간이 좁다 → 표본이 많거나 데이터가 안정적(분산이 작음) → 모평균 추정이 비교적 정확
- 신뢰구간이 넓다 → 표본이 적거나 데이터가 들쭉날쭉함(분산이 큼) → 추정이 불확실
- 두 그룹의 신뢰구간이 겹치지 않는다 → 두 그룹의 평균이 유의미하게 다를 가능성이 있다는 힌트 (정식 검증은 이후 배울 t검정/ANOVA 등으로)

## 10. 오늘 자주 헷갈릴 수 있는 포인트 모음

- **표준편차 vs 표준오차**: 표준편차는 "개별 데이터가 평균에서 얼마나 퍼져있나", 표준오차는 "표본평균 자체가 얼마나 흔들리나" (표준편차를 `sqrt(n)`으로 나눔 → 표본이 클수록 표준오차는 작아짐 = 평균 추정이 더 정확해짐)
- **`t.interval()`의 `scale`에는 표준편차가 아니라 표준오차를 넣는다** (자주 헷갈리는 부분)
- **`ax=None`이면 함수가 새 캔버스를 만들고, `ax=ax`를 넘기면 기존 캔버스에 이어 그린다** — 여러 그래프 요소를 겹쳐 그릴 때 핵심 개념
- **melt 후 `variable`/`value` 컬럼의 역할을 헷갈리지 말 것**: `variable`(카테고리)은 `hue`, `value`(숫자)는 `x`
- **함수 docstring과 실제 동작이 항상 일치하지는 않으므로, 애매하면 직접 실행해서 확인**
