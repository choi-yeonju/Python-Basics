# [LAB-07] 8. 이원분산분석 (Two-way ANOVA) — 본검정 + 사후검정 통합본

> 08-1(본검정)과 08-2(사후검정) 두 문서를 하나로 합치고, 중복 설명은 한 번만 남겼다.
> 순서는 실제 분석 흐름 그대로: **개념 → 본검정 → 사후검정 → 모듈 사고방식 → 재사용 템플릿**.
> 앞으로 다른 데이터셋으로 이원분산분석 할 때 이 파일부터 펴놓고 시작할 것.

## 1. 이게 뭘 하는 분석인가 (개념부터)

### 1-1. 일원분산분석과 뭐가 다른가

일원분산분석(one-way ANOVA)은 **독립변수(명목형)가 1개**일 때, 그 변수의 수준(그룹)에 따라 종속변수(연속형)의 평균이 다른지를 본다. 예: "관수빈도(주1회 vs 매일)에 따라 식물 키가 다른가?"

이원분산분석(two-way ANOVA)은 **독립변수가 2개**다. 예: "관수빈도"와 "햇빛 노출량" 두 가지가 동시에 식물 키에 영향을 주는가? 이때 궁금한 건 세 가지로 쪼개진다.

1. **관수빈도의 주효과(main effect)** — 햇빛은 무시하고, 관수빈도만 놓고 봤을 때 키가 다른가?
2. **햇빛 노출량의 주효과** — 관수는 무시하고, 햇빛만 놓고 봤을 때 키가 다른가?
3. **상호작용 효과(interaction effect)** — 관수빈도가 키에 미치는 영향이 햇빛 노출량 수준에 따라 달라지는가? (반대로 말해도 같음)

세 번째 **상호작용**이 이원분산분석의 핵심이자 일원분산분석과 결정적으로 다른 지점이다. 두 요인을 따로따로 일원분산분석 두 번 돌리면 절대 알 수 없는 정보다.

### 1-2. ANOVA(분산분석)가 근본적으로 하는 일

분산분석은 "여러 집단의 평균이 모두 같다"는 가정(귀무가설)이 맞는지를 검정하는 방법이다. **ANOVA는 "어딘가에 차이가 있다/없다"만 알려줄 뿐, "정확히 어느 조합끼리 다른지"는 답해주지 않는다.** 그래서 뒤에 나오는 사후검정(6절)이 필요해진다.

### 1-3. 상호작용을 말로 풀면

"상호작용이 있다"는 말은 **"A의 효과가 B에 따라 달라진다"**는 뜻이다. 독극물(poison) 실습 문제가 가장 좋은 예다.

- 해독제 T4가 전체 평균으로는 가장 좋았다 (T4 > T3 > T2 > T1)
- 그런데 독극물이 P1일 때만 따로 보면, 오히려 T2가 제일 좋고 T4는 3등으로 밀린다
- 즉 "어떤 해독제가 최선인가"라는 질문의 답이 "어떤 독극물이냐"에 따라 뒤바뀐다 → 이게 상호작용이 있다는 것

반대로 "상호작용이 없다"는 건 두 요인의 효과가 **평행하게(독립적으로) 더해진다**는 뜻이다. 교육방법 실습에서 "2번 교육방법이 국어에서 +6.8점, 영어에서 +4.5점"처럼 방향과 크기가 비슷하게 유지되면 상호작용이 없다고 본다. 그래프로 그리면 선이 서로 교차하지 않고 거의 평행하게 나온다 (→ interaction plot으로 시각 확인하는 이유).

**실무적으로 왜 중요한가**: 상호작용이 유의하면, 주효과만 보고 "A 요인이 좋다"고 결론 내리면 안 된다. 조합(셀) 단위로 다시 봐야 한다. 독극물 문제의 결론도 "해독제 하나를 표준으로 채택"이 아니라 "독극물별로 다른 해독제를 써야 한다"였다. (이 서브그룹 확인 방법은 7절에서 다시 자세히 다룸)

## 2. 가설 설정 — 기호만 말고 말로 풀어서

이원분산분석은 가설이 세 쌍(주효과 A, 주효과 B, 상호작용) 나온다는 걸 꼭 기억해야 한다.

**요인 A (예: 관수빈도)의 주효과**

- 귀무가설 H0: 관수빈도의 각 수준(주1회, 매일)에 따른 식물 키의 모평균은 모두 같다. (관수빈도는 키에 영향을 주지 않는다)
- 대립가설 H1: 관수빈도의 수준 중 적어도 하나는 평균 키가 다르다.

**요인 B (예: 햇빛 노출량)의 주효과**

- H0: 햇빛 노출량 수준(low, med, high)에 따른 식물 키의 모평균은 모두 같다.
- H1: 적어도 하나의 수준에서 평균 키가 다르다.

**상호작용 효과 (관수빈도 × 햇빛 노출량)**

- H0: 관수빈도가 키에 미치는 효과는 햇빛 노출량 수준과 관계없이 일정하다. (두 요인은 독립적으로 작용한다 = 상호작용 없음)
- H1: 관수빈도가 키에 미치는 효과가 햇빛 노출량 수준에 따라 달라진다. (상호작용 있음)

기호로 쓰면 μ₁ = μ₂ = ... 형태지만, 말로 풀면 "여러 조합 사이에 실제로는 아무 차이가 없다"가 귀무가설, "적어도 한 조합은 평균이 다르다"가 대립가설이다. **주의**: 대립가설은 "모든 조합이 서로 다르다"는 뜻이 아니라 "전부 같다고는 말할 수 없다"는 뜻이다 — 이 뉘앙스 차이를 헷갈리면 안 된다.

세 가지 검정(주효과A, 주효과B, 상호작용)을 **한 번의 이원분산분석에서 동시에** 얻어낸다는 게 포인트. 면접에서는 "뮤(μ), 모평균이 서로 같다는 게 귀무가설이고, 적어도 하나는 다르다는 게 대립가설이다" 정도로 풀어 말하면 된다.

## 3. 전체 분석 파이프라인 (본검정 → 사후검정)

이 순서를 몸에 익히면 다른 데이터셋에도 그대로 적용 가능하다.

```
[본검정]
1) 데이터 불러오기 + 형태 확인 (long format인지 확인, 필요하면 melt로 wide→long)
2) 데이터 분포 시각화로 감 잡기 (kdeplot 등)
3) 분산분석의 가정 확인
   └─ 정규성 검정 (normaltest)
   └─ 등분산성 검정 (Bartlett or Levene) — 정규성 결과에 따라 자동 선택됨
4) 가정 충족 여부에 따라 분석 방법 분기
   ├─ 등분산 충족 → 일반 이원분산분석 (pingouin.anova)
   └─ 등분산 미충족 → OLS(HC3) 기반 Type-II ANOVA
5) 결과표 해석 (p-value로 유의성 / np2로 효과크기, 3개 효과 각각)
6) 상호작용 플롯으로 시각화 (두 방향 다 그려봄)

[사후검정] (상호작용 또는 주효과가 유의하다면, 혹은 세부 확인이 필요하다면)
7) 두 명목형 변수를 조합해 "셀(cell)" 단위 그룹 컬럼 생성
8) 등분산성 가정 재검정 (셀 단위로)
9) 등분산 충족 여부에 따라 사후검정 방법 분기
   └─ 충족 → Tukey HSD / 미충족 → Games-Howell
10) 결과표 가공 (significant, effect_size 컬럼 추가, A·B 기준 정렬)
11) 시각화 (조합별 boxplot)
12) 결과 요약 (비교쌍 수 / 유의한 쌍 수 / 최대·최소 차이 쌍 / 요인 수준별 유의 쌍 수)
```

**왜 이 순서인가?**

- 1→3: 통계에서 "가정을 확인하고 → 그 가정에 맞는 검정을 선택한다"는 흐름은 LAB-07 전체(대응표본, 독립표본, ANOVA, 사후검정)에서 반복되는 원칙.
- 6→7: 이원분산분석의 "상호작용"을 사후검정에서 직접 보려면, 두 요인의 조합을 하나의 그룹으로 묶어야 짝비교가 가능해진다.
- 7→9: 짝비교 방법(Tukey vs Games-Howell)을 고르기 전에 반드시 등분산 가정을 먼저 확인해야 한다. 순서가 바뀌면 안 된다.

이 순서는 일원분산분석(LAB07 앞부분)의 "가정확인 → 분기 → 사후검정" 골격과 동일하다. 다른 점은 독립변수가 2개라서 **주효과 두 개 + 상호작용 하나**로 결과가 세 줄 나온다는 것.

## 4. 가정 확인 — 왜 하고 뭘 보는가

이원분산분석도, 사후검정도 결국 분산 기반 검정이라 아래 가정이 필요하다.

- **정규성(normality)**: 각 조합(셀)의 데이터가 정규분포를 따르는가. `normaltest`로 검정.
- **등분산성(homogeneity of variance)**: 조합들 간 분산(퍼짐 정도)이 서로 비슷한가.
  - 귀무가설 H0: 모든 집단의 모분산이 같다 (σ₁² = σ₂² = ... = σₖ²). 말로 하면 "집단마다 데이터가 퍼진 정도에 차이가 없다."
  - 대립가설 H1: 적어도 한 집단은 분산이 다르다.
  - 정규성 충족되면 → **Bartlett 검정** 사용 (정규분포를 가정하는 검정이라 더 정확함)
  - 정규성 깨지면 → **Levene 검정** 사용 (정규성에 덜 민감한 대안)
  - `test_assumptions()` 함수가 이 분기를 내부에서 자동으로 처리한다.

**왜 등분산성이 결과 방법을 갈라놓는가**: 일반 ANOVA(F검정)나 Tukey HSD는 "모든 집단의 분산이 같다"는 전제 위에서 세워진 공식이다. 이게 깨지면 F값과 p값이 왜곡될 수 있다. 그래서 등분산이 깨지면, 분산이 달라도 안정적으로 작동하는 방법(본검정은 강건표준오차 HC3 회귀모형, 사후검정은 Games-Howell)으로 우회한다.

**조합별 데이터 배치**: 등분산성 검정을 하려면 "요인A × 요인B" 조합(셀)별로 값을 따로 묶어야 한다. 원본 코드에서는 이중 for문으로 직접 만들었고, 모듈에서는 `my_prep.long2wide()`가 이 작업을 대신해준다.

## 5. 본검정 — 등분산 충족 vs 미충족 두 갈래

### 5-1. 등분산 충족 시: 일반 이원분산분석

```python
aov = anova(data=data, dv=yname, between=xname)  # pingouin
```

- `dv`(dependent variable) = 종속변수, `between` = 독립변수 리스트(길이 2)
- 결과표(`Source` 컬럼)에 나오는 줄: 요인A, 요인B, 요인A*요인B(상호작용), Residual(잔차)

### 5-2. 등분산 미충족 시: OLS(HC3) 기반 Type-II ANOVA

```python
model = ols(f"{yname} ~ C({xname[0]}) * C({xname[1]})", data=data)
fit = model.fit(cov_type="HC3")
aov = sm.stats.anova_lm(fit, typ=2, robust="hc3")
```

- `C(변수명)`: 해당 변수를 범주형(Categorical)으로 명시.
- `*`: "두 변수의 주효과 + 상호작용을 모두 포함해라"는 뜻의 공식(formula) 문법. (`+`만 쓰면 상호작용 항이 빠짐)
- `cov_type="HC3"`: 등분산 가정이 깨져도 안정적인 표준오차를 계산하는 방식
- `typ=2`: Type-II 제곱합 방식 (불균형 설계에서도 상호작용이 없다는 전제하에 주효과를 안정적으로 추정)
- **주의**: statsmodels 결과표에는 np2가 기본으로 없어서, 모듈에서는 직접 계산한다: `np2 = SS_effect / (SS_effect + SS_residual)`

### 5-3. 실무 판단 포인트

"이 데이터가 등분산을 충족하는지"는 매번 다르므로, 사람이 눈으로 보고 판단하는 대신 `equal_var` 불리언 값으로 자동 분기시켜서 재사용 가능하게 만든 것. → 이게 모듈화하는 이유이기도 하다 (8절 참고).

## 6. 본검정 결과표 읽는 법

| 컬럼                   | 의미                                                           |
| ---------------------- | -------------------------------------------------------------- |
| `Source`             | 어떤 효과인지 (요인A / 요인B / 요인A*요인B / Residual)         |
| `F`                  | F통계량. 클수록 "집단간 차이가 집단내 차이보다 크다"는 뜻      |
| `p_unc` / `PR(>F)` | 유의확률.**< 0.05면 귀무가설 기각 (그 효과가 유의하다)** |
| `np2`                | partial eta-squared(부분 에타제곱). 효과크기                   |
| `significant`        | p < alpha 여부를 True/False로 판정한 컬럼                      |
| `effect_size`        | np2를 등급으로 변환한 것                                       |

### 효과크기(partial η², np2) 해석 기준 — 코헨(Cohen) 기준표

- np2 ≥ 0.14 → **Large(큼)**
- np2 ≥ 0.06 → **Medium(중간)**
- np2 ≥ 0.01 → **Small(작음)**
- 그 미만 → **Negligible(미미함)**

## 7. p-value와 유의수준, 효과크기 — 본검정·사후검정 공통으로 계속 나오는 개념

이원분산분석부터 사후검정까지 계속 반복해서 쓰이는 세 가지 개념을 여기서 한 번에 정리한다.

### 7-1. p-value란 무엇인가 (말로)

- **p-value**: 귀무가설이 참이라고 가정했을 때, 지금 관찰된 정도(또는 더 극단적인 정도)의 차이가 우연히 나타날 확률.
- p-value가 작다 = "이 정도 차이가 순전히 우연으로 생기기는 어렵다" = 귀무가설을 의심할 근거가 커진다.
- **유의수준(α, 보통 0.05)**: "이 정도 확률 이하로 드물면, 우연이 아니라고 판단하겠다"는 미리 정해두는 기준선.
- p-value < α → 귀무가설 기각 (통계적으로 유의한 차이가 있다고 판단)
- p-value ≥ α → 귀무가설을 기각할 근거 부족. **"차이가 없다"는 뜻이 아니라 "차이가 있다고 말할 만큼 증거가 충분하지 않다"는 뜻** — 면접에서 자주 물어보는 표현 차이.

교육방법 예제(본검정)가 이 상황을 정확히 보여준다: 교육방법 효과는 p=0.057로 "유의하지 않다"고 판정됐지만, np2=0.088로 Medium 등급이었다. "통계적으로 확실하다고 말하긴 어렵지만, 효과 크기 자체는 무시할 수준이 아니다" → 표본을 늘려 재검정해볼 필요가 있다는 결론.

edu 사후검정 예제에서도 (1,국어) vs (2,국어)의 p-value가 0.356으로 나왔는데, 평균 차이는 6.818점으로 커 보였다. 집단당 표본이 11명뿐이라 "이 차이가 우연이 아니다"라고 말할 만큼 증거가 부족했던 것 — 같은 논리다.

### 7-2. 효과크기(Effect Size) — 본검정용 vs 사후검정용이 다르다

- **np2 (partial eta squared, 편에타제곱)**: **본검정(ANOVA) 단계**에서 쓴다. "전체 변동 중 이 요인(또는 상호작용)이 설명하는 비율"을 뜻함. 기준: ≥0.14 큼 / ≥0.06 중간 / ≥0.01 작음 / 미만 미미함.
- **Hedges' g**: **사후검정(짝비교) 단계**에서 쓴다. 두 집단 평균 차이를 표준편차 단위로 표준화한 값 (Cohen's d와 비슷하지만 표본이 작을 때 보정이 추가된 버전). 기준: 절댓값 ≥0.8 큼 / ≥0.5 중간 / ≥0.2 작음 / 미만 미미함.

**핵심 사고방식**: p-value는 "차이가 우연이 아니라고 말할 수 있는가"를 답하고, 효과크기는 "그 차이가 실질적으로 얼마나 큰가"를 답한다. **완전히 다른 질문**이라서 "유의하지 않지만 효과크기는 Medium" 같은 상황이 실제로 생긴다. 이 두 지표는 항상 같이 봐야 한다.

## 8. 사후검정 — 왜, 어떻게

### 8-1. 왜 사후검정이 필요한가 (핵심 논리)

ANOVA에서 귀무가설이 기각되면 "적어도 한 곳은 다르다"는 것만 안다. 어느 조합과 어느 조합 사이인지 알려면, 조합을 둘씩 짝지어서 **개별적으로** t검정과 비슷한 비교를 해야 한다.

문제는 여기서 발생한다. 조합이 4개면 짝의 수는 4×3÷2 = 6쌍, 12개면 12×11÷2 = 66쌍이다. **비교 횟수가 많아지면, 유의수준 5%를 그대로 써도 우연히 유의하게 나오는 쌍이 늘어난다** (제1종 오류의 누적). 그래서 Tukey HSD나 Games-Howell 같은 사후검정 방법은 **다중비교를 보정**해서, 여러 번 비교해도 전체적인 오류율이 5%를 넘지 않도록 더 엄격한 기준을 적용한다. → "쌍마다 t검정을 따로 돌리는 것보다 보수적인 결과가 나온다"는 표현이 이 뜻.

### 8-2. Tukey HSD vs Games-Howell — 언제 뭘 쓰는가

| 구분      | Tukey HSD                                                                     | Games-Howell                                                    |
| --------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 전제 조건 | 등분산 충족 + (대체로) 표본 크기 비슷                                         | 등분산 불충족 시에도 사용 가능                                  |
| 원리      | 모든 집단이 같은 분산을 공유한다고 가정하고, 표준화된 차이(HSD 통계량)로 비교 | 각 집단의 분산을 따로 반영해서 비교 (Welch t검정과 비슷한 원리) |
| 언제 선택 | `equal_var == True`                                                         | `equal_var == False`                                          |

**중요한 사고방식**: "어떤 사후검정을 쓸지"는 사람이 임의로 정하는 게 아니라, **직전에 수행한 등분산성 검정 결과가 자동으로 결정**하도록 코드가 짜여 있다. 이게 `posthoc_twoway` 함수 내부에서 `equal_var` 변수 하나로 분기 처리되는 이유.

### 8-3. 사후검정 결과표에서 봐야 할 컬럼

- `diff`: 두 조합 평균의 차이
- `pval`: 그 차이가 유의한지 (7-1절 참고)
- `hedges`: 표준화된 효과크기 (7-2절 참고)
- `significant`: pval < alpha 여부
- `effect_size`: hedges 절댓값을 등급으로 변환한 것

## 9. 상호작용 효과 — 사후검정에서 실제로 확인하는 법

이원분산분석에서 상호작용이 유의하다는 것은 "한 요인의 효과가 다른 요인의 수준에 따라 달라진다"는 뜻이다 (1-3절에서 개념 설명함). 사후검정 단계에서는 이걸 **서브그룹 분석**으로 직접 눈으로 확인한다.

poisons 예제가 좋은 사례다: P1(독극물1)에서는 해독제를 뭘 써도 통계적으로 차이가 없었지만(6쌍 모두 유의하지 않음), P3(독극물3)에서는 6쌍 중 5쌍이 유의했다. **같은 데이터, 같은 사후검정인데 독극물 종류에 따라 결론이 완전히 달라진다** — 이게 상호작용 효과가 실무적으로 의미하는 바다.

그래서 사후검정 결과를 볼 때 전체 평균으로 뭉뚱그리지 않고, **한 요인의 수준을 고정한 채 나머지 요인끼리만 비교하는 서브그룹 분석**을 같이 해야 한다 (코드의 `for lv in df[between[0]].unique():` 부분). 상호작용이 유의하면 "요인 하나만 놓고 본 주변평균(marginal mean)"이 아니라 "두 요인을 조합한 셀 평균(cell mean)"으로 결론을 내려야 한다는 원칙이 여기서 나온다.

**주의**: "평균이 높다" ≠ "통계적으로 유의하게 낫다". poisons 문제에서 T4가 전체 평균 1위였지만 P1에서는 3위였던 게 정확히 이 함정을 보여준다. 평균 순위만 보고 실무 결정을 내리면 안 된다.

## 10. 데이터 재배치 — melt (wide → long)

이원분산분석은 **"요인 = 값(하나의 열에 범주로 들어있음)"인 long 형태**를 요구한다. "국어 점수", "영어 점수"가 각각 별도 컬럼(wide)으로 있으면 안 되고, "과목"이라는 하나의 컬럼에 "국어"/"영어"가 값으로 들어가고 "점수"라는 컬럼에 숫자가 들어가야 한다.

```python
from pandas import melt

df_long = melt(origin,
               id_vars='교육방법',           # 유지할 식별자 컬럼
               value_vars=['국어', '영어'],   # 녹여서 값으로 만들 컬럼들
               var_name='과목',              # 원래 컬럼명들이 모일 새 컬럼명
               value_name='점수')            # 원래 값들이 모일 새 컬럼명
```

- 원본 22행(학생) × (교육방법, 국어, 영어) → melt 후 44행(학생×과목) × (교육방법, 과목, 점수)
- 학생 1명이 국어/영어 두 개의 관측치를 갖게 되므로 **행 수가 배로 늘어난다**
- 이 44라는 숫자가 나중에 잔차 자유도(44 - 4개 셀 = 40)로 다시 연결된다 → 데이터 구조를 이해하면 결과표의 자유도(df)도 검산 가능

**판단 기준**: 데이터를 보고 "요인이 몇 개인지, 그 요인이 지금 열 이름으로 숨어있는지 값으로 들어있는지"를 먼저 파악하는 습관이 중요하다. 열 이름 자체가 사실은 하나의 요인 수준이라면 melt가 필요하다는 신호.

## 11. 코드 두 가지 버전 — "직접 코딩" vs "모듈 호출"

오늘 실습에는 정확히 두 층위의 코드가 같이 존재했다. 본검정(anova_twoway)과 사후검정(posthoc_twoway) 둘 다 마찬가지 구조다.

**버전 A. 소스에 직접 풀어 쓴 코드**

```python
# 본검정 예: 조합별 데이터를 직접 wide로 만들고 anova() 직접 호출
groups = {}
for i in data[xname[0]].unique():
    for j in data[xname[1]].unique():
        filtered_data = data[(data[xname[0]]==i) & (data[xname[1]]==j)][yname]
        groups["{0}, {1}".format(i, j)] = filtered_data.reset_index(drop=True)
...
aov = anova(data=data, dv=yname, between=xname)

# 사후검정 예: pairwise_tukey 직접 호출
posthoc = pairwise_tukey(data=ph, dv=yname, between='group')
posthoc['significant'] = posthoc['pval'] < 0.05
```

- **목적**: 검정이 내부적으로 어떤 단계를 거치는지 눈으로 직접 확인하고, 원리를 이해하기 위한 코드.
- 처음 배울 때는 이 버전을 한 줄씩 실행하면서 각 단계에서 데이터가 어떻게 바뀌는지 확인하는 게 맞다.

**버전 B. 모듈 함수 호출**

```python
aov = my_stats.anova_twoway(origin, y='height', between=['water', 'sun'])
post = my_stats.posthoc_twoway(df2, y='time', between=['poison', 'treat'], palette='tab10')
```

- **목적**: 버전 A의 모든 단계(가정 검정 → 방법 분기 → 결과 가공 → 시각화 → 요약 출력)를 함수 하나로 캡슐화해서 다음부터는 한 줄로 재사용하기 위한 코드.
- 실무/포트폴리오에서는 이 버전을 쓰게 된다.

**두 버전을 넘나드는 사고방식**

1. 먼저 버전 A로 원리를 이해한다 — 등분산 검정이 뭘 하는지, anova()/pairwise_tukey()가 뭘 반환하는지, significant/effect_size 컬럼을 왜 만드는지.
2. 이해가 끝나면 버전 B(모듈)로 옮긴다 — 매번 여러 단계를 손으로 치지 않고, 검증된 함수 하나로 처리.
3. **모듈을 새 데이터셋에 쓸 때는 처음부터 끝까지 다 도는 게 아니라, 먼저 작은 단위로 작동 확인부터 한다.** 예:
   - `test_assumptions(wide)` 결과만 먼저 찍어보고 등분산 여부 확인
   - `pairwise_tukey`/`pairwise_gameshowell` 결과표의 컬럼 이름이 예상과 같은지 확인 (pingouin 버전에 따라 `p-tukey`/`p_tukey`처럼 다를 수 있어서, 코드에도 방어 로직이 이미 들어있음: `pcol = "p-tukey" if "p-tukey" in result.columns else "p_tukey"`)
   - 문제없으면 그제서야 전체 함수를 호출

이게 **"처음부터 끝까지 다 코딩한다"가 아니라 "이미 검증된 부품(모듈)을 가져다 쓰되, 그 부품이 뭘 하는지는 알고, 새 데이터에는 먼저 작동부터 확인한다"**는 맞는 사고방식이다.

## 12. `helpers` 모듈 사고방식 — `my_stats`, `my_plot`, `my_prep`을 어떻게 대해야 하는가

```
helpers/
├── __init__.py      # 패키지를 초기화하고 하위 모듈들을 묶어서 노출시키는 역할
├── my_stats.py       # test_assumptions, anova_twoway, posthoc_twoway 등 통계 함수
├── my_plot.py         # init, pointplot, kdeplot, boxplot, show 등 시각화 함수
├── my_prep.py         # long2wide 등 데이터 형태 변환 함수
└── my_qtcheck.py
```

- `__init__.py`는 "이 폴더가 하나의 패키지(package)"라고 파이썬에게 알려주면서, 동시에 `my_stats`, `my_plot`, `my_prep` 같은 하위 모듈들을 밖에서 `모듈이름.함수이름()` 형태로 바로 부를 수 있게 연결해준다.
- `from helpers import *`를 하면 `__init__.py`가 노출시킨 이름들이 지금 코드에서 바로 쓸 수 있게 들어온다. 그래서 `my_stats.anova_twoway(...)`처럼 **"모듈이름.함수이름"** 형태로 호출하는 것.

### 모듈을 "블랙박스"가 아니라 "내가 만든 부품 상자"로 대하는 법

1. **함수 안에서 무슨 일이 일어나는지 한 번은 직접 열어본다.** docstring(Args/Returns 설명)을 먼저 읽고, 내부 코드를 주석 단위로 따라가며 흐름을 손으로 그려본다.
2. **함수는 항상 "입력 → 처리 → 반환"의 관점에서 본다.**
   - 입력: `data`(long형 DataFrame), `y`(연속형 컬럼명), `between`(명목형 컬럼명 리스트 2개)
   - 처리: 결측 제거 → wide 변환 → 가정 검정 → 검정 실행 → 결과 가공
   - 반환: 결과표(DataFrame) — 다음 분석(시각화, 요약, 다른 함수 입력)에 재사용됨
3. **함수 간 의존관계를 파악해둔다.** 예를 들어 `posthoc_twoway`는 내부에서 `my_prep.long2wide`, `my_stats.test_assumptions`, `my_plot.boxplot`, `my_plot.show`를 호출한다. `my_stats`가 `my_prep`과 `my_plot`을 조합해서 쓰는 상위 계층이라는 걸 알아야, 버그가 났을 때 어디부터 볼지 감이 잡힌다.
4. **모듈을 확장할 때는 기존 함수의 스타일(파라미터 순서, 반환 형태, 컬럼명 규칙)을 그대로 따라간다.** 모든 검정 함수가 `test`, `significant`, `effect_size` 컬럼을 관례적으로 붙이듯, 새 함수도 이 관례를 유지하면 나중에 결과표를 한꺼번에 다룰 때 편해진다.
5. **버그는 항상 "재현 → 최소 예제로 축소 → 수정 → 재검증" 순서로 잡는다.**

### `anova_twoway()` 한 줄 뒤에 숨은 단계 (예시로 순서를 익혀두면 다른 함수도 같은 방식으로 뜯어볼 수 있다)

```
1) y, between 컬럼만 추출 + 결측치 제거
2) 두 명목변수를 합쳐 "조합(셀)" 컬럼 생성 → long2wide로 등분산성 검정용 표 생성
3) test_assumptions()로 등분산성(equal_var) 판정
4) equal_var 값에 따라 pingouin.anova() 또는 ols(...).fit(cov_type="HC3") 실행
5) np2 계산, effect_size 등급 매기기, significant 컬럼 추가
6) plot=True면 상호작용 플롯 2개(x축/hue를 서로 바꿔서) 자동으로 그림
7) 결과표(DataFrame) 반환
```

### 파라미터 기본값을 볼 때 체크하는 습관

- `alpha=0.05`: 관행적 유의수준. (예전에 확인했던 버그 `alpha=0.5`와 헷갈리지 않기)
- `order=None`: 안 주면 categorical 타입 순서 또는 데이터 등장 순서를 그대로 씀 → 그래프 순서가 이상하면 직접 지정해야 한다는 신호
- `plot=True`: 매번 그래프가 자동으로 그려지므로, 결과표만 빠르게 보고 싶을 때는 `plot=False`로 꺼야 함

### 모듈 사용시 체크리스트 (새 함수를 처음 쓸 때)

- [ ] docstring(Args/Returns)부터 읽는다
- [ ] 필요한 컬럼(y, between)이 데이터에 실제로 있는지, 타입이 맞는지 확인한다
- [ ] 결측치가 얼마나 빠지는지 직접 확인한다 (내부에서 `dropna()` 하더라도)
- [ ] 함수를 한 번 호출해보고 반환된 DataFrame의 컬럼 구성을 `head()`/`columns`로 확인한다

## 14. 자주 헷갈리는 포인트 정리

- **"평균이 높다" ≠ "통계적으로 유의하게 낫다".** 평균 순위만 보고 실무 결정을 내리면 안 된다.
- **"유의하지 않다" ≠ "차이가 없다".** "차이가 있다고 말할 근거가 부족하다"로 표현해야 정확하다.
- **p-value와 effect size는 다른 질문에 답한다.** 유의하지 않아도 효과크기는 Medium/Large일 수 있다.
- **다중비교가 많아질수록(조합 수가 늘수록) 보정된 사후검정을 반드시 써야 한다.** 쌍마다 개별 t검정을 쓰면 안 되는 이유.
- **등분산 가정 검정 결과가 검정 방법(일반 ANOVA vs Type-II, Tukey vs Games-Howell)을 자동으로 결정한다.** 사람이 임의로 고르는 게 아니다.
- **모듈 함수는 pingouin 버전에 따라 반환 컬럼명이 달라질 수 있다.** 새 환경에서 에러가 나면 이 부분부터 의심.

## 15. 면접용 한 문장 요약 모음

- **이원분산분석이 일원분산분석과 다른 점**: "독립변수가 2개라서 두 요인의 주효과뿐 아니라, 두 요인이 서로 맞물려 작용하는 상호작용 효과까지 한 번에 검정할 수 있습니다."
- **사후검정이 필요한 이유**: "ANOVA는 '어딘가 차이가 있다'는 것만 알려주기 때문에, 어느 집단 사이에 차이가 있는지 확인하려면 다중비교를 보정하는 사후검정을 추가로 수행합니다."
- **등분산성에 따른 분기(본검정)**: "등분산 가정을 만족하면 일반 이원분산분석을, 만족하지 않으면 강건표준오차(HC3)를 적용한 회귀 기반 Type-II ANOVA를 사용합니다."
- **Tukey HSD vs Games-Howell 선택 기준**: "등분산성 가정을 만족하면 Tukey HSD를, 만족하지 않으면 분산 차이를 보정하는 Games-Howell을 사용합니다."
- **p-value와 효과크기의 관계**: "p-value는 그 차이가 우연이 아니라고 말할 수 있는지를 보여주고, 효과크기는 그 차이가 실질적으로 얼마나 큰지를 보여줘서, 두 지표를 함께 봐야 합니다."
- **상호작용 효과**: "한 요인의 효과가 다른 요인의 수준에 따라 달라지는 것을 말하며, 그래서 전체 평균만 보지 않고 한 요인을 고정한 서브그룹 비교를 함께 확인합니다."
