# LAB-09. 단순선형회귀 가정 검정 — 기본기 정리

> 이 문서는 `cars` 데이터셋으로 단순선형회귀를 적합한 뒤, 4대 가정(선형성/정규성/등분산성/독립성)을
> 검정하는 실습을 복습하기 위한 기준 문서다. 앞으로 다른 데이터셋으로 회귀분석을 할 때마다
> 이 문서를 먼저 열어서 순서와 개념을 다시 확인하는 용도로 쓴다.

## 0. 오늘 한 일 한 줄 요약

`cars` 데이터로 `dist ~ speed` 단순선형회귀를 적합하고, 잔차(residual)를 이용해
**선형성 → 정규성 → 등분산성 → 독립성** 순서로 4가지 가정을 검정했다. 그리고 이 과정을
매번 손으로 치는 대신 `my_ols.py` 라는 나만의 모듈로 함수화했고, `father-son` 데이터로
연습문제까지 풀어서 **완성된 모듈**로 검증했다.

**최종적으로 `my_ols.py` 모듈에 채워진 함수 목록** (이게 사실상 "나만의 회귀분석 도구 세트"다):

| 함수                                  | 역할                                                           |
| ------------------------------------- | -------------------------------------------------------------- |
| `fit_model(data, y, summary=False)` | 모델 적합 (y 뺀 나머지 전부 독립변수)                          |
| `predict(fit, new_data)`            | 새 데이터에 대한 예측값 생성                                   |
| `test_linear(fit, ...)`             | 선형성 검정 (Ramsey RESET + 잔차 산점도)                       |
| `test_normal(fit, ...)`             | 정규성 검정 (Shapiro/K-S 자동선택 + Q-Q plot + 루트MSE 잔차도) |
| `test_equalvar(fit, alpha=0.05)`    | 등분산성 검정 (Breusch-Pagan)                                  |
| `test_independent(fit)`             | 독립성 검정 (Durbin-Watson)                                    |
| `report_fitness(fit, ...)`          | 모형 적합도를 논문 보고 형식 문장으로 자동 생성                |
| `report_variables(fit, data)`       | 독립변수별 B·베타·VIF 등을 표로 정리                         |
| `report_variables_text(fit, ...)`   | 독립변수별 해석을 불릿 문장으로 자동 생성                      |

즉 오늘 배운 걸로 앞으로는 **가정검정 4줄 + 보고 문장 자동생성 3줄**, 총 7~8줄 정도로
"데이터 넣고 → 가정 확인하고 → 보고서 문장까지 뽑는" 흐름이 끝난다.

## 1. 전체 분석 파이프라인 (순서가 중요함)

회귀분석의 가정 검정은 아무렇게나 순서를 바꿔도 되는 게 아니라, **잔차를 만들어야
그 다음 단계들을 검정할 수 있는 구조**다. 순서를 이렇게 기억하면 된다.

```
0) [EDA] 산점도 + 상관분석 (my_stats.correlation)
      │  → 회귀분석을 적용해도 되는지 사전 근거 확보
      ▼
1) 데이터 로드
2) OLS 모델 적합 (fit)
      │
      ▼
3) 예측값(y_pred) 추출  ─┐
4) 잔차(resid) 계산      ├─ 이 둘을 원본 데이터에 합쳐서 분석용 df(ols_df) 생성
      │
      ▼
5) [선형성 검정]  예측값 vs 잔차 산점도 + Ramsey RESET Test
      │
      ▼
6) [정규성 검정]  Q-Q Plot + 루트MSE 68-95-99.7 구간 + Shapiro-Wilk/K-S 검정
      │
      ▼
7) [등분산성 검정]  Breusch-Pagan Test
      │
      ▼
8) [독립성 검정]  Durbin-Watson
      │
      ▼
9) [예측]  새 데이터(new_x)로 predict() → 원본과 병합해 시각화로 검증
      │
      ▼
10) [보고]  report_fitness / report_variables / report_variables_text
       → 적합도·계수·해석을 사람이 읽는 문장/표로 자동 생성
```

**왜 이 순서인가?**

- EDA(상관분석)를 가장 먼저 하는 이유는 애초에 "이 두 변수를 선형회귀로 묶어도 되는가"부터
  확인해야 하기 때문이다. `my_stats.correlation()`은 정규성·선형성·영향점을 미리 점검해서
  Pearson을 쓸지 Spearman을 쓸지 자동으로 골라준다 — **회귀를 적합하기 전에 이미 한 번
  선형성 비슷한 걸 훑어보는 단계**라고 이해하면 된다.
- 선형성이 깨져 있으면 애초에 "직선 모형"이 잘못된 것이므로, 뒤의 정규성/등분산성/독립성
  검정 자체가 의미가 없어질 수 있다. 그래서 4대 가정 중에서는 선형성을 제일 먼저 본다.
- 정규성·등분산성·독립성은 전부 **잔차(resid)에 대한 가정**이지 예측값에 대한 가정이 아니다.
  → 실습 코드 주석에도 있었지만, "단순회귀에서 y_pred는 speed의 선형변환이라 잔차의
  정규성과 무관"하다는 게 핵심. **표준화(zscore)는 항상 resid에 해야지 y_pred에 하면 안 된다.**
- 가정검정이 다 끝난 뒤에야 "예측"과 "보고"로 넘어간다. 가정이 깨진 모형으로 예측하거나
  보고서를 쓰면 그 결과 자체가 신뢰할 수 없기 때문에, 순서상 맨 마지막에 둔다.

## 2. 두 가지 코드 버전 — "원본 코드"와 "모듈화 코드"를 어떻게 봐야 하나

문서에 두 세트의 코드가 있었다:

- **버전 A (직접 코딩)**: `#01~#06` 셀에서 numpy/scipy/statsmodels 함수를 하나하나 직접 호출
- **버전 B (모듈화)**: `my_ols.fit_model(origin, y='dist')`, `my_ols.test_linear(fit)` 처럼
  내가 만든 `my_ols.py` 모듈의 함수 하나로 압축

### 이 두 버전을 어떻게 이해해야 하는가?

1. **버전 A는 "설계도"고, 버전 B는 "완제품"이다.**
   직접 코딩 버전에서 로직이 맞는지 한 줄씩 확인한 다음, 검증이 끝난 로직만
   함수로 옮겨서 모듈화한다. 순서를 거꾸로 하면(모듈부터 짜면) 버그가 나도
   어디서 틀렸는지 찾기 어렵다.
2. **모듈화의 목적은 "재사용"이다.** 오늘은 `cars` 데이터로 `dist~speed`를 검정했지만,
   내일 다른 데이터셋으로 회귀분석을 해도 `my_ols.fit_model(new_df, y='target')` →
   `my_ols.test_linear(fit)` → (앞으로 만들) `my_ols.test_normal(fit)` 처럼
   **똑같은 4줄로 전체 가정검정이 끝나야 한다.** 이게 모듈을 만드는 이유다.
3. **처음부터 끝까지 다 짜고 나서 테스트하지 않는다.** 함수 하나를 완성하면
   바로 그 함수만 셀에서 호출해서 결과가 기존 수동 코드와 똑같이 나오는지
   대조 확인부터 한다 (`## #02. 모듈화 기능 확인` 셀이 그 역할). 이 방식이
   "작은 단위로 짜고 즉시 검증"하는 습관이고, 실무에서도 그대로 쓰는 방식이다.
4. **`from helpers import *` / `from . import my_plot`의 의미**: `helpers`는 패키지,
   `my_plot`은 그 안의 모듈. `my_ols.py` 안에서 `from . import my_plot`으로
   같은 패키지 안의 다른 모듈(그래프 담당)을 가져와 쓰는 구조다. 즉 **하나의
   기능(그래프 그리기)은 한 모듈이 전담하고, 다른 모듈(my_ols)은 그 모듈을
   불러다 쓰기만 한다** — 통계 계산 따로, 시각화 따로 역할을 나누는 설계다.
   앞으로 모듈을 확장할 때도 "이 기능이 이미 다른 모듈에 있나?"부터 확인하고,
   없으면 새로 만들되 역할이 겹치지 않게 분리해야 한다.
5. **회귀분석 자체를 구현하는 방식도 두 가지였다는 것을 기억.**

   - **행렬(matrix) 기반**: `add_constant(x)`로 상수항을 직접 만들어 붙이고
     `OLS(y, x_input)`에 넣는 방식. **`my_ols.fit_model`이 내부적으로 쓰는 방식이
     바로 이거다.**
   - **formula 기반**: `formula_ols("dist ~ speed", data=origin)`처럼 R 스타일
     수식 문자열로 종속변수~독립변수 관계를 표현하는 방식. 상수항을 자동으로
     넣어주고, 변수 이름을 그대로 써서 가독성이 좋다.
   - 두 방식 모두 **같은 결과(같은 회귀계수)** 를 낸다 — 표현 방식만 다를 뿐
     내부적으로 푸는 수식(최소자승법)은 동일하다. 모듈에서는 y 컬럼명만 넘기면
     나머지를 자동으로 독립변수 처리하는 행렬 방식이 범용적으로 재사용하기 편해서
     `fit_model`의 구현 방식으로 채택된 것.

## 3. 통계 개념 — 말로 풀어서 정리 (면접 대비용)

### 3-1. 선형성 (Linearity) — Ramsey RESET Test

**가정 자체가 무슨 뜻인가**: "독립변수(speed)와 종속변수(dist) 사이의 관계가
직선 하나로 잘 설명된다"는 가정이다. 만약 실제로는 관계가 곡선(예: 2차 함수
모양)인데 직선으로 억지로 맞추면, 잔차 안에 아직 설명 못 한 패턴(곡선 모양)이
남아있게 된다.

**Ramsey RESET Test가 확인하는 것**: 지금 적합한 직선 모형에, 예측값의 제곱항
(2차항)을 추가로 넣었을 때 그 항이 통계적으로 유의미하게 설명력을 더해주는지를
검정한다.

- **귀무가설(H0)**: "고차항(제곱항)을 추가해도 설명력이 유의미하게 늘지 않는다"
  → 즉 지금의 직선 모형으로 충분하다 (선형성 가정 충족)
- **대립가설(H1)**: "고차항을 추가하면 설명력이 유의미하게 늘어난다"
  → 즉 직선만으로는 부족하고 곡선 관계가 남아있다 (선형성 가정 위배)

**판정 방법**: F-검정을 수행해서 p-value가 유의수준(보통 0.05)보다 **크면**
귀무가설을 채택 → 선형성 가정을 충족한다고 본다. p-value가 0.05보다 **작으면**
귀무가설을 기각 → 선형성이 위배됐다고 판단한다.

**시각적으로 보는 법**: 예측값(x축) vs 잔차(y축) 산점도를 그리고, 그 위에
lowess(국소회귀) 추세선을 얹는다. 이 추세선이 잔차=0 기준선 근처에서
거의 평평하게(수평으로) 유지되면 선형성 OK. 만약 이 선이 U자나 역U자 모양으로
휘어 있으면 곡선 관계가 남아있다는 뜻이다.

### 3-2. 정규성 (Normality of Residuals)

**가정 자체가 무슨 뜻인가**: "잔차들이 정규분포를 따른다"는 가정. 여기서
꼭 기억해야 할 것 — **정규성은 종속변수(dist)나 예측값(y_pred)에 대한 가정이
아니라 잔차(resid)에 대한 가정**이다. 회귀분석의 유의성 검정(t-검정, F-검정 등)이
타당하려면 잔차가 정규분포를 따라야 한다는 전제가 깔려 있기 때문이다.

#### (1) Q-Q Plot (Quantile-Quantile Plot)

잔차를 표준화(z-score)한 다음, 그 값들의 분위수(quantile)를 이론적인
표준정규분포의 분위수와 비교해서 산점도로 그린 것. 점들이 대각선(y=x) 위에
가지런히 놓이면 정규분포에 가깝다는 뜻이고, 점들이 대각선에서 휘어지거나
양 끝(꼬리)에서 크게 벗어나면 정규성이 깨졌다는 신호다.

#### (2) 68-95-99.7 규칙 (경험적 규칙, Empirical Rule)

정규분포를 따르는 데이터는 이론적으로:

- 평균 ± 1×표준편차 구간 안에 전체의 **약 68%**가 들어있어야 하고
- 평균 ± 2×표준편차 구간 안에 전체의 **약 95%**가 들어있어야 하고
- 평균 ± 3×표준편차 구간 안에 전체의 **약 99.7%**가 들어있어야 한다.

여기서는 표준편차 대신 **잔차의 표준오차(루트MSE, √MSE)** 를 기준 단위로 써서,
실제 잔차 중 몇 %가 각 구간 안에 들어있는지 계산하고 68/95/99.7과 비교한다.
실제 비율이 이 기대치에서 크게 벗어나면(허용 오차 범위 밖이면) 정규성이
의심된다고 판단하는 방식이다. (통계적 검정이라기보다 눈으로 보는 보조 규칙)

#### (3) 검정 통계량 — 표본 크기에 따라 다른 검정을 쓴다

- **표본수 30 미만 → Shapiro-Wilk 검정**: 소표본에서 정규성 검정력이 좋은 검정.
- **표본수 30 이상 → Kolmogorov-Smirnov(K-S) 검정**: 대표본에 적합. 단, 잔차를
  먼저 표준화(z-score)해서 표준정규분포(N(0,1))와 비교해야 한다. (표준화 없이
  원본 잔차로 바로 K-S를 돌리면 안 됨 — 분포의 평균/분산이 다르면 검정 자체가
  틀어짐)
- **귀무가설(H0)**: "잔차는 정규분포를 따른다"
- **대립가설(H1)**: "잔차는 정규분포를 따르지 않는다"
- **판정**: p-value ≥ 0.05 → 귀무가설 채택(정규성 만족), p-value < 0.05 →
  귀무가설 기각(정규성 위배)

### 3-3. 등분산성 (Homoscedasticity) — Breusch-Pagan Test

**가정 자체가 무슨 뜻인가**: "잔차의 분산이 독립변수 값과 상관없이 일정하다"는
가정. 예를 들어 speed가 커질수록 잔차가 점점 더 넓게 퍼지는 모양(나팔 모양,
`funnel shape`)이 나타나면 등분산성이 깨진 것 — 이걸 **이분산성
(heteroscedasticity)** 이라고 부른다.

**Breusch-Pagan 검정이 확인하는 것**: 잔차의 제곱을 독립변수들로 회귀시켰을 때,
그 회귀가 독립변수로 잔차의 크기를 유의미하게 설명하는지를 검정한다. 설명이
된다는 건 잔차 크기가 독립변수 값에 따라 체계적으로 달라진다는 뜻이므로
등분산성 위배다.

- **귀무가설(H0)**: "잔차의 분산은 일정하다 (등분산성 만족)"
- **대립가설(H1)**: "잔차의 분산은 독립변수에 따라 달라진다 (이분산성 존재)"
- **판정**: 실습 코드 주석대로 **F p-value가 0.05보다 작으면 등분산성 가정
  위배**. LM 통계량 쪽도 있지만 F 통계량/p-value를 기준으로 보면 된다.

### 3-4. 독립성 (Independence of Residuals) — Durbin-Watson 검정

**가정 자체가 무슨 뜻인가**: "잔차들끼리 서로 상관관계(자기상관, autocorrelation)가
없다"는 가정. 특히 시계열 데이터나 순서가 있는 데이터에서, 한 시점의 잔차가
다음 시점의 잔차와 비슷한 방향으로 움직이면(양의 자기상관) 독립성이 깨진 것이다.

**Durbin-Watson(DW) 통계량**: 0~4 사이의 값을 가지며,

- **DW ≈ 2** → 자기상관이 거의 없음 (독립성 만족)
- **DW < 1.5** → 양(+)의 자기상관 가능성 (바로 이전 잔차와 같은 방향으로 움직임)
- **DW > 2.5** → 음(-)의 자기상관 가능성 (이전 잔차와 반대 방향으로 진동)

이 검정은 p-value로 판단하는 게 아니라 **통계량 값 자체의 위치**로 해석한다는
점이 다른 셋(RESET, Shapiro/K-S, Breusch-Pagan)과 다르다.

### 3-5. 다중공선성 (Multicollinearity) — VIF / 공차

> 단순선형회귀(독립변수 1개)에서는 등장하지 않지만, `report_variables` 함수가
> VIF를 계산하는 걸 보면 앞으로 다중회귀(독립변수 여러 개)로 넘어갈 때 반드시
> 필요한 개념이라 미리 정리해둔다.

**가정 자체가 무슨 뜻인가**: 독립변수가 여러 개일 때, "그 독립변수들끼리
서로 너무 강하게 상관되어 있지는 않은가"를 보는 것. 예를 들어 "키(cm)"와
"키(inch)"를 둘 다 독립변수로 넣으면 사실상 같은 정보를 중복으로 넣은
셈이라 각 변수의 개별 효과(회귀계수)를 신뢰할 수 없게 된다.

- **VIF (Variance Inflation Factor, 분산팽창계수)**: 어떤 독립변수 하나를
  나머지 독립변수들로 회귀시켰을 때 설명이 얼마나 잘 되는지를 바탕으로 계산한
  값. **VIF가 크다 = 이 변수가 다른 독립변수들로 거의 다 설명된다 = 중복
  정보가 많다**는 뜻. 일반적으로 VIF가 10을 넘으면(또는 보수적으로는 5) 다중
  공선성이 심각하다고 판단한다.
- **공차 (Tolerance)**: `공차 = 1 / VIF`. VIF와 반대로 값이 **작을수록**
  문제가 있다는 뜻 (보통 0.1 미만이면 위험 신호).

**표준화 회귀계수(베타, β)란?**: 원래 회귀계수(B)는 "독립변수 1단위 증가할 때
종속변수가 B만큼 변한다"는 뜻인데, 문제는 변수마다 단위가 다르면(예: 나이는
"살" 단위, 소득은 "원" 단위) B값끼리 크기를 직접 비교할 수 없다는 것.
그래서 **모든 변수를 표준화(단위를 없앰)한 뒤 다시 구한 계수가 베타**이고,
`베타 = B × (그 독립변수의 표준편차 / 종속변수의 표준편차)`로 계산한다.
이 베타값끼리는 단위가 없으므로 "어떤 독립변수가 종속변수에 상대적으로
더 큰 영향을 주는가"를 서로 비교할 때 쓴다.

### 3-6. 로그 변환된 변수의 해석 (`report_variables_text`에서 다룬 내용)

회귀분석에서 변수를 원본 그대로 안 쓰고 로그(log) 또는 log1p(=ln(1+x))로
변환해서 넣는 경우가 있다 (분포가 한쪽으로 치우쳤을 때 정규성을 개선하려는
목적 등). 이때는 계수 해석 방식이 원본 변수와 달라진다.

- **원본(X) → 원본(Y)**: "X가 1 증가하면 Y는 B만큼 (절대량으로) 증가/감소한다"
  — 가장 직관적인 해석.
- **로그(X) → 원본(Y)**: "X가 1% 증가하면 Y는 약 (B×ln(1.01))만큼 증가/감소한다"
  — X의 % 변화에 대한 Y의 절대 변화.
- **원본(X) → 로그(Y)**: "X가 1 증가하면 Y는 약 (e^B − 1)×100% 만큼 증가/감소한다"
  — 이게 실무에서 자주 쓰이는 "% 변화" 해석이다.
- **로그(X) → 로그(Y)**: "X가 1% 증가하면 Y도 약 B% 증가/감소한다" (탄력성 해석에 가까움)

**주의**: log1p(=ln(1+x))를 쓴 경우는 해석 기준이 "X"가 아니라 "**(1+X)**"이고,
이 %근사는 값이 어느 정도 큰 구간에서만 잘 맞는다. 0 근처의 작은 값 구간에서는
근사가 부정확해지므로, 그런 경우엔 부호·유의성 중심으로만 해석하거나 `expm1`로
원래 척도로 되돌려서 비교해야 한다.

# 0) EDA — 상관분석(가정 점검 자동 포함) + 산점도
corr = my_stats.correlation(df, x='독립변수명', y='종속변수명')

my_ols.test_linear(fit)
my_ols.test_normal(fit)
my_ols.test_equalvar(fit)
my_ols.test_independent(fit)

## 6. 실전 적용 사례 — father-son 데이터로 모듈 검증 (숫자로 감 잡기)

`sheight ~ fheight` (아들 키를 아버지 키로 설명, n=1,078건)로 완성된 모듈 4개
함수를 실제로 돌려본 결과와, 거기서 얻은 판단력 포인트.

| 가정     | 검정                      | 결과       | 판정          |
| -------- | ------------------------- | ---------- | ------------- |
| 선형성   | Ramsey RESET              | p ≈ 0.86  | 충족          |
| 등분산성 | Breusch-Pagan             | p ≈ 0.96  | 충족          |
| 정규성   | K-S (n≥30이라 자동 전환) | p ≈ 0.67  | 충족          |
| 독립성   | Durbin-Watson             | DW ≈ 0.77 | 통계량상 위반 |

여기서 **숫자만 보고 기계적으로 결론 내리면 안 되는 두 가지 판단 포인트**가 나왔다:

1. **표본이 클수록 Shapiro-Wilk는 정규성을 너무 쉽게 기각한다.** n=1,078처럼
   표본이 크면 아주 미세한 차이도 "통계적으로 유의미"하게 잡아내는 경향이
   있어서, 모듈이 규칙대로(`n<30`) Shapiro-Wilk 대신 K-S로 자동 전환한 것.
   즉 **표본 크기에 따라 검정 방법을 바꾸는 이유가 "적합한 검정력을 쓰기
   위해서"** 라는 걸 실제 숫자로 확인한 것.
2. **Durbin-Watson은 원래 시계열(시간 순서가 있는) 데이터를 위한 지표다.**
   father-son 데이터는 서로 다른 부자(父子) 쌍을 그냥 모아놓은 자료라 "순서"
   자체가 의미가 없다. 그래서 DW 통계량이 0.77로 "위반"처럼 나와도, **데이터의
   성격상 이 신호는 실질적인 문제로 보지 않고 무시할 수 있다**고 판단한 것.
   → **통계 검정 결과를 그대로 받아쓰지 말고, "이 검정이 애초에 이 데이터에
   적용 가능한 전제를 갖고 있는가"부터 따져야 한다**는 게 핵심 교훈. 면접에서
   "가정을 다 확인했다"고 말할 때, 이런 예외적 판단까지 설명할 수 있으면 훨씬
   더 좋은 답변이 된다.
