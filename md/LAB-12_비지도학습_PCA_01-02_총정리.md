## 0. 비지도학습이란 (큰 그림부터)

| | 지도학습 (Supervised) | 비지도학습 (Unsupervised) |
|---|---|---|
| 정답(라벨) | 있음 | 없음 |
| 목적 | 특정 변수의 예측·분류 | 데이터의 숨겨진 구조 발견 |
| 예 | 스팸 분류, 집값 예측 | 고객 세분화, 이상 탐지 |
| 평가 | 정답과 비교해 명확히 평가 | 지표·해석 기반이라 다소 모호함 |
| 대표 기법 | 회귀, 로지스틱, 트리 계열 | **군집분석(KMeans 등)**, **차원축소(PCA)** |

비지도학습의 3가지 특징: **① 분석가의 판단이 결과를 크게 좌우한다 ② 평가 기준이 모호하다(정답이 없으니까) ③ 숨겨진 구조·패턴을 탐색하는 게 목적이다.**

이 LAB에서 다루는 두 기법은 성격이 다르다.
- **PCA (차원축소)**: "변수(열)"를 줄인다 → 전처리 단계에 가깝다.
- **KMeans (군집분석)**: "관측치(행)"를 그룹으로 나눈다 → 분석 결과물 자체다.

두 기법의 공통점이자 이 LAB 전체를 관통하는 핵심 원칙 하나: **둘 다 "거리/분산"을 계산해서 작동하기 때문에, 변수의 눈금(단위)이 다르면 스케일링을 반드시 먼저 해야 한다.** 이 문서 전체에서 이 얘기가 계속 반복되는데, 그만큼 중요하다는 뜻이다.

## 1. 차원축소(PCA)

### 1-1. 개념 정리

**차원축소란?** 정보를 최대한 지키면서 변수(열)의 개수를 줄이는 작업. `10행 × 7열` 데이터에서 변수 3개를 줄이면 `10행 × 4열`이 되는 식. 모델에 넣을 독립변수를 고르는 방법 중 하나로, "특성 선택(중요한 변수만 남긴다)"과 "특성 추출(변수들을 조합해 새 변수를 만든다)"로 나뉘는데 **PCA는 특성 추출**에 해당한다. 원래 변수를 버리는 게 아니라, 원래 변수들을 섞어서 새로운 변수(주성분)를 만들어내는 것이다.

**PCA의 핵심 아이디어**: 데이터가 가장 넓게 퍼진(=분산이 가장 큰) 방향을 찾아서 그 방향을 새 축으로 삼는다. 분산이 큰 방향일수록 그 안에 정보가 많이 들어있다고 보기 때문이다. 가장 많이 퍼진 방향이 **PC1(제1주성분)**, 그다음으로 많이 퍼진(PC1과 직각인) 방향이 **PC2**, 이런 식으로 PCn까지 만든다.

**대가**: 원래 변수 하나하나의 의미는 사라진다. "알코올 도수가 몇 도" 같은 해석이 안 되고 대신 "PC1이 0.8이다" 같은 추상적인 값만 남는다. 그 대신 변수들 사이의 관계를 반영한 안정적인 데이터를 얻는다.

| 질문 | 답 |
|---|---|
| PCA는 무엇을 하나 | 정보를 최대한 지키면서 변수 개수를 줄인다 |
| 왜 표준화가 필요한가 | 단위가 큰 변수 하나가 분산을 독차지하지 않도록 |
| 몇 개를 남기나 | 누적 설명력이 기준(보통 80%)을 넘는 지점까지 |
| 언제 쓰면 안 되나 | 변수 하나하나의 해석이 목적일 때 |

> **판단 기준 한 줄 요약: 해석이 목적이면 PCA ❌, 성능·구조 파악이 목적이면 PCA ⭕**

### 1-2. 통계 개념을 말로 풀어서 (면접용)

#### ① 분산 (Variance)
데이터가 평균으로부터 얼마나 흩어져 있는지를 나타내는 값. PCA는 "분산이 가장 큰 방향 = 정보가 가장 많은 방향"이라는 전제를 깔고 시작하기 때문에, 분산 계산 자체가 PCA의 출발점이다.

#### ② 왜 표준화(Standardization)가 필수인가
공식: **z = (x − μ) / σ** (μ: 그 변수의 평균, σ: 그 변수의 표준편차)

말로 풀면: 각 값에서 그 변수의 평균을 빼고, 표준편차로 나눠서 **평균 0, 표준편차 1**로 눈금을 통일하는 작업이다. wine_qt 데이터를 예로 들면 알코올 도수는 9~14 범위인데 총 이산화황은 6~289 범위다. 표준화를 안 하면 "분산이 가장 큰 방향을 찾는다"는 PCA 로직 때문에, 숫자가 큰 변수(총 이산화황) 하나가 사실상 PC1을 혼자 결정해버린다. 즉 13개 지표를 요약한 게 아니라 그냥 그 변수 하나를 재포장한 꼴이 된다. **PCA에서 표준화는 선택이 아니라 필수 과정.**

#### ③ 주성분 (Principal Component)
원래 변수들을 어떤 비율(가중치)로 섞어서 만든 새로운 변수. 수식으로 쓰면:

**PC1 = w₁ × x₁ + w₂ × x₂ + w₃ × x₃ + …**

여기서 x₁, x₂, …는 원래 변수(표준화된 값)이고, w₁, w₂, …는 각 변수가 이 주성분에 얼마나 기여하는지를 나타내는 가중치 — 이걸 **로딩(loading)**이라고 부른다. 주성분들은 서로 직각(수학적으로는 "직교" = 상관관계가 0)이 되도록 만들어진다. 그래서 PCA 결과로 나온 PC1, PC2, …는 서로 겹치는 정보가 전혀 없는, 완전히 독립적인 축들이다.

#### ④ 설명력 (Explained Variance Ratio)
그 주성분 하나가 전체 데이터의 분산(정보) 중 몇 %를 담고 있는지를 나타내는 비율. 표준화를 하면 변수 하나하나의 분산이 전부 1이 되므로, 전체 정보량은 "변수 개수"와 같아진다(예: 13개 변수 → 전체 정보량 13). 각 주성분은 그중 자기가 담아낸 몫을 설명력으로 보고한다.

#### ⑤ 누적 설명력 (Cumulative Explained Variance)
1번째 주성분부터 지금 보는 주성분까지 설명력을 다 더한 값. PCA에서 "몇 개를 남길지" 결정하는 가장 실무적인 기준이 바로 이거다. 보통 **80%를 넘는 지점**까지 채택한다(단, 80%는 정해진 법칙이 아니라 분석가가 잡는 임계점 — 목적에 따라 70%, 90%로 바뀔 수 있다).

#### ⑥ 로딩 벡터 읽는 법
- **절댓값이 크다(보통 0.3 이상)** → 그 변수가 이 주성분을 만드는 데 크게 기여했다는 뜻
- **부호가 같은 변수들끼리** → 함께 커지고 함께 작아지는 관계
- **부호가 반대인 변수** → 한쪽이 커지면 다른 쪽은 작아지는 관계
- **로딩이 0에 가깝다** → "이 변수가 쓸모없다"가 아니라 **"이 축으로는 이 변수를 설명하지 못한다"**는 뜻일 뿐(boston 연습문제의 CHAS가 이 사례)

#### ⑦ Biplot (바이플롯)
관측치(PCA 점수, 점)와 원래 변수(로딩, 화살표)를 같은 평면에 겹쳐서 그린 그래프.
- 화살표가 어느 축과 나란한가 → 그 주성분에 크게 기여하는 변수
- 화살표 길이가 길수록 → 그 평면에서 영향이 큼
- 화살표끼리 가까울수록 → 서로 비슷하게 움직이는 변수

### 1-3. 직접 코딩 버전 — 실습 워크플로우 (wine_qt 데이터)

전체 흐름은 **"① 종속변수 제거 → ② 표준화 → ③ PCA 적합 → ④ 결과 데이터프레임화 → ⑤ 설명력 확인 → ⑥ 로딩 벡터 해석 → ⑦ Biplot 시각화"** 순서다. 하나씩 왜 이 순서인지 짚어보자.

```python
# 1) 라이브러리 참조
from jussam import load_data
from helpers import *
from pandas import DataFrame
from sklearn.decomposition import PCA

# 2) 데이터 가져오기
origin = load_data("wine_qt")

# 3) 전처리(1) - 종속변수 제거
# 차원축소는 "독립변수"에만 적용하는 기법이다.
# quality(종속변수)까지 같이 축소해버리면 예측하려는 대상 자체가 섞여버린다.
df1 = origin.drop("quality", axis=1)

# 4) 전처리(2) - 표준화 (PCA는 표준화가 필수)
sdf = my_prep.scaling(df1, method="standard", verbose=False)

# 5) PCA 수행
# n_components="mle" : 개수를 통계적 기준으로 알아서 정함
# random_state : 재현성을 위한 랜덤시드 고정
estimator = PCA(n_components="mle", random_state=9901)
pca = estimator.fit_transform(sdf)

# 6) 결과를 데이터프레임으로 정리 (PC1, PC2 ... 이름 규칙)
n = pca.shape[1]
cols = [f"PC{i+1}" for i in range(n)]
pca_df = DataFrame(pca, columns=cols)
pca_df["target"] = origin["quality"]   # 나중에 모델링/시각화에 쓰려고 다시 붙여둠
```

> 💡 **여기서 만든 pca_df는 이후 회귀·로지스틱·군집분석 등 어떤 모델링에도 그대로 투입할 수 있는 "재사용 가능한 산출물"**이다. 다만 예측 성능은 원본보다 대체로 좋아지는 반면, 결과 해석은 매우 어려워진다는 트레이드오프를 항상 같이 얘기해야 한다.

**주성분 개수를 정하는 3가지 방식**

| 지정 방식 | 의미 |
|---|---|
| 정수 (예: 6) | 분석가가 개수를 직접 지정 |
| `'mle'` | 통계적 기준(최대우도추정)으로 자동 결정 |
| 0~1 사이 실수 (예: 0.8) | 누적 설명력이 그 비율을 넘는 지점까지 |

```python
# "mle"로 몇 개가 뽑히는지 먼저 본 다음, 실무에서 가장 많이 쓰는
# "누적 설명력 80%" 기준으로 다시 뽑는 게 일반적인 흐름
estimator = PCA(n_components=0.8, random_state=9901)
pca = estimator.fit_transform(sdf)
```

**설명력 확인 + 스크리 플롯(누적 설명력 그래프)**

```python
cum = estimator.explained_variance_ratio_.cumsum()
k_list = list(range(1, len(cum) + 1))

fig, ax = my_plot.init(title="주성분 개수에 따른 누적 설명력",
                       xlabel="주성분 개수", ylabel="누적 설명력")
my_plot.lineplot(x=k_list, y=cum, marker="o", ax=ax)

ax.axhline(0.8, color="red", linestyle="--", linewidth=1)  # 80% 기준선
ax.text(1, 0.81, "80%", color="red")
my_plot.show()
```
가로축은 주성분 개수, 세로축은 누적 설명력. 빨간 점선(80%)을 **처음** 넘어서는 지점이 채택할 주성분 개수다. wine_qt에서는 PC6에서 85.8%로 처음 80%를 넘었다 → PC1~PC6까지만 쓴다.

**로딩 벡터 추출 및 표로 정리**

```python
# estimator.components_ : (주성분 개수) x (원래 변수 개수) 형태의 ndarray
# → 그대로 보면 해석하기 어려우니 DataFrame으로 가공한다
loadings = DataFrame(estimator.components_, columns=sdf.columns, index=cols)
loadings["[설명력]"] = estimator.explained_variance_ratio_
loadings["[누적 설명력]"] = estimator.explained_variance_ratio_.cumsum()
loadings = loadings.T          # 변수를 행으로 두는 게 읽기 편함
loadings.index.name = "Features"
```

> 왜 `.T`(전치)를 하나? sklearn의 `components_`는 "주성분(행) × 원래변수(열)" 형태로 나온다. 원래 변수가 11개, 주성분이 6개면 6행 11열이라 가로로 길다. 변수를 행으로, 주성분을 열로 두면(전치하면) 표가 세로로 길어져서 **변수별로 어느 주성분에 크게 기여했는지 한눈에 훑기 쉬워진다.**

```python
# 숫자표보다 색으로 보면 빠르다: 진한 색(양끝)일수록 그 주성분을 대표하는 변수
my_plot.heatmap(data=loadings.iloc[:-2, :], fmt="0.2f", palette="coolwarm",
                title="주성분 로딩", width=1000, height=700)
```
`.iloc[:-2, :]`로 마지막 두 행(설명력, 누적설명력)을 빼는 이유: 그 두 행은 "로딩 값"이 아니라 "요약 통계"라서 히트맵에 같이 넣으면 색상 스케일이 왜곡된다.

**Biplot 시각화 (직접 코딩)**

```python
xname, yname = "PC1", "PC2"

score = estimator.transform(sdf)      # 관측치별 주성분 점수
components = estimator.components_    # 로딩 벡터

x_index = cols.index(xname)
y_index = cols.index(yname)
xs = score[:, x_index]
ys = score[:, y_index]

# 점(점수)과 화살표(로딩)의 크기 단위가 다르므로, 같은 화면에서 비슷한 크기로 보이게
# 점수 쪽을 화살표 크기(대략 -1~1)에 맞춰 축소한다
scalex = 1.0 / (xs.max() - xs.min())
scaley = 1.0 / (ys.max() - ys.min())

vdf = DataFrame({xname: xs * scalex, yname: ys * scaley,
                 "target": origin["quality"]})

fig, ax = my_plot.init(title="PCA Biplot", xlabel=xname, ylabel=yname,
                       width=1000, height=800)
my_plot.scatterplot(data=vdf, x=xname, y=yname, hue="target",
                    size=20, alpha=0.6, outline=False, ax=ax)

for i, feature in enumerate(sdf.columns):
    ax.arrow(0, 0, components[x_index, i], components[y_index, i],
             color="r", alpha=0.6, head_width=0.02, head_length=0.02)
    ax.text(components[x_index, i] * 1.15, components[y_index, i] * 1.15,
            feature, color="b", fontsize=8, ha="center", va="center")
my_plot.show()
```

### 1-4. 모듈화 버전 — `my_prep.pca()`

강사님 실습코드는 마지막에 **"2. PCA 모듈화"**라는 제목만 있고 빈 코드 셀로 끝난다. 이건 "이제 위에서 짠 직접코딩을 함수 하나로 묶어보자"는 다음 단계 과제라는 뜻이다. 실제로 `my_prep.py`에는 이미 `pca()`라는 함수가 준비돼 있는데, **구조는 완성돼 있지만 8번(바이플롯) 부분은 뼈대(주석)만 있고 실제 실행 코드는 비어있는 미완성 상태**다. (연습문제 노트북 결과 이미지들은 완성된 버전으로 미리 실행된 것으로 보이며, 지금 업로드된 소스와는 별개다.)

**함수 시그니처**
```python
my_prep.pca(df, y=None, n_components=0.8, scale=True, method='standard',
            save_path=None, report=True, plot=True, biplot=None,
            palette='coolwarm', hue_palette='tab10',
            width=1280, height=640, random_state=RANDOM_STATE)
```

| 파라미터 | 의미 |
|---|---|
| `y` | 종속변수 컬럼명. 지정하면 분석에서 빼뒀다가 결과에 다시 붙여준다 |
| `n_components` | 0~1 실수(누적설명력 기준) / 정수(개수) / `'mle'` |
| `scale` | 표준화 자동 수행 여부(기본 True) |
| `method` | 스케일러 종류 (`standard`/`minmax`/`robust`/`maxabs`) |
| `report` | 로딩 벡터표 출력 여부 |
| `plot` | 누적설명력 그래프 + 로딩 히트맵 출력 여부 |
| `biplot` | `[["PC1","PC2"], ["PC1","PC4"]]`처럼 그릴 쌍의 리스트, `'all'`이면 전체 조합 |

**함수 내부 처리 순서 (1~10단계)** — 직접코딩과 거의 1:1 대응된다.

| 내부 단계 | 직접코딩에서의 대응 |
|---|---|
| 1) 종속변수 분리 + 수치형만 선택 | `origin.drop("quality", ...)` |
| 2) 표준화 | `my_prep.scaling(...)` |
| 3) 전체 주성분으로 누적설명력 먼저 확보 → 기준만큼만 재추출 | `PCA(n_components="mle")` → `PCA(n_components=0.8)` 두 번 실습한 부분을 자동화 |
| 4) 결과를 PC1..PCn DataFrame으로 | `pca_df = DataFrame(pca, columns=cols)` |
| 5) 로딩 벡터표 구성(+설명력/누적설명력 행 추가, 전치) | `loadings = DataFrame(estimator.components_, ...).T` |
| 6) 로딩표 출력 | `display(loadings)` |
| 7) 스크리플롯 + 로딩 히트맵 | 누적설명력 lineplot + heatmap |
| 8) **바이플롯 (⚠️ 로컬 소스 미완성)** | Biplot 코드 (`ax.arrow`, `ax.text` 반복문) |
| 9) 스케일러/PCA 객체 저장(선택) | 별도 저장 로직 |
| 10) 결과 DataFrame 반환 | `return result` |

**8번(바이플롯) 부분을 채운다면 어떤 순서로 사고해야 하는가** — 함수 안 주석(8-1~8-11)이 이미 사고 순서를 다 알려주고 있다. 위 "1-3 직접 코딩" 섹션의 Biplot 코드를 참고해서 이 순서 그대로 옮기면 된다.

1. `biplot` 인자가 `'all'`이면 → 채택된 주성분(`cols`)에서 만들 수 있는 모든 쌍을 `combinations(cols, 2)`로 생성
2. 리스트로 직접 지정했으면 그 리스트를 그대로 `pairs`로 사용 (여기서 지금 `pairs`가 정의 안 돼 있어서 `NameError`가 나는 상태 — 1·2번을 채워야 `pairs`가 생긴다)
3. 그릴 쌍 개수만큼 2열로 서브플롯을 미리 만들어 둠(홀수면 마지막 칸 비움)
4. 반복문 안에서: 그 쌍에 해당하는 PC 점수(`score[:, x_index]`, `score[:, y_index]`) 추출
5. 점·화살표 크기 맞추기(`scalex`, `scaley`)
6. `y`가 있으면 색 구분용으로 같이 담기
7. 점 산점도
8. 화살표(로딩) 겹쳐 그리기
9. 서브플롯 제목/축 이름
10. 남는 칸 축 숨기기
11. 그래프 출력

> **재사용 관점 메모**: `my_ols`, `my_logit`, `my_ts` 도 전부 "직접 코딩 → 검증 → 모듈화" 순서로 자라났던 패턴과 완전히 동일하다. 지금 `my_prep.pca()`가 딱 그 성장 중간 단계(뼈대는 있고 일부만 비어있는 상태)에 있다고 보면 된다.

## 2. 군집분석 — KMeans

### 2-1. 개념 정리

**KMeans란?** 관측치(행)들을 서로 가까운 것끼리 k개의 그룹으로 나누는 기법. "그룹의 중심점(centroid)"을 기준으로 거리를 재서 가장 가까운 중심점에 소속시키는 방식으로 작동한다.

**작동 원리를 말로 풀면**: ① k개의 중심점을 임의로 놓는다 → ② 각 데이터를 가장 가까운 중심점 그룹으로 배정한다 → ③ 그룹별로 배정된 데이터들의 평균 좌표로 중심점을 다시 계산한다 → ④ 중심점이 더 이상 안 움직일 때까지 ②~③을 반복한다. 그래서 이름이 "K-**Means**"(K개의 평균)다.

**왜 스케일링이 필수인가 (KMeans도 PCA와 같은 이유)**: KMeans는 "거리"로 가까운 정도를 판단하는데, 변수의 눈금이 다르면 값이 큰 변수 하나가 거리 계산을 사실상 독점해버린다. 실습에서 `game level`(13~999, 표준편차 276.7)이 `time spent`(1~96, 표준편차 27.9)보다 약 10배 크다 보니, 표준화 없이 군집화하면 **사실상 game level 값에 따라서만 가로 띠 모양으로 그룹이 나뉘는 문제**가 실제로 확인됐다. 두 변수를 함께 고려한 군집이 아니라 한 변수만 본 군집이 돼버리는 것.

**표준화 vs 정규화**
| 방법 | 공식 | 결과 범위 | 언제 |
|---|---|---|---|
| 표준화(Standard) | (x−평균)/표준편차 | 평균 0, 표준편차 1 | 일반적인 기본 선택 |
| 정규화(MinMax) | (x−최소)/(최대−최소) | 0~1 | 값의 범위를 딱 0~1로 맞추고 싶을 때 |

**군집 개수(k)는 데이터가 정해주지 않는다.** 이게 이 LAB 연습문제의 최종 결론이자 가장 중요한 태도다. k를 늘리면 큰 덩어리가 잘게 쪼개지면서 인원이 적은(설명하기 애매한) 그룹이 생긴다. "몇 개가 맞다"는 정답은 없고, **"무엇에 쓸 그룹인지"라는 목적(운영 조건, 이벤트 개수 등)에 따라 몇 개가 적절한지가 정해진다.**

**중심점 좌표 읽는 법**: 표준화된 데이터로 군집화했다면 중심점 좌표는 "전체 평균을 0으로 놓고 본 값"이다. 그래서 좌표가 0에서 많이 벌어질수록 그 변수가 그 그룹의 특징을 강하게 대표한다는 뜻이고, 두 좌표가 모두 0 근처면 "평균적이라 특징이 뚜렷하지 않은 그룹"이라는 뜻이다.

> ⚠️ **그룹 번호(0,1,2,3...)는 크기순도 중요도순도 아니다.** 실행할 때마다 임의로 붙는 이름표일 뿐이라 랜덤시드를 바꾸면 같은 무리에 다른 번호가 붙는다. 번호 자체에 의미를 부여하지 말 것.

### 2-2. 직접 코딩 버전 — 실습 워크플로우 (game_usage 데이터)

```python
from jussam import load_data
from helpers import *
from pandas import DataFrame
from sklearn.cluster import KMeans

origin = load_data("game_usage")

# 분포부터 눈으로 확인 (스케일링 전)
my_plot.scatterplot(data=origin, x="time spent", y="game level",
                    title="게임 이용시간과 레벨의 분포")

# 1) 표준화 없이 4개 그룹으로 군집화 (문제 상황을 보여주기 위한 비교용)
estimator = KMeans(n_clusters=4, random_state=RANDOM_STATE)
estimator.fit(origin)
cluster_pred = estimator.predict(origin)

df = origin.copy()
df["그룹번호"] = cluster_pred

my_plot.scatterplot(data=df, x="time spent", y="game level", hue="그룹번호",
                    outline=True, title="K-Means 군집 결과 (k=4)")

# 중심점 확인 + 시각화에 겹쳐 그리기
center_df = DataFrame(estimator.cluster_centers_, columns=["x", "y"])

fig, ax = my_plot.init(title="K-Means 군집 결과 (경계선 + 중심점)",
                       xlabel="time spent", ylabel="game level")
my_plot.scatterplot(data=df, x="time spent", y="game level", hue="그룹번호",
                    outline=True, ax=ax)
my_plot.scatterplot(data=center_df, x="x", y="y", marker="X",
                    size=150, color="#ff0000", edgecolor="#000000", ax=ax)
my_plot.show()

# 두 축 눈금을 동일하게 맞춰서 "진짜 모양"을 확인 (문제 진단용)
ax.set_xlim(ax.get_ylim())   # y축 범위를 x축에 그대로 적용

# 2) 표준화 후 다시 군집화 (해결책)
sdf = my_prep.scaling(origin, method="standard")
estimator = KMeans(n_clusters=4, random_state=RANDOM_STATE)
estimator.fit(sdf)
sdf["그룹번호"] = estimator.predict(sdf)

# 3) 정규화(MinMax) 버전도 비교해볼 수 있음
mdf = my_prep.scaling(origin, method="minmax")
estimator = KMeans(n_clusters=4, random_state=RANDOM_STATE)
estimator.fit(mdf)
mdf["그룹번호"] = estimator.predict(mdf)
```

**왜 `ax.set_xlim(ax.get_ylim())`을 하나?** matplotlib은 기본적으로 x축과 y축의 눈금 범위를 데이터에 맞춰 각각 따로 잡는다. 그러다 보니 실제로는 세로로 길쭉하게 퍼진 데이터가 화면에서는 정사각형처럼 보이는 착시가 생긴다. 두 축의 범위를 강제로 똑같이 맞춰야 **KMeans가 실제로 계산에 사용한 "진짜 거리 감각"**을 눈으로 확인할 수 있다.

### 2-3. 모듈화 버전 — `my_cluster.kmeans()`

```python
estimator, df, center_df = my_cluster.kmeans(origin, k=4)
```

기본 호출 하나로 "표준화 → 군집화 → 결과 데이터프레임화 → 시각화(외곽선+중심점)"까지 한 번에 처리한다. 확인된 옵션들:

| 파라미터 | 의미 |
|---|---|
| `k` | 군집 개수 |
| `scaling` | 스케일링 방법. `None`이면 미적용, `"standard"`/`"minmax"` 등 |
| `equal_scale` | 두 축 눈금을 동일하게 맞출지 (위의 `set_xlim(get_ylim())` 자동화) |
| `outline` | 점 외곽선 표시 여부 |
| `center_marker`, `center_size`, `center_color`, `center_edgecolor`, `center_linewidth` | 중심점 마커 스타일 |
| `plot` | 시각화 여부(False면 결과 객체만 반환) |
| `verbose` | 출력 여부 |
| `random_state` | 랜덤시드 (기본은 helpers의 `RANDOM_STATE`) |

**반환값 3개를 항상 기억할 것**: `estimator`(학습된 KMeans 객체, `.cluster_centers_` 등 접근용), `df`(원본 + `그룹번호` 컬럼), `center_df`(중심점 좌표표). 세 개를 각각 언제 쓰는지: 통계치/모델 자체를 더 파고들 땐 `estimator`, 그룹별로 인원수 세거나 후속 분석할 땐 `df`, 중심점 성격을 해석할 땐 `center_df`.

### 2-4. 연습문제 전체 정리 (game_usage — 한울소프트 시나리오)

**시나리오**: 게임 이용자 100명을 하루 이용시간·레벨 기준으로 몇 개 그룹으로 나눠서 이벤트를 다르게 준비해야 하는데, 팀마다 원하는 그룹 개수가 다르다(마케팅팀 3개, 팀장 4개, 기획팀 5~6개). 몇 개가 맞는지 근거를 대야 한다.

```python
from jussam import load_data
from helpers import *
from pandas import DataFrame

origin = load_data('game_usage')

# 그룹 개수를 2~6개로 바꿔가며 나눠보고, 매번 그룹별 인원까지 확인
for k in range(2, 7):
    estimator, df, center_df = my_cluster.kmeans(origin, k=k, verbose=False,
                                                   title=f'게임 이용자 군집 (k={k})')
    center_df['인원'] = df['그룹번호'].value_counts().sort_index()
    sizes = sorted(center_df['인원'], reverse=True)
    print(f'[k={k}] 그룹별 인원: {sizes} / 가장 작은 그룹: {min(sizes)}명')
    display(center_df.round(2))

# 그래프 없이 요약표만 빠르게 뽑기 (k별 비교표)
summary = []
for k in range(2, 7):
    estimator, df, center_df = my_cluster.kmeans(origin, k=k, plot=False, verbose=False,
                                                   random_state=RANDOM_STATE)
    sizes = sorted(df['그룹번호'].value_counts(), reverse=True)
    summary.append({'그룹 개수': k, '그룹별 인원': sizes, '가장 작은 그룹': min(sizes)})
DataFrame(summary)
```

> 랜덤시드를 반드시 고정하는 이유(문제 서두에 명시됨): 고정하지 않으면 실행할 때마다 그룹 번호도 인원도 달라져서, k=2 결과와 k=4 결과를 나란히 비교하는 일 자체가 무의미해진다.

| # | 질문 요지 | 정답 | 핵심 근거 |
|---|---|---|---|
| 1 | k=2일 때 두 그룹을 실질적으로 가른 변수는? | **game level** | 중심점 (-0.05,-0.92) vs (0.04,0.82) — level 좌표차 1.74 >> time 좌표차 0.09 |
| 2 | k=4일 때 가장 큰 그룹의 인원은? | **42명** | 그룹별 인원 42/23/21/14명 |
| 3 | 15명 미만 그룹이 처음 나타나는 k는? | **4** | 최소인원: k2=47, k3=25, **k4=14**, k5=10, k6=10 |
| 4 | k=5일 때 두 좌표가 모두 0.5 미만인(특징이 흐린) 그룹의 인원은? | **24명** | 중심점 (-0.15,-0.42)만 두 좌표 모두 0.5 미만 |
| 5 | "모든 그룹 15명 이상" 조건을 만족하는 가장 큰 k는? | **3** | 15명 이상 조건 만족: k2(47명), k3(25명) — 이 중 큰 쪽 |

**이 연습문제의 결론(그대로 기억할 가치가 있음)**: 데이터는 몇 개로 나눠 달라고 하든 군말 없이 나눠준다. 어느 쪽도 데이터가 골라준 "정답"이 아니다. k=3이 답이 될 수 있었던 건 순전히 "한 그룹 15명 이상"이라는 **운영 조건**이 있었기 때문이다. **군집분석에서 개수를 정하는 것은 데이터가 아니라 분석 목적이다.**

## 3. 재사용 코드 템플릿 (다른 데이터셋에 그대로 적용)

### PCA 템플릿

```python
from jussam import load_data
from helpers import *
from pandas import DataFrame
from sklearn.decomposition import PCA

origin = load_data("데이터셋이름")

# --- 버전 A: 직접 sklearn 사용 (세부 숫자를 하나하나 확정하고 싶을 때) ---
x = origin.drop("종속변수명", axis=1)                       # 종속변수 제거
sdf = my_prep.scaling(x, method="standard", verbose=False)  # 표준화

estimator = PCA(n_components=0.8, random_state=RANDOM_STATE)
score = estimator.fit_transform(sdf)

cols = [f"PC{i+1}" for i in range(score.shape[1])]
pca_df = DataFrame(score, columns=cols)
pca_df["target"] = origin["종속변수명"]

loadings = DataFrame(estimator.components_, columns=sdf.columns, index=cols)
loadings["[설명력]"] = estimator.explained_variance_ratio_
loadings["[누적 설명력]"] = estimator.explained_variance_ratio_.cumsum()
loadings = loadings.T

# --- 버전 B: 모듈 한 줄 호출 (빠르게 훑어볼 때) ---
pca_df = my_prep.pca(origin, y="종속변수명", n_components=0.8,
                      biplot=[["PC1", "PC2"]])
```

### KMeans 템플릿

```python
from jussam import load_data
from helpers import *
from pandas import DataFrame
from sklearn.cluster import KMeans

origin = load_data("데이터셋이름")

# --- 버전 A: 직접 sklearn 사용 ---
sdf = my_prep.scaling(origin, method="standard")
estimator = KMeans(n_clusters=4, random_state=RANDOM_STATE)
estimator.fit(sdf)
sdf["그룹번호"] = estimator.predict(sdf)
center_df = DataFrame(estimator.cluster_centers_, columns=sdf.columns[:-1])

# --- 버전 B: 모듈 한 줄 호출 ---
estimator, df, center_df = my_cluster.kmeans(origin, k=4)

# k값 탐색이 필요할 때 (연습문제 패턴)
for k in range(2, 7):
    estimator, df, center_df = my_cluster.kmeans(origin, k=k, plot=False, verbose=False)
    sizes = sorted(df["그룹번호"].value_counts(), reverse=True)
    print(f"[k={k}] 그룹별 인원: {sizes}")
```

## 4. 모듈을 확장해서 쓴다는 것 — 어떻게 사고해야 하는가

이건 `my_prep`/`my_cluster`뿐 아니라 지금까지 만든 `my_ols`, `my_logit`, `my_ts` 전부 똑같이 거쳐온 성장 패턴이다.

**3단계 원칙: 직접 코딩(raw) → 검증(작동 확인) → 모듈화(함수로 추상화)**

1. **직접 코딩 단계**: sklearn 함수를 노트북에 바로 풀어써서, 각 줄이 정확히 무슨 일을 하는지 눈으로 확인한다. 이 단계를 건너뛰고 바로 모듈을 쓰면, 모듈이 뭘 잘못했는지(버그) 알아챌 방법이 없어진다.
2. **검증 단계**: 직접 코딩한 결과가 말이 되는지(설명력 합이 1인지, 그룹 인원 합이 전체와 같은지 등) 확인한다.
3. **모듈화 단계**: 검증까지 끝난 로직을 함수로 감싸서, 다음에 다른 데이터셋에서는 한두 줄로 재사용할 수 있게 만든다. 이때 함수는 한 번에 다 만들지 않는다 — `my_prep.pca()`의 바이플롯 부분(8번)처럼, 먼저 필요한 부분(1~7번: 설명력·로딩)부터 완성해서 검증하고, 그 다음 단계(8번: 시각화)를 추가하는 식으로 **점진적으로 확장**한다.

지금 `my_prep.pca()`가 딱 이 중간 지점에 있다. 1~7단계(표준화, PCA 적합, 설명력, 로딩표, 히트맵)는 이미 완성돼서 실전에 쓸 수 있고, 8단계(바이플롯)는 뼈대(생각의 순서를 적어둔 주석)만 있는 상태다. 실습 노트북 맨 끝의 "2. PCA 모듈화" 빈 셀이 바로 이 8단계를 채워보라는 신호다.

**처음부터 끝까지 한 번에 다 짜지 않는 이유**: PCA·KMeans처럼 단계가 많은 파이프라인은 중간에 하나만 틀려도(표준화를 빼먹었다든지) 최종 결과가 전부 의미 없어진다. 그래서 "종속변수 제거 → 확인 → 표준화 → 확인 → PCA 적합 → 확인 → …" 처럼 **작은 단위로 나눠서 매 단계 작동을 확인하며 진행**하는 습관이 중요하다. 모듈화는 이 확인이 끝난 다음에 하는 마지막 작업이다.

**랜덤시드(RANDOM_STATE) 사용 습관**: PCA 실습에서는 `random_state=9901`처럼 숫자를 직접 써넣었고, KMeans 실습/연습문제에서는 `helpers`에 정의된 공용 변수 `RANDOM_STATE`를 가져다 썼다(연습문제 기준 값은 3217). **다른 데이터셋에 재사용할 걸 감안하면 하드코딩보다 공용 변수 `RANDOM_STATE`를 쓰는 쪽이 낫다** — 나중에 시드를 한 곳에서만 바꿔도 모든 분석에 일괄 반영되고, 랩마다 숫자가 달라 헷갈리는 일도 없어진다.

## 5. 다른 데이터셋에 적용할 때 체크리스트

**PCA**
- [ ] 종속변수(예측 대상)를 먼저 뺐는가?
- [ ] 수치형 변수만 남았는가? (문자형/범주형 섞여있으면 라벨링·더미인코딩 먼저)
- [ ] 표준화를 했는가? (변수 간 눈금 차이가 있다면 필수)
- [ ] 누적 설명력 몇 %에서 끊을지(80% 등) 기준을 정했는가?
- [ ] 로딩표까지 같이 봤는가? (설명력 숫자만 보고 판단 금지)
- [ ] "몇 개로 줄었고, 얼마를 버렸는지"를 함께 보고할 준비가 됐는가?

- [ ] 표준화(또는 정규화)를 했는가?
- [ ] 두 축 눈금을 맞춰서(`equal_scale`) 실제 데이터 모양을 확인했는가?
- [ ] k(그룹 개수)를 몇 개로 할지, "이 그룹을 어디에 쓸 것인지" 목적을 먼저 정했는가?
- [ ] 그룹 번호에 순서/중요도 의미를 부여하지 않았는가?
- [ ] 중심점 좌표로 각 그룹의 성격을 문장으로 설명할 수 있는가?

## 6. 자주 하는 실수 / 함정 정리

| 함정 | 설명 |
|---|---|
| 표준화 생략 | PCA에서는 눈금 큰 변수가 PC1을 독점, KMeans에서는 그 변수 혼자 거리 계산을 독점 |
| 설명력 숫자만 보고 판단 | 표준화 안 한 PCA는 설명력이 오히려 더 높게 나올 수 있음(착시) → 로딩을 반드시 같이 확인 |
| 로딩 0 ≈ "쓸모없는 변수" 로 오해 | 로딩 0은 "이 축으로는 설명 안 됨"이지 "변수 자체가 무의미"라는 뜻이 아님 |
| 그룹 번호에 의미 부여 | 그룹 번호는 실행마다 임의로 붙는 이름표일 뿐, 크기·중요도 순서 아님 |
| k(군집 개수)를 데이터가 정해준다고 생각 | k는 목적(운영 조건 등)이 정하는 것이지 데이터가 "정답"을 주는 게 아님 |
| PCA를 해석 목적으로 사용 | 해석이 목표라면 PCA 대신 원래 변수를 그대로 쓰거나 특성 선택을 고려 |
