- **모듈화 = "다음 데이터셋에 빨리 적용하기 위한 것"**. 연습문제(서울 기온)에서 바로 `my_ts.decompose(...)`, `my_ts.auto_correlation(...)`처럼 함수 호출만 바꿔서 적용한 게 그 증거.

- `result = 함수(...)` 처럼 **결과를 변수에만 담고, 화면에 보고 싶으면 마지막 줄에 변수명만 따로 적는다** (`sd.dropna()`, `rolling.head()`처럼). 화면 출력용 코드와 계산용 코드를 섞지 않는다.

## 2. [03단원] 분해 시계열 (Decomposition)

### 2-1. 분해가 왜 필요한가 (개념)

시계열은 4가지 힘이 겹쳐서 만들어진다고 본다: **추세(Trend)**, **계절성(Seasonal)**, **순환(Cyclic)**, **불규칙(Irregular/Residual)**. `seasonal_decompose`는 이 중 추세·계절·잔차 3개를 분리해준다(순환은 추세에 섞여 나옴).

**왜 이걸 따로 뽑아야 하는가?** — 서울 기온 예제가 정확한 이유를 보여준다. 원본 그래프만 보면 계절(여름/겨울 진폭 ±9.8℃)이 너무 커서, 50년간 실제로 오른 추세(+2.83℃, 표준편차로 치면 0.739)가 눈에 안 보인다. **"계절이 추세를 가린다"** — 이걸 숫자로 증명하는 게 분해의 존재 이유다.

### 2-2. 가법 모델 vs 승법 모델 (제일 먼저 판단해야 하는 것)

두 가지 결합 방식이 있다:

- **가법(additive)**: `원본 = 추세 + 계절 + 잔차`
- **승법(multiplicative)**: `원본 = 추세 × 계절 × 잔차`

**판단 기준(개념을 말로 풀면)**:
> 데이터를 연 단위(혹은 계절 주기 단위)로 묶었을 때, 규모(수준)가 커져도 계절 진폭이 그대로면 **가법**이고, 규모가 커질수록 계절 진폭도 비례해서 커지면 **승법**이다.

이걸 숫자로 판정하는 방법이 **변동계수(CV, Coefficient of Variation)**다.

```
변동계수(CV) = 표준편차 / 평균
```

- 표준편차만 보면 가법인지 승법인지 헷갈린다(승법이어도 표준편차 자체는 커질 수 있으니까).
- 하지만 **변동계수가 기간별로 일정하다** = "평균 대비 흔들리는 비율이 똑같다" = 승법 모델의 정의 그 자체.
- 표준편차도 변동계수도 둘 다 거의 일정하다 → 가법.

| 판정 | 표준편차(기간별) | 변동계수(기간별) |
|---|---|---|
| 가법 모델 | 거의 일정 | (표준편차가 일정하니 자연히) 일정 |
| 승법 모델 | 점점 커짐 | 거의 일정 |

- air_passengers: 표준편차 최대/최소 5.67배로 크게 벌어지지만, 변동계수는 1.56배로 거의 일정 → **승법**, 그리고 "로그변환 권장"까지 함께 알려줌(승법 모델을 로그 취하면 가법 형태로 바뀌기 때문 — 로그(A×B×C) = 로그A+로그B+로그C).
- temperatures_seoul: ℃는 절대 눈금이라 여름·겨울 진폭이 평균 기온과 무관하게 일정 → **가법**. 계절 성분 평균이 0 근처(가법 특징. 승법이면 계절 성분 평균이 1 근처).

> **면접 답변 포인트**: "승법 모델을 로그변환하면 가법 모델처럼 다룰 수 있다" — 로그를 씌우는 이유가 바로 이거다. 곱셈 구조를 덧셈 구조로 바꿔서 선형적으로 다루기 쉽게 만드는 것.

### 2-3. 분해 실행과 4개 성분 이해

statsmodels의 `seasonal_decompose()`가 원본(observed)·추세(trend)·계절(seasonal)·잔차(resid) 4개를 계산해준다.

**⚠️ 주의사항 2가지 (실습 코드에 명시됨)**:
1. **분해는 차분하기 전의 원본으로 해야 한다.** 차분은 추세·계절성을 "지우는" 작업인데, 분해는 그 추세·계절성을 "보려는" 작업이라 목적이 정반대다. 정상화(01단원)와 분해(03단원)는 서로 다른 목적의 전처리이므로 섞지 말 것.
2. **trend와 resid의 앞뒤 절반(period/2)은 결측치가 된다.** 추세를 계산할 때 "계절 주기 크기의 이동평균"을 쓰기 때문에, 데이터 양 끝에서는 평균 낼 값이 모자라서 NaN이 된다. (예: period=12 → 앞뒤 6개월씩 NaN, 144개월 중 132개월만 남음)

**직접 코딩 버전**:
```python
from statsmodels.tsa.seasonal import seasonal_decompose

# model: "additive" 또는 "multiplicative", period: 계절 주기
result = seasonal_decompose(df["Passengers"], model="multiplicative", period=12)

# 4개 성분을 하나의 DataFrame으로 묶어서 다루기 편하게 정리
sd = DataFrame({
    "original": result.observed,   # 원본
    "trend": result.trend,         # 추세 (장기 방향)
    "seasonal": result.seasonal,   # 계절 (주기적 반복)
    "resid": result.resid,         # 잔차 (설명 안 되는 나머지)
})
```

**모듈화 버전**:
```python
# model 생략 시 가법/승법을 스스로 판정
result = my_ts.decompose(df, 12, "Passengers")
```

### 2-4. 4개 성분 해석하는 법

| 성분 | 무엇을 보여주는가 | air_passengers 해석 예시 |
|---|---|---|
| trend | 계절 요동이 제거된 순수 성장/하락 곡선 | 126.8 → 475.0 매끄러운 우상향 |
| seasonal | 1년 주기로 완전히 동일하게 반복되는 패턴 | 7~8월 최대(1.22배), 11월 최소(0.80배) |
| resid | 추세+계절로도 설명 안 되는 나머지(불규칙 요인) | 승법 모델이면 1 주변에 무작위로 분포 |

**잔차 기준선 주의**: 가법이면 잔차 기준선이 **0**, 승법이면 **1**이다(그래서 코드에 `ax.axhline(1, ...)`가 있음). 잔차가 기준선 주변에 무작위로 흩어져 있으면 "분해가 잘 됐다"는 뜻이고, 잔차에 뚜렷한 패턴(주기성 등)이 남아 있으면 주기(period)를 잘못 잡았거나 모델(가법/승법) 선택이 틀렸다는 신호.

**승법 모델에서 계절 성분 읽는 법**: 승법이므로 계절 성분은 "배수"로 읽는다. `seasonal = 1.227`이면 "그 달은 추세선보다 22.7% 높다"는 뜻. (가법이면 그냥 "몇 ℃/몇 단위 더하고 뺀다"로 읽으면 됨 — 서울 기온에서 1월 계절지수 -15.024는 "1월은 그 시점 추세보다 15.024℃ 낮다"는 뜻.)

### 2-5. 추세(trend) = 이동평균(창 = 계절 주기) 인 이유

02단원에서 배운 이동평균과 03단원 분해의 trend는 **사실상 같은 것**이다. 직접 확인하는 코드:

```python
# 02단원에서 만든 함수로 12개월 이동평균
rolling = my_ts.plot_rolling(df, 12, "Passengers")

# 분해의 trend와 나란히 놓고 상관계수로 확인
check = DataFrame({"분해의 trend": sd["trend"], "rolling(12)": rolling["이동평균"]})
my_stats.correlation(check, "분해의 trend", "rolling(12)")
```
결과: 상관계수 = 1 (p<0.05). "상관이 있는 정도"가 아니라 **동일한 정보**라고 봐야 함. 즉 분해의 trend 성분 = "창 크기를 계절 주기로 맞춘 이동평균"과 같은 것.

> **상관계수 유의성 검정, 말로 풀면**:
> - 귀무가설(H0): 모상관계수 ρ = 0 이다 (두 변수는 상관이 없다)
> - 대립가설(H1): 모상관계수 ρ ≠ 0 이다 (상관이 있다)
> - p < 0.05이면 귀무가설을 기각 → "상관이 있다"고 통계적으로 판단. 이번 경우 상관계수가 아예 1이라, "상관이 있다" 수준을 넘어 "동일한 값"이라는 결론.

### 2-6. 계절 성분(계절지수)의 특성

계절 성분은 매년 똑같이 반복되므로 **1년치(12개월)만 뽑으면 전체 패턴을 알 수 있다.**

```python
# 계절 성분에서 1년치만 추출 (월별 첫 값 = 매년 동일하므로 첫 값이 곧 대표값)
season = sd["seasonal"].groupby(sd.index.month).first()
```

**승법 모델 계절지수 해석**: 원본 = 추세×계절×잔차이므로 계절지수는 배수. 기준점 1(=추세와 동일)에서 1을 빼고 ×100하면 "추세 대비 몇 % 증감"이 됨.
```python
sdf["추세 대비"] = ((season - 1) * 100).round(1).astype(str) + "%"
```

**가법 모델(서울 기온)이면 그냥 뺄셈값 자체가 ℃ 단위 편차**. 배수 변환이 필요 없음.

**⚠️ 함정 — "주기 내 위치"는 월이 아니다**: `report_seasonal`이 반환하는 인덱스는 "1~12의 위치"이지, 실제 달력상 월이 아니다. 위치 1은 **데이터가 시작하는 달**이다.
- air_passengers는 1월부터 시작해서 위치=월이 우연히 같았음.
- temperatures_seoul은 **7월**부터 시작하므로 위치 1 = 7월, 위치 7 = 1월. 이걸 안 따지고 "최저 위치: 7"을 그대로 "7월"이라고 답하면 오답(실제로 7월은 두 번째로 더운 달). 반드시 아래처럼 위치→월 환산이 필요:
```python
start = df.index[0].month
ss["월"] = [((start - 1 + p - 1) % 12) + 1 for p in ss.index]
```

### 2-7. 계절조정 vs 계절차분 (계절을 지우는 두 가지 방법 — 목적이 다르다)

이 구분이 03단원 연습문제의 핵심 질문이었다. **둘 다 계절을 지우지만 용도가 완전히 다르다.**

| | 계절조정(Seasonal Adjustment) | 계절차분(Seasonal Differencing) |
|---|---|---|
| 계산 | 가법: `원본 - 계절` / 승법: `원본 / 계절` | `y_t - y_(t-주기)` (전년 동월 값을 뺌) |
| 추세 | **남는다** (수준 정보 유지) | **사라진다** (구간 평균이 0 근처로 수렴) |
| 관측치 손실 | 없음 (원본 개수와 동일) | **주기 길이만큼 손실** (앞쪽 1년치가 없어짐) |
| 목적 | **사람에게 보고**("지금 몇 도인가/몇 명인가" 수준 정보 필요) | **모형에 투입**(ARIMA는 정상 시계열이 필요) |
| 예시 | "계절조정 실업률" (경제 통계 용어) | ARIMA의 D차수 |

**직접 코딩(계절조정)**:
```python
# 승법이면 나누기로 제거, 가법이면 빼기로 제거
adjusted = sd["original"] / sd["seasonal"]   # 승법
# adjusted = sd["original"] - sd["seasonal"]  # 가법이면 이렇게
```

**모듈화 버전**:
```python
adjusted = my_ts.adjust_seasonal(df, 12, "Passengers")   # 가법/승법 자동 판단해서 처리
```

**계절차분(01단원부터 써온 transform으로)**:
```python
diffed = my_ts.transform(df, "평균기온(℃)", log=False, diff=0, seasonal_diff=1, period=12)
```

**두 결과를 구간 평균으로 비교하는 판별법** (표준편차만 보면 둘이 비슷해 보여서 구분이 안 됨 — 반드시 **구간 평균의 추세**를 봐야 함):
```python
display(my_ts.report_split(adjusted, size=3))  # 계절조정: 11.891 → 12.747 → 13.048 (계속 상승 = 추세 살아있음)
display(my_ts.report_split(diffed, size=3))    # 계절차분: 0.088 → 0.046 → 0.021 (전부 0 근처 = 수준정보 없음)
```

> **정리 문장(암기용)**: "시민 보고서에는 계절조정, 예측 모형에는 계절차분. 계절조정 계열은 정상 시계열이 아니라서 그대로 ARIMA에 못 넣고, 계절차분 계열은 수준 정보가 사라져서 사람이 보기엔 의미가 없다."

## 3. [04단원] 시계열의 통계적 접근 — 자기상관(ACF)과 부분자기상관(PACF)

### 3-1. 이 단원의 목적

ARIMA 모형은 `ARIMA(p, d, q)` 형태로 3개의 숫자(차수)가 필요하다. d는 이미 01단원에서 ADF 검정으로 구했다. **04단원의 목적은 나머지 p(AR 차수)와 q(MA 차수), 그리고 계절형이면 P·Q까지 찾는 것.** 그 도구가 ACF(자기상관함수)와 PACF(부분자기상관함수)다.

### 3-2. 왜 반드시 "정상 시계열"에만 적용해야 하는가

이게 04단원에서 가장 강조된 개념이다. 먼저 정상 시계열을 만들고 시작한다:
```python
stationary = my_ts.transform(df, "Passengers", log=True, diff=1, seasonal_diff=1, period=12)
my_ts.adf_test(stationary)   # p-value = 0.0002 → 정상성 충족
```

**직접 증명하는 실험** (lag plot):
```python
origin_shift = df["Passengers"].shift(1)          # 원본을 한 칸 밀어서 "직전 값" 열 생성
stationary_shift = stationary.shift(1)             # 정상 시계열도 동일하게
```
- 원본(비정상)과 원본의 shift 값의 상관계수 = **+0.960** (거의 완벽한 직선)
- 정상 시계열과 그 shift 값의 상관계수 = **-0.342** (흩어진 구름, 약한 우하향)

**해석**: 원본의 0.960은 **가짜 상관(허구적 회귀, spurious regression)**이다. 둘 다 그냥 계속 커지고 있으니까 자동으로 상관계수가 높게 나오는 것뿐, 아무 정보가 없다. 반면 정상 시계열의 -0.342는 **진짜 정보**다 — "지난달에 많이 늘었으면 이번 달은 덜 는다"는 되돌림(mean reversion) 패턴을 실제로 보여준다.

> **결론(암기)**: 비정상 시계열의 자기상관은 추세를 반영할 뿐 모형에 쓸 정보를 주지 않는다. **ACF·PACF는 반드시 정상 시계열(ADF 검정을 통과한 시계열)에만 적용한다.**

### 3-3. 자기상관(Autocorrelation) 개념과 수식

**자기상관이란?** 한 시계열이 "자기 자신의 과거 값"과 얼마나 상관관계가 있는지를 재는 것. 시차(lag) k만큼 떨어진 두 시점의 값 사이의 상관계수를 구한다.

**자기상관계수 수식 (시차 k에서)**:

```
r_k = Σ_{t=k+1}^{n} (y_t - ȳ)(y_{t-k} - ȳ)  /  Σ_{t=1}^{n} (y_t - ȳ)²
```

말로 풀면: 전체 분산(분모, 자기 자신과의 공분산이므로 lag 0의 값)을 기준으로, 시차 k만큼 떨어진 값들끼리의 공분산(분자)이 차지하는 비율. 일반 피어슨 상관계수와 원리는 같고, 대상이 "다른 두 변수"가 아니라 "같은 변수의 현재값 vs k시점 전 값"이라는 점만 다르다.

**유의성 판정 기준값**:

```
임계값 = 2 / √n     (n = 관측치 개수)
```

말로 풀면: 만약 이 시계열이 완전히 무작위(백색잡음, white noise)라면, 자기상관계수는 이론상 평균 0을 중심으로 대략 ±2/√n 범위 안에서 우연히 움직인다(근사적으로 95% 신뢰구간에 해당). 즉 **계산된 자기상관계수의 절댓값이 이 기준값을 넘으면 "우연이라고 보기 어렵다 → 통계적으로 유의한 상관"**이라고 판정한다. (statsmodels의 `plot_acf`/`plot_pacf` 그래프에서 파란 음영이 바로 이 기준값 범위다.)

```python
LAGS = 36
N = len(stationary)
THRESHOLD = 2 / np.sqrt(N)
acf_values = acf(stationary, nlags=LAGS)[1:]     # lag 0(자기자신=항상1)은 제외
acf_df = DataFrame({"lag": range(1, LAGS+1), "acf": acf_values.round(3)})
acf_df["유의성"] = np.abs(acf_values) > THRESHOLD
```

### 3-4. lag(시차) 범위를 정하는 규칙

- 계절 주기가 있는 경우: **계절 주기의 2~3배**, 단 **관측치길이/4**를 넘지 않는 선까지. (예: 주기 12 → 2배=24, 3배=36. 관측치 144개 → 144/4=36. 36이 상한과 같아서 그대로 36까지 사용)
- 계절 주기가 없는 경우: `10 * log10(n)` 과 `n/4` 중 **더 작은 값**.

> 뒤쪽 시차(lag)일수록 계산에 쓰이는 관측치 쌍이 줄어들어서 신뢰도가 떨어지기 때문에 상한을 둔다.

### 3-5. ACF 판독 — q값(비계절 MA 차수) 찾기

**판독 규칙**: 유의성이 **처음으로 끊기는(단절되는) 지점**을 찾는다. 그 **직전 시차**가 q값이다. (끊기는 지점이 아예 없으면 전체 lag를 다 쓴다.)

```python
fmin = acf_df[acf_df["유의성"] == False].index.min()   # 처음 비유의로 판정된 행의 인덱스
if np.isnan(fmin): fmin = LAGS
print(f"유의성이 단절되는 시차: {acf_df.iloc[fmin-1]['lag']} (q값)")
```

**⚠️ 실수 포인트**: "끊긴 지점의 시차 번호"를 그대로 답하면 안 된다. 예를 들어 서울 기온 데이터에서 lag 4에서 처음 비유의로 끊겼다면, q는 4가 아니라 **그 직전인 3**이다. ("유의했던 구간이 어디까지였는가"가 차수이지, "끊긴 지점"이 차수가 아니다.)

### 3-6. PACF(부분자기상관) 개념과 p값(비계절 AR 차수) 찾기

**PACF란?** ACF는 "시차 k만큼 떨어진 두 값의 상관"인데, 이 상관에는 **중간에 낀 시차들을 거쳐 전달된 간접 영향**까지 섞여 있다. PACF는 중간 시차들의 영향을 통계적으로 통제(제거)하고, **딱 그 시차만의 직접적인 관계**만 남긴 것이다.

- 예: lag 2의 ACF에는 "t와 t-1의 관계, t-1과 t-2의 관계"가 겹쳐서 전달된 간접효과가 섞여있을 수 있음. lag 2의 PACF는 그 간접효과를 걷어내고 t와 t-2 사이의 순수한 직접 관계만 본 값.

계산 방식·유의성 판정·lag 범위는 ACF와 완전히 동일하고, 함수만 `acf()` → `pacf()`로 바뀐다:

```python
pacf_values = pacf(stationary, nlags=LAGS)[1:]
pacf_df = DataFrame({"lag": range(1, LAGS+1), "pacf": pacf_values.round(3)})
pacf_df["유의성"] = np.abs(pacf_values) > THRESHOLD
```

**판독 규칙(p값)**: ACF와 동일 — 처음 끊기는 지점의 **직전 시차**가 p.

### 3-7. ACF/PACF로 AR/MA 차수를 구분하는 원리 (핵심 이론)

| 모형 | ACF 패턴 | PACF 패턴 |
|---|---|---|
| AR(p) | 서서히 감소(tail-off, 감쇠) | 시차 p 이후 **절단(cut-off)** |
| MA(q) | 시차 q 이후 **절단(cut-off)** | 서서히 감소(tail-off, 감쇠) |
| ARMA(p,q) | 둘 다 서서히 감소 | 둘 다 서서히 감소 |

**왜 이런 차이가 생기는가(개념으로 이해하기)**:
- MA(q) 모형은 "최근 q개의 오차항"으로만 현재 값이 결정되는 구조라서, q시차보다 먼 과거와는 수학적으로 상관이 정확히 0이 된다 → ACF가 q에서 뚝 끊김(절단).
- AR(p) 모형은 "최근 p개의 과거 값"으로 현재가 결정되지만, 그 과거 값들이 또 그 이전 값의 영향을 받는 연쇄 구조라 이론상 모든 시차에 흔적이 남는다(다만 크기는 점점 작아짐) → ACF는 서서히 감소. 반면 PACF는 "중간 경로를 통제"하기 때문에 p시차를 넘어서면 딱 끊긴다.

**실습에서 실제로 확인한 예 (air_passengers)**: ACF가 9,13,32 근처에서도 임계값에 걸치지만 "간신히 넘기는 경계값"이라 무시. 상한선(32.8)을 넘는 33 이후 lag는 애초에 판정하지 않음. → 통계 기준값은 "기계적으로 따르는 것"이 아니라 **맥락을 함께 봐서 판단**해야 함을 보여주는 사례.

**연습문제(서울기온) 실제 판독 결과**:
- ACF: lag1=0.200, lag2=0.099, lag3=0.105(모두 유의, 기준 0.082) → lag4=0.056에서 처음 비유의 → **q=3**
- PACF: lag1=0.200만 유의 → lag2=0.061에서 비유의 → **p=1**
- "ACF는 3, PACF는 1로 다르게 나온 게 정상" — ACF는 q를 알려주는 도구, PACF는 p를 알려주는 도구라서 서로 다른 게 당연함. (둘 다 서서히 감소하는 모양이면 그때는 AR과 MA를 함께 쓰는 ARMA 형태로 판단.)

### 3-8. 계절 차수 P·Q 찾기 (대문자)

**소문자 p·q**가 "지난달과의 관계"라면, **대문자 P·Q**는 "작년 같은 달(계절 주기 배수 시차)과의 관계"다. 세는 원리는 완전히 동일하고, **세는 단위만 "1시차"에서 "1주기(1배수)"로 바뀔 뿐**이다.

**판정 대상 시차 고르기**: 계절 주기의 배수(12, 24, 36, ...)만 뽑는다. 사이의 시차(13, 14, ... 는 계절 판정과 무관)는 쓰지 않는다. 단, 앞서 정한 상한(관측치수/4)을 넘는 배수는 제외.

```python
PERIOD = 12
LIMIT = N // 4
season_lags = [k for k in range(PERIOD, LAGS+1, PERIOD) if k <= LIMIT]
```

**계절 시차의 계수만 뽑아서 같은 규칙 적용**: 새로 계산할 게 없고, 이미 만든 acf_df/pacf_df에서 해당 lag 행만 골라온다. 유의성 기준값도 비계절과 동일한 걸 그대로 쓴다(판정 기준은 "관측치 수"로 정해지지 "시차가 계절이냐 아니냐"로 정해지는 게 아니기 때문).

```python
acf_idx = acf_df.set_index("lag")
pacf_idx = pacf_df.set_index("lag")
season_df = DataFrame({
    "lag": season_lags,
    "acf": acf_idx.loc[season_lags, "acf"].values,
    "acf 유의성": acf_idx.loc[season_lags, "유의성"].values,
    "pacf": pacf_idx.loc[season_lags, "pacf"].values,
    "pacf 유의성": pacf_idx.loc[season_lags, "유의성"].values,
})
```

**차수 계산**: 유의성이 처음 끊기는 지점의 **직전까지의 "배수 개수"**가 차수. (시차 번호가 아니라 배수 몇 개째인지를 센다는 점이 비계절과 다름!)

```python
acf_break = season_df[season_df["acf 유의성"] == False].index.min()
pacf_break = season_df[season_df["pacf 유의성"] == False].index.min()
if np.isnan(acf_break): acf_break = len(season_df)
if np.isnan(pacf_break): pacf_break = len(season_df)
Q = int(acf_break)    # 계절 ACF → 계절 MA 차수
P = int(pacf_break)   # 계절 PACF → 계절 AR 차수
```

**연습문제(서울기온) 실제 결과**:

| 계절시차 | acf | pacf | 판정 |
|---|---|---|---|
| 12(1배수) | -0.441 | -0.458 | 둘 다 유의 |
| 24(2배수) | -0.094 | -0.364 | 둘 다 유의(0.094는 기준 0.082를 간신히 넘긴 경계값) |
| 36(3배수) | 0.067 | -0.229 | acf만 비유의 → ACF는 여기서 절단 |

→ 계절 ACF는 24까지 유의, 36에서 끊김 → **Q=2**. 계절 PACF는 판정범위(36) 안에서 끊기지 않음 → **P=3**.

**⚠️ 실수 포인트**: "끊긴 시차 번호(36)"를 그대로 답하면 안 됨 — 대문자 차수는 **시차 번호가 아니라 유의했던 "배수의 개수"**. lag 24까지 유의했으면 그건 2배수째이므로 답은 24가 아니라 **2**.

**⚠️ 한계 인지하기**: P=3은 "판정 범위 안에서 끊기지 않았다"는 뜻이지 확정값이 아니다. 실제로 계절 PACF가 -0.458→-0.364→-0.229로 서서히 작아지는 tail-off 모양이라, 이건 절단이 아니라 감쇠 패턴 — 즉 계절 쪽은 AR보다 MA(Q)가 주도할 가능성이 있다는 힌트. **ACF·PACF는 정답을 확정해주는 게 아니라 "후보의 상한"만 좁혀주는 도구**이고, 이 상한 안에서 여러 조합을 다 적합해보고 AIC/BIC로 최종 선택하는 게 다음(05)단원의 일이다.

## 4. 통계 개념 총정리 (말로 풀어서, 면접 답변용)

### 4-1. 변동계수(CV, Coefficient of Variation)
- 정의: 표준편차 ÷ 평균. 단위가 없는(무차원) 상대적 변동성 지표.
- 왜 쓰는가: 표준편차는 데이터의 "규모"에 영향을 받아서, 규모가 다른 두 구간을 그냥 표준편차로만 비교하면 왜곡됨. 변동계수는 평균으로 나눠서 규모를 통제한 뒤 "흔들리는 비율"만 비교할 수 있게 해줌.
- 이 랩에서의 쓰임: 시계열 분해에서 가법/승법 모델을 판정하는 기준. "규모가 커져도 흔들리는 비율(CV)이 일정하면 승법"이라는 논리.

### 4-2. 상관계수 유의성 검정
- 귀무가설(H0): 모상관계수 ρ = 0이다 (두 변수 사이에 선형 상관관계가 없다)
- 대립가설(H1): 모상관계수 ρ ≠ 0이다 (선형 상관관계가 있다)
- p-value가 유의수준(보통 0.05)보다 작으면 귀무가설을 기각하고, "통계적으로 유의한 상관관계가 있다"고 결론.
- 이 랩에서의 쓰임: 분해된 trend 성분과 이동평균이 사실상 같은 값임을 증명(상관계수=1, p<0.05).

### 4-3. ADF 검정(단위근 검정) — 04단원에서 다시 등장
- 귀무가설(H0): 시계열에 단위근이 존재한다 (= 비정상 시계열이다)
- 대립가설(H1): 단위근이 존재하지 않는다 (= 정상 시계열이다)
- p-value < 0.05이면 귀무가설을 기각 → "정상 시계열이다"라고 판단.
- 이 랩에서의 쓰임: ACF/PACF를 적용하기 전에 반드시 정상성을 확보했는지 확인하는 관문. p=0.0002로 통과 확인 후 분석 진행.

### 4-4. 자기상관계수(ACF, Autocorrelation Coefficient)
- 정의: 같은 시계열의 현재 값과, 시차(lag) k만큼 떨어진 과거 값 사이의 상관계수.
- 수식: r_k = [시차 k만큼 떨어진 값들의 편차곱 합] ÷ [전체 편차제곱 합]
- 해석: r_k가 0에 가까우면 그 시차와는 선형적 관계가 없다는 뜻이고, ±1에 가까울수록 강한 (양/음의) 관계.
- 유의성 판정: 백색잡음(완전 무작위 시계열)이라면 자기상관계수가 이론적으로 대략 ±2/√n 범위 안에서 우연히 나온다고 보고, 이 범위를 벗어나면 우연이 아닌 유의한 상관으로 판정.

### 4-5. 부분자기상관계수(PACF, Partial Autocorrelation Coefficient)
- 정의: 시차 k의 자기상관 중에서, 그 사이(1~k-1시차)의 간접적인 영향을 통계적으로 제거하고 남은 "순수한 직접 관계"만 나타낸 값.
- ACF와의 차이를 한 문장으로: ACF는 "간접 영향까지 포함한 전체 관계", PACF는 "중간을 다 통제하고 남은 직접 관계".
- 쓰임: ACF는 MA 차수(q)를, PACF는 AR 차수(p)를 추정하는 데 쓰임.

### 4-6. AR / MA / ARMA / ARIMA / SARIMA 구조 이해 (말로)
- **AR(p) (자기회귀, AutoRegressive)**: 현재 값을 "과거 p개 관측값들의 선형결합"으로 설명하는 모형. 예: AR(1)은 "오늘 값은 어제 값에 비례한다"는 구조.
- **MA(q) (이동평균, Moving Average)**: 현재 값을 "과거 q개 오차(예측 못한 충격)들의 선형결합"으로 설명하는 모형. 이동평균 평활법(스무딩)의 그 이동평균과는 다른 개념이니 혼동 주의 — 여기서는 "과거 오차항들의 가중합"이라는 뜻.
- **ARMA(p,q)**: AR과 MA를 합친 모형. 정상 시계열에만 쓸 수 있음.
- **ARIMA(p,d,q)**: ARMA에 차분(Integrated, d번 차분)을 추가해서 비정상 시계열도 d번 차분해 정상화한 뒤 ARMA를 적용하는 구조.
- **SARIMA(p,d,q)(P,D,Q)s**: ARIMA에 계절성 항(P,D,Q, 주기 s)까지 추가한 구조. 이 랩에서 최종적으로 확정하려는 것이 바로 이 7개 숫자.
- 차수를 정하는 원리(재확인): ACF가 끊기면 MA(q), PACF가 끊기면 AR(p), 둘 다 서서히 줄어들면 ARMA. 이 원리가 계절(대문자 P,Q)에도 "세는 단위만 주기로" 바뀌어 동일하게 적용됨.

## 5. 자주 하는 실수 모음 (전체 통합)

1. **분해는 원본으로, 차분은 별개의 목적** — 차분된 데이터로 분해하지 않는다.
2. **"주기 내 위치"는 달력 월이 아니다** — 데이터 시작 월이 위치 1. 반드시 실제 월로 환산 후 해석.
3. **표준편차만으로 판단 금지** — 계절조정 vs 계절차분처럼 표준편차가 비슷해도 구간 평균(추세 보존 여부)을 봐야 실제 차이가 드러남.
4. **ACF/PACF 절단 지점 ≠ 차수** — 차수는 "끊기기 직전까지" 유의했던 마지막 시차.
5. **계절 차수(대문자)는 "배수 개수"이지 "시차 번호"가 아니다** — lag 24까지 유의 = 2배수 = 차수 2 (24가 아님).
6. **로그변환은 양수 데이터에만** — 음수가 있으면(기온 등) 로그변환 후보에서 제외해야 함, 안 그러면 해당 구간이 결측 처리되어 버려짐.
7. **경계값(기준값을 간신히 넘는 값)을 기계적으로 확정 답처럼 쓰지 말 것** — 근접한 값은 최종 결정 전에 맥락으로 재검토.
8. **ACF/PACF는 최종 답이 아니라 후보 상한** — 실제 최종 차수는 다음 단계(AIC/BIC 등)에서 여러 조합을 적합해보고 확정.

## 6. 다음 랩 예고 (05단원, 아직 학습 전)

지금까지 확정한 것: 계절 주기 s=12, 정상화 조합(d, D), 비계절 p=1·q=3(서울기온 기준), 계절 P=3·Q=2(상한). 다음 단계는 이 후보들을 조합해 `SARIMA(p,d,q)(P,D,Q)12` 여러 모형을 실제로 적합시키고, AIC/BIC 같은 정보기준으로 최종 모형을 선택하는 것 — "그래서 내년 여름은 얼마나 더운가"에 답하는 예측 단계로 이어진다.
