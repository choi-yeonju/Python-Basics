## 1. 데이터 타입 변환 (astype)

`.astype()` 에 원하는 타입을 문자열로 넘기면 됨.

```python
df['국어'] = df['국어'].astype('float')              # 컬럼 하나씩
df = origin.astype({'국어': 'float', '수학': 'str'})  # 여러 컬럼 한 번에
```

### 범주형(category) — 명목 vs 서열

- **명목척도(Nominal)**: 순서 없는 분류 (예: 성별) → `astype('category')`
- **서열척도(Ordinal)**: 순서 있는 분류 (예: 학년 1<2<3<4)
  → `CategoricalDtype(categories=[1,2,3,4], ordered=True)`로 변환해야 순서 정보가 담김.
  단순히 `'category'`로만 바꾸면 순서 없는 명목척도가 됨.

> 전처리 체크: `astype({'컬럼':'category'})`는 더미변수 만들기 전 기술통계 산출에도 유리 (14장 참고).

## 2. 컬럼/인덱스 이름 변경 (rename)

`.rename()`은 컬럼명과 인덱스(행 이름)를 동시에 바꿀 수 있음.

```python
df = origin.rename(
    columns={'국어': 'kor', '영어': 'eng'},
    index={'석영': 'suk', '호영': 'ho'}
)
```

바꾸고 싶은 것만 딕셔너리에 명시하면 나머지는 그대로 유지됨.

## 3. 행/열 추가·삭제·재배치

### 3-1. 재배치 (reindex)

```python
df.reindex(columns=['국어', '수학', '과학', '영어'])  # 열 순서 변경
df.reindex(index=['석영', '호영', '민철', '수현'])     # 행 순서 변경
```

### 3-2. 행 추가 (loc)

`.loc[새인덱스명]`에 값을 대입 → 새 행 추가. 값은 리스트/딕셔너리/Series 다 가능.

```python
df.loc['정호'] = [2, '남자', 90, 80, 70, 60]                            # 리스트
df.loc['민정'] = {'학년': 4, '성별': '여자', '국어': 81}                 # 딕셔너리
df.loc['형석'] = Series([2, '남자', 90], index=['학년', '성별', '국어']) # Series
```

딕셔너리/Series는 **이름 기준 매핑**이라 컬럼 순서 실수가 줄어듦. 일부 값만 넘기면 나머지는 자동 `NaN`.

### 3-3. 열 추가

```python
df['한국사'] = [72, 56, 90, None, 92, 90, 75, 80, 60]  # 리스트
df['체육'] = df['과학']                                  # 기존 열 복사
df['체육'] = 100                                        # 단일 값 채우기
```

딕셔너리로 추가 시 인덱스 이름이 키. 없는 키는 무시, 없는 인덱스는 `NaN`.

### 3-4. 행/열 삭제 (drop)

```python
df.drop(index='철수')                # 단일 행 삭제
df.drop(index=['철수', '민철'])       # 다중 행 삭제
df.drop(columns='학년')              # 단일 열 삭제
df.drop(columns=['학년', '성별'])     # 다중 열 삭제

df.drop(index=df.index[0:7])         # 슬라이싱으로 삭제 (처음 7행)
df.drop(columns=df.columns[1:-2])    # 1번째부터 끝에서 2번째 전까지 삭제
```

`axis=1`을 붙이면 `columns=` 없이도 열 삭제 가능.

### 3-5. 인덱스가 문자열일 때 행 복사의 함정 (monsters 실습)

```python
df.loc['M004'] = df.loc['M003']   # 새 행의 인덱스는 'M004'가 되지만
                                    # monster_id 컬럼값은 복사 안 돼서 NaN!
```

인덱스와 컬럼은 별개 개념이기 때문. 올바른 해결 패턴:

```python
df = df.reset_index()             # 인덱스를 일반 컬럼으로 내림 → 정수 인덱스 확보
df.loc[3] = df.loc[2].copy()      # 정수 인덱스로 행 복사
df.loc[3, 'monster_id'] = 'M003_copy'  # monster_id 컬럼값 직접 수정
```

| 상황 | 쓸 수 있는 것 |
|---|---|
| 인덱스가 문자열 | `rename(index=...)` |
| 인덱스가 정수 | `.loc[숫자]`로 행 조작 |
| 둘 다 필요 | `reset_index()` 후 작업 |

**막히면 "지금 인덱스가 뭔지" 먼저 확인하는 습관.**

## 4. 원본 불변 원칙 (pandas 공통 규칙) ⭐ 중요

**pandas 대부분의 메서드는 원본을 직접 수정하지 않고, 결과를 새 객체로 리턴한다.**
`drop`, `rename`, `reindex`, `astype` 모두 동일.

```python
축열삭제DF = origin.copy()
축열삭제DF.drop(['학년', '성별'], axis=1)  # ← 결과가 반영 안 됨! 리턴값을 안 받았기 때문
축열삭제DF  # 여전히 학년, 성별 열이 남아있음
```

해결 방법 두 가지:

```python
# 방법 1: 리턴값을 변수에 받기 (권장 — 원본 보존, 단계별 추적 용이)
축열삭제DF = 축열삭제DF.drop(['학년', '성별'], axis=1)

# 방법 2: inplace=True (원본 직접 수정)
축열삭제DF.drop(['학년', '성별'], axis=1, inplace=True)
```

이 원칙은 이상치 처리(15장), 결측치 처리(8장) 등 이후 모든 단계에서도 그대로 적용됨.
매 단계 `.copy()`로 새 변수를 만들고(`outline_df`, `outline_df2`, `outline_df3`...), 단계별로 이름을 분리하면 중간에 틀렸을 때 되돌아가기 쉬움 — 학습 단계에서는 `df1, df2, df3`처럼 나누는 게 `df` 하나로 계속 덮어쓰는 것보다 디버깅에 유리함.

## 5. DataFrame / Series 만드는 방법

### 5-1. Series 생성 — 두 가지 방식, 결과 동일

```python
Series([2.2, 'Kelpie', 'Medium'], index=['height', 'species', 'caution_level'])  # 리스트+index
Series({'height': 2.2, 'species': 'Kelpie', 'caution_level': 'Medium'})          # 딕셔너리 (가독성 더 좋음)
```

### 5-2. DataFrame 생성 — 3가지 방법

**방법 1 — 컬럼 기준 딕셔너리 (직접 넣기)**
```python
df = DataFrame({
    'customer_id': [101, 102, 103],
    'name': ['Alice', 'Bob', 'Charlie']
})
```

**방법 2 — 컬럼 기준 딕셔너리 (변수로 분리, 데이터 길 때 가독성 좋음)**
```python
data = {
    "class": ["A1","A1","A1", "A2","A2","A2"],
    "time":  [62, 60, 63,    67, 71, 64]
}
df = DataFrame(data)
```
→ 타이핑 적고 깔끔하지만, 행이 많아지면 어느 값이 어느 행인지 파악 어려움.

**방법 3 — 행 기준 딕셔너리 리스트**
```python
data = [
    {"class": "A1", "time": 62},
    {"class": "A1", "time": 60}
]
df = DataFrame(data)
```
→ 딕셔너리 하나 = 행 하나. 행 단위로 읽고 수정하기 편하고, 실제 JSON 구조와 같아서 실무에서 자주 쓰임.

| | 구조 | 방향 |
|---|---|---|
| 방법 1, 2 | `{컬럼: [값, 값, 값]}` | 컬럼 기준 |
| 방법 3 | `[{컬럼: 값}, {컬럼: 값}]` | 행 기준 |

### 5-3. 자주 하는 실수

```python
# ❌ 이미 DataFrame인데 또 감싸기 (불필요)
origin = load_data('monsters')
df = DataFrame(origin)

# ❌ 괄호 쌍 틀림
DataFrame({'customer_id': [101, 102], 'name': ['Alice', 'Bob'])  # } 빠짐

# ❌ 존재하지 않는 문법
DataFrame(index={}, column={})

# ✅ 뼈대 먼저 닫고 채우기
DataFrame({})
```

`load_data()`류 함수가 이미 DataFrame을 반환하는 경우가 많으므로, 뭔가 불러왔을 땐 `type(origin)` 한 번 찍어보는 습관을 들이면 이런 실수를 줄일 수 있음.

## 7. 시계열 데이터 처리

큰 흐름: **변환 → 추출 → 연산**

### 7-1. 문자열 → 날짜 타입 변환

```python
from pandas import to_datetime
df['주문일_변환'] = to_datetime(df['주문일'], format='%Y년 %m월 %d일')
```
`format=`엔 원본 문자열의 날짜 형식 그대로 기술 (`%Y`=4자리 연도, `%m`=월, `%d`=일).

### 7-2. 날짜 정보 추출 (`.dt.` accessor)

```python
df['년도'] = df['주문일_변환'].dt.year
df['월']   = df['주문일_변환'].dt.month
df['일']   = df['주문일_변환'].dt.day
df['요일'] = df['주문일_변환'].dt.day_name()    # 영문 요일명, 메서드라 () 필요
df['요일번호'] = df['주문일_변환'].dt.dayofweek  # 0=월요일, 속성이라 () 없음!
df['분기'] = df['주문일_변환'].dt.quarter
df['연중몇일째'] = df['주문일_변환'].dt.dayofyear
```

**헷갈리기 쉬운 포인트:** `dt.day_name()`은 메서드(괄호 필요), `dt.dayofweek`는 속성(괄호 없음). 붙이면 에러.

### 7-3. 한글 요일 매핑

```python
요일매핑 = {0:'월요일', 1:'화요일', 2:'수요일', 3:'목요일', 4:'금요일', 5:'토요일', 6:'일요일'}
df['요일'] = df['요일번호'].map(요일매핑)
```

### 7-4. 날짜 연산

날짜끼리 빼면 timedelta 타입 → `.dt.days`로 정수(일수) 추출.

```python
df['배송소요일'] = (df['배송완료일시'] - df['주문일_변환']).dt.days
df['경과일'] = (dt.now() - df['배송완료일시']).dt.days
```

| 도구 | 용도 | 특징 |
|---|---|---|
| `timedelta(days=n)` | 일/시간 단위 연산 | Python 내장, 정확한 시간 단위 |
| `DateOffset(years=n, months=n)` | 년/월 단위 연산 | pandas 제공, 달력 기준 |

`timedelta`는 정확히 n일, `DateOffset`은 "한 달 후"처럼 달력 기준 → 월마다 일수가 달라 `timedelta(days=30)` ≠ `DateOffset(months=1)` 일 수 있음.

## 8. 결측치 처리 (SimpleImputer)

### 핵심 개념

- `isnull()` → 결측치 여부 True/False
- `isnull().sum()` → 열별 결측치 개수
- `dropna()` → 결측치 있는 행/열 삭제
- `fillna(값)` → 특정 값으로 대체
- `SimpleImputer` → 통계적 값(평균 등)으로 대체

### SimpleImputer 전체 흐름

```python
from sklearn.impute import SimpleImputer
import numpy as np

# 1. 특정 컬럼만 추출 후 2D로 변환
reshape = df['Price'].values.reshape(-1, 1)
# .values          → numpy 1D 배열
# .reshape(-1, 1)  → SimpleImputer가 요구하는 2D 배열

# 2. Imputer 생성 + 적용
imr = SimpleImputer(missing_values=np.nan, strategy='mean')
df_imr = imr.fit_transform(reshape)
# fit       → NaN 제외하고 평균 계산
# transform → NaN 자리에 평균값 채워넣기

# 3. 결과를 DataFrame에 반영
df_copy = df.copy()
df_copy['Price'] = df_imr
```

### 왜 reshape(-1, 1) 하나?

| 형태 | shape | SimpleImputer 수용 여부 |
|---|---|---|
| `df['Price'].values` | `(100,)` 1D | ❌ 거부 |
| `.reshape(-1, 1)` | `(100, 1)` 2D | ✅ OK |

`-1`은 "행 수는 알아서 계산", `1`은 열이 1개.

### 여러 컬럼(전체 DataFrame) 한 번에 처리하는 패턴

```python
imr = SimpleImputer(missing_values=np.nan, strategy='mean')
df_imr = imr.fit_transform(원본df.values)
결과df = DataFrame(df_imr, index=원본df.index, columns=원본df.columns)
```
`.fit_transform()`은 numpy 배열을 반환하므로, 다시 `DataFrame()`으로 감싸서 index/columns를 원본과 동일하게 지정해야 함 (안 그러면 컬럼명이 0,1,2...로 날아감).

### strategy 종류

- `'mean'` (평균) — 수치형 일반적
- `'median'` (중앙값) — 이상치 영향 적음
- `'most_frequent'` (최빈값) — 범주형 결측치에 사용
- `'constant'` (지정값)

### 범주형 결측치 → 최빈값으로 채우는 패턴

```python
imr = SimpleImputer(missing_values=np.nan, strategy='most_frequent')
imr_value = imr.fit_transform(df[['컬럼명']])
imr_df = DataFrame(imr_value, index=df.index, columns=['컬럼명'])
df['컬럼명'] = imr_df['컬럼명']
```

### ❌ 자주 하는 실수 — 변수 덮어쓰기

```python
df3 = df2.copy()       # df3 = DataFrame ✅
df3 = SimpleImputer()  # df3 = Imputer로 덮어씀 ❌
origin = df3.copy()    # Imputer에 .copy() → TypeError 💥
```
**원인:** 파이썬 변수는 하나의 값만 담음. 새로 할당하면 이전 값 사라짐.
**해결:** Imputer는 다른 변수명(`imr`, `imr2`)으로 저장.

```python
df3 = df2.copy()            # DataFrame 유지
imr2 = SimpleImputer(...)   # Imputer는 따로 저장
origin = df3.copy()         # ✅ 정상
```

## 9. 데이터 병합 (merge, concat)

### merge — 열 기준 병합

```python
from pandas import merge

merge(df1, df2)                                     # inner join (기본)
merge(df1, df2, how='left')                         # left outer join
merge(df1, df2, how='right')                        # right outer join
merge(df1, df2, how='outer')                        # full outer join
merge(df1, df2, on='customer_id')                   # 병합 기준 열 지정
merge(df1, df2, left_on='이름', right_on='성명')      # 컬럼명 다를 때
merge(df1, df2, left_index=True, right_index=True)  # 양쪽 다 인덱스 기준
merge(customers_df, purchases_df, left_index=True, right_on='user_id')  # 한쪽은 index, 한쪽은 컬럼 기준
merge(df1, df2, left_on='id', right_on='user_id')   # 양쪽 다 특정 컬럼 기준
```
> `left_index`/`right_index`/`left_on`/`right_on`을 상황에 맞게 섞어 쓸 수 있음. 여러 테이블을 다룰 땐 병합 전에 어떤 컬럼(또는 index)이 기준키인지 꼭 확인.

> ⚠️ **병합 후 행이 갑자기 늘어났다면**: key가 한쪽에서 중복돼 있어서(1:N 관계) 매칭되는 만큼 행이 곱해진 것. 병합 전후 `.shape`을 비교하는 습관을 들일 것.

**사전 방어 — `validate`**
```python
merge(orders, customers, on='고객ID', how='left', validate='many_to_one')
```
예상한 관계(`one_to_one`/`one_to_many`/`many_to_one`/`many_to_many`)와 다르면 merge가 에러를 내며 멈춰서, 조용히 행이 부풀려지는 사고를 막아줌.

**매칭 여부 확인 — `indicator`**
```python
df = merge(orders, customers, on='고객ID', how='outer', indicator=True)
df['_merge'].value_counts()   # left_only / right_only / both 개수 확인
```

**merge 전 체크리스트**
- [ ] 양쪽 key 컬럼의 dtype이 같은가? (`"1001"` 문자열 vs `1001` 숫자면 매칭 실패 — 1번 섹션 타입 변환 개념과 동일한 함정)
- [ ] 양쪽 key에 중복값이 있는가? (`df['key'].duplicated().sum()`)
- [ ] key 표기(공백/대소문자)가 일치하는가? (`.str.strip()`, `.str.lower()`로 정리 후 병합)

```python
merge(df_a, df_b, on='ID', suffixes=('_주문', '_배송'))   # 겹치는 컬럼명 구분
```

## 11. 그룹집계 (groupby)

### 기본 사용법

```python
df.groupby('년도').sum()
df.groupby('년도').mean()
df.groupby(['년도', '월']).mean()   # 복수 기준
```

### 여러 집계함수 동시 적용

```python
df.groupby('년도').agg(['sum', 'max', 'min', 'mean'])

# 컬럼별로 다른 집계함수
df.groupby('년도').agg({
    '발생건수': ['mean', 'sum'],
    '사망자수': 'max',
    '부상자수': 'min'
})
```

### 사용자 정의 함수

```python
def myFunction(x):
    return x.max() - x.min()

df.groupby('년도').agg(['max', 'min', myFunction])
df.groupby('년도').agg(['max', 'min', lambda x: x.max() - x.min()])  # 람다식
```

### 인덱스 해제

```python
df.groupby('년도', as_index=False).sum()   # 기준 컬럼이 인덱스로 안 빠지게
```

### count() vs size() — 결측치 포함 여부 주의

```python
df.groupby('지역')['매출'].count()     # 지역별 값 개수 (NaN 제외)
df.groupby('지역').size()              # 지역별 행 개수 (NaN 포함! count와 다름)
```
> ⚠️ "몇 개인지 세고 싶다"고 할 때 이 둘을 헷갈리면 결측치가 있는 데이터에서 숫자가 달라짐. `count()`는 결측치 제외 개수, `size()`는 결측 포함 전체 행 개수.

### cumcount() — 그룹 내 일련번호 생성 (count()와 구분 주의)

`count()`와 이름이 비슷해서 헷갈리기 쉬우나 역할이 완전히 다름.

| 함수 | 하는 일 | 결과 |
|---|---|---|
| `count()` | 그룹별 개수를 **집계** | 그룹 수만큼의 행으로 축약 |
| `cumcount()` | 그룹 **내부**에서 0부터 순번 매김 | 원본 행 개수 그대로, 각 행에 순번 부여 |

```python
df.groupby('sex').count()     # 그룹별 총 개수 (집계)
df.groupby('sex').cumcount()  # 그룹 내 순번: 0,1,2,... (그룹 바뀌면 다시 0부터)
```

**신호 (다음에 이 패턴 알아채는 법):** 원본 데이터에 "그룹라벨 + 값" 컬럼만 있고, 각 행을 구분할 고유 식별자(ID)가 없는 상태에서 wide로 pivot해야 할 때.

**왜 필요한가:** pivot_table로 long → wide 변환할 때 `index`에 값 자체(예: `height`)를 넣으면, 같은 값끼리 (index, columns) 조합이 겹쳐서 **집계**되어버려 개별 관측치가 사라짐. `groupby().cumcount()`로 그룹별 순번 컬럼을 만들어 그걸 index로 써야, 겹치는 조합이 없어서 집계 없이 형태만 바뀜.

```python
df['idx'] = df.groupby('sex').cumcount()
df_wide = pivot_table(df, index='idx', columns='sex', values='height')
df_wide.columns.name = None   # pivot 후 남는 columns 이름표(name) 제거
```

**검증:** 값 손실 없이 변환됐는지 확인하는 습관.
```python
len(df) == df_wide.count().sum()   # True면 정상 변환
```

**주의 — NaN 발생은 정상:** 그룹별 관측치 개수가 다르면(F=30, M=28 등) 짧은 쪽에 `NaN`이 자동으로 채워짐. 에러가 아니라 정상 동작이며, 이후 통계 함수에서 각 컬럼을 `.dropna()`로 개별 처리하면 문제없음.

> ⚠️ 12번 섹션 "wide ↔ long 재구조화"에서 pivot_table의 index 선택 문제와 직결됨 — 함께 참고.

## 12. wide ↔ long 재구조화

**변환 전에 "지금 데이터가 wide야, long이야?" 먼저 파악할 것.**

- wide → long : `melt()` 또는 `stack()`
- long → wide : `pivot_table()` 또는 `pivot()`

> ⚠️ 가장 많이 틀리는 부분: pivot_table은 long → wide인데, 원본이 이미 wide인 상황에서 pivot_table을 쓰려는 방향 착오가 잦음. 코드 짜기 전에 방향부터 확정할 것.

### pivot_table() — long → wide

```python
pivot_table(df,
            index='행으로 쓸 컬럼',
            columns='열로 펼칠 컬럼',
            values='값 컬럼',
            aggfunc='집계 방법')  # 기본값: mean
```
index, columns에 리스트로 여러 개 지정 가능. aggfunc도 `['sum', 'mean']`처럼 여러 개 지정 가능.
> 💡 index로 쓸 고유 식별자가 없는 경우 → 11번 섹션 `cumcount()` 참고.

**crosstab() — 두 범주형 변수의 조합별 "개수(빈도)"가 필요할 때**
```python
from pandas import crosstab

crosstab(df['성별'], df['가입여부'])          # 값 대신 개수를 바로 표로
crosstab(df['성별'], df['가입여부'], margins=True)  # 맨 끝에 합계(All) 행/열 자동 추가
```
`pivot_table`은 값(연속형)을 요약하는 용도, `crosstab`은 범주 조합의 빈도를 세는 용도로 구분해서 씀 (Heatmap 그리기 전 단계로도 자주 쓰임).

### melt() — wide → long (pivot_table의 반대)

```python
melt(df,
     id_vars,      # 고정할 컬럼 (녹이지 않을 것)
     value_vars,   # 녹일 컬럼들 (생략 시 id_vars 제외 전부 자동)
     var_name,     # 컬럼명들이 값으로 들어갈 컬럼 이름 (기본값: "variable")
     value_name)   # 실제 수치가 들어갈 컬럼 이름 (기본값: "value")
```
생각 순서: **"뭘 고정? → 뭘 녹여? → 녹인 결과 컬럼 이름은?"**
`var_name`, `value_name` 생략해도 결과는 나오지만 컬럼명이 variable/value로 기본값이 됨 → 제출용/후속 분석 헷갈리지 않게 명시적으로 쓰는 습관.

### stack() — 인덱스 기반 wide → long

```python
df2 = df1.set_index('player')   # 고정할 컬럼을 인덱스로 올림
df3 = DataFrame(df2.stack())    # 나머지 컬럼들을 행으로 녹임
df4 = df3.reset_index()         # 인덱스를 다시 컬럼으로 내림
```
stack() 결과의 값 컬럼 이름은 숫자 `0`으로 나옴 → 이후 `filter(['player', 0])`처럼 접근.

### ❌ 자주 하는 실수

1. **방향 반대로 씀**: wide→long인데 pivot_table을 쓰려 함 (도구 선택 오류).
2. **컬럼 없는데 groupby 먼저 씀**: 파생변수(예: Total) 만들기 전에 groupby부터 하려 함 → 순서는 "파생변수 만들기 → groupby → sort".
3. **melt에서 옵션 생략**: id_vars만 쓰고 var_name/value_name 생략 → 컬럼명이 variable/value로 나와 의미 불명확.

### 도구 선택 기준 요약

| 목적 | 도구 |
|---|---|
| wide → long | melt() 또는 stack() |
| long → wide | pivot_table() |

df['Total'] = df['Price'] * df['Quantity']

### 조건부 파생변수 3가지 방법

**1. np.where() — 조건 1개 (if/else)**

df['결과'] = np.where(df['평균'] >= 80, '합격', '불합격')

df['성별코드'] = df['성별'].map({"남자": "M", "여자": "F"})

## 14. 더미변수 / 인코딩

### 14-1. 더미변수란?

명목형(범주형) 변수를 숫자로 변환해서 모델이 이해할 수 있게 만드는 것. 단순 라벨링(0,1,2...)을 순서 없는 범주에 쓰면 모델이 크기 관계로 착각할 위험 있음 (예: 색상 {빨강=0,파랑=1,초록=2} → "초록이 빨강보다 크다"는 잘못된 관계 발생). 그래서 순서 없는 명목형은 **더미변수(원-핫 인코딩)**로 처리.

### 14-2. 라벨링 vs 더미변수(원-핫 인코딩)

| 구분 | 라벨링(Label Encoding) | 더미변수(One-Hot Encoding) |
|---|---|---|
| 방식 | 카테고리마다 정수 하나 부여 | 카테고리마다 별도 컬럼 생성 (0/1) |
| 적합한 경우 | 순서 있는 범주형 (예: A>B>C) | 순서 없는 명목형 (예: 성별, 색상) |
| 문제점 | 순서 없는 데이터에 쓰면 크기 오해 | 컬럼 수가 카테고리 수만큼 증가 |
| 결과 컬럼 수 | 1개 | N개 또는 N-1개 |

### 14-3. 방법 A — pandas `get_dummies()`

간단·빠름, EDA/전처리 단계에서 자주 사용. 원본 컬럼 **자동 삭제**됨.

```python
from pandas import get_dummies

dummy_df = get_dummies(df, columns=['컬럼명'], dtype='int')                       # 단일 컬럼
dummy_df = get_dummies(df, columns=['컬럼명1', '컬럼명2'], dtype='int')            # 여러 컬럼 동시
dummy_df = get_dummies(df, columns=['컬럼명1', '컬럼명2'], dtype='int', drop_first=True)  # N-1개 (다중공선성 방지)
```

### 14-4. 방법 B — sklearn `OneHotEncoder`

ML 파이프라인용 (train/test 분리 후 일관된 인코딩 적용에 유리). 원본 컬럼 **수동 삭제 필수**.

```python
from pandas import DataFrame, merge
from sklearn.preprocessing import OneHotEncoder

# 1. 인코딩 대상 컬럼 추출 (2차원 형태로!)
X = df[['컬럼명']]

# 2. 인코더 생성 및 학습/변환
encoder = OneHotEncoder(sparse_output=False, drop=None, dtype=int)
result = encoder.fit_transform(X)

# 3. 새 컬럼명 생성
new_cols = encoder.get_feature_names_out(['컬럼명'])

# 4. 결과를 DataFrame으로 변환 (index를 원본과 맞춰야 병합 정확)
one_hot_df = DataFrame(result, columns=new_cols, index=df.index)

# 5. 원본과 병합
result_df = merge(df, one_hot_df, left_index=True, right_index=True)

# 6. 원본 컬럼 제거 (자동 삭제 안 됨! 수동 필수)
result_df = result_df.drop(columns=['컬럼명'])
```

여러 컬럼 동시 처리 시 `df[['컬럼명1', '컬럼명2']]`로 추출 후 동일 흐름. N-1개만 원하면 `OneHotEncoder(drop='first')`.

> **정리:** get_dummies는 "한 번에 다 처리 + 원본 자동 삭제", OneHotEncoder는 "단계별 명시적 처리 + 원본 수동 삭제 필요".

### 14-5. 참고 — 라벨링(Label Encoding) 코드 패턴

순서 있는 범주형이거나 간단히 정수로만 바꾸고 싶을 때 쓰는 수동 매핑.

```python
vcounts = df['컬럼명'].value_counts()
values = vcounts.sort_index()   # 고유값 오름차순 확인

labels = {}
for i, v in enumerate(values.index):
    labels[v] = i

df['컬럼명'] = df['컬럼명'].map(labels)
```

### 14-6. N개 vs N-1개 더미변수 (다중공선성 함정)

카테고리 N개 → 더미변수 N개 만들면 **다중공선성(Multicollinearity)** 문제 발생 가능 (예: 성별이 "남=0,여=0"이면 자동으로 "여"라는 게 결정 → 정보 중복). 해결: **N-1개만 생성**.

| 방법 | 옵션 |
|---|---|
| get_dummies | `drop_first=True` |
| OneHotEncoder | `drop='first'` |

- **이진 변수(값 2개)**: N-1 처리 여부 상관없이 정보 손실 없음 → 대체로 drop_first 권장
- **3개 이상 범주**: 회귀분석 등에서는 N-1 필수, 트리 기반 모델(RF 등)은 N개로 둬도 무방한 경우 많음

### 14-7. 전체 분석 과정 순서 (체크리스트)

1. 데이터 불러오기 & 병합 (공통 키 기준 `merge()`)
2. 결측치 처리 (더미변수 만들기 전에! 범주형은 보통 최빈값 `strategy='most_frequent'`)
3. 타입 확인/변환 (선택 — `astype({'컬럼':'category'})`)
4. 어떤 컬럼을 더미변수로 만들지 결정 (순서 없음→더미, 순서 있음→라벨링)
5. 더미변수 생성 (get_dummies 또는 OneHotEncoder, 이진/다중공선성 우려 시 `drop_first=True`)
6. 원본 컬럼 정리 (OneHotEncoder는 수동 drop 필수)
7. 최종 확인 (`.head()`, `.info()`로 컬럼 수/타입 검증)

### 14-8. 헷갈리기 쉬운 포인트

- get_dummies는 원본 컬럼 자동 삭제, OneHotEncoder는 수동 drop 필요
- `sparse_output=False`: 결과를 dense array로 받겠다는 옵션 (기본은 희소행렬)
- 더미변수 생성은 **train/test 분할 이전에** 통일된 카테고리 기준으로 하는 게 안전 (분할 후 하면 카테고리 불일치 위험)
- 라벨링 시 `value_counts().sort_index()`로 먼저 고유값 확인 후 딕셔너리 매핑하는 패턴이 자주 나옴

## 15. 이상치 처리 (Boxplot, IQR)

### 15-1. 핵심 파이프라인 한 줄 요약

**"결측치 정제 → 이상치 판별(주관적/통계적) → 이상치를 결측치로 바꿔서 재정제"**
이상치는 "삭제"하는 게 아니라 **결측치로 치환한 뒤 다시 평균 등으로 채워 넣는다.**

### 15-2. 결측치 vs 이상치

| 구분 | 정의 | 예시 |
|---|---|---|
| 결측치 | 값이 아예 비어있음 (NaN) | 국어 점수 칸이 비어있음 |
| 이상치 | 값은 있는데 비정상적으로 크거나 작음 | 국어 점수가 150점 (100점 만점인데) |

### 15-3. Boxplot으로 시각적 확인

```python
df.boxplot()
plt.show()
```
박스 = Q1(25%)~Q3(75%), whisker 밖 점 = 이상치 후보. 여러 컬럼 동시 비교 가능. 종/그룹별로 나눠서 그리기도 가능: `df[df['species']=='GlowLeaf'].boxplot()`.

> ⚠️ Boxplot은 "이상치가 있는 것 같다"는 **시각적 힌트**일 뿐, 확정은 IQR 계산으로.

### 15-4. IQR(사분위간 범위)로 확정

**IQR = Q3 - Q1**

```
하한 경계 = Q1 - (IQR × 1.5)
상한 경계 = Q3 + (IQR × 1.5)
```

```python
Q1 = df['컬럼'].quantile(0.25)
Q3 = df['컬럼'].quantile(0.75)
iqr = Q3 - Q1

outline_min = Q1 - iqr * 1.5   # 하한 경계
outline_max = Q3 + iqr * 1.5   # 상한 경계
```
> 왜 1.5를 곱하나?: 통계학 관습 배수. 값을 3.0으로 올리면 더 극단적인 값만 잡음(더 보수적).

### 15-5. 판별 방식 두 가지

| 방식 | 설명 |
|---|---|
| 분석가 주관 판별 | "상식적으로 말이 안 된다"는 조건을 사람이 직접 걸어 자르는 방식 (예: 100점 만점인데 100 초과) |
| 통계적(IQR) 판별 | Q1/Q3/IQR 공식으로 기계적/객관적으로 경계 계산 |

실무에서는 **둘 다 같이** 쓰는 경우가 많음: 도메인 지식으로 먼저 거르고, 통계적 기준으로 한 번 더 점검.

### 15-6. 전체 분석 순서

```
① 데이터 불러오기
   ↓
② 원본 결측치 확인 → SimpleImputer로 1차 정제 (평균 대체)
   ↓
③ boxplot()으로 이상치 있는 변수 눈으로 스캔
   ↓
④-A (주관) 상식적으로 말이 안 되는 값 조건 걸어 NaN 처리
   또는
④-B (통계) 컬럼별 Q1/Q3/IQR → 경계 계산 → 벗어난 값 NaN 처리
   ↓
⑤ NaN으로 치환된 이상치를 SimpleImputer로 다시 평균 대체 (최종 정제)
```
**원본은 절대 건드리지 않는다** (4장 원본 불변 원칙 참고). 매 단계 `.copy()` 후 새 변수명(`outline_df`, `outline_df2`...)으로 진행.

### 15-7. ❌ 실제 발견된 버그 (부호/부등호 실수 — 복습 시 꼭 볼 것)

**버그 1 — 상한 경계 계산 및 조건 부호 오류**
```python
# ❌ 잘못된 코드
outline_max = 수학Q3 - 수학iqr*1.5     # -가 아니라 +여야 함
outline_min = 수학Q1 - 수학iqr*1.5
outline_df2.loc[outline_df2['math'] < outline_min, 'math'] = np.nan
outline_df2.loc[outline_df2['math'] < outline_max, 'math'] = np.nan   # <가 아니라 >여야 함

# ✅ 올바른 코드
outline_max = 수학Q3 + 수학iqr * 1.5
outline_min = 수학Q1 - 수학iqr * 1.5
outline_df2.loc[outline_df2['math'] < outline_min, 'math'] = np.nan
outline_df2.loc[outline_df2['math'] > outline_max, 'math'] = np.nan
```
`outline_max`를 `Q3 - iqr*1.5`로 잘못 계산하면 상한 경계가 오히려 Q3보다 작아짐. 두 번째 조건도 `>`가 아니라 `<`로 쓰면 상한 초과값이 아니라 대부분의 정상값을 NaN으로 날려버림.

**버그 2 — 윈저라이징(경계값 대체) 반복문 부등호 오류**
```python
# ❌ 잘못된 코드
for c in outline_df3.columns:
    ...
    outline_df3.loc[outline_df3[c] < outline_min, c] = outline_min
    outline_df3.loc[outline_df3[c] < outline_max, c] = outline_max   # <가 아니라 >여야 함

# ✅ 올바른 코드
outline_df3.loc[outline_df3[c] < outline_min, c] = outline_min
outline_df3.loc[outline_df3[c] > outline_max, c] = outline_max
```
목적은 "하한보다 작으면 하한값, 상한보다 크면 상한값으로 대체"인데 `< outline_max`로 쓰면 상한값보다 작은 대부분의 정상값까지 상한값으로 뭉개버림.

> **왜 이런 실수가 반복됐나:** 컬럼마다 변수명(수학Q1, 과학Q1...)을 새로 만들며 손으로 복붙하다 보니 부등호 방향을 놓침 → **함수화하면 이런 복붙 실수 자체가 원천 차단됨.**

### 15-8. 연습문제 적용 흐름 (plant_growth 데이터 예시)

1. 데이터 로드 & 기본 정보 확인 (`df.head()`, `df.info()`, `df.isnull().sum()`)
2. 그룹별(species) 시각화 → 종마다 이상치 있는 변수가 다름을 확인
3. 그룹 구분 없이 전체 데이터로 IQR 계산 (문자열 컬럼은 `drop(columns='species')`로 제외)
4. 경계값 벗어나는 행 조회: `.loc[(df2['col'] < min) | (df2['col'] > max)]` — `|`(or)로 하한/상한 동시 검사
5. 이상치 → NaN 치환 → SimpleImputer로 평균 대체 (여러 컬럼 동시 처리 가능)

### 15-9. 재사용 템플릿 (그대로 갖다 쓸 것)

```python
def flag_outliers_as_nan(df, col, whisker=1.5):
    """IQR 기준으로 컬럼의 이상치를 NaN으로 바꿔서 반환"""
    df = df.copy()
    q1 = df[col].quantile(0.25)
    q3 = df[col].quantile(0.75)
    iqr = q3 - q1
    lower = q1 - iqr * whisker
    upper = q3 + iqr * whisker
    df.loc[(df[col] < lower) | (df[col] > upper), col] = np.nan
    return df, lower, upper


def flag_outliers_all_columns(df, whisker=1.5):
    """수치형 컬럼 전체 일괄 처리 (버그 수정 버전)"""
    df = df.copy()
    for c in df.select_dtypes(include='number').columns:
        q1 = df[c].quantile(0.25)
        q3 = df[c].quantile(0.75)
        iqr = q3 - q1
        lower = q1 - iqr * whisker
        upper = q3 + iqr * whisker
        df.loc[df[c] < lower, c] = np.nan
        df.loc[df[c] > upper, c] = np.nan
    return df


def impute_mean(df):
    """결측치(이상치 포함) 평균 대체 마무리"""
    imr = SimpleImputer(missing_values=np.nan, strategy='mean')
    arr = imr.fit_transform(df.values)
    return DataFrame(arr, index=df.index, columns=df.columns)


# 최종 파이프라인 (한 줄로 실행)
cleaned = impute_mean(flag_outliers_all_columns(원본df))
```
`select_dtypes(include='number')`를 넣은 이유: 문자열 컬럼(예: species)이 섞여 있어도 에러 없이 수치형 컬럼만 골라 처리하기 위함.

### 15-10. 체크리스트

- [ ] 결측치/이상치 차이, "이상치→NaN→재대체" 흐름 설명 가능
- [ ] SimpleImputer 파라미터(`missing_values`, `strategy`) 의미 이해
- [ ] boxplot은 "확정"이 아니라 "힌트"라는 것 이해
- [ ] IQR 공식(`Q1-1.5×IQR`, `Q3+1.5×IQR`) 손으로 쓸 수 있음
- [ ] 주관적 판별 vs 통계적(IQR) 판별 차이 이해
- [ ] `.loc[(조건1) | (조건2)]` 문법으로 하한/상한 동시 조회 가능
- [ ] 매 단계 `.copy()`로 새 변수명 쓰는 이유(원본 미변경 원칙) 이해
- [ ] 컬럼별 반복 작업은 함수화/for문으로 처리해 복붙 실수 방지

## 16. 로그변환

### 16-1. 왜 하는가

한쪽으로 심하게 치우친 분포(왜곡, skewed)는:
- 평균·표준편차 같은 통계량이 왜곡됨 (극단값에 민감)
- 회귀분석 등에서 정규성 가정이 깨짐
- 시각화 시 대부분의 데이터가 한쪽에 뭉쳐 보임

**로그변환**은 치우친 분포를 정규분포에 가깝게 펴주는 기법 (값이 큰 쪽 꼬리를 압축).
**모든 변수에 적용하는 게 아니라, 분포를 먼저 진단하고 필요한 변수에만 적용.**

### 16-2. 판단 기준: 왜도(skew) / 첨도(kurt)

| 지표 | 의미 | 확인 방법 |
|---|---|---|
| 왜도 (skew) | 좌우 어느 쪽으로 치우쳤는지 | `df["col"].skew()` |
| 첨도 (kurt) | 얼마나 뾰족한지(극단값 많은지) | `df["col"].kurt()` |

- `skew > 0` → 오른쪽 꼬리 (예: 매출액)
- `skew < 0` → 왼쪽 꼬리 (예: 만족도처럼 상한 근처에 몰림)
- `skew ≈ 0` → 좌우 대칭 (변환 불필요)
- `kurt > 0` → 정규분포보다 뾰족 (극단값/이상치 많을 가능성)

예시 (실습 데이터):

| 변수 | 왜도 | 첨도 | 판정 |
|---|---|---|---|
| daily_customers | 0.12 | 0.07 | 거의 대칭 → 변환 불필요 |
| daily_sales | 1.97 | 6.37 | 강한 오른쪽 꼬리 → `log1p` |
| waiting_satisfaction | -2.67 | 11.50 | 강한 왼쪽 꼬리 → `reverse_log1p` |

### 16-3. 판정 함수 — ⚠️ 로직 버그 주의

```python
# ❌ 버그 있는 버전 (조건 순서 오류)
def judge_log_transform(skew, kurt):
    if skew >= 1:
        return "log1p"
    elif skew > 0.5 and kurt > 0:
        return "log1p"
    elif skew <= 1:                      # skew>=1 통과 못하면 자동으로 skew<1 → 이 조건이 항상 참
        return "reverse_log1p"           # 이 아래는 죽은 코드가 됨
    elif skew < -0.5 and kurt > 0:
        return "reverse_log1p"
    else:
        return "none"
```
`elif skew <= 1`이 너무 넓은 범위를 먼저 잡아먹어서, 대칭 분포("none")를 절대 골라내지 못하는 문제가 있었음.

```python
# ✅ 수정된 버전
def judge_log_transform(skew, kurt):
    if abs(skew) < 0.5:                     # 대칭 분포 → 변환 불필요
        return "none"
    elif skew >= 1 or (skew > 0.5 and kurt > 0):
        return "log1p"                       # 오른쪽 꼬리
    elif skew <= -1 or (skew < -0.5 and kurt > 0):
        return "reverse_log1p"               # 왼쪽 꼬리
    else:
        return "none"
```

**기억할 원칙:** 조건문을 여러 개 쓸 때는 "먼저 걸리는 조건이 그 뒤 모든 조건을 잡아먹지 않는지" 항상 검산할 것. 특히 `<=`, `>=`처럼 경계 포함 조건은 겹치기 쉬움.

### 16-4. 오른쪽 꼬리(양의 왜도) → log1p

```python
df["log_daily_sales"] = np.log1p(df["daily_sales"])
```
`np.log()` 대신 `np.log1p()`를 쓰는 이유: 0 값이 있으면 `log(0)`은 -inf 에러 → `log1p(x)=log(1+x)`는 0을 넣어도 안전. 매출액처럼 0 이상 값만 있는 데이터에 적합.

### 16-5. 왼쪽 꼬리(음의 왜도) → reverse_log1p

`log1p`는 오른쪽 꼬리 압축 함수이므로, 왼쪽 꼬리는 먼저 방향을 뒤집어 오른쪽 꼬리 형태로 만든 다음 적용.

```python
x_max = df["waiting_satisfaction"].max()
df["rev_log_waiting"] = np.log1p(x_max - df["waiting_satisfaction"])
```
1. `x_max - 원래값` → 값이 클수록 결과가 작아지도록 방향 뒤집기
2. 뒤집은 값에 `log1p` 적용

**재사용 패턴:** 왼쪽 꼬리 변수를 만나면 "최댓값 구하기 → (최댓값-원본)으로 뒤집기 → log1p" 순서 그대로 적용.

### 16-6. 로그 역변환

`np.log1p()`의 역함수는 `np.expm1()` (`expm1(x)=exp(x)-1`).

```python
# 오른쪽 꼬리였던 경우
df["exp_daily_sales"] = np.expm1(df["log_daily_sales"])

# 왼쪽 꼬리였던 경우 (뒤집었던 방향까지 되돌려야 함)
df["exp_rev_log_waiting"] = x_max - np.expm1(df["rev_log_waiting"])
```
**주의:** 왼쪽 꼬리 변환은 "뒤집기+log1p" 2단계였으므로, 역변환도 "expm1+다시 뒤집기" 2단계로 순서 맞춰야 함. 한 단계만 되돌리면 값이 틀어짐.

### 16-7. 전체 순서 정리

1. 분포 진단: `skew()`, `kurt()` 확인
2. 꼬리 방향 판단: 양수→오른쪽, 음수→왼쪽, 0 근처→변환 불필요
3. 변환 방식 선택: 오른쪽 `log1p(x)` / 왼쪽 `log1p(x_max - x)` / 대칭 → 변환 안 함
4. 원본 컬럼은 남기고 새 컬럼에 저장 (`df["log_컬럼명"]`)
5. 분석/모델링에 로그변환 컬럼 사용
6. 결과 해석 시점엔 역변환으로 원래 단위로 복원

## 17. 피처 스케일링 (Feature Scaling)

### 17-1. 왜 하는가

컬럼마다 단위/범위가 다르면 값 크기 자체가 모델/거리 계산에 영향을 줌 (예: 필기점수 0~800 vs 병원경력 0~4년 → 범위 큰 쪽이 결과를 압도).

- **정규화(Normalization)**: 값을 특정 범위(보통 0~1)로 압축 → Min-Max Scaler
- **표준화(Standardization)**: 평균 0, 표준편차 1로 변환(z-score) → Standard Scaler

**언제 필요한가:** 거리 기반 알고리즘(KNN, K-means), 경사하강법 기반 모델(선형/로지스틱 회귀, 신경망), 정규화(regularization) 들어간 모델 등.
**트리 기반 모델(랜덤포레스트 등)은 스케일링 영향을 거의 안 받음** → 무조건 하는 게 아니라 "왜 필요한지" 먼저 생각.

### 17-2. 준비 작업 패턴

```python
from sklearn.preprocessing import MinMaxScaler, MaxAbsScaler, StandardScaler, RobustScaler

origin = load_data('nursing_grades')   # 실무에서는 pd.read_csv() 등으로 대체
minmax_df = origin.copy()              # 원본은 항상 복사본 만들어 작업
```
여러 스케일러를 비교 실험할 땐 원본은 항상 따로 보존 (매번 `origin.copy()`로 새로 시작).

실습 진행 방식: **① 수식으로 직접 계산 → ② sklearn으로 계산 → ③ 결과 일치 확인** — sklearn이 내부적으로 뭘 하는지 모르고 쓰지 않기 위함.

### 17-3. 4가지 스케일러

**(1) Min-Max Scaler — 정규화, 0~1 범위**
- 공식: `(x - min) / (max - min)`
- 이상치에 매우 취약 (이상치가 max/min이 되면 나머지 값이 한쪽으로 쏠림)
- 데이터 범위가 정해져 있고 이상치 적을 때 (예: 시험 점수, 확률)
```python
x = df[['필기점수']]          # 2차원(DataFrame)! 1차원 Series는 에러
scaler = MinMaxScaler()
df['필기점수_MinMax'] = scaler.fit_transform(x)
```

**(2) Max-Abs Scaler — -1~1 범위**
- 공식: `x / max(|x|)`
- 0 기준 대칭 유지, 음수 포함 데이터에 적합 (Min-Max는 항상 0~1이라 부호 정보 소실)

**(3) Standard Scaler — 표준화, z-score**
- 공식: `(x - 평균) / 표준편차`
- 범위 고정 안 됨(이론상 -∞~+∞), 정규분포에 가까운 데이터에 적합
- **가장 널리 쓰임** — 회귀/신경망/PCA 등 기본값처럼 사용
```python
scaler = StandardScaler()
df['학부성적_Standard'] = scaler.fit_transform(df[['학부성적']])
```

**(4) Robust Scaler — 이상치에 강함**
- 공식: `(x - 중앙값) / IQR`
- 평균/표준편차 대신 중앙값/사분위수 사용 → 이상치 영향 거의 없음
- 이상치 많거나 의심되는 컬럼(급여, 매출 등 꼬리 긴 분포) → **무조건 Robust부터 고려**

### 17-4. 한눈에 비교

| 스케일러 | 공식 | 결과 범위 | 이상치 영향 | 주로 쓰는 상황 |
|---|---|---|---|---|
| Min-Max | (x-min)/(max-min) | 0~1 | 큼 (취약) | 범위 명확, 이상치 적음 |
| Max-Abs | x/max(\|x\|) | -1~1 | 큼 (취약) | 음수 포함 데이터 |
| Standard | (x-평균)/표준편차 | 제한 없음 | 중간 | 정규분포 근접, 회귀/신경망 |
| Robust | (x-중앙값)/IQR | 제한 없음 | 작음 (강함) | 이상치 많은 데이터 |

### 17-5. sklearn 사용 시 주의사항

**1. 입력은 항상 2차원**
```python
# ❌ df['컬럼'] (Series, 1차원)
# ✅ df[['컬럼']] (DataFrame, 2차원)

# 여러 컬럼 동시 적용
scaled = StandardScaler().fit_transform(df[['ProjectHours', 'InnovationScore']])
df['ProjectHours_scaled'] = scaled[:, 0]
df['InnovationScore_scaled'] = scaled[:, 1]
```

**2. `fit_transform` vs `fit`+`transform` 구분 (실무 핵심)**

train/test 분리 상황에서는 절대 `fit_transform()`을 test에 다시 쓰면 안 됨.

```python
scaler = StandardScaler()
scaler.fit(train_x)                       # 기준(평균/표준편차)은 train으로만 학습
train_scaled = scaler.transform(train_x)
test_scaled  = scaler.transform(test_x)   # test는 transform만! fit 다시 하면 안 됨
```
이유: test의 통계량이 스케일링 기준에 섞이면 **데이터 누수(data leakage)** 발생 → 모델 성능이 실제보다 좋아 보이는 착시. 운영 환경의 새 데이터에도 같은 기준을 적용해야 하므로, 학습된 `scaler` 객체는 `pickle`/`joblib`으로 저장해 재사용하는 게 일반적.

**3. 원본 컬럼을 덮어쓰지 말고 새 컬럼에 저장** — `df['원본컬럼_스케일러이름']` 형태로 원본과 비교/검증 가능하게.

**4. 스케일러 선택은 컬럼별로 다르게 가능** — "이 데이터가 왜 이 스케일러에 어울리는지" 먼저 판단 (무조건 Standard만 쓰는 습관 지양). 예:
   - `MonthlySales` → Min-Max (범위형)
   - `CustomerSatisfaction` → Max-Abs
   - `ProjectHours`, `InnovationScore` → Standard (여러 컬럼 동시)

**5. 스케일링 후 합산/비교의 함정** — Min-Max/Max-Abs는 범위 고정(0~1, -1~1)이지만 Standard는 열려있어서, 이상치가 있으면 Standard 스케일 값이 합계를 왜곡할 수 있음. 서로 다른 스케일러 결과를 단순 합산할 땐 이 비대칭성 인지하고 해석할 것.

### 17-6. 진행 순서 템플릿

1. 필요한 스케일러만 import
2. 원본 로드 → `.copy()`로 복사본 생성
3. 스케일링할 컬럼 선택 (`df[['컬럼명']]`, 2차원 유지)
4. (선택) 수식으로 직접 계산해서 원리 확인
5. `Scaler()` 생성 → `fit_transform()` (또는 train/test 분리 시 `fit`+`transform`)
6. 결과를 새 컬럼으로 저장, 원본과 비교
7. 필요 시 여러 컬럼 결과 합산/비교 → 후속 분석(랭킹, 세그먼트 등)

### 17-7. 체크리스트

- [ ] 이 컬럼에 이상치가 있는가? → 있으면 Robust 우선 고려
- [ ] 이 컬럼이 음수를 포함하는가? → Max-Abs 고려
- [ ] 데이터가 정규분포에 가까운가? → Standard 고려
- [ ] 단순 비율/상한선이 명확한 값인가? → Min-Max 고려
- [ ] train/test를 나눠야 하는 상황인가? → `fit`은 train에만, `transform`은 둘 다
- [ ] 스케일러 객체를 나중에 재사용해야 하는가? → 저장(pickle/joblib) 필요
- [ ] 결과 컬럼은 원본과 별도로 저장했는가?

## 18. 전체 분석 파이프라인 요약 (End-to-End)

다른 데이터셋을 받았을 때, 이 순서로 진행하면 됨:

```
1. 데이터 로드 & 병합 (merge/concat) — 여러 테이블이면 공통 키 확인
        ↓
2. 기본 정보 확인 — df.head(), df.info(), df.isnull().sum(), type(origin) 확인
        ↓
3. 타입 변환 (astype) — 범주형은 명목/서열 구분
        ↓
4. 결측치 처리 (SimpleImputer, strategy는 컬럼 성격에 맞게: mean/median/most_frequent)
        ↓
5. 이상치 처리 (Boxplot으로 스캔 → IQR로 확정 → NaN 치환 → 재대체)
        ↓
6. 파생변수 생성 (np.where / np.select / apply / map / cut)
        ↓
7. 분포 진단 & 로그변환 (skew/kurt 확인 → 필요한 컬럼만 log1p/reverse_log1p)
        ↓
8. 인코딩 (더미변수 get_dummies/OneHotEncoder, 또는 라벨링)
        ↓
9. 스케일링 (컬럼 성격에 맞게 MinMax/MaxAbs/Standard/Robust 선택)
        ↓
10. 필요 시 재구조화 (melt/pivot_table/stack), 정렬/필터링(query), groupby 집계
        ↓
11. 모델링 / 분석 / 시각화
```

**공통 원칙 (전 단계 관통):**
- 원본은 절대 직접 수정하지 않는다 — 매 단계 `.copy()` 후 새 변수명
- 결과를 리턴하는 메서드는 반드시 변수에 다시 받기 (`inplace=True`는 예외적으로만)
- 컬럼별 반복 작업은 함수화/for문으로 — 복붙 실수(부등호, 변수명 등) 방지
- 코드 한 줄 치기 전에 "이게 뭘 하는 건지" 말로 설명할 수 있어야 함
- 셀 실행할 때마다 `df.head()` / `df.columns`로 상태 추적하는 습관

## 19. 자주 하는 실수 모음 (전체 통합)

| # | 실수 유형 | 내용 | 해결 |
|---|---|---|---|
| 1 | drop 결과 미반영 | `.drop()` 결과를 변수에 안 받아서 원본이 그대로 남음 | 리턴값을 변수에 받거나 `inplace=True` |
| 2 | monster_id NaN | 문자열 인덱스 상태에서 `.loc['새행']=df.loc['기존행']` 하면 컬럼값 복사 안 됨 | `reset_index()` 후 정수 인덱스로 작업 |
| 3 | 불필요한 이중 래핑 | 이미 DataFrame인데 `DataFrame()`으로 또 감쌈 | `type(origin)` 확인 습관 |
| 4 | 변수 덮어쓰기 | `df3 = SimpleImputer()`로 DataFrame 변수를 Imputer로 덮어씀 | Imputer는 별도 변수명(`imr`) 사용 |
| 5 | ignore_index 누락 | `concat()` 후 인덱스 중복 | `concat([...], ignore_index=True)` |
| 6 | 필터 조건 분리 | 두 조건을 따로 걸어서 교집합이 아니게 됨 | `&` 또는 `query()`로 동시에 걸기 |
| 7 | wide/long 방향 착오 | 이미 wide인데 pivot_table 시도 | 코드 짜기 전 방향부터 확정 |
| 8 | groupby 순서 오류 | 파생변수 만들기 전에 groupby부터 시도 | "파생변수 → groupby → sort" 순서 |
| 9 | melt 옵션 생략 | var_name/value_name 생략해서 컬럼명이 variable/value로 나옴 | 명시적으로 다 쓰기 |
| 10 | IQR 상한 계산 부호 오류 | `Q3 - iqr*1.5`로 잘못 계산 (+가 맞음) | `Q3 + iqr*1.5` |
| 11 | IQR 조건 부등호 오류 | `< outline_max`로 써서 정상값을 다 지움/뭉갬 | `> outline_max` |
| 12 | 로그판정 함수 조건 순서 오류 | `elif skew <= 1`이 범위를 다 잡아먹어 "none" 도달 불가 | `abs(skew) < 0.5`를 먼저 체크 |
| 13 | scaler 입력 1차원 | `df['컬럼']`(Series)을 넣어서 에러 | `df[['컬럼']]`(DataFrame) 형태로 |
| 14 | train/test에 fit_transform 둘 다 적용 | 데이터 누수(data leakage) 발생 | train엔 `fit`, test엔 `transform`만 |
| 15 | DataFrame 생성 괄호 오류 | 딕셔너리/괄호 쌍 안 맞음 | 뼈대(`{}`) 먼저 닫고 안을 채우기 |
