## 0. 오늘 배운 것 한 줄 요약

matplotlib/seaborn으로 그래프를 그리기 **전에** 세팅해야 하는 것들(한글 폰트, 해상도, 기본 옵션)과,

즉 이 LAB의 핵심은 그래프 문법(seaborn 함수들)이 아니라 **"그래프를 그리기 위한 무대 세팅 + 재사용 가능한 구조"**야.

## 2. 개념별 정리

### 2-1. 한글 폰트 설정이 왜 필요한가

matplotlib 기본 폰트는 한글을 지원 안 해서 그래프에 한글 쓰면 네모(□)로 깨짐.
그래서 아래 3단계를 거쳐야 함:

```python
from matplotlib import font_manager as fm

fpath = "../helpers/fonts"
font_files = gl.glob(os.path.join(fpath, "*.ttf"))   # 1) ttf 파일 경로 찾기

for f in font_files:
    fm.fontManager.addfont(f)             # 2) matplotlib에 폰트 등록
    fprop = fm.FontProperties(fname=f)    # 3) 폰트 속성 읽기
    fname = fprop.get_name()              #    → 폰트 "이름" 추출
    plt.rcParams['font.family'] = fname   # 4) 전역 기본 폰트로 지정
```

**중요 포인트 (재활용 시 실수 포인트)**
- `fpath = "../helpers/fonts"` 는 **상대경로**야. 이 노트북 파일이 있는 위치를 기준으로 한 단계 위 → helpers/fonts 폴더를 가리킴.
  → 노트북 파일 위치가 바뀌거나, 다른 프로젝트 폴더에서 이 코드를 복붙하면 `font_files`가 빈 리스트가 되고 폰트 등록이 조용히 실패함(에러 안 남!).
  → **재사용할 때 체크리스트**: 새 프로젝트에서 이 코드를 쓸 거면 `os.getcwd()`로 현재 작업 폴더 확인 → `fpath`를 절대경로 또는 올바른 상대경로로 고쳐야 함. (노트북에 `os.getcwd()` 셀이 따로 있는 이유가 이거)
- `rcParams['font.family']`는 **전역 설정**이라 한 번 설정하면 같은 커널 세션 내내 유지됨. 커널을 껐다 켜면 초기화되니까 새 세션에서는 다시 실행해야 함.

### 2-2. 그래프 기본 옵션 (`rcParams`)

```python
my_dpi = 200
plt.rcParams['font.size'] = 12                  # 기본 글자 크기
plt.rcParams['axes.unicode_minus'] = False      # 마이너스(-) 부호 깨짐 방지
plt.rcParams['figure.dpi'] = my_dpi             # 화면에 보여줄 때 해상도
plt.rcParams['savefig.dpi'] = my_dpi            # 파일로 저장할 때 해상도
plt.rcParams['lines.linewidth'] = 2             # 선 굵기 기본값
plt.rcParams['axes.axisbelow'] = True           # 격자선을 그래프 뒤로 (선/점에 안 가려지게)
```

- `axes.unicode_minus = False`를 안 하면 음수 축 눈금이 네모로 깨지는 경우가 있음 (한글 폰트 특성).
- `axes.axisbelow = True`는 은근 잘 빼먹는데, 이거 없으면 grid 선이 막대그래프나 점 위에 그려져서 지저분해 보임.
- `my_dpi`는 변수로 빼놨기 때문에 `figure.dpi`, `savefig.dpi` 둘 다 같은 값을 쓰게 되어 있음 → **화면에 보이는 해상도랑 저장되는 파일 해상도를 일치시키는 습관**, 이거 그대로 가져가면 됨.

### 2-3. 그래프 기본 템플릿 (4단계) — 제일 중요한 개념

```python
# 1) 그래프 초기화
width, height = 1280, 640
rows, cols = 1, 1
my_figsize = (width/100, height/100)   # px → inch 변환 (100은 관례적인 기준)
fig, ax = plt.subplots(rows, cols, figsize=my_figsize, dpi=my_dpi)
ax.grid(True, alpha=0.5)

# 2) 옵션 설정 (제목/축 라벨)
ax.set_title("제목", color="#6a91ca", fontsize=24, fontweight=700, pad=15)
ax.set_xlabel("X축", color="#ff6600", fontsize=16, fontweight=500, labelpad=5)
ax.set_ylabel("Y축", color="#ff00ff", fontsize=16, fontweight=500, labelpad=5)

# 3) 그래프 그리기 ← 이 노트북에서는 생략됨 (다음 LAB에서 seaborn 함수들이 여기 들어감)
#    예: sb.lineplot(data=df, x=..., y=..., ax=ax)

# 4) 출력
plt.tight_layout()
plt.savefig("myplot.png", dpi=my_dpi)
plt.show()
plt.close()
```

**왜 이 순서가 고정인지 이해하고 넘어가야 함:**

| 단계 | 하는 일 | 빠지면 생기는 문제 |
|---|---|---|
| 1) 초기화 | `fig, ax` 객체 생성 — 그림판(fig)과 그 안의 좌표축(ax)을 만듦 | ax가 없으면 뒤 코드가 실행 자체가 안 됨 |
| 2) 옵션 설정 | 제목/축 이름 등 "꾸미기" | 없어도 그래프는 그려지지만 뭘 보여주는지 알 수 없음 |
| 3) 그리기 | 실제 데이터를 ax 위에 시각화 (seaborn/matplotlib 함수) | 이게 빠지면 빈 액자만 남음 |
| 4) 출력 | 저장 + 화면 표시 + 메모리 정리 | `plt.close()` 안 하면 그래프 객체가 메모리에 계속 쌓임 (주피터에서 그래프 여러 개 그릴 때 느려지는 원인) |

→ **이 4단계는 "그래프 종류(선그래프냐 막대그래프냐)"와 무관하게 항상 똑같은 뼈대**야.
3단계(그리기)에 들어가는 함수만 lineplot, barplot, scatterplot 등으로 바뀌는 거고 나머지는 고정.
→ 그래서 이걸 함수로 뽑아내는 게 자연스러운 다음 단계 → 그게 `my_plot` 모듈.

### 2-4. 모듈화: `my_plot.init()` / `my_plot.show()`

```python
from helpers import my_plot

fig, ax = my_plot.init(rows=1, cols=1, width=1280, height=640,
                        title="My Plot", xlabel="X-axis", ylabel="Y-axis")
my_plot.show()
```

이 한 줄이 위 4단계 템플릿의 **1)초기화 + 2)옵션 설정**을 대신해주고, `my_plot.show()`가 **4)출력**을 대신해줌.
즉 나는 이제 3)그리기 부분(실제 seaborn 함수 호출)만 신경 쓰면 됨. → **이게 모듈화의 목적**.

## 3. "직접 코딩 버전" vs "모듈 사용 버전" — 반드시 구분해서 이해하기

이 노트북에는 같은 그래프를 만드는 두 가지 방법이 나란히 있음:

| | #03 직접 코딩 버전 | #04 모듈 사용 버전 |
|---|---|---|
| 코드량 | 길다 (약 10줄) | 짧다 (1~2줄) |
| 내부 동작 확인 | 눈에 다 보임 → 원리 이해용 | 안 보임 → `my_plot.py` 안에 숨어있음 |
| 커스터마이징 | 그 자리에서 자유롭게 수정 | `my_plot.py`를 고쳐야 함 |
| 용도 | **처음 배울 때 / 원리 이해할 때** | **원리 이해 끝난 후 / 실전에서 빠르게 그릴 때** |

**초보자 입장에서 사고 순서 (중요):**
1. 새로운 옵션이나 그래프 종류를 배우면 → 먼저 **직접 코딩 버전(#03 스타일)** 으로 셀 하나하나 실행해보면서 "뭐가 뭘 하는지" 확인한다.
2. 잘 작동하는 걸 확인했으면 → 그 반복되는 부분을 **모듈(`my_plot.py`)에 함수로 넣어서 재사용 가능하게 만든다.**
3. 그 다음부터는 모듈 버전으로 빠르게 그래프를 찍어낸다.

즉 순서는 **"직접 손으로 → 검증 → 모듈로 추상화 → 재사용"** 이지, 처음부터 모듈만 쓰면서 배우면 안의 원리를 모른 채 블랙박스로 쓰게 됨. 지금처럼 두 버전을 나란히 두고 배우는 게 맞는 방식임.

## 4. `my_plot` 모듈, 앞으로 어떻게 확장할지에 대한 사고방식

지금은 `init()` / `show()` 두 함수뿐이지만, 앞으로 lineplot/barplot/scatter 등 그래프 종류가 늘어날 때마다
이 모듈에 함수를 추가하게 될 거야. 그때 계속 부딪히는 설계 이슈들 미리 정리:

### 4-1. `ax=None` 패턴을 항상 기본으로 깐다

```python
def my_lineplot(data, x, y, ax=None, title=None, xlabel=None, ylabel=None, ...):
    if ax is None:
        fig, ax = init(...)   # ax를 안 주면 알아서 새로 만든다
    sb.lineplot(data=data, x=x, y=y, ax=ax)   # ← ax=ax 전달 빠뜨리면 다른 그림에 그려지거나 에러남
    return ax
```

- **모든 그리기 함수의 시그니처에 `ax=None`을 기본값으로 넣는다** — 이래야 이 함수를 단독으로도 쓰고(`ax=None`),
  subplot(여러 칸)의 특정 칸에 그릴 때도 쓸 수 있음(`ax=axes[0][1]`처럼 넘기기).
- seaborn 함수 호출할 때 **`ax=ax`를 빠뜨리면** 새 figure가 생겨버리거나(figure-level 함수의 경우) 엉뚱한 축에 그려짐.
  → 함수 만들 때마다 "seaborn 호출부에 ax=ax 넣었나?"를 체크리스트처럼 확인.

### 4-2. figure-level 함수 vs axes-level 함수 구분

- **axes-level**: `sb.lineplot`, `sb.barplot`, `sb.scatterplot`, `sb.histplot` 등 → `ax=` 파라미터를 받음 → 내가 만든 `ax` 위에 그릴 수 있음 → **모듈화하기 쉬움**.
- **figure-level**: `sb.lmplot`, `sb.pairplot`, `sb.catplot`, `sb.relplot`(FacetGrid 기반) → `ax=`를 안 받고 **자기가 알아서 새 figure를 만들어버림** → `my_plot.init()`으로 만든 ax에 못 끼워 넣음.
  → 이런 애들은 지금 만드는 `my_plot.init/show` 패턴과 안 맞기 때문에, 모듈에 넣을 때는 **별도 처리 방식**(예: 반환된 FacetGrid 객체의 `.fig`, `.figure`를 다루는 별도 함수)이 필요함. 나중에 무작정 같은 패턴으로 넣으려다 안 되는 이유가 이거.

### 4-3. 함수 이름 겹치지 않게 관리

- 같은 이름의 함수를 실수로 두 번 정의하면 나중에 정의한 게 앞의 걸 덮어씀 (에러 없이 조용히 무시됨) → 함수 늘어날수록 이름 규칙을 정해두는 게 좋음 (예: `plot_line`, `plot_bar`, `plot_scatter`처럼 접두어 통일).

### 4-4. `init()` 안에서만 적용되는 옵션 vs 밖에서 계속 적용되는 옵션 구분

- `title`, `xlabel`, `ylabel`, `width`, `height`는 **`init()` 호출 시점에만** 적용됨.
  나중에 `ax=ax`를 다른 그리기 함수에 넘기면서 title 등을 다시 바꾸고 싶으면, 그 함수 안에서 **다시 `ax.set_title(...)` 등을 호출해야 함** — `init()`을 또 부른다고 적용되는 게 아님.
  → "이 옵션이 언제 적용되는 옵션인지" 함수 만들 때마다 헷갈리지 않게 주석으로 남겨두는 습관 추천.

### 4-5. `rows=1, cols=1`을 벗어난 subplot(여러 칸)일 때 주의

- `twinx()`(보조 y축)는 지금 구조에서 **rows=1, cols=1일 때만** 깔끔하게 됨. 여러 칸 subplot에서 특정 칸에만 twinx를 걸고 싶으면 `ax` 객체를 리스트/배열로 다루는 로직이 추가로 필요함 → 지금 단계에서는 "일단 1칸짜리에서만 쓴다"로 제한해두고, 여러 칸 대응은 필요해질 때 확장.

### 4-6. 커널 캐시 문제 — 모듈 수정할 때 자주 걸리는 함정

- `helpers/my_plot.py` 파일을 수정하고 저장해도, 이미 `import`된 상태의 주피터 커널은 **예전 버전을 메모리에 들고 있음**.
  → 수정 후 바로 반영이 안 될 때는:
  1. `importlib.reload(my_plot)` 사용하거나
  2. 커널 재시작(Restart) 후 처음부터 다시 실행
  → "코드는 고쳤는데 왜 안 바뀌지?" 싶을 때 제일 먼저 의심할 것.

## 5. 새 데이터셋으로 그래프 그릴 때 체크리스트 (실전용)

앞으로 mpg, penguins, diamonds 등 다른 데이터셋으로 그래프 그릴 때 이 순서로 진행:

1. **환경 세팅(#02)** 이 세션에서 이미 했는지 확인 (폰트/rcParams는 세션당 한 번이면 충분, 매 그래프마다 반복 안 해도 됨)
2. 그리려는 그래프가 **axes-level**인지 **figure-level**인지 먼저 구분 (2-3 참고)
   - axes-level → `my_plot.init()`으로 ax 만들고 그 위에 그리기
   - figure-level(lmplot, pairplot 등) → `my_plot` 패턴 쓰지 말고 seaborn이 반환하는 객체(FacetGrid) 그대로 다루기
3. 처음 써보는 옵션/함수는 **직접 코딩 버전으로 먼저 검증** (노트북 셀 하나씩 실행하며 결과 확인) — 한 번에 끝까지 코드 다 쳐놓고 실행하지 않기
4. 검증 끝난 패턴 중 **반복해서 또 쓸 것 같은 것만** 모듈에 함수로 추가 (모든 걸 다 모듈화하려고 하지 않기 — 한 번 쓰고 말 거면 그냥 직접 코딩)
5. 모듈 수정했으면 **커널 재시작 또는 reload**로 반영 확인
6. 그래프 저장 파일명(`myplot.png`)은 데이터셋/그래프 종류별로 겹치지 않게 이름 규칙 정해서 저장 (안 그러면 계속 덮어써짐)
