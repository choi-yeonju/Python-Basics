## 1. 핵심 개념 정리 (말로 풀어서, 면접에서 설명할 수 있게)

### 1-1. 로지스틱 회귀는 왜 필요한가?

종속변수가 0 또는 1(예: 이겼다/졌다, 당뇨다/아니다)일 때, 그냥 선형회귀(OLS)를 적용하면 두 가지 문제가 생긴다.

- **예측값이 0~1을 벗어난다.** 선형회귀 직선은 x가 커지거나 작아지면 예측값이 음수가 되거나 1을 넘어버린다. 그런데 종속변수는 "확률"로 해석해야 하므로 반드시 0과 1 사이에 있어야 한다.
- **관계가 실제로 직선이 아니다.** 실제 데이터는 0 또는 1, 딱 두 개의 높이에만 점이 찍힌다. 이걸 직선 하나로 뚫고 지나가는 건 애초에 이 데이터의 모양과 맞지 않는다.

그래서 "직선의 예측값을 0과 1 사이로 눌러 담아주는 함수"가 필요한데, 그게 **시그모이드 함수**다.

### 1-2. 시그모이드 함수 (Sigmoid)

$$\sigma(z) = \frac{1}{1+e^{-z}}, \quad z = \beta_0 + \beta_1 x$$

- 말로 풀면: "선형회귀가 만든 직선의 예측값 z를, 아무리 크거나 작아도 0과 1 사이의 값으로 눌러주는 S자 모양 함수"다.
- z가 아주 크면(양의 무한대) σ(z)는 1에 가까워지고, z가 아주 작으면(음의 무한대) 0에 가까워진다. z=0일 때 정확히 0.5가 된다.
- 이 성질 때문에 시그모이드를 통과한 값을 "확률"이라고 해석할 수 있게 된다.

코드로는 이렇게 확인했다.
```python
sample['σ(z)'] = 1/(1+np.exp(-sample['예측값']))
```

### 1-3. 로지스틱 회귀식과 상수항(const)

$$z = \beta_0 + \beta_1 x \quad (\beta_0: \text{절편}, \ \beta_1: \text{기울기})$$

- 시그모이드 안에 들어가는 식이 `z = ax + b` 형태이므로, b(절편) 역할을 하는 **상수항**을 반드시 추가해야 한다.
- `statsmodels.api.Logit`을 행렬 방식으로 쓸 때는 `add_constant(x)`로 **직접** 상수항 열을 만들어줘야 한다. 안 그러면 절편이 0으로 고정된 잘못된 모델이 된다.
- 반면 `statsmodels.formula.api.logit("y ~ x", data=df)` 방식(formula API)은 상수항을 **자동으로** 처리해준다. 결과는 두 방식이 완전히 동일하다 — 상수항을 누가 챙기느냐의 차이일 뿐이다.

> **재사용 포인트**: 새 데이터셋에서도 "행렬 방식이면 `add_constant` 잊지 않기", "formula 방식이면 문자열 수식으로 편하게 쓰기" — 이 두 가지 습관을 항상 기억할 것.

### 1-4. 최대우도추정 (MLE, Maximum Likelihood Estimation)

- 선형회귀는 잔차제곱합을 최소화(OLS)해서 계수를 구하지만, 로지스틱 회귀는 그 방식을 쓸 수 없다(종속변수가 0/1이라 잔차 개념이 딱 안 맞음).
- 대신 "**지금 가진 데이터(0/1 관측치들)가 나올 확률이 가장 높아지도록** 계수(β)를 거꾸로 추정하는" 방식을 쓰는데, 이것이 **최대우도추정(MLE)**이다.
- `fit = model.fit()`을 호출하면 내부적으로 이 MLE 계산을 반복(iterative)해서 β를 찾아준다. summary에 "Optimization terminated successfully" 같은 로그가 뜨는 게 이 반복계산 과정이다.

### 1-5. 회귀계수(B)를 "그대로" 해석하면 안 되는 이유

- 선형회귀라면 "x가 1 증가할 때 y가 B만큼 증가한다"고 읽으면 된다.
- 하지만 로지스틱 회귀에서 "x가 1cm 늘면 **확률**이 B만큼 증가한다"고 읽으면 **틀린다.**
  - 이유: 확률은 0~1 사이 값인데 B는 2.0129 같은 값일 수 있어서, 애초에 그렇게 증가할 수가 없다.
  - 게다가 실제로 확률의 증가폭은 x의 위치마다 다르다. S자 곡선은 가운데(0.5 근처)에서는 가파르게 변하고, 양 끝(0 또는 1 근처)에서는 거의 평평하다. 즉 "구간마다 기울기가 다른" 비선형 관계라서 계수 하나로 "확률 증가량"을 말할 수 없다.
- 그럼 B는 뭘 의미하는가? → **로짓(logit)** 스케일에서는 직선 관계이므로, B는 "x가 1 증가할 때 **로짓**이 얼마나 증가하는가"를 뜻한다. (아래 1-7 참고)

### 1-6. 오즈 (Odds)

$$\text{Odds} = \frac{P}{1-P}$$

- 말로 풀면: "그 일이 일어날 확률이, 일어나지 않을 확률의 몇 배인가"를 나타내는 수치.
- 확률 P=0.5면 오즈는 1(반반), P=0.8이면 오즈는 4(일어날 가능성이 4배 더 높다는 뜻).
- 확률(P)은 0~1 사이로 갇혀 있지만, 오즈는 0부터 무한대까지 갈 수 있다. (P→1이면 오즈는 폭발적으로 커짐)
- 실습에서 확인한 성질: **오즈는 x가 1씩 증가할 때마다 "일정한 비율(배율)"로 증가한다.** (더하기가 아니라 곱하기로 커진다는 게 핵심)

### 1-7. 로짓 (Logit)

$$\text{logit}(P) = \ln\left(\frac{P}{1-P}\right) = \ln(\text{Odds}) = \beta_0 + \beta_1 x$$

- 로짓은 "오즈에 자연로그를 씌운 것"이다.
- 실습에서 확률/오즈/로짓 세 가지를 나란히 그래프로 그려봤을 때:
  - **확률**: S자 곡선
  - **오즈**: 폭발적으로 휘어지는 곡선 (지수적으로 증가)
  - **로짓**: **완벽한 직선**
- 즉, 로지스틱 회귀는 "로짓이라는 자(scale)를 대야 비로소 직선으로 보이는" 모형이다. 그래서 회귀계수 B는 "x가 1 증가할 때 **로짓**이 B만큼 증가한다"고 정확히 해석해야 한다.
- 확률 → 오즈 → 로짓으로 갈수록 "선형회귀처럼 다루기 쉬운 스케일"로 변환된다고 이해하면 된다.

### 1-8. 오즈비 (Odds Ratio, OR)

$$OR = e^{\beta}$$

- 로짓 스케일의 계수(B)는 직관적으로 와닿지 않으니, 지수변환(exp)해서 **오즈의 배율**로 바꾼 것이 오즈비다.
- 해석: "x가 1 증가할 때, 오즈가 OR배가 된다."
  - OR = 1.039라면 → x가 1 오를 때 오즈가 1.039배(즉 약 3.9% 증가)
  - **OR > 1**: 위험을 높이는 변수 (양의 관계)
  - **OR < 1**: 위험을 낮추는 변수 (음의 관계)
  - **OR = 1**: 영향이 없는 변수
- **주의할 점 (실습에서 강조된 부분)**:
  1. 오즈비는 "확률의 증가"가 아니라 "오즈의 배수"다. 절대 "확률이 3.9% 늘어난다"고 말하면 안 된다.
  2. x가 여러 단위(예: 10단위) 증가할 때는 계수에 그 단위를 곱한 뒤 지수변환해야 한다. **곱해서 누적**되는 것이지, 오즈비를 단위만큼 곱하는 게 아니다.
     $$OR_{10} = e^{\beta \times 10} \neq (e^{\beta}) \times 10$$
     예: 혈당이 10 증가 → $e^{0.03787 \times 10} = 1.46$배. (1.039×10 = 10.39배가 절대 아님)

### 1-9. 계수의 통계적 유의성 검정 (Wald test)

로지스틱 회귀 summary 표에 나오는 `coef`, `std err`, `z`, `P>|z|`, `[0.025, 0.975]`를 이렇게 읽는다.

- **귀무가설(H₀)**: 이 독립변수의 회귀계수는 0이다 (β = 0) → "이 변수는 종속변수(로짓)에 영향을 주지 않는다"
- **대립가설(H₁)**: 이 회귀계수는 0이 아니다 (β ≠ 0) → "이 변수는 종속변수에 영향을 준다"
- `z`값은 계수를 표준오차로 나눈 값이고, `P>|z|`(p값)가 유의수준(보통 0.05)보다 작으면 귀무가설을 기각 → "이 변수는 통계적으로 유의한 영향을 준다"고 결론 내린다.
- **오즈비의 95% 신뢰구간으로도 같은 판단을 할 수 있다.** 신뢰구간이 **1을 포함하면** "오즈비가 1일 가능성(=영향 없음)을 배제할 수 없다" → 유의하지 않음. 신뢰구간이 1을 포함하지 않으면(전부 1보다 크거나 전부 1보다 작으면) → 유의함. p값 판단과 항상 같은 결론이 나온다.

### 1-10. 모형 전체의 적합도 — LLR 카이제곱 검정과 Pseudo R²

- **LL (Log-Likelihood, 로그우도)**: 지금 모형이 데이터를 얼마나 잘 설명하는지를 나타내는 값 (0에 가까울수록 잘 맞음, 즉 값이 클수록—덜 음수일수록—좋음).
- **LL-Null**: 독립변수를 하나도 넣지 않고 절편만 있는 모형의 로그우도. "아무 정보 없이 그냥 평균 비율로만 찍었을 때"의 기준선이다.
- **LLR χ² 검정 (Likelihood Ratio Test)**:
  - **귀무가설(H₀)**: 모형에 넣은 독립변수들은 전부 종속변수 설명에 도움이 안 된다 (모든 β = 0, 즉 지금 모형 = Null 모형)
  - **대립가설(H₁)**: 적어도 하나의 독립변수는 도움이 된다
  - LL과 LL-Null의 차이를 카이제곱분포로 검정한 것이 `LLR p-value`다. 이 값이 0.05(또는 0.001)보다 작으면 "지금 모형이 아무것도 없는 모형보다 유의하게 낫다"고 결론 내린다.
- **Pseudo R² (McFadden's R² 등)**: 선형회귀의 R²(결정계수)와 비슷한 역할이지만, **절대로 "설명력 몇 %"로 해석하면 안 된다.** 로지스틱 회귀에서는 보통 0.2~0.4 정도만 되어도 매우 우수한 적합으로 본다. (실습에서 Pseudo R²=0.186이 "변수 하나치고는 상당히 양호한 수준"이라고 판단한 이유)

### 1-11. VIF (다중공선성) — 단순회귀에서도 표시되는 이유

- `report_variables()` 표에 VIF 열이 같이 나오는데, 독립변수가 하나뿐인 단순모형에서는 다중공선성 문제 자체가 성립하지 않으므로 VIF=1(또는 해당 없음)로 나온다. 변수가 여러 개일 때(다중 로지스틱 회귀) 비로소 의미를 갖는 지표다. (LAB-09에서 다룬 VIF 개념과 동일)

## 2. 분석 워크플로우 (항상 이 순서로 진행)

새로운 데이터셋으로 단순 로지스틱 회귀를 할 때는 아래 순서를 그대로 따라가면 된다. 이번 실습(iris_bin, pitcher_wins, pima_indians_diabetes)에서 실제로 이 순서를 반복했다.

```
1. 라이브러리 참조
   ↓
2. 데이터 가져오기 (load_data)
   ↓
3. 분석에 쓸 변수만 추출 + 전처리
   - 종속변수가 문자열(예: versicolor/virginica)이면 my_prep.labeling()으로 0/1 변환
   - 종속변수가 이미 0/1 숫자면 라벨링 생략 (pima_indians_diabetes의 Outcome이 그 예)
   ↓
4. 탐색적 데이터 분석(EDA)
   4-1. 종속변수 분포 확인 (countplot) → 클래스 균형이 심하게 안 깨졌는지 확인
   4-2. 집단별 독립변수 분포 비교 (boxplot, groupby().mean()) → 분포 차이가 클수록 좋은 독립변수
   ↓
5. 모델 적합 (Logit 또는 my_logit.fit_model)
   ↓
6. 모형 적합도 확인 (LLR χ², Pseudo R², 계수 유의성)
   ↓
7. 오즈비 계산 및 해석 (report_variables, plot_odds)
   ↓
8. 예측값(확률) 생성 → 임계값(threshold, 보통 0.5) 적용해서 0/1로 분류
   ↓
9. 분류 경계(boundary = -b/a, 즉 z=0이 되는 x) 계산
   ↓
10. 시각화로 전체 결과 검증 (plot_sigmoid)
```

> **왜 이 순서인가?** 4번(EDA)을 먼저 하는 이유는, 모델을 적합하기 전에 "이 변수가 애초에 쓸모 있는 변수인지"를 눈으로 먼저 확인하기 위해서다. 종속변수가 너무 한쪽으로 치우쳐 있거나, 두 집단 간 독립변수 분포 차이가 거의 없다면 모델을 적합해봤자 의미 있는 결과가 안 나올 가능성이 높다. **"무작정 끝까지 다 코딩"하는 게 아니라, 단계마다 결과가 말이 되는지 확인하면서 진행하는 습관**이 여기서 나온다.

## 3. 두 가지 코딩 버전 — 직접 코딩 vs 모듈 호출

이번 LAB에서 같은 결과를 두 가지 방식으로 만들어봤다. 이 차이를 이해하는 게 이번 랩의 핵심 중 하나다.

### 3-1. 직접 코딩 (원리를 이해하기 위한 버전) — 01-1, 02-1

```python
from statsmodels.api import add_constant, Logit
from statsmodels.formula.api import logit as formula_logit

# 방법 A: 행렬 기반
x = df[["Sepal_Length"]]          # 독립변수는 반드시 2차원(DataFrame)
y = df["Species"]                  # 종속변수는 1차원(Series), 반드시 0/1
x_input = add_constant(x)          # 상수항 직접 추가 (필수!)
model = Logit(y, x_input)          # 모형의 '틀'만 생성 (아직 미학습)
fit = model.fit()                  # MLE로 계수 추정 (실제 학습)
print(fit.summary())

# 방법 B: formula 기반 (상수항 자동 처리, 더 간결)
model = formula_logit("Species ~ Sepal_Length", data=df)
fit2 = model.fit()
```

- 이 버전을 쓰는 목적: **개념을 눈으로 확인하기 위해서.** z값 계산 → 시그모이드 통과 → 확률 → 오즈 → 로짓까지, 각 단계를 직접 코드로 짜보면서 "왜 그런 결과가 나오는지" 손으로 확인하는 용도다.
- `x.head()`, `y.head()`를 매번 찍어보는 것도 "행렬/시리즈 형태가 맞는지" 중간중간 확인하는 습관이다.

### 3-2. 모듈 호출 (실전에서 반복 사용하는 버전) — 01-2, 02-2

```python
fit = my_logit.fit_model(df, y='Species', summary=True)
pred = my_logit.predict(fit, df[['Sepal_Length']])
my_logit.plot_sigmoid(fit, new_df, x='Sepal_Length')
my_logit.report_variables(fit1, data1)
display(Markdown(my_logit.report_fitness(fit1)))
display(Markdown(my_logit.report_variables_text(fit1, data=data1)))
my_logit.plot_odds(fit1, data1, title="오즈비(Odds Ratio)", height=200)
```

- 이 버전을 쓰는 목적: **반복 작업을 자동화해서, 매번 add_constant / summary 파싱 / 시각화 코드를 새로 안 짜도 되게 하기 위해서.** 새로운 데이터셋이 들어와도 위 6줄 정도면 EDA부터 보고서 문장까지 다 나온다.
- 원리를 직접 코딩으로 이해한 다음, 그걸 함수로 감싸서 재사용 가능하게 만든 것 — 이게 `my_logit` 모듈의 정체다.

### 3-3. `my_logit` 모듈에 들어있는 함수들 (지금까지 확인된 것)

| 함수 | 역할 |
|---|---|
| `fit_model(df, y=..., summary=True)` | 상수항 추가 + Logit 적합 + (옵션) summary 출력까지 한번에 |
| `predict(fit, X)` | 예측 확률(`proba`)과 임계값 적용 분류(`pred`)를 DataFrame으로 반환 |
| `plot_sigmoid(fit, df, x=...)` | 관측치 산점도 + 시그모이드 곡선 + 임계값 + 분류경계를 한 그림에 |
| `report_fitness(fit)` | LL, LLR χ², Pseudo R² 등을 마크다운 문자열로 정리 (→ `display(Markdown(...))`로 렌더링) |
| `report_variables(fit, data)` | 계수(coef), 오즈비(OR), 95% 신뢰구간, VIF를 표로 정리 |
| `report_variables_text(fit, data=...)` | 위 결과를 해석 문장으로 자동 생성 (마크다운 문자열) |
| `plot_odds(fit, data, title=..., height=...)` | 오즈비를 오차막대 그래프로 시각화 (OR=1 기준선과 비교) |

> **모듈 확장 사고방식**: 지금은 단순(독립변수 1개) 로지스틱 회귀만 다뤘지만, 다음 랩에서 다중 로지스틱 회귀로 넘어가면 `my_logit` 모듈 함수들이 여러 개의 독립변수를 받아도 동작하도록 확장될 가능성이 높다. `my_ols`가 단순선형→다중선형→가정검정→전처리 파이프라인까지 확장됐던 패턴(LAB-09)과 같은 흐름이다. 즉, **지금 만든 함수의 인터페이스(입력/출력 형태)를 기억해두면, 나중에 함수 내부가 복잡해져도 "쓰는 방법"은 크게 안 바뀔 가능성이 높다.**

## 4. `helpers` 패키지 구조를 어떻게 사고해야 하는가

이번에도 `from helpers import *` 한 줄로 `my_plot`, `my_prep`, `my_ols`, `my_logit` 등 여러 모듈을 한 번에 불러왔다. 이 구조를 아래처럼 이해하면 된다.

```
helpers/               (패키지 = 폴더)
├── __init__.py         → "이 패키지를 import할 때 무엇을 노출할지" 정의
├── my_plot.py           → 시각화 전용 (countplot, boxplot, scatterplot, lineplot, init, show ...)
├── my_prep.py           → 전처리 전용 (labeling, dummies, log_transform, reduce_vif, scaling ...)
├── my_ols.py            → 선형회귀 전용 (auto_ols, fit_pipeline, test_linear, test_normal ...)
├── my_logit.py          → 로지스틱회귀 전용 (fit_model, predict, plot_sigmoid, report_* ...)
└── my_qtcheck.py         → 데이터 품질 점검 전용
```

- **역할별로 파일을 쪼개놓은 이유**: "이 함수가 어디 있는지 찾기 쉽게" + "각 파일이 하나의 책임만 갖게(단일 책임 원칙)" 하기 위해서다. 시각화는 무조건 `my_plot`, 전처리는 무조건 `my_prep`처럼 규칙이 명확하면, 새 함수를 추가할 때도 "이건 시각화니까 my_plot에 넣어야지"라고 바로 판단할 수 있다.
- **`__init__.py`의 역할**: 패키지 폴더를 그냥 만들어놓는다고 `from helpers import *`가 되는 게 아니다. `__init__.py`가 "이 패키지 안의 어떤 모듈들을 밖에서 접근 가능하게 할지"를 정의해줘야, `my_logit.fit_model(...)`처럼 점(`.`) 표기로 바로 접근할 수 있다.
- **앞으로 확장할 때 사고 순서**:
  1. 새로운 통계 기법(예: 다음 랩의 다변량 분류, 군집분석 등)을 배우면 → 새 파일(`my_xxx.py`)을 하나 추가하는 방식으로 확장될 가능성이 크다.
  2. 기존 모듈에 기능을 추가할 때(예: `my_logit`에 다중 로지스틱 지원 추가)는 → 기존 함수의 시그니처(입력 파라미터)를 최대한 유지하면서 내부 로직만 확장하는 방식이 안전하다. (예: `fit_model(df, y=...)`가 독립변수 1개든 여러 개든 같은 방식으로 동작하게)
  3. 모듈 코드를 고쳤을 때 노트북에 바로 반영이 안 되면 → `importlib.reload()`로 다시 불러오는 것 잊지 말기 (LAB-04~06부터 계속 써온 습관).

## 6. 면접 대비 — 말로 설명하는 연습

- **"로지스틱 회귀가 뭔가요?"**
  → "종속변수가 0/1처럼 이진(binary)일 때, 선형회귀의 예측값을 시그모이드 함수에 통과시켜서 0과 1 사이의 확률로 변환해주는 회귀 모형입니다. 계수는 최대우도추정(MLE)으로 추정합니다."

- **"회귀계수를 어떻게 해석하나요?"**
  → "계수 자체는 확률의 변화가 아니라, 로짓(log-odds)의 변화를 의미합니다. 실무적으로는 계수를 지수변환한 오즈비(Odds Ratio)로 해석하는데, 'x가 1 증가할 때 오즈가 몇 배가 되는가'로 읽습니다. OR이 1보다 크면 위험을 높이는 변수, 1보다 작으면 낮추는 변수입니다."

- **"모형이 통계적으로 유의한지 어떻게 판단하나요?"**
  → "개별 변수는 계수의 z검정(귀무가설: 계수=0)의 p값이나, 오즈비 95% 신뢰구간이 1을 포함하는지로 판단합니다. 모형 전체는 LLR 카이제곱검정(귀무가설: 모든 계수=0)의 p값으로 판단합니다."

- **"Pseudo R²는 선형회귀의 R²와 같은 의미인가요?"**
  → "아닙니다. 값의 범위나 계산 방식은 비슷하지만 '설명된 분산의 비율'로 해석하면 안 되고, 로지스틱 회귀에서는 0.2~0.4 정도만 되어도 우수한 적합으로 간주하는 게 일반적입니다."

## 7. 정형화된 코드 템플릿 (외워서 쓸 수 있게)

### 7-1. 라이브러리 참조 (매번 똑같음, 통째로 외우기)

```python
from jussam import load_data
```

### 7-2. 데이터 로드 + 전처리 (2줄 고정 패턴)

```python
origin = load_data("<데이터셋명>")
df = origin[["<독립변수>", "<종속변수>"]]

# 종속변수가 문자열(예: yes/no, versicolor/virginica)이면 라벨링 필수
df = my_prep.labeling(df, columns=["<종속변수>"])
# 종속변수가 이미 0/1 숫자면(예: Outcome) 라벨링 줄 생략
```

### 7-3. EDA 템플릿 (3줄 고정 패턴)

```python
# 1) 종속변수 분포
print(df["<종속변수>"].value_counts())
my_plot.countplot(df, x="<종속변수>", hue="<종속변수>", title="종속변수의 분포")

# 2) 집단별 독립변수 분포 비교

```

### 7-4. 모델 적합 — 모듈 버전 (실전용, 한 줄)

```python
fit = my_logit.fit_model(df, y="<종속변수>", summary=True)
```

### 7-5. 모델 적합 — 직접 코딩 버전 (원리 확인용, 개념 설명할 때)

```python
from statsmodels.api import add_constant, Logit
from statsmodels.formula.api import logit as formula_logit

# 행렬 방식
x = df[["<독립변수>"]]              # 반드시 2차원(DataFrame)
y = df["<종속변수>"]                 # 반드시 1차원(Series), 0/1이어야 함
x_input = add_constant(x)           # 상수항 직접 추가 — 절대 빠뜨리지 말 것
model = Logit(y, x_input)
fit = model.fit()
print(fit.summary())

# formula 방식 (상수항 자동 처리, 더 짧음)
model = formula_logit("<종속변수> ~ <독립변수>", data=df)
fit = model.fit()
print(fit.summary())
```

### 7-6. 예측값 생성 (모듈 버전, 고정 3줄)

```python
pred = my_logit.predict(fit, df[["<독립변수>"]])

new_df = df.copy()
new_df[["proba", "pred"]] = pred
new_df.head()
```

### 7-7. 예측값 생성 (직접 코딩 버전 — 상수항 다시 챙겨야 함)

```python
predict_input = add_constant(df[["<독립변수>"]])
new_df = df.copy()
new_df["proba"] = fit.predict(predict_input)

threshold = 0.5
new_df["pred"] = (new_df["proba"] > threshold).astype(int)
```

### 7-8. 분류 경계 계산 (외워둘 공식)

```python
a = fit.params["<독립변수>"]   # 기울기
b = fit.params["const"]        # 절편
boundary = -b / a              # z = ax+b = 0 을 만족하는 x
print(f"기울기 a = {a:.4f}, 절편 b = {b:.4f}")
print(f"분류경계 : {boundary:.2f}")
```

### 7-9. 오즈비 계산 (외워둘 공식)

```python
B = fit.params["<독립변수>"]
OR = np.exp(B)                 # 1단위 증가 시 오즈비
OR_n = np.exp(B * n)           # n단위 증가 시 오즈비 (n을 계수에 먼저 곱하고 지수변환!)
```

```python
# 독립변수 보고 표 (coef, 오즈비, 95% CI, VIF)

# 오즈비 시각화 (OR=1 기준선과 비교)
```

```python
my_logit.plot_sigmoid(fit, new_df, x="<독립변수>")
```

### 7-12. 시그모이드 곡선 시각화 (직접 코딩 버전 — 원리 확인용)

```python
fig, ax = my_plot.init(title="<제목>", xlabel="<x축 라벨>", ylabel="<y축 라벨>")

my_plot.scatterplot(df, x="<독립변수>", y="<종속변수>", color="#888888", alpha=0.4, ax=ax)
```
