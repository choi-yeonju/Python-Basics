## 1. 오늘 배운 것 한 줄 요약

**같은 대상을 두 번 측정했을 때(전/후, 상반기/하반기 등) 그 차이가 통계적으로 의미 있는지 확인하는 방법**을 배웠다. 이걸 대응표본 검정(paired test)이라고 부른다.

핵심은 두 갈래로 나뉜다:
- 차이값이 정규분포를 따르면 → **Paired T-Test** (모수적 방법)
- 차이값이 정규분포를 따르지 않으면 → **Wilcoxon signed-rank test** (비모수적 방법)

## 2. 통계 개념을 말로 풀어보기

시험이나 면접에서 기호(μ, H0, H1)만 던지면 이해했다는 인상을 주기 어렵다. 아래처럼 말로 설명할 수 있어야 진짜 이해한 것이다.

### 2-1. 모평균과 표본평균
- **모평균(population mean)**: 우리가 관심 있는 전체 집단(모집단)의 진짜 평균값. 보통은 전체를 다 잴 수 없어서 모른다. 기호로는 μ(뮤)라고 쓴다.
- **표본평균(sample mean)**: 모집단에서 일부를 뽑아(표본) 실제로 계산한 평균. 기호로는 x̄(엑스바)라고 쓴다.
- 통계적 검정은 결국 "표본평균을 보고, 모평균에 대해 어떤 주장을 할 수 있을까?"를 판단하는 작업이다.

### 2-2. 귀무가설(H0)과 대립가설(H1)
- **귀무가설**: "차이가 없다", "효과가 없다"처럼 기본적으로 참이라고 가정하고 시작하는 보수적인 주장. 재판에서 "무죄 추정의 원칙"과 비슷하다 — 증거가 확실하지 않으면 무죄(=차이 없음)로 본다.
- **대립가설**: 우리가 실제로 증명하고 싶은 주장. "차이가 있다", "효과가 있다" 같은 것.
- 검정의 결과는 항상 두 가지 중 하나다: **귀무가설을 기각한다(대립가설 채택)** 혹은 **귀무가설을 기각하지 못한다(대립가설을 증명하는 데 실패)**. "귀무가설이 참이다"라고 적극적으로 증명하는 게 아니라는 점이 중요하다.

### 2-3. 대응표본(paired sample)이란
- **같은 대상**을 두 번 측정한 데이터. 예를 들면:
  - 사슴 한 마리의 앞다리 길이 vs 뒷다리 길이 (같은 사슴)
  - 같은 자동차에 첨가제 넣기 전/후 주행거리
  - 같은 상권(code)의 상반기 매출 vs 하반기 매출
- 왜 "같은 대상"이어야 하는가? 개체마다 원래 차이가 크게 나는 상황(사슴마다 체구가 다 다르다든지)에서, **같은 대상 안에서의 전/후 차이만 뽑아내면 개체 간 차이라는 잡음(noise)을 제거**할 수 있기 때문이다. 이게 독립표본검정과 가장 큰 차이점이다.

### 2-4. Paired T-Test의 가설 (예: 첨가제 실험)
- 귀무가설(H0): 첨가제를 쓴 그룹의 평균 주행거리와, 쓰지 않은 그룹의 평균 주행거리가 같다. (μ(A) = μ(B))
- 대립가설(H1): 두 평균이 다르다. (μ(A) ≠ μ(B)) — 양측검정 기준

### 2-5. 정규성 가정(normality assumption)
- Paired T-Test를 쓰려면 **"두 그룹 각각"이 아니라 "두 그룹의 차이값(diff)"이 정규분포를 따라야 한다.** 이게 자주 헷갈리는 부분이다.
- 이유: paired t-test는 사실 "diff라는 하나의 변수가 평균 0인지 아닌지"를 보는 **단일표본 t검정**으로 환원되는 구조이기 때문이다. 그래서 diff 하나만 정규성을 체크하면 된다.
- 참고로 등분산성(두 그룹의 퍼짐 정도가 같은지)은 대응표본 검정에서는 확인하지 않는다. 독립된 두 그룹을 비교하는 게 아니라 diff 하나로 합쳐서 보기 때문에 애초에 등분산성이라는 개념이 적용될 자리가 없다.

### 2-6. 정규성 검정 결과 해석 (주의: 방향이 반대다!)
- 정규성 검정(Shapiro-Wilk 등)의 귀무가설은 **"정규분포를 따른다"**이다. 일반적인 검정과 귀무가설의 방향이 반대라서 헷갈리기 쉽다.
- p-value < 0.05 → 귀무가설(정규성) 기각 → **정규분포를 따르지 않는다** → Paired T-Test 대신 Wilcoxon으로 넘어가야 한다.
- p-value ≥ 0.05 → 귀무가설(정규성) 기각 못함 → 정규분포를 따른다고 봐도 무방 → Paired T-Test 사용 가능.

### 2-7. Wilcoxon signed-rank test (비모수 검정)
- 차이값이 정규분포를 따르지 않을 때 쓰는 대안. 평균(mean) 대신 **순위(rank)** 를 이용해서 검정하기 때문에 정규성을 가정하지 않아도 된다.
- "차이값들의 크기 순서를 매겨서, 양수 차이의 순위 합과 음수 차이의 순위 합이 비슷한지"를 보는 방식이라고 이해하면 된다.

### 2-8. 양측검정 vs 단측검정 (좌측/우측)
- **양측검정(two-sided)**: "차이가 있는지 없는지"만 본다. 방향(더 큰지 작은지)은 신경 안 씀. H1: μ(A) ≠ μ(B)
- **우측 단측검정(greater)**: "A가 B보다 큰지"만 본다. H0: μ(A) ≤ μ(B), H1: μ(A) > μ(B)
- **좌측 단측검정(less)**: "A가 B보다 작은지"만 본다. H0: μ(A) ≥ μ(B), H1: μ(A) < μ(B)
- 함수 기준으로는 `alternative` 파라미터가 항상 **"첫 번째 인수 − 두 번째 인수"**를 기준으로 해석된다는 규칙만 기억하면 된다. 순서를 바꾸면 `less`/`greater`도 같이 뒤집어야 같은 가설이 유지된다.

### 2-9. p-value와 유의수준(α)
- **유의수준(α)**: 귀무가설을 기각하는 기준선. 보통 0.05(5%)를 쓴다. "우연히 이런 차이가 나올 확률이 5% 미만이면 우연이 아니라고 보자"는 약속.
- **p-value**: 귀무가설이 참이라고 가정했을 때, 지금 관찰된 데이터(혹은 더 극단적인 데이터)가 나올 확률.
- p < α → 귀무가설 기각 (통계적으로 유의한 차이가 있다)
- p ≥ α → 귀무가설 기각 못함 (유의한 차이가 있다고 말할 근거 부족 — "차이가 없다"를 증명한 게 아니라는 점 주의)

### 2-10. 임계값(critical value)과 기각역(rejection region)
- **임계값**: 귀무가설을 기각할지 말지 가르는 경계선의 검정통계량 값.
- **기각역**: 검정통계량이 여기 떨어지면 귀무가설을 기각하는 구간. 전체 분포에서 α만큼의 면적을 차지한다.
- p-value 방식과 임계값 방식은 수학적으로 동치다. 요즘은 소프트웨어가 p-value로 바로 계산해주기 때문에 임계값을 직접 찾을 일은 적지만, 개념은 알고 있어야 한다.

## 3. 분석 프로세스 — 항상 이 순서로 진행한다

대응표본 검정을 할 때는 아래 순서를 그대로 따라가면 된다. 이 순서 자체가 이번 LAB의 핵심 뼈대다.

```
1. 데이터 불러오기 (load_data)
2. (선택) 시각화를 위해 wide → long 형태로 재배치 (melt)
3. 분포 시각화로 데이터 감 잡기 (kdeplot 등)
4. 분석 목적에 맞게 데이터 준비
   - 필요한 그룹/유형만 필터링
   - 필요하면 pivot_table로 "짝"을 명시적으로 맞춘 wide 형태 생성
5. diff(차이값) 계산 → diff의 정규성 검정 (test_assumptions)
6. 정규성 결과에 따라 검정 방법 분기
   - 정규성 만족 → ttest_rel (Paired T-Test)
   - 정규성 위반 → wilcoxon (Wilcoxon signed-rank test)
7. 필요에 따라 양측/좌측/우측 검정 각각 수행
8. 결과 시각화 (boxplot + Annotator로 검정 결과 주석 달기)
```

### 왜 이 순서가 중요한가
- **3번(분포 시각화)을 건너뛰고 바로 검정으로 가면 안 된다.** 눈으로 먼저 분포 모양을 보는 게, 나중에 정규성 검정 결과가 이상하게 나왔을 때 "어? 이상한데?"를 알아챌 수 있는 감각을 길러준다.
- **5번(diff 정규성 검정)이 검정 방법을 결정하는 분기점이다.** 이걸 확인 안 하고 무조건 t-test를 쓰면, 가정이 깨진 상태에서 잘못된 결론을 낼 위험이 있다.
- **4번의 "짝을 명시적으로 맞추는 것"**이 대응표본 검정에서 가장 실수하기 쉬운 부분이다. (아래 4번 항목에서 자세히)

## 4. 이번 LAB에서 가장 중요한 함정 — "짝(pair)"을 어떻게 보장하는가

대응표본 검정은 **"같은 대상"의 전/후 값을 짝지어야** 의미가 있다. 그런데 코드를 짤 때 이 "짝"이 자동으로 보장되지 않는 경우가 많다.

### 위험한 방법 (분기별로 그냥 필터링)
```python
df_1 = df[df['quarter']==1]
df_2 = df[df['quarter']==2]
my_stats.test_paired(data=df_1, before='sales_amount', after=df_2['sales_amount'])
```
이 방식은 `df_1`과 `df_2`의 **행 순서가 같은 상권(code) 기준으로 정렬되어 있다는 보장이 없다.** 순서가 어긋나면 A상권의 1분기 매출과 B상권의 2분기 매출을 짝지어버리는 심각한 오류가 날 수 있다.

### 안전한 방법 (pivot_table로 짝을 명시적으로 고정)
```python
df6 = pivot_table(df5, index='code', columns='구분', values='sales_amount')
my_stats.test_paired(df6, '상반기', '하반기', title='...')
```
`code`(고유 식별자)를 index로 잡고 비교하려는 두 조건(상반기/하반기)을 컬럼으로 피벗하면, **같은 code의 두 값이 항상 같은 행에 나란히 놓인다.** 이게 wide format이고, 대응표본 검정에는 이 형태가 정석이다.

> **체크리스트**: 대응표본 검정을 할 때는 항상 "이 두 컬럼이 같은 대상(row)을 가리키는가?"를 먼저 확인한다. 확신이 안 서면 `pivot_table`로 고유 식별자를 index로 고정해서 짝을 강제로 맞춘다.

## 5. 코드 두 가지 버전 — Raw 코드 vs 모듈화 코드

이번 LAB 자료에는 같은 분석을 **두 가지 스타일**로 보여주고 있다. 이 차이를 이해하는 게 앞으로 모듈을 어떻게 키워나갈지에 대한 감각을 잡는 데 중요하다.

### 버전 A — Raw 코드 (직접 다 풀어쓰기, #02·#03 예제)
```python
df1_diff = df1.copy()
df1_diff['diff'] = df1_diff['뒷다리'] - df1_diff['앞다리']

my_stats.test_assumptions(data=df1_diff, columns='diff')

s, p = ttest_rel(df1['뒷다리'], df1['앞다리'], alternative='two-sided')
print(f"t-statistic: {s:.4f}, p-value: {p:.4f}")

fig, ax = my_plot.init()
my_plot.boxplot(data=df1_melt, x="group", y="length", hue="group", ax=ax)
annotator = Annotator(data=df1_melt, x='group', y='length', pairs=[('앞다리','뒷다리')], ax=ax)
annotator.configure(test='t-test_paired')
annotator.apply_and_annotate()
my_plot.show()
```
- 정규성 검정 → 검정 수행 → 시각화까지 **모든 단계를 눈으로 다 보면서** 진행한다.
- 장점: 각 단계에서 무슨 일이 일어나는지 정확히 확인할 수 있다. 디버깅하기 쉽다.
- 단점: 코드가 길고, 같은 패턴을 다른 컬럼에 또 적용하려면 전부 복붙해야 한다.

### 버전 B — 모듈화 코드 (`my_stats.test_paired()` 하나로, #04 이후)
```python
my_stats.test_paired(data=df1, before='앞다리', after='뒷다리')
```
- 위 버전 A의 "diff 계산 → 정규성 검정 → 분기 처리 → t-test 또는 wilcoxon 실행 → 결과 정리"까지의 로직이 **함수 하나 안에 캡슐화**되어 있다고 추정할 수 있다.
- 장점: 한 줄로 끝난다. 같은 분석을 여러 컬럼 쌍에 반복할 때(#03 연습문제의 for문 예시처럼) 압도적으로 편하다.
- 단점: 함수 내부에서 정확히 뭘 하는지 모르면 "블랙박스"가 되어버린다. 뭔가 이상한 결과가 나와도 원인을 찾기 어렵다.

### 두 버전을 대하는 사고방식
1. **처음 배우는 개념/함수는 반드시 버전 A(raw 코드)로 먼저 손으로 풀어본다.** 정규성 검정 따로, t-test 따로, 시각화 따로 — 각 단계 결과를 직접 눈으로 확인한다.
2. **같은 패턴을 3번 이상 반복하게 되면 그때 모듈화한다.** (#03 연습문제에서 강사님이 `field_group` 리스트 + for문으로 3개 항목을 한 번에 처리한 것처럼, 반복되는 건 함수나 반복문으로 묶는다.)
3. **모듈 함수를 쓸 때도, 그 함수가 raw 코드로 하면 어떤 단계들의 조합인지 한 번은 뜯어봐야 한다.** `my_stats.py` 안의 `test_paired` 함수 정의를 열어서, 안에서 정규성 검정 → 분기 → t-test/wilcoxon 선택을 어떻게 구현했는지 확인하는 습관을 들이면, 나중에 에러가 나도 "아, 이 함수가 내부적으로 이 계산을 하다가 실패했겠구나"를 바로 짐작할 수 있다.

## 6. `my_plot`, `my_stats` 같은 헬퍼 모듈, 어떻게 사고해야 하는가

지금 만들고 있는 `helpers` 패키지(`my_plot.py`, `my_stats.py`, `my_qtcheck.py`)는 앞으로 계속 커질 것이다. 이걸 다루는 사고방식을 정리해둔다.

### 6-1. 모듈은 "반복되는 작업 패턴"을 함수로 굳힌 것
- 예: `my_stats.test_assumptions()` → "정규성 검정하고 결과를 표로 정리하는" 반복 작업을 함수 하나로 굳힌 것.
- 예: `my_stats.test_paired()` → "diff 계산 → 정규성 검정 → t-test/wilcoxon 자동 분기 → 결과 정리"라는 훨씬 긴 반복 작업을 함수 하나로 굳힌 것.
- 즉 모듈은 처음부터 설계해서 만드는 게 아니라, **raw 코드를 여러 번 반복해서 짜본 뒤에 "아 이 패턴 매번 똑같이 쓰네" 싶을 때 함수로 뽑아내는 것**이다. 순서가 거꾸로면 안 된다 (먼저 raw로 이해 → 그다음 모듈화).

### 6-2. 함수 시그니처(파라미터) 설계는 "내가 실제로 뭘 반복해서 넘기고 있는가"를 보고 정한다
- `test_paired(data, before, after, title=None)` 같은 구조라면:
  - `data`: 하나의 DataFrame (짝이 이미 맞춰진 wide format)
  - `before`, `after`: 비교할 두 컬럼명 (문자열)
  - `title`: 결과 표시용 제목 (선택)
- 이런 시그니처를 보면 "아, 이 함수는 **하나의 DataFrame 안에서 두 컬럼명을 비교하는 용도**로 설계됐구나"를 알 수 있다. 그래서 지난 실수(#04)처럼 `before`엔 컬럼명, `after`엔 다른 DataFrame의 Series를 섞어 넣으면 함수가 기대하는 입력 형태와 안 맞아서 문제가 생긴다.
- **모듈을 쓸 때 에러가 나면 가장 먼저 확인할 것: "이 함수가 기대하는 입력 형태(파라미터 타입)에 내가 맞게 넣고 있나?"**

### 6-3. 새 기능이 필요할 때 확장하는 순서
1. 지금 하려는 분석을 raw 코드로 먼저 짜서 제대로 작동하는지 확인한다.
2. 작동을 확인한 뒤, 기존 모듈 함수와 얼마나 비슷한지 비교한다.
   - 완전히 똑같은 패턴이면 → 기존 함수를 그대로 재사용.
   - 조금 다르면(예: 세 그룹 비교, 다른 통계량 필요) → 기존 함수에 옵션(파라미터)을 추가할지, 새 함수를 만들지 고민.
3. 함수를 고치거나 새로 만들면, **Jupyter의 모듈 캐싱 문제** 때문에 `importlib.reload()`를 하거나 커널을 재시작해서 변경사항이 반영됐는지 반드시 확인한다. (이 부분은 이미 겪었던 문제이기도 함.)
4. 확장한 함수도 여러 데이터셋에 실제로 적용해보면서 엣지 케이스(결측치, 컬럼명 다름 등)를 잡아나간다.

### 6-4. "처음부터 끝까지 다 짠다"가 아니라 "단계마다 확인한다"
- 이번 LAB 흐름을 보면 알 수 있듯, 강사님도 셀 단위로 하나씩 실행하면서 결과를 확인하고 넘어가는 방식으로 진행한다 (`display()`로 매 단계 결과를 바로 보여주는 것도 같은 이유).
- **한 셀에 모든 로직을 다 몰아넣지 말고, "데이터 준비 → 가정 확인 → 검정 → 시각화" 각 단계를 별도 셀로 나눠서 하나씩 실행하고 눈으로 확인한 뒤 다음으로 넘어가는 습관**을 들이면, 어디서 문제가 생겼는지 바로 알 수 있다.

## 7. 새로운 데이터셋을 만났을 때 적용할 체크리스트

1. `load_data()`로 불러온 뒤 `.head()`, `.isna().sum()`, 컬럼/카테고리 `.unique()`로 데이터 구조부터 파악한다.
2. **비교하려는 두 값이 "같은 대상"에 대한 것인지** 확인한다 (대응표본인지 독립표본인지 구분하는 첫 단추).
3. 비교 축이 여러 개(예: 여러 항목, 여러 상권 유형)라면 필터링/파생변수로 분석 단위를 정확히 좁힌다.
4. 짝을 명시적으로 보장해야 하면 `pivot_table`로 고유 식별자를 index로 wide format을 만든다.
5. diff 계산 → 정규성 검정 → t-test/wilcoxon 분기 순서를 지킨다.
6. 필요하면 양측/좌측/우측 검정을 각각 목적에 맞게 수행한다 (방향성 있는 질문인지 아닌지로 판단).
7. boxplot + Annotator로 결과를 시각화하고, 인사이트는 **p-value뿐 아니라 방향(어느 쪽이 더 큰지)까지 포함해서** 문장으로 정리한다.
