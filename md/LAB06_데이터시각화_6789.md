## 0. 전체 그림 먼저 잡기

이번 LAB에서 배운 건 결국 **"탐색적 데이터 분석(EDA) → 시각화" 파이프라인**의 뒷부분이다. 순서는 항상 이렇다.

## 1. 헬퍼 모듈 구조 이해하기 (`my_qtcheck`, `my_plot`)

### 1-1. `my_qtcheck.py` — EDA 품질 점검 모듈

| 함수                               | 역할                                                                              | 언제 쓰나                                      |
| ---------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------- |
| `set_type()`                     | 컬럼 타입 일괄 변환 (int/float/string/category/datetime) +`df.info()` 자동 출력 | 데이터 로드 직후, 분석 시작 전 항상 1회        |
| `get_number_column_names()`      | 숫자형 컬럼명 리스트 반환                                                         | `numerical_summary` 등에서 내부적으로도 사용 |
| `get_categorical_column_names()` | 범주형(category) 컬럼명 리스트 반환                                               | `categorical_summary`에서 내부적으로도 사용  |
| `check_duplicates()`             | 중복행 탐지 + (옵션) 제거                                                         | 로드 직후                                      |
| `check_missing_values()`         | 컬럼별 결측치 개수·비율 표 반환                                                  | 로드 직후                                      |
| `categorical_summary()`          | 범주형 기술통계 +`value_counts()` 요약, Excel 저장 옵션                         | 범주형 변수 분포 파악                          |
| `numerical_summary()`            | **핵심 함수** — 숫자형 컬럼 전체 진단 (아래 상세)                          | 이상치/분포 파악 후 시각화 방향 결정           |

#### `numerical_summary()`가 자동으로 뽑아주는 것 (이게 이 모듈의 진짜 핵심)

1. **평균-중앙값 상대 차이율** `rel_diff = |mean - 50%| / 50%`
   - < 0.1 → `similar`, < 0.5 → `diff`, 그 외 → `large_diff`
   - → 분포가 좌우대칭에 가까운지 1차 판단
2. **IQR 기반 이상치 경계**
   - `iqr = Q3 - Q1`
   - `upper_bound = Q3 + 1.5*iqr`, `lower_bound = Q1 - 1.5*iqr`
   - 이 경계로 **상한/하한/전체 이상치 개수·비율**까지 자동 계산
3. **왜도(skew) / 첨도(kurt) 및 해석**
   - skew < -0.5 → `left tail`, > 0.5 → `right tail`, 그 외 → `symmetric`
   - kurt < 0 → `platykurtic`(평평), > 0 → `leptokurtic`(뾰족), 0 → `mesokurtic`
4. **로그 변환 필요성 자동 판정** (`log_need` 컬럼)
   - skew ≥ 1 또는 (skew > 0.5 and kurt > 0) → `log1p` 추천
   - skew ≤ -1 또는 (skew < -0.5 and kurt > 0) → `reverse_log1p` 추천
   - 그 외 → `none`

> **재사용 포인트**: `numerical_summary()`를 돌리면 "이 컬럼은 이상치가 몇 % 있고, 오른쪽 꼬리가 길고, 로그 변환이 필요하다"는 걸 **표 하나로 한 번에** 알 수 있다. 즉, boxplot/histplot/kdeplot을 뭘 그려야 할지 이 표가 먼저 알려준다. → **시각화 전에 항상 `numerical_summary()`부터 돌리는 습관**이 핵심.

⚠️ 주의: docstring에 `"반드시 set_type으로 범주형 처리 후 사용"`이라고 명시되어 있음 — 범주형으로 남아있어야 할 컬럼(예: 코드성 숫자)을 숫자형 통계에 섞으면 왜곡됨.

## 2. Violin Plot — 분포의 "모양"까지 보고 싶을 때

### 개념

Violin Plot = **Box Plot(사분위수) + KDE(밀도 분포)**를 합친 그래프. Box Plot은 중앙값·사분위·이상치는 보여주지만 "그 안에서 데이터가 어떻게 몰려있는지(단봉/쌍봉 등)"는 못 보여준다. Violin은 그걸 보완한다.

### 데이터 지정 5가지 패턴 (전부 같은 그래프를 만드는 다른 방법)

| 패턴                     | 코드                                                                     | 특징                                     |
| ------------------------ | ------------------------------------------------------------------------ | ---------------------------------------- |
| 1. 자동 인식(Series)     | `sb.violinplot(data=origin['중간고사'], orient="h")`                   | 컬럼 하나를 Series로 직접 전달           |
| 2. 자동 인식(DataFrame)  | `sb.violinplot(data=origin, orient="v")`                               | DataFrame 전체 → 숫자형 컬럼들이 나란히 |
| 3. 개별 데이터 직접 지정 | `sb.violinplot(x=df['기말고사'])`                                      | x에 넣으면 가로 방향이 됨                |
| 4. DataFrame + 컬럼명    | `sb.violinplot(data=origin, y="중간고사")`                             | 컬럼명을 문자열로 지정 (가독성 good)     |
| 5. 범주(hue) 지정        | `sb.violinplot(data=origin, y='중간고사', hue='전공', palette='Set2')` | 그룹별 분포 비교                         |

**분석 순서 포인트**: 처음엔 컬럼 하나(패턴1~4)로 전체 분포를 보고, 이후 **집단 간 비교가 필요할 때 hue를 추가**(패턴5)하는 순서로 확장해가는 게 자연스럽다.

### 모듈화 버전

```python
my_plot.violinPlot(data=origin, y='중간고사', hue='전공', ylabel="중간고사",
                    width=800, height=480, palette='pastel')
```

### 연습문제(cookie_cats)에서 얻은 실전 패턴 — **이상치 제거 후 비교 시각화**

```python
# 1) 그룹별로 나눠서
df_a = origin[origin['version'] == 'A']
df_b = origin[origin['version'] == 'B']

# 2) 그룹별 numerical_summary()로 IQR 경계를 각각 구하고
desc_df = my_qtcheck.numerical_summary(df_a)

# 3) 그 경계로 각 그룹의 이상치를 제거한 뒤
df_a_qt = df_a[(df_a['col'] >= desc_df['lower_bound']['col']) &
               (df_a['col'] <= desc_df['upper_bound']['col'])]

# 4) 다시 합쳐서 (index는 원본 유지하려면 ignore_index=False)
df_qtcheck = concat([df_a_qt, df_b_qt], ignore_index=False)

# 5) violin plot으로 그룹 간 분포 비교
my_plot.violinPlot(data=df_qtcheck, y='sum_gamerounds', hue='version', ...)
```

> **왜 그룹별로 따로 이상치 기준을 잡았나?** — A/B 그룹의 분포가 다를 수 있어서, 전체 기준(global bound)이 아니라 **그룹별 IQR**로 이상치를 제거해야 그룹 간 비교가 왜곡되지 않는다. (Olist 프로젝트에서 percentile 기준을 동적으로 잡았던 것과 같은 논리 — 하드코딩 X, 데이터 기반 동적 기준.)

## 3. Heatmap — 두 범주 조합에 따른 수치 패턴을 보고 싶을 때

### 개념

Heatmap은 **피벗 테이블(행×열×값)을 색상으로 시각화**한 것. 즉 "히트맵을 그린다"는 건 사실상 **"피벗 테이블을 먼저 만든다"**는 뜻이다 — 이 순서를 반드시 기억할 것.

### 표준 처리 순서 (flights 예제)

```python
# 1) 전처리: 시각화에 방해되는 타입(문자열 월 등)을 숫자로 변환
df['month'] = df['month'].map({"January":1, ..., "December":12})

# 2) 재구조화: index=행, columns=열, values=색상으로 표현할 값
df2 = pivot_table(df, index="year", columns="month", values="passengers")

# 3) 필요시 정렬 (최신 연도가 위로 오게 등)
df3 = df2.sort_index(ascending=False)

# 4) 시각화
sb.heatmap(data=df3, annot=True, fmt="0.1f", linewidths=0.5, cmap="GnBu")
```

### 파라미터 정리

| 파라미터       | 의미                            |
| -------------- | ------------------------------- |
| `annot=True` | 셀 안에 실제 수치값 표시        |
| `fmt="0.1f"` | annot 표시 형식 (소수점 자리수) |
| `linewidths` | 셀 사이 구분선 두께             |
| `cmap`       | 컬러맵 (`GnBu`, `PuRd` 등)  |

⚠️ **주의사항**: `my_plot.heatmap()` 함수 내부 파라미터명은 `linewidths`(복수형)로 통일되어 있음. seaborn 원본도 `linewidths`가 맞는 이름 — `linewidth`(단수)로 잘못 쓰면 에러. (앞서 실수로 기록됐던 포인트.)

### 모듈화 버전

```python
my_plot.heatmap(df3, palette="PuRd", width=1200, height=600,
                title="...", xlabel="Month", ylabel="Year")
```

### 재사용 패턴 요약

**"두 범주형 축(연도×월, 지역×상품군 등) + 하나의 집계값" 구조만 되면 언제든 heatmap 후보.** `pivot_table(index=, columns=, values=, aggfunc=)`만 바꿔 끼우면 됨 (연습문제에서 `aggfunc="mean"`으로 년도×월별 평균 사고건수/사망자수를 각각 그린 것도 같은 패턴 재사용).

## 4. Bar Plot / Count Plot — 범주별 "크기"를 비교하고 싶을 때

### 개념 차이 (이게 헷갈리기 쉬운 포인트)

| 구분        | Bar Plot                                                      | Count Plot               |
| ----------- | ------------------------------------------------------------- | ------------------------ |
| y축 값      | `estimator`로 계산된 값 (기본: 평균)                        | 항상**개수(빈도)** |
| 필요한 컬럼 | x(범주) + y(수치)                                             | x(범주)만 있으면 됨      |
| 관계        | Count Plot =`estimator=len`으로 고정된 Bar Plot의 특수 버전 | —                       |

### Bar Plot 확장 순서

```python
# 1) 기본: 집단별 평균
sb.barplot(data=origin, x="species", y="body_mass_g")

# 2) 방향 전환: x/y를 바꾸면 가로 막대 (+ hue 쓸 땐 palette 필수 세트)
sb.barplot(data=origin, x="body_mass_g", y="species", palette="Set2", hue="species")

# 3) 집계 방법 변경 + 정렬 순서 지정
sb.barplot(data=origin, x="species", y="body_mass_g",
           estimator=np.max, order=['Gentoo', 'Chinstrap', 'Adelie'])

# 4) 범주 세분화 (hue로 그룹 나누기)
sb.barplot(data=origin, x="species", y="body_mass_g", hue="sex", palette="pastel")
```

> **핵심 규칙 1개**: **`palette`는 반드시 `hue`와 함께 써야 적용됨.** hue 없이 palette만 쓰면 무시되거나 경고가 난다 (matplotlib/seaborn 최신 버전 기준).

### Count Plot

```python
sb.countplot(data=origin, x="species", palette="spring", hue="sex")
```

→ `estimator=len`이 고정된 barplot이라고 생각하면 됨. "종별 몸무게 평균"이 아니라 "종별 개체수"처럼 **단순 빈도 비교**일 때 사용.

### 모듈화 버전

```python
my_plot.barplot(data=origin, x="species", y="body_mass_g", hue="sex",
                estimator=np.mean, palette="Set2", ...)
my_plot.countplot(data=origin, x="species", hue="sex", palette="tab20", ...)
```

### 재사용 패턴 — `melt()`로 wide → long 변환 후 barplot

연습문제(jobs_by_scale)에서:

```python
df = melt(origin, id_vars='종사자규모별', var_name='년도', value_name='종사자 수')
my_plot.barplot(data=df, x="종사자규모별", y="종사자 수", hue="년도", ...)
```

→ **"연도별 컬럼이 옆으로 넓게 퍼진(wide) 원본"을 barplot에 바로 못 넣을 때, `melt()`로 세로 형태(long)로 바꿔서 hue에 태우는 패턴.** 이건 실무에서 매우 자주 쓰는 전처리 → 시각화 흐름이므로 꼭 기억.

## 5. Pie Plot / Donut Plot — 전체 대비 비율을 보고 싶을 때

### 개념

범주형 데이터의 **구성비(부분/전체)**를 보여줌. 단, 범주가 많으면(6개 이상) 가독성이 떨어지므로 상위 N개 + 기타로 묶는 걸 고려해야 함(이번 자료엔 명시 안 됐지만 실무 적용 시 유의).

### 표준 처리 순서 (cafe_sales 예제)

```python
# 1) 집계: 범주별 합계 구하고 내림차순 정렬
df1 = origin[['메뉴명','금액']].groupby('메뉴명').sum()
df1.sort_values('금액', ascending=False, inplace=True)

# 2) 기본 파이
ax.pie(x=df1['금액'], labels=df1.index, autopct='%.1f%%')

# 3) 회전/방향
ax.pie(..., startangle=260, counterclock=False)  # 시작각도 + 시계방향

# 4) 색상 팔레트 직접 생성해서 적용
colors = sb.color_palette("Set2", n_colors=len(df1['금액']))
ax.pie(..., colors=colors)

# 5) 특정 조각 분리(explode) — 리스트 길이는 데이터 개수와 동일해야 함
explode = [0.1, 0, 0, 0, 0]
ax.pie(..., explode=explode)
```

### Donut 만들기 = `wedgeprops`만 추가

```python
wedgeprops = {'width':0.7, 'edgecolor':'#ffffff', 'linewidth':3}
ax.pie(..., wedgeprops=wedgeprops)
```

→ `width < 1`이면 가운데가 뚫리는 도넛 형태가 됨. `edgecolor`/`linewidth`는 조각 사이 경계선 스타일.

### 모듈화 버전

```python
my_plot.pieplot(x=df1['금액'], labels=df1.index, palette='pastel')                 # 파이
my_plot.pieplot(x=df1['금액'], labels=df1.index, palette='pastel', donutchart=True) # 도넛
```

→ `donutchart=True` 플래그 하나로 파이/도넛을 전환하도록 설계된 게 포인트 (내부적으로 `wedgeprops`를 조건부 생성).

## 6. 그래프 선택 가이드 (한눈에 보는 비교표)

| 목적                                     | 그래프                | 필요한 전처리                                      |
| ---------------------------------------- | --------------------- | -------------------------------------------------- |
| 수치 하나의 분포 모양(대칭/치우침)       | KDE / Histogram       | 없음 (또는 log1p)                                  |
| 수치 하나의 요약(중앙값·이상치)         | Box Plot              | `numerical_summary()`로 이상치 확인              |
| 수치 하나의 분포 모양 + 요약 둘 다       | **Violin Plot** | 위와 동일, 그룹 비교 시 groupby 불필요(hue로 처리) |
| 범주별 수치 "대표값" 비교 (평균/최대 등) | **Bar Plot**    | wide면`melt()`로 long 변환                       |
| 범주별 "빈도" 비교                       | **Count Plot**  | 없음                                               |
| 두 범주 조합 × 하나의 수치 패턴         | **Heatmap**     | `pivot_table()` 필수                             |
| 전체 대비 구성비                         | **Pie / Donut** | `groupby().sum()` + 내림차순 정렬                |

## 8. 자주 하는 실수 / 유의사항 정리

1. **복붙 후 변수명·타이틀 안 고치는 습관** — 그래프마다 `title`, `xlabel`, `ylabel`을 그 그래프의 실제 내용에 맞게 매번 확인하고 수정할 것.
2. **`palette`는 `hue`와 세트로만 동작** — hue 없이 palette 쓰면 적용 안 됨.
3. **`linewidths`(heatmap) vs `linewidth`(line/kde/hist)** — 함수마다 파라미터명이 다르므로 seaborn 공식 문서 기준으로 철자 확인.
4. **pandas 메서드 대부분은 원본을 바꾸지 않음** (`drop`, `rename`, `astype` 등) — 결과를 유지하려면 재할당하거나 `inplace=True` 사용. (`my_qtcheck.set_type()`은 내부에서 `df = data.copy()`로 명시적으로 복사 후 처리하는 이유가 바로 이것 — 원본 보호.)
5. **그룹 간 비교 시 이상치 기준은 그룹별로 따로 계산** (전체 기준으로 한 번에 자르면 그룹 특성이 왜곡될 수 있음).
6. **히트맵은 "피벗 테이블을 그린다"는 것과 동의어** — 시각화 전에 반드시 `pivot_table()` 결과 형태(행/열/값)를 먼저 확인.

## 9. Olist 프로젝트 등 실전 적용 시 연결 지점

- **`numerical_summary()`의 동적 percentile/IQR 계산 로직**은 Olist에서 SLA 임계값(delay_p80, handling_p80 등)을 하드코딩이 아니라 데이터 기반으로 산출했던 것과 완전히 같은 사고방식 → 이 함수를 그대로 SLA 관련 컬럼(배송 지연일수 등) 진단에 재사용 가능.
- **Heatmap**은 "지역×월" 매출/주문 패턴, "카테고리×배송등급" 조합 등 Olist의 다차원 교차 분석에 바로 적용 가능 (pivot_table만 갈아 끼우면 됨).
- **Bar/Count Plot + melt() 조합**은 Olist에서 "카테고리별 반복구매 비율(Analysis D)"처럼 여러 지표를 하나의 그래프에 비교할 때 활용 가능.
- **Violin Plot**은 SLA 등급별 배송 소요일 분포처럼, 단순 평균 비교(barplot)로는 안 보이는 "분포 모양 차이"를 보여줘야 할 때(H-2 분석 등) 유용.
