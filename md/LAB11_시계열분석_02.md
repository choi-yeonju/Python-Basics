## 1. 핵심 개념

### 1-1. 평활(Smoothing)이란

**정의**: 시계열에 섞인 잡음(noise)을 지우고 신호(signal)만 남기는 작업. 결과적으로 그래프가 매끄러워진다.

시계열 하나에는 항상 두 가지 움직임이 섞여 있다.

| 구분 | 내용 | 예시 | 알고 싶은가 |
|---|---|---|---|
| 신호 (signal) | 장기적으로 반복되거나 지속되는 패턴 | 매년 여름 성수기, 몇십 년간의 우상향 추세 | ✅ 알고 싶은 것 |
| 잡음 (noise) | 우연히 그 시점에만 발생한 변동 | 이번 달만 유독 낮았던 수치 | ❌ 알고 싶은 게 아님 |

평활 기법은 이 둘 중 신호만 남기고 잡음을 지우는 필터 역할을 한다. 크게 두 가지가 있고, 둘 다 **탐색적 데이터 분석(EDA)**이지 예측 모형 자체는 아니다.

| 기법 | 하는 일 | 성격 |
|---|---|---|
| 이동평균법 (Moving Average) | 노이즈를 지워 흐름만 남긴다 | 순수 탐색(EDA) |
| 지수평활법 (Exponential Smoothing) | 최근 값에 더 무게를 두어 "지금 상태"를 본다 | 탐색과 예측의 경계 |

---

### 1-2. 이동평균법 (Moving Average)

**말로 풀면**: 어떤 시점의 값을, 그 시점을 포함해서 바로 이전 k개 값들의 평균으로 바꿔치기하는 방법이다. "이웃한 k개를 똑같은 비중으로 평균 낸다"가 핵심이다.

**수식**:

```
MA_t(k) = ( y_t + y_(t-1) + ... + y_(t-k+1) ) / k
```

- `y_t` : t 시점의 원래 관측값
- `k` : **창(window)** — 몇 개를 묶어 평균 낼지, 분석가가 직접 정하는 값
- 창 안의 **모든 값을 똑같은 비중(가중치)**으로 취급한다 (=단순 평균)
- 앞쪽 `k-1`개 지점은 평균 낼 과거 값이 부족해서 **결측치(NaN)**가 된다 → 이게 뒤에서 `df.rolling(12).mean()`을 쓰면 앞 11개가 NaN이 되는 이유다.

**언제, 왜 쓰는가**

| 항목 | 내용 |
|---|---|
| 목적 | 단기 변동(노이즈) 제거, 추세를 시각적으로 확인 |
| 계산 성질 | 모든 관측값을 동일 취급 → 계산이 단순하지만 변화에 느리게 반응(lag가 큼) |
| 활용 상황 | 시계열 초기 탐색, 그래프를 매끄럽게 볼 때, 증감 경향(우상향/우하향) 확인 |
| 예측력 | 이동평균은 **예측보다는 패턴 관찰용**이다. 미래를 내다보는 용도가 아니다. |

**pandas 코드**:
```python
데이터프레임[컬럼명].rolling(k).mean()   # 창 크기 k의 단순이동평균
데이터프레임[컬럼명].rolling(k).std()    # 창 크기 k의 이동표준편차 (변동성 추적)
```

#### ⭐ 창 크기(window)를 정하는 규칙 — 이 랩에서 가장 중요한 원칙

> **창 크기는 반드시 계절 주기(또는 그 배수)로 잡는다.**

왜 그런가를 논리로 풀면:
1. 예를 들어 월별 데이터이고 계절 주기가 12개월(1년)이라고 하자.
2. 12개월 치를 평균 내면 그 안에 여름(고점)과 겨울(저점)이 **골고루 다 들어가서 서로 상쇄**된다.
3. 그러면 계절 등락은 사라지고 "1년 단위로 수준이 얼마나 이동했는가"라는 **장기 추세만** 남는다.

반대로 창을 **어중간하게(예: 6개월)** 잡으면 무슨 일이 생기는가:
- 6개월 평균은 반 년치만 섞이므로 여름과 겨울이 **절반만 상쇄**된다.
- 그 결과 봉우리(계절성)가 절반만 지워지고, **원래 데이터에 없던 "6개월짜리 가짜 주기"**가 생긴 것처럼 보인다.
- 이건 이 랩의 실습(항공승객, 서울기온)에서 실제 숫자로 확인된 함정이다 (아래 3장 참고).

그리고 이동평균은 뒤에서 배울 **시계열 분해(decomposition)**에서도 내부적으로 이 계산(창=주기의 이동평균)을 그대로 사용한다. 즉 이 랩의 개념이 다음 랩의 기초가 된다.

### 1-3. 지수평활법 (Exponential Smoothing)

**이동평균의 두 가지 약점**과 **지수평활이 그것을 어떻게 고치는지**부터 이해하면 수식이 저절로 이해된다.

| 이동평균의 약점 | 지수평활의 해결 |
|---|---|
| 창 밖의 데이터는 완전히 버린다 | 모든 과거 데이터를 다 사용한다 |
| 창 안의 데이터를 전부 똑같이 취급한다 | 최근 값일수록 더 큰 가중치를 준다 |

**수식**:

```
S_t = α · y_t + (1 - α) · S_(t-1)
```

- `y_t` : t 시점의 실제 관측값
- `S_t` : t 시점의 평활된 값 (지수평활 결과)
- `S_(t-1)` : 바로 이전 시점의 평활값
- **α (알파, 평활계수, 0 < α < 1)** : 최근 값을 얼마나 믿을지 정하는 값. "지금 값에 α만큼, 과거까지 반영된 이전 평활값에 (1-α)만큼 가중치를 둔다"는 뜻.

**말로 풀면**: 오늘의 평활값은, 오늘 실제로 관측된 값과 어제까지 누적된 평활값을 α : (1-α) 비율로 섞은 것이다. 이 식을 계속 과거로 펼쳐보면(재귀적으로 대입하면) 과거로 갈수록 가중치가 `α, α(1-α), α(1-α)², α(1-α)³, ...` 식으로 **기하급수적으로(지수적으로)** 줄어든다. 이게 이름이 "지수"평활인 이유다. 즉 아주 먼 과거값도 완전히 버려지지는 않지만, 영향력이 지수적으로 옅어질 뿐이다 — 이동평균이 "창 밖=0, 창 안=전부 동일"인 계단식 가중치인 것과 대비된다.

**α 크기에 따른 성질**:

| α | 성질 |
|---|---|
| 크다 (1에 가까움) | 최근 값을 크게 반영 → 민감하게 반응하지만 잡음도 그대로 따라간다 |
| 작다 (0에 가까움) | 과거를 오래 기억 → 부드럽지만 변화에 느리게 반응한다 |

#### ⚠ pandas에서 α 대신 span을 쓰는 이유와 함정 (암기 필수)

pandas의 `.ewm()`은 α를 직접 쓰지 않고 **span(기간)**으로 지정하는 게 더 직관적이라서 보통 `span=`을 쓴다.

```
α = 2 / (span + 1)
```

즉 `span=12`는 "대략 12개 기간을 반영한다"는 뜻이 된다.

**⚠⚠⚠ 진짜 함정 (반드시 외울 것)**: `.ewm()`의 **첫 번째 위치 인자는 span이 아니라 com(중심질량, center of mass)**이다. 그래서 파라미터 이름을 반드시 명시(`span=`)해야 한다.

```python
데이터프레임[컬럼명].ewm(span=p).mean()   # 올바른 표기 — 기간 p의 지수가중이동평균
```

| 쓴 코드 | 실제 해석 | 실제 평활 강도 |
|---|---|---|
| `ewm(3)` | 첫 인자 = com = 3 | **span = 7** (!!) |
| `ewm(span=3)` | span = 3 | span = 3 |

**왜 3이 7이 되는가 (변환식)**:
- pandas의 com은 `α = 1 / (1 + com)` 으로 정의된다.
- 위에서 본 span 공식 `α = 2 / (span + 1)` 과 같다고 놓고 풀면:
  ```
  1 / (1+com) = 2 / (span+1)
  → span = 2 · com + 1
  ```
- 그래서 `com = 3` 이면 `span = 2×3+1 = 7`이 된다.

**왜 위험한가**: 변수 이름을 `ewm3`이라고 지어놓고 `.ewm(3)`을 쓰면, 코드도 변수명도 "3짜리 평활"처럼 보이지만 실제로는 **span=7짜리 평활**이 계산된다. 그래프도 그럴듯하고 결과표도 숫자가 나오기 때문에 **끝까지 발견되지 않는 버그**가 된다. → 결론: `.ewm()`을 쓸 때는 무조건 `span=` 처럼 키워드를 명시한다.

### 1-4. 이동평균 vs 지수평활 — 언제 뭘 쓰는가

이 둘은 우열 관계가 아니라 **"무엇을 알고 싶은가"에 따라 갈리는 목적의 문제**다.

- "이 데이터의 **장기 추세**가 뭐지?" → **이동평균** (창 = 계절 주기)
- "**지금 상태**가 어떻지? 다음 달은?" → **지수평활**

| 비교 항목 | 이동평균 | 지수평활 |
|---|---|---|
| 사용하는 데이터 범위 | 창 안의 k개만 | 전체 과거 (가중치만 다름) |
| 가중치 | 창 안에서 모두 동일 | 최근일수록 크다 (지수적으로 감소) |
| 결측치 | 앞쪽 k-1개 발생 | 거의 없음 (첫 값부터 계산됨) |
| 계절성 제거 | 창=주기면 완전히 제거됨 | 완전히 제거되지 않음 (최근 계절의 흔적이 남음) |
| 변화에 대한 반응 속도 | 느리다 | 빠르다 |
| 그래프 모양 | 봉우리가 사라진 매끈한 곡선 | 원본을 뒤쫓듯 출렁이는 곡선 |
| 주 용도 | 추세 추출, 구조 파악 | 단기 예측, 현재 상태 추적 |

**실습에서 직접 확인된 수치 근거** (같은 기간=12를 줬을 때):
- 항공승객 데이터: 이동평균(12)은 봉우리가 완전히 사라지고 꾸준히 우상향. 지수평활(span=12)은 봉우리가 남고, 같은 시점에 이동평균은 상승 중인데 지수평활은 하락하기도 했다 (원본이 최근에 떨어진 것을 바로 따라갔기 때문).
- 서울기온 데이터 표준편차 비교 (원본 std = 9.932):

  | 기간(창/span) | 이동평균 표준편차 | 지수평활 표준편차 |
  |---|---|---|
  | 3 | 8.970 | 7.991 |
  | 6 | 6.332 | 5.483 |
  | **12** | **0.745** | **3.251** |
  | 24 | 0.627 | 1.983 |

  → 기간이 3, 6일 때는 지수평활이 오히려 더 매끈하지만(표준편차가 더 작음), **12에서 순위가 뒤집힌다**. 이동평균은 정확히 1년을 균등하게 평균 내므로 계절이 정확히 상쇄되는 반면, 지수평활은 아무리 span을 키워도 "최근 값 가중"이라는 구조 자체 때문에 현재 계절 쪽으로 계속 끌려가서 계절성이 4.4배(0.745 vs 3.251)나 더 많이 남는다.

- **지연(lag)**: 지수평활 곡선은 원본보다 약간 오른쪽으로 밀려서 그려진다. 과거 값을 끌고 오기 때문에 생기는 자연스러운 지연이다.

## 2. 통계적 개념 상세 설명 (말로 풀어서)

이 랩은 검정이 아니라 EDA이므로 "귀무가설 vs 대립가설" 같은 가설검정 틀은 등장하지 않는다. 대신 아래 두 통계량이 "얼마나 매끈해졌는지"를 객관적으로 뒷받침하는 핵심 지표로 쓰인다. 면접에서 설명할 수 있어야 하는 개념들이다.

### 2-1. 표준편차 (Standard Deviation, std)

**정의를 말로 풀면**: 데이터 하나하나가 평균으로부터 평균적으로 얼마나 떨어져 있는지를 나타내는 값이다. 값이 크면 데이터가 들쭉날쭉하다는 뜻이고, 작으면 평균 근처에 몰려 있다는 뜻이다.

**이 랩에서의 역할**: "평활이 잘 됐는가"를 판단하는 잣대로 쓰인다. 원본의 표준편차가 9.932인데, 이동평균(12)을 적용한 뒤의 표준편차가 0.745라면, "원래 있던 들쭉날쭉함(계절 변동)의 대부분(92.5%)이 사라지고 완만한 추세만 남았다"고 해석한다. 즉 눈으로 "매끈해 보인다"고 말하는 대신, **표준편차가 몇 %로 줄었는지 숫자로 근거를 댄다**.

### 2-2. 변동계수 (Coefficient of Variation, CV)

**정의를 말로 풀면**: 표준편차를 평균으로 나눈 값이다 (`CV = 표준편차 / 평균`). 표준편차는 데이터의 "단위"에 따라 크기가 달라지므로, 서로 다른 수준(평균값)을 가진 구간끼리 변동성을 비교하려면 평균으로 나눠서 "상대적인 변동 크기"로 맞춰줘야 한다. 이것이 변동계수다.

**이 랩(정확히는 `my_ts.py`의 `report_variation` 함수)에서의 역할**: 시계열을 연 단위 등으로 묶었을 때, **표준편차는 계속 커지는데 변동계수는 일정하다면** → 이는 "변동의 절대적인 크기가 커진 게 아니라, 데이터 수준(평균) 자체가 커졌기 때문에 표준편차도 따라 커진 것"이라는 뜻이다. 이 경우 로그변환이 필요하다는 신호로 해석한다 (승법적 구조 → 가법적 구조로 바꾸기 위함). 반대로 표준편차도 일정하고 변동계수도 일정하면 로그변환 없이 원본을 그대로 써도 된다 (가법 모델).

### 2-3. 정상성(Stationarity)과 평활의 관계

LAB-11-01에서 배운 정상성 개념이 이 랩에서 실전으로 확인된다.
- **정상 시계열**이라면, 평활(이동평균)을 아무리 적용해도 **더 이상 뽑아낼 구조(추세)가 없어야** 한다. 즉 이동평균 곡선이 0 근처의 수평선에 가깝게 유지되어야 하고, 창을 키워도 뚜렷한 흐름이 나타나지 않아야 한다.
- 실습에서 로그변환+1차차분+계절차분을 거친 정상 시계열에 이동평균을 적용해보니 실제로 곡선이 수평선에 가까웠다. → "평활을 해도 남는 구조가 없다"는 것은 "잡음만 남았다"는 뜻이고, 이래야 다음 단계에서 배울 ARIMA 같은 모형이 제대로 작동한다.
- 즉 이 랩은 정상성 개념을 **눈(그래프)으로 재확인**하는 역할도 겸한다.

### 2-4. (참고) 이 랩에 직접 등장하지는 않지만 `my_ts.py`에 남아있는 ADF 검정 개념

`my_ts.py` 모듈에는 LAB-11-01에서 만든 `adf_test`, `adf_diff`, `adf_transform` 함수가 그대로 들어있다 (오늘 노트북에서는 호출하지 않았지만, `my_ts.transform()`으로 로그+차분 전처리를 재사용했다). 복습 차원에서 다시 짚으면:

- **ADF 검정(Augmented Dickey-Fuller test)**은 시계열에 "단위근(unit root)"이 있는지를 검정한다.
  - **귀무가설 H0**: 시계열에 단위근이 존재한다 (= 비정상 시계열이다).
  - **대립가설 H1**: 단위근이 존재하지 않는다 (= 정상 시계열이다).
  - p-value가 유의수준(보통 α=0.05)보다 **작으면** 귀무가설을 기각 → "정상 시계열"로 판정한다.
  - 이 방향이 직관과 반대이므로 (p가 작아야 좋은 결과) 항상 헷갈리기 쉬운 부분이라 다시 짚어둔다.

1. **먼저 직접 코딩**으로 "무슨 계산을 하는지"를 눈으로 확인한다 (rolling, ewm을 for문으로 직접 돌림).
2. 직접 코딩이 잘 작동하는 걸 확인한 뒤에야 **같은 로직을 함수로 감싸서 모듈화**한다 (`my_ts.plot_rolling`, `my_ts.compare_smoothing`). 처음부터 모듈을 만들지 않고, 검증된 코드를 함수로 승격시키는 순서다. 이건 LAB-09/LAB-10에서 `my_ols`, `my_logit`이 만들어진 패턴과 동일하다.
3. **연습문제(서울 기온)**는 직접 코딩 없이 **처음부터 모듈만으로** 재현한다. 이게 모듈화의 목적이다 — 한 번 검증된 로직을 다음 데이터셋에 그대로 재사용하는 것.

## 4. 직접 코딩 버전 vs 모듈 버전 — 코드 비교

같은 결과를 만드는 두 가지 코드를 나란히 두면 모듈이 내부에서 뭘 하는지 명확해진다.

### 4-1. "창 크기별 이동평균 비교 + 격자 시각화"

**직접 코딩 버전** (노트북 #02):
```python
ma = DataFrame({"원본": df["Passengers"]})

for k in (3, 6, 12):
    ma[f"이동평균({k})"] = df["Passengers"].rolling(k).mean()

# 원본 + 창 3개 = 4칸이므로 2행 2열 격자에 한 칸씩 그린다.
fig, ax = my_plot.init(rows=2, cols=2, width=960, height=400,
                       title="이동평균 - 창 크기별 비교")

for i, col in enumerate(ma.columns):
    my_plot.lineplot(x=ma.index, y=ma[col], ax=ax[i])
    ax[i].set_title(col)

my_plot.show()
ma.tail(3)
```

**모듈 버전** (노트북 #07, `my_ts.compare_smoothing`):
```python
ma_result = my_ts.compare_smoothing(df, (3, 6, 12), "Passengers", method="ma",
                                    title="이동평균 - 창 크기별 비교")
ma_result
```

**모듈이 내부에서 하는 일** (`my_ts.py` 소스 기준):
```python
def compare_smoothing(data, sizes, column=None, method="ma", overlay=False,
                      plot=True, title=None, xlabel=None, ylabel=None,
                      width=960, height=400, save_path=None):
    # --- 1) 컬럼 추출 ---
    if column is not None:
        data = data[column]

    result_df = DataFrame({"원본": data})

    for size in sizes:
        # --- 이동평균 ---
        if method == "ma" or method == "both":
            result_df[f"이동평균({size})"] = data.rolling(size).mean()
        # --- 지수평활 (com이 아니라 span임을 반드시 명시) ---
        if method == "ewm" or method == "both":
            result_df[f"지수평활({size})"] = data.ewm(span=size).mean()

    if not plot:
        return result_df

    # --- overlay=True면 한 축에 겹쳐 그리기, False면 격자에 분산 ---
    if overlay:
        fig, ax = my_plot.init(width=width, height=height, title=title, xlabel=xlabel, ylabel=ylabel)
        for col in result_df.columns:
            my_plot.lineplot(x=result_df.index, y=result_df[col], label=col, ax=ax)
        ax.legend()
        my_plot.show(save_path=save_path)
        return result_df

    # --- 격자로 나눠 그리기: 열 개수에 맞춰 행/열 자동 계산 ---
    cols = 2
    rows = int(np.ceil(len(result_df.columns) / cols))
    fig, ax = my_plot.init(rows=rows, cols=cols, width=width, height=height, title=title)

    for i, col in enumerate(result_df.columns):
        my_plot.lineplot(x=result_df.index, y=result_df[col], ax=ax[i])
        ax[i].set_title(col)

    # 칸 수가 남으면(홀수 개) 마지막 빈 칸을 숨긴다
    for i in range(len(result_df.columns), rows * cols):
        ax[i].set_visible(False)

    my_plot.show(save_path=save_path)
    return result_df
```

**직접 코딩과 모듈의 대응 관계**:

| 직접 코딩에서 한 일 | 모듈 안의 대응 코드 |
|---|---|
| `for k in (3,6,12): ma[...] = rolling(k).mean()` | `for size in sizes: result_df[...] = data.rolling(size).mean()` |
| `my_plot.init(rows=2, cols=2, ...)` | `rows = ceil(열개수/2)`로 **행 개수를 자동 계산** (창 개수가 몇 개든 대응 가능) |
| `for i, col in enumerate(...): lineplot(...)` | 동일한 반복 구조를 함수 내부로 그대로 이식 |
| method 구분 없음 (이동평균만) | `method` 파라미터로 `"ma"`/`"ewm"`/`"both"` 세 가지를 하나의 함수로 통합 |
| overlay 개념 없음 (매번 격자만) | `overlay` 파라미터로 "겹쳐그리기/격자그리기"를 스위치로 만듦 |

**이렇게 사고해야 하는 이유**: 모듈은 "새로운 로직"이 아니라 "직접 짠 코드에서 매번 바뀌는 부분(창 크기 목록, 컬럼명, method)만 파라미터로 뽑아내고 나머지 뼈대는 그대로 유지"한 것이다. 그래서 모듈 코드를 읽을 때는 "내가 직접 짰던 for문이 어디에 들어가 있는지" 찾아보는 방식으로 읽으면 이해가 훨씬 빠르다.

### 4-2. "원본+이동평균+이동표준편차 한 번에" 비교

**직접 코딩 버전은 노트북에 별도로 없고**, 모듈 버전만 있다 (`my_ts.plot_rolling`). 이건 이미 LAB-11-01에서 정상성을 눈으로 확인할 때 반복적으로 쓰던 패턴이라, 이번 랩에서는 처음부터 모듈로 제공된 것으로 보인다 — 모든 개념이 이 랩에서 "직접 코딩 → 모듈화" 두 단계를 다 거치는 건 아니고, 이미 검증된 패턴은 바로 모듈로 시작하기도 한다는 뜻이다.

```python
def plot_rolling(data, window, column=None, title=None, xlabel=None, ylabel=None,
                 width=1280, height=480, save_path=None):
    # --- 1) 대상 데이터 준비 ---
    if column is not None:
        data = data[column]

    # --- 2) 이동평균과 이동표준편차 계산 ---
    result_df = DataFrame({
        "원본": data,
        "이동평균": data.rolling(window).mean(),
        "이동표준편차": data.rolling(window).std(),
    })

    # --- 3) 그래프 그리기 및 결과 반환 ---
    if title is None:
        title = f"원본, 이동평균, 이동표준편차 (window={window})"

    fig, ax = my_plot.init(width=width, height=height, title=title, xlabel=xlabel, ylabel=ylabel)
    for col in result_df.columns:
        my_plot.lineplot(x=result_df.index, y=result_df[col], label=col, ax=ax)
    ax.legend()
    my_plot.show(save_path=save_path)

    return result_df
```

**호출 코드**:
```python
rolling = my_ts.plot_rolling(df, 12, "Passengers",
                             xlabel="연도", ylabel="승객 수 (천 명)")
rolling.tail(3)
```

**함수가 하는 일을 순서대로 말로 풀면**:
1. 컬럼명이 주어졌으면 그 컬럼만 뽑는다 (Series로 만듦).
2. "원본", "이동평균"(`rolling(window).mean()`), "이동표준편차"(`rolling(window).std()`) 세 개를 컬럼으로 가진 데이터프레임을 만든다.
3. 세 줄을 한 그래프 위에 겹쳐 그린다 (범례 자동 표시).
4. 계산된 데이터프레임 자체를 반환한다 → 그래프만 보고 끝나는 게 아니라, 이후에 `rolling["이동평균"].dropna()`처럼 **숫자로 다시 뽑아 쓸 수 있게** 반환값을 설계한 것이 핵심이다.

## 5. `my_ts` 모듈 함수 목록 및 역할 정리

`my_ts.py`는 LAB-11-01(정상성)과 LAB-11-02(평활)의 함수를 모두 담고 있는 하나의 모듈이다. 오늘 실제로 쓴 함수는 `set_index`, `transform`, `plot_rolling`, `compare_smoothing` 네 개이고, 나머지(`adf_test`, `adf_diff`, `adf_transform`, `report_split`, `report_variation`)는 LAB-11-01에서 만든 것이 그대로 남아 재사용되고 있다.

| 함수 | 역할 | 오늘 사용 여부 |
|---|---|---|
| `set_index(data, column, freq=None, sort=True)` | 날짜 컬럼을 인덱스로 바꾸고 관측 간격(freq)을 명시한다 | ✅ 사용 |
| `transform(data, column, log, diff, seasonal_diff, period)` | 로그변환→일반차분→계절차분을 순서대로 적용해 정상 시계열을 만든다 | ✅ 사용 (정상 시계열 재현용) |
| `plot_rolling(data, window, column, ...)` | 원본+이동평균+이동표준편차를 한 그래프에 그린다 | ✅ 사용 |
| `compare_smoothing(data, sizes, column, method, overlay, ...)` | 여러 창 크기/span을 비교해서 격자 또는 겹쳐 그린다 | ✅ 사용 |
| `report_split(data, column, size)` | 시계열을 구간별로 잘라 평균·표준편차·변동계수를 비교한다 | ⛔ (LAB-11-01용) |
| `report_variation(data, column, freq)` | 기간 단위로 묶어 변동폭이 수준에 비례하는지(로그변환 필요 여부) 판정한다 | ⛔ (LAB-11-01용) |
| `adf_test(data, column, name, alpha)` | ADF 검정으로 정상성 여부를 판정한다 | ⛔ (LAB-11-01용, 모듈에는 남아있음) |
| `adf_diff(data, column, max_diff, alpha)` | 차분 차수를 늘려가며 ADF 검정, 과대차분 여부 자동 판정 | ⛔ (LAB-11-01용) |
| `adf_transform(data, column, period, max_diff, log, alpha)` | 로그·차분·계절차분의 모든 조합을 만들어 ADF 검정, 최적 조합 자동 추천 | ⛔ (LAB-11-01용) |

### 왜 이렇게 한 모듈에 다 몰아넣었을까 (설계 사고방식)

- `my_ols`, `my_logit`처럼 "회귀분석 전용", "로지스틱회귀 전용" 모듈이 아니라, `my_ts`는 **"시계열 분석"이라는 하나의 큰 주제**로 묶여 있다.
- 정상성 검정(`adf_*`)과 평활(`plot_rolling`, `compare_smoothing`)은 서로 다른 기법처럼 보이지만, 둘 다 **"이 시계열이 정상인가/어떤 구조를 가졌는가"를 확인하는 도구**라는 공통 목적을 가진다. 그래서 같은 모듈 안에 있는 게 자연스럽다.
- 앞으로 시계열 분해(decomposition), ARIMA 적합 등이 추가되면 아마 `my_ts.py`에 계속 함수가 늘어나거나, 파일이 너무 커지면 `my_ts_decompose.py`처럼 쪼개질 수도 있다 (LAB-10에서 `my_logit`이 커지면서 `my_qtcheck`/`my_prep`으로 역할이 나뉘었던 패턴과 같은 흐름).

### 창 크기를 정하는 판단 절차 (템플릿에 그대로 적용)

1. 데이터의 계절 주기를 먼저 파악한다 (월별=12, 분기별=4, 요일 패턴=7 등 도메인 지식으로 판단).
2. 후보 창 크기들(예: 주기의 1/4, 1/2, 1배, 2배)로 `compare_smoothing`을 실행하고 `.std()`를 비교한다.
3. 표준편차가 급격히 줄어드는 지점(꺾이는 지점)을 찾는다 — 보통 창=주기 지점에서 크게 떨어진다.
4. 그 이상으로 창을 더 키워도 표준편차가 크게 줄지 않는다면, **결측치가 늘어나는 손해만 있으므로 가장 작은 창(=주기)을 선택**한다.

## 7. 연습문제 전체: 서울 월평균 기온의 평활

**문제**: `temperatures_seoul` 데이터는 1973년 7월 ~ 2023년 8월까지 서울의 월평균 기온이다. 계절 요동이 지배적이어서 원본 그래프로는 장기 변화를 읽을 수 없다. 평활로 계절 요동을 걷어내고 장기 추세를 드러내시오.
1. 창 크기 3·6·12·24를 비교해 어떤 창을 써야 하는지와 이유를 답하시오.

### 전체 코드 (모듈만 사용, 처음부터 끝까지)

```python
# #01. 준비작업
from jussam import load_data
from helpers import *

origin = load_data('temperatures_seoul')

# freq="MS"로 매월 1일 간격임을 명시해야 창 크기 12가 "1년"을 의미하게 된다
```

### 각 코드가 왜 필요한지 (생각의 로직)

- `freq="MS"` **를 지정하는 이유**: pandas의 `rolling(window)`은 "행(row) 개수" 기준으로 창을 잡는다. freq가 없으면 중간에 결측월이 있어도 그냥 무시하고 다음 행을 이웃으로 취급해버릴 수 있다. `freq="MS"`로 "매월 1일 간격"임을 명시해야 `window=12`가 정확히 "달력상 12개월(=1년)"을 의미하게 되고, 계절 상쇄 논리가 성립한다. → 이건 옵션이 아니라 **분석의 전제조건**이다.
- **원본을 먼저 그려보는 이유**: 평활이 "왜 필요한지"를 스스로 확인하는 절차다. -7℃~+30℃로 요동치는 원본에서는 장기 추세(몇십 년간 몇 도 올랐는지)가 계절 진폭에 완전히 묻혀서 눈으로 안 보인다. 이 "안 보임"을 먼저 확인해야 평활의 효과를 대조할 수 있다.
- **창 크기 3·6·12·24를 비교하는 이유**: "12가 정답이다"를 결과만 알고 외우는 게 아니라, 여러 후보를 실제로 계산해서 **왜 12가 최적인지** 표준편차 숫자로 스스로 증명하는 절차다.
- **`method="both", overlay=True`를 마지막에 쓰는 이유**: 창 크기 비교는 "이동평균 안에서"의 비교였고, 이 단계는 "이동평균 대 지수평활"이라는 **다른 축의 비교**다. 같은 기간(12)을 줬을 때 두 방법의 결과가 왜 다른지(위 1-4절 참고)를 시각적으로 마지막에 확인하는 것.
- **`plot_rolling`으로 마무리하는 이유**: 지금까지는 "평균"만 봤는데, 마지막엔 이동표준편차도 같이 그려서 "변동폭 자체가 시간에 따라 커지는지/일정한지"까지 확인한다. 이동표준편차가 평평하면 로그변환이 필요 없다는 뜻이므로, 이후 분석(ARIMA 등)에서 로그변환 단계를 건너뛸 근거가 된다.

## 8. 반드시 기억할 것 (암기용 총정리)

| 원칙 | 내용 |
|---|---|
| 🔑 창 크기는 계절 주기로 | 주기의 배수가 아니면 계절성이 크게 남는다 (어중간한 창은 가짜 주기를 만든다) |
| 🔑 목적이 방법을 정한다 | 장기 추세를 보고 싶다 → 이동평균(창=주기) / 지금 상태·단기 예측을 하고 싶다 → 지수평활 |
| 🔑 가장 작은 창을 쓴다 | 창이 넓을수록 결측치가 늘고 최근 변화 반영이 둔해진다. 효과가 비슷하면 작은 쪽을 선택 |
| 🔑 평활은 EDA다 | 평활로 드러난 "+2.8℃ 상승" 같은 결과는 눈으로 확인한 것이지, 통계적으로 검정된 결론이 아니다 |
| ⚠ `.ewm()` 함정 | 첫 번째 위치 인자는 span이 아니라 com이다. `ewm(3)`은 실제로 span=7. 반드시 `ewm(span=p)`로 키워드 명시 |
| ⚠ `freq` 필수 | `set_index`에서 freq를 지정 안 하면 `window=12`가 "12개월"이 아니라 그냥 "행 12개"가 되어 계절 상쇄 논리가 깨진다 |
| 📐 이동평균 수식 | `MA_t(k) = (y_t + y_(t-1) + ... + y_(t-k+1)) / k` — 창 안 k개를 동일 가중치로 단순평균 |
| 📐 지수평활 수식 | `S_t = α·y_t + (1-α)·S_(t-1)` — 최근 값에 α, 과거 누적값에 (1-α) 가중치를 재귀적으로 적용 |
| 📐 span ↔ com 변환 | `α = 2/(span+1)`, `α = 1/(1+com)` → `span = 2·com + 1` |

## 9. 다음 랩을 위한 연결고리

- 이동평균(창=계절 주기)은 다음에 배울 **시계열 분해(seasonal_decompose)**에서 추세(trend) 성분을 뽑아낼 때 내부적으로 그대로 재사용되는 계산이다. 즉 오늘 배운 "창=주기" 원칙이 다음 랩에서도 그대로 적용된다.
- `my_ts.py`에는 이미 `seasonal_decompose`가 import되어 있는데(코드 상단), 아직 이 랩에서는 쓰이지 않았다 → 다음 랩에서 이 함수를 감싼 새로운 `my_ts` 함수가 추가될 가능성이 높다.
