## 1. 핵심 개념 — 말로 풀어서 정리 (면접용)

### 1-1. 시계열 데이터란

일정한 시간 간격으로, **순서대로** 기록된 관측값의 집합이다. 핵심은 "순서"다. 행의 순서를 섞으면 데이터 자체가 파괴된다. 회귀분석에서 배운 "관측치는 서로 독립이다"라는 가정이 시계열에서는 애초에 성립하지 않는다.

시계열 분석이 답하려는 질문은 세 가지다: 지금까지 어떻게 변해왔는가, 이 변화에는 어떤 구조가 있는가, 앞으로 어떻게 될 것인가. 그리고 그 변화를 이루는 4대 구성요소는 **추세(Trend), 계절성(Seasonality), 순환(Cycle), 불규칙(Irregular)**이다.

- **추세**: 장기적으로 증가하거나 감소하는 큰 흐름
- **계절성**: 고정된 주기(1년, 1주일 등)로 반복되는 패턴
- **순환**: 계절성처럼 고정 주기는 아니지만 상승-하강을 반복하는 장기적 파동(경기순환 등)
- **불규칙**: 위 세 가지로 설명되지 않는 나머지 무작위 변동

시계열 분석은 검정 통계량이 아니라 **선 그래프 한 장**에서 시작한다. 숫자를 보기 전에 눈으로 먼저 확인하는 것이 관례다.

### 1-2. 정상성(Stationarity)이란 무엇이고 왜 필요한가

**정상성**이란 "시간이 흘러도 데이터의 통계적 성질이 변하지 않는 상태"를 말한다. 시간축의 어느 구간을 잘라내도 비슷하게 생긴 상태라고 이해하면 된다.

왜 이게 중요하냐면, 시계열 분석의 논리 자체가 "과거에 성립하던 규칙이 미래에도 성립한다"는 전제 위에 서 있기 때문이다. 만약 평균이 시간이 갈수록 계속 올라가는 데이터라면, 과거의 평균과 미래의 평균이 다르다는 뜻이고, 그 말은 시점마다 규칙이 달라진다는 뜻이다. 그러면 과거 데이터에서 학습한 규칙을 미래에 그대로 적용할 수 없다 — 예측 모델을 세울 근거 자체가 사라진다.

그래서 시계열 분석의 시작점은 "우리 데이터가 정상인가?"가 아니라 **"어떻게 정상으로 만들 것인가?"**다. 현실에서 수집되는 대부분의 원본 데이터는 비정상(non-stationary)이고, 그걸 전처리해서 정상 시계열로 바꾸는 것이 목표다.

**정상성의 3가지 조건**
1. 평균이 일정하다 (시간에 따라 평균 수준이 변하지 않는다)
2. 분산이 일정하다 (변동폭이 시간에 따라 커지거나 작아지지 않는다)
3. 공분산이 시차(lag)에만 의존한다 (같은 시차만큼 떨어진 두 시점의 공분산은 어느 시점에서 재도 같다)

여기서 중요한 포인트: **1번과 2번의 처방이 서로 다르다.** 추세(조건1 위배)를 로그변환으로 고치려 하거나, 분산 문제(조건2 위배)를 차분으로 고치려 하는 것은 잘못된 처방이다. 문제를 먼저 정확히 진단하고, 그 문제에 맞는 도구를 골라야 한다.

**강정상성 vs 약정상성**
- **강정상성(Strict Stationarity)**: 시계열의 모든 분포(1차 모멘트뿐 아니라 전체 확률분포)가 시간 이동에 대해 불변한 상태. 이론적으로는 정의되지만 실무에서 검증이 사실상 불가능하다.
- **약정상성(Weak Stationarity)**: 평균 일정 + 분산 일정 + 공분산이 시차에만 의존, 이 세 조건만 만족하면 된다. 실무에서 "정상성"이라고 하면 보통 이것을 가리킨다. 이 강의에서도 정상성 = 약정상성으로 취급한다.

### 1-3. 단위근(Unit Root)과 ADF 검정

**단위근**은 시계열 모형(AR 모형)에서 계수 파이(φ)가 1인 상태를 말한다. 파이가 1이면 이번 시점의 값이 "직전 값 + 순수한 무작위 충격"이 되는데, 이 경우 충격이 시간이 지나도 사라지지 않고 계속 누적된다 — 그 결과가 비정상 시계열(추세를 만들어냄)이다. 반대로 파이가 1보다 작으면(예: 0) 충격이 시간이 지나면서 줄어들어 평균으로 되돌아온다 — 정상 시계열이다.

이걸 직접 눈으로 확인하기 위해 두 가지 인공 데이터를 만들어 비교했다:
- **백색잡음(White Noise)**: 매번 독립적으로 생성되는 무작위 값. φ=0. 아무리 벗어나도 0 주변으로 되돌아온다. → 정상
- **랜덤워크(Random Walk)**: 백색잡음의 누적합. φ=1. 한번 움직이면 그 자리에서 다시 출발할 뿐, 되돌아올 이유가 없다. → 비정상(단위근 존재)

**ADF(Augmented Dickey-Fuller) 검정**은 이 단위근의 존재 여부를 통계적으로 검정하는 방법이다.

- **귀무가설(H0)**: 단위근이 존재한다 → 이 시계열은 비정상이다
- **대립가설(H1)**: 단위근이 없다 → 이 시계열은 정상이다

여기서 반드시 기억해야 할 것: **ADF는 귀무가설이 "비정상"이다.** 우리가 흔히 접하는 정규성 검정(귀무가설: 정규분포를 따른다) 등과는 방향이 반대다. 그래서 판정 로직도 거꾸로다 — **p-value가 작아야(보통 0.05 미만) 귀무가설을 기각하고 "정상이다"라고 결론 내린다.** p-value가 크면 귀무가설을 기각하지 못하므로 "비정상"으로 남는다.

ADF 검정은 검정통계량, p-value 외에도 1%/5%/10% 유의수준별 기각값(critical value)을 함께 제공한다. 검정통계량이 기각값보다 더 작은(음수 방향으로 더 극단적인) 경우 귀무가설을 기각한다.

**중요한 한계 하나**: ADF 검정은 단위근(=추세성 문제)만 본다. 계절성은 단위근이 아니다. 매년 여름에 오르고 겨울에 내려오는 계절성은 결국 평균으로 되돌아오는 패턴이기 때문에, ADF 입장에서는 "정처 없이 떠돌지 않으므로 정상"이라고 판정할 수 있다. 그래서 **p-value만 보고 "전처리 끝"이라고 판단하면 안 된다** — 반드시 그래프로 계절성이 남아있는지 따로 확인해야 한다. (아래 5번 연습문제 섹션에서 서울 기온 데이터가 정확히 이 함정을 보여준다.)

### 1-4. 변환(Transformation) vs 차분(Differencing) — 서로 다른 문제, 서로 다른 도구

이 둘을 헷갈리면 안 된다는 게 이번 랩의 핵심 메시지 중 하나다.

| 구분 | 푸는 문제 | 조건 | 도구 |
|---|---|---|---|
| **변환(Transformation)** | 분산이 일정하지 않음 | 조건 ② | 로그변환 `np.log()` |
| **차분(Differencing)** | 평균(추세)이 일정하지 않음 | 조건 ① | `np.diff()` / `.diff()` |

**변환(로그변환)**: 변동폭이 데이터의 수준(level)에 비례해서 커질 때 딱 들어맞는다. 승객이 100명일 때와 500명일 때 성수기 증가분은 절대량이 다르지만, 로그를 취하면 "몇 % 증가했는가"라는 상대적인 척도로 바뀌기 때문에 변동폭이 균일해진다. **단, 로그변환은 양수 데이터에만 쓸 수 있다.** 0 이하 값이 있으면 정의되지 않는다. 그래서 기온·수익률·위도처럼 0을 지나는(영상·영하가 있는) 데이터에는 적용할 수 없다. 승객 수·매출·인구처럼 "비율로 커지는 양수 데이터"에 쓰는 도구다.

**차분**: 각 관측값과 바로 이전 관측값의 차이를 구하는 것. "얼마인가(수준, level)"를 "얼마나 변했는가(변화량, change)"로 바꾸는 작업이다. 이번 달 승객이 432명이라는 절대적 수준 대신 "지난달보다 30명 줄었다"는 변화량으로 바꾸면, 수준이 계속 커지던 것과 달리 증감은 0 주변을 맴돌게 되어 평균이 일정해진다. 차분을 하면 **해석의 단위 자체가 바뀐다** — 예측 대상이 "승객 수"가 아니라 "승객 수의 변화량"이 된다는 뜻이다. 또한 차분 즉시 첫 번째 값(들)은 비교할 이전 값이 없어 결측치가 된다.

### 1-5. 과대차분(Over-differencing) — 가장 흔하고 나쁜 실수

"p-value가 0.05를 못 넘으니 차분을 한 번 더 하자"는 판단이 이번 랩에서 가장 강조된 함정이다.

차분을 반복하면서 표준편차의 변화를 관찰해보면, 어느 차수까지는 표준편차가 줄어들다가 그 지점을 넘기면 오히려 **다시 커지기 시작**한다. p-value는 계속 작아져서(더 "정상"으로) 보이지만, 표준편차가 커진다는 것은 **원래 데이터에 없던 노이즈를 인위적으로 만들어냈다**는 뜻이다.

**과대차분 판별 규칙**: 표준편차가 최소가 되는 차수를 넘기지 않는다.

과대차분된 데이터로 ARIMA 같은 예측모델을 만들면 계수 추정이 불안정해지고 예측 구간이 쓸데없이 넓어진다. **p-value를 최소화하는 것이 목표가 아니라, 필요한 만큼만 차분하는 것이 목표다.**

**⚠️ 표준편차 비교 시 반드시 지킬 것 — "같은 스케일끼리만 비교한다"**

실습 데이터(항공승객)로 여러 조합의 표준편차를 비교해보면 원본 스케일(승객 수)의 표준편차와 로그 스케일(log 승객 수)의 표준편차는 **자릿수 자체가 다르다** (예: 원본 계열은 십 단위, 로그 계열은 소수점 단위). 이 둘을 직접 같은 줄에 놓고 "숫자가 더 작은 쪽이 이겼다"고 판단하면 안 된다. **원본 스케일 후보들끼리, 로그 스케일 후보들끼리 각각 비교**한 다음, 그 중에서도 그래프상 분산이 안정된(수준에 비례해 변동폭이 커지는 문제가 해결된) 스케일을 최종적으로 고르는 것이 맞는 순서다. 아래 §3-8에서 실제 숫자로 이 판단을 그대로 재현한다.

판정이 애매할 때의 3단계 판단 순서:
1. 기각값(critical value)과 검정통계량을 비교한다
2. 그래프에서 "무엇이 남았는지" 확인한다 (예: 평균은 잡혔는데 진폭이 여전히 커지고 있다면, 남은 문제는 추세가 아니라 분산이다)
3. 남은 문제에 정확히 맞는 처방을 쓴다 — 분산이 남았으면 로그변환(차분을 더 하면 오히려 분산이 커짐), 계절성이 남았으면 계절차분(일반차분을 더 하면 안 됨)

### 1-6. 계절차분(Seasonal Differencing)

일반차분이 **바로 직전 값**과 비교하는 것이라면, 계절차분은 **작년 같은 시점(주기 s 이전)**과 비교하는 것이다.

수식으로는:

$$\Delta_{12}\, y_t = y_t - y_{t-12}$$

(월간 데이터, 주기 s=12인 경우)

계절 주기 s는 데이터 특성에 따라 다르다: 월간 데이터면 12, 분기 데이터면 4, 일간 데이터에서 요일 패턴을 본다면 7이다.

pandas에서는 `.diff(12)`처럼 시차(lag) 값을 인자로 넘기면 바로 수행된다. 일반차분이 앞의 1개 행을 결측치로 만드는 것처럼, 계절차분(주기 s)은 **앞의 s개 행을 결측치**로 만든다 — 비교할 "작년 값"이 아예 존재하지 않기 때문이다.

계절차분을 적용하면 매년 반복되던 봉우리·골이 사라지고 0을 중심으로 무작위로 흩어지는 모습이 된다. 표준편차가 큰 폭으로 줄어든다면, 그건 **원본 변동의 대부분이 계절성이었다**는 뜻이다.

### 1-7. ARIMA에 필요한 파라미터 (d, D, s)

이번 랩의 최종 산출물은 예측 모델 그 자체가 아니라, **모델에 넣어줄 전처리 파라미터를 결정하는 것**이다.

| 파라미터 | 의미 |
|---|---|
| **d** | 일반차분을 몇 번 적용했는가 |
| **D** | 계절차분을 몇 번 적용했는가 |
| **s** | 계절 주기(월간=12, 분기=4 등) |

이 외에 로그변환 여부는 d/D/s에는 포함되지 않고, 모델에 넣기 전 **모델 외부에서** 별도로 처리하는 변환이다.

```
  └─ 선 그래프 1장으로 추세 / 계절성 / 변동폭 3가지를 눈으로 확인

#05. 비정상이면 처방
  ├─ 분산이 안 잡히면 → 변환(로그) — 단, 0 이하 값 있으면 적용 불가
  ├─ 추세가 안 잡히면 → 일반차분, 반복 적용 시 과대차분 여부(표준편차 최소값) 체크
  └─ 계절성이 남아있으면 → 계절차분(주기 s)

#06. 여러 조합을 한꺼번에 비교
  └─ combos = {"이름": 처리결과, ...} 딕셔너리로 정의 → for문으로 일괄 adf_test 수행

#07. 결론 정리
```

**주의할 점 — 판정 기준의 우선순위**
1순위: 그래프에서 뭐가 남았는지 눈으로 본다
2순위: ADF p-value로 "정상/비정상" 여부를 1차 스크리닝한다
3순위: 여러 후보가 다 "정상"으로 나오면, 같은 스케일끼리 묶어서 **표준편차가 최솟값인 조합**을 고른다

p-value는 "이 정도면 통계적으로 정상이라고 부를 수 있는가"를 판단하는 문턱값일 뿐, 낮을수록 좋은 목표 지표가 아니라는 점을 계속 강조하고 있다.

```python
fig, ax = my_plot.init(rows=1, cols=2, width=800, height=400,

ax[0].set_title("백색잡음 - 0 주변을 맴돈다")

my_plot.lineplot(x=range(144), y=random_walk, ax=ax[1])

my_plot.show()
```

**생각의 로직**: 실제 데이터로 바로 들어가기 전에, **정상/비정상이 뭔지 눈과 숫자로 감을 잡기 위한 인공 데이터 실험**이다. `np.cumsum(rng.normal(...))`이 랜덤워크를 만드는 핵심인데, "매 시점 독립적인 잡음을 계속 누적해서 더한다"는 게 랜덤워크의 정의 그 자체다(단위근 φ=1이 바로 "누적한다"는 뜻과 같다). 144개로 개수를 맞춘 이유는 실제 항공승객 데이터가 144개월(12년×12개월)이라서 나중에 비교하기 좋게 맞춘 것.

```python
    adf_test(white_noise, "백색잡음 (정상일 것)"),

    adf_test(np.diff(random_walk), "랜덤워크의 1차 차분")
]

DataFrame(check)[["대상", "검정통계량(ADF)", "p-value", "5% 기각값", "판정"]]
```

**생각의 로직**: 이 표 3줄이 이번 랩 전체의 "예고편"이다. 백색잡음은 예상대로 정상, 랜덤워크는 예상대로 비정상. 그리고 **비정상이었던 랜덤워크를 딱 한 번 차분했더니 정상이 됐다** — 이게 뒤에서 실제 데이터에 그대로 적용할 "차분으로 추세를 없앤다"는 처방의 축소판 시연이다. (참고로 이 셀은 `adf_test` 함수가 나오기 전에 먼저 쓰였지만 실제 실행 순서상 함수 정의가 이 코드보다 뒤에 나온다 — 노트북에서는 함수를 먼저 정의해두고 이 검증 셀을 그 아래에서 실행한 것으로 이해하면 된다.)

### 3-6. ADF 검정 함수 정의 — 이후 계속 재사용하는 핵심 함수

```python
def adf_test(data, name):
    x = Series(data).dropna() # 결측치 제거
    stat, pvalue, lag, _, crit, _ = adfuller(x) # ADF 검정 수행

    return {
        "대상": name,
        "관측치 수": len(x),
        "검정통계량(ADF)": round(stat, 3), #검정통계량
        "p-value": round(pvalue, 3), # p-value
        "사용 시차": lag, # 사용된 시차 수
        "1% 기각값": round(crit["1%"], 3),
        "5% 기각값": round(crit["5%"], 3),
        "10% 기각값": round(crit["10%"], 3),
        "판정": "정상" if pvalue < 0.05 else "비정상",
    }
```

**생각의 로직**: `adfuller()`를 그냥 호출하면 `(검정통계량, p-value, 사용시차, 관측치수, {기각값 딕셔너리}, 기타정보)` 형태의 튜플이 돌아온다. 이 순서를 매번 외워서 `result[0]`, `result[1]`처럼 인덱스로 꺼내 쓰면 코드를 읽을 때마다 "이 숫자가 뭐였지?"를 확인해야 해서 비효율적이고 실수하기도 쉽다. 그래서 **의미를 알 수 있는 이름을 가진 딕셔너리로 즉시 변환**하는 함수를 만든 것 — 이게 "왜 함수로 감싸는가"에 대한 답이다. `x = Series(data).dropna()`를 함수 맨 앞에 둔 이유는, 차분한 데이터를 바로 넣을 걸 예상했기 때문이다(차분하면 앞부분에 NaN이 생기는데, `adfuller`는 NaN이 있으면 에러가 난다 — 그래서 이 함수 하나로 "어떤 형태의 데이터를 넣어도 알아서 결측치를 정리하고 검정해준다"는 재사용성을 확보한 것).

`"판정": "정상" if pvalue < 0.05 else "비정상"` — 이 한 줄이 앞서 설명한 "ADF는 귀무가설이 비정상이라 p-value가 작아야 정상"이라는 로직을 코드로 그대로 옮긴 부분이다.

```python

Series(r_origin)
```

**생각의 로직**: 원본 데이터를 처음으로 실제 검정에 넣어본 것. `Series(r_origin)`으로 감싸서 출력하는 이유는 딕셔너리를 그냥 출력하면 한 줄로 나오는데, Series로 바꾸면 세로로 "항목: 값" 형태로 보기 편하게 나오기 때문이다(표 하나짜리 결과를 보기 좋게 포맷팅하는 습관). p-value가 0.992로 압도적으로 크다 — 귀무가설(비정상)을 전혀 기각하지 못한다. 앞서 그래프와 구간분석에서 본 "추세 있음"이 숫자로도 확정된 셈이다.

### 3-8. 차분 — 추세 문제 처리

```python
# 차분 수행 -> 차분의 결과로 발생하는 결측치는 제거한다.
df2 = df1.diff().dropna()

print(f"원본 {len(df1)}개 -> 1차 차분 {len(df2)}개 (첫 행 손실)")
df2.head()
```
```
원본 144개 -> 1차 차분 143개 (첫 행 손실)
```

**생각의 로직**: `.diff()`는 기본적으로 "바로 이전 행과의 차이"를 구한다(= 1차 차분). 첫 번째 행은 비교할 이전 값이 없어서 자동으로 NaN이 되고, `.dropna()`로 그 행을 제거한다. 그래서 144개였던 데이터가 143개로 줄어든다 — **차분을 한 번 할 때마다 데이터가 1개씩 줄어든다**는 걸 숫자로 확인하는 습관이 중요하다(나중에 계절차분까지 겹치면 훨씬 많이 줄어들기 때문).

**생각의 로직**: y축 라벨이 "승객 수"에서 "전월 대비 증감"으로 바뀐 걸 주목해야 한다 — 차분을 하면 데이터의 **단위와 의미 자체가 바뀐다**(§1-4에서 말한 부분이 여기서 실제로 확인된다). p-value가 0.992→0.054로 극적으로 떨어졌지만 **아직 0.05를 살짝 넘어서 "비정상" 판정**이다. 딱 경계선에 걸려있는 애매한 상황 — 이럴 때 무작정 차분을 더 하고 싶은 유혹이 생기는데, 그게 바로 다음 셀에서 확인하는 과대차분 함정이다.

```python
over_diff = [] #차분 횟수별 ADF 검정 결과를 담을 리스트
tmp = df1["Passengers"].copy() # 원본 데이터를 복사하여 차분 수행

for i in range(4): #0차 ~ 3차 차분까지 반복
    r = adf_test(tmp,f"{i}차 차분" if i >0 else "원본") # ADF 검정 수행
    r["표준편차"] = round(tmp.std(),2) #표준편차 계산
    over_diff.append(r) #결과를 리스트에 추가
    tmp = tmp.diff().dropna() # 다음 차분을 위해 1차 차분 수행 후 결측치 제거

DataFrame(over_diff)[["대상", "관측치 수", "검정통계량(ADF)", "p-value","판정", "표준편차"]]
```
```
      대상  관측치 수  검정통계량(ADF)  p-value   판정    표준편차
0     원본    144       0.815    0.992  비정상 119.970
1  1차 차분    143      -2.829    0.054  비정상  33.750
2  2차 차분    142     -16.384    0.000   정상  39.860
3  3차 차분    141      -9.435    0.000   정상  60.980
```

**생각의 로직**: `for i in range(4)` 루프 안에서 **매 반복마다 tmp를 한 번씩 더 차분**해서(`tmp = tmp.diff().dropna()`) 0차(원본)부터 3차 차분까지 순서대로 ADF 검정과 표준편차를 같이 기록한다. 이렇게 "반복하면서 표준편차의 변화를 추적"하는 게 과대차분을 판별하는 표준적인 방법이다.

표를 보면: 표준편차가 119.97 → 33.75(1차) → 39.86(2차) → 60.98(3차)로, **1차에서 최소가 되고 그 뒤로는 오히려 커진다.** 그런데 정작 ADF "판정"은 2차부터 "정상"이 된다 — 이게 바로 **p-value와 표준편차가 서로 다른 신호를 준다는 것**을 보여주는 대목이다. p-value만 보면 "2차 차분이 정상이니 여기서 쓰면 되겠다"고 착각하기 쉽지만, 표준편차 기준으로 보면 이미 1차에서 최소이고 2차부터는 과대차분 구간에 들어선 것이다. (실습에서는 이 문제를 일반차분을 더 반복하는 대신, 다음 단계인 **계절차분**으로 풀어간다 — 즉 "1차 차분에 아직 남은 문제는 추세가 아니라 계절성"이라는 진단으로 이어진다.)

### 3-10. 여러 조합을 한꺼번에 비교 — 최종 파라미터 결정

```python
s = df1["Passengers"]
ls = np.log(s)

combos = {
    "1. 원본":s,
    "2. 1차 차분": s.diff(),
    "3. 2차 차분": s.diff().diff(),
    "4. 로그변환": ls,
    "5. 로그 + 1차 차분": ls.diff(),
    "6. 계절차분(12)": s.diff(12),
    "7. 로그 + 계절 차분(12)":ls.diff(12),
    "8. 로그+ 1차 차분 + 계절차분(12)": ls.diff().diff(12),
}
```

**생각의 로직**: 지금까지 하나씩 따로 해봤던 처리들(차분, 로그, 계절차분)을 **가능한 조합으로 전부 나열**해서 한 번에 비교하는 단계다. `combos`를 딕셔너리로 만든 이유는 "이름: 처리결과" 쌍을 만들어두면 다음 for문에서 이름표를 붙인 채로 결과표를 만들기 편하기 때문이다. 여기서 `ls.diff().diff(12)`처럼 메서드를 체이닝(연쇄 호출)하면 "로그를 취하고 → 1차 차분하고 → 그 결과에 다시 계절차분"이라는 순서로 처리가 겹겹이 쌓인다.

```python
report = [] # ADF 검정 결과를 담을 리스트
```

3. **원본 스케일끼리 비교**: 2차 차분(39.856) vs 계절차분(17.655) → 계절차분이 더 작다. 즉 원본 스케일에서 남아있던 문제의 정체는 "추세"가 아니라 "계절성"이었다는 뜻이다(2차 차분처럼 일반차분을 반복하는 건 잘못된 처방이었다).
4. **그런데 원본 스케일 계절차분(17.655)만으로는 아직 진폭 확대(분산 불안정) 문제가 안 잡힌다** — 애초에 §3-7에서 확인했듯 이 데이터는 로그변환이 필요한 데이터였다.
5. **로그 스케일 조합끼리 비교**: 8번(로그+1차차분+계절차분, 표준편차 0.046)이 5번·7번보다 작고, ADF도 "정상"이다.
6. **최종 결론**: 로그변환(분산 안정) + 일반차분 1회(d=1, 추세 제거) + 계절차분 1회(D=1, s=12, 계절성 제거) 조합이 이 데이터에 필요한 전체 처방이다. 이 조합은 통계학에서 이미 "**항공모형(Airline Model)**"이라는 이름이 붙어있을 만큼 전형적인 사례다.

**정리하면 이 표 하나가 정상성의 3가지 조건(평균/분산/공분산 일정)을 각각 어떤 도구로 풀었는지 한눈에 보여준다**: 분산 문제 → 로그, 평균(추세) 문제 → 일반차분, 계절성(공분산이 시차 12마다 반복되는 패턴) 문제 → 계절차분.

### 4-5. ADF 검정 함수 재정의 + 원본 검정

```python
def adf_test(data, name):
    x = Series(data).dropna()
    stat, pvalue, lag, _, crit, _ = adfuller(x)

    return {
        "대상": name,
        "관측치 수": len(x),
        "검정통계량(ADF)": round(stat, 3),
        "p-value": round(pvalue, 3),
        "사용 시차": lag,
        "1% 기각값": round(crit["1%"], 3),
        "5% 기각값": round(crit["5%"], 3),
        "10% 기각값": round(crit["10%"], 3),
        "판정": "정상" if pvalue < 0.05 else "비정상",
    }
```

**생각의 로직**: 실습에서 만든 함수를 노트북(커널)이 다르므로 그대로 다시 정의한 것 — 로직은 완전히 동일하다. (나중에 이 함수가 계속 반복 정의되는 걸 보면서, §6에서 다룰 "모듈로 승격시켜야 할 신호"를 스스로 캐치할 수 있어야 한다.)

```python

Series(r_origin)
```

**생각의 로직 (이 랩에서 가장 중요한 반전 포인트)**: 원본 데이터 그대로 ADF 검정을 돌렸는데 **p-value가 0.002로, 이미 "정상" 판정이 나온다.** 항공승객 데이터는 원본이 명백히 비정상(p=0.992)이었던 것과 정반대다. 그런데 §4-2의 그래프를 다시 떠올려보면 계절성이 저렇게 뚜렷한데 "정상"이라는 판정이 나온 게 뭔가 이상하게 느껴져야 정상이다 — **바로 이 위화감이 §1-3에서 말한 "ADF는 단위근(추세)만 보고 계절성은 못 잡는다"는 한계를 실제 데이터로 체험하는 순간이다.** 기온은 여름에 올라가도 결국 겨울에 다시 내려와 평균으로 되돌아오는 패턴이라 "정처 없이 떠돌지 않는다"는 의미에서는 ADF 기준 정상이 맞다. 하지만 계절성이라는 반복 구조 자체는 전혀 처리되지 않은 상태다. **여기서 배워야 할 태도는 "p-value 하나만 보고 전처리를 끝내면 안 된다"는 것**이다.

`ls = np.log(s)`는 이 셀에 남아있지만 실제로 combos 안에서는 쓰이지 않는다 — 로그가 안 된다는 걸 확인했음에도 습관적으로 남겨둔 코드로 보이며, 직접 다른 데이터셋에 적용할 때는 애초에 이 줄 자체를 지우거나 조건문으로 감싸는 게 더 안전하다(예: `if (s <= 0).sum() == 0: ls = np.log(s)`).

```python
report = []

for name , x in combos.items() :
    r = adf_test(x, name)
    r["표준편차"] = round(x.dropna().std(),3)
    report.append(r)

DataFrame(report)[["대상", "관측치 수","검정통계량(ADF)", "p-value", "5% 기각값", "표준편차", "판정"]]
```

```
0                1. 원본    602      -3.877    0.002  -2.866 9.932  정상
1             2. 1차 차분    601     -10.529    0.000  -2.866 5.407  정상

3          4. 계절차분(12)    590      -8.829    0.000  -2.867 1.881  정상
4  5. 1차 차분 + 계절차분(12)    589     -10.251    0.000  -2.867 2.371  정상

```

**생각의 로직 — 최종 결론을 도출하는 사고 과정**

여기서 놀라운 점: **5개 조합이 전부 "정상" 판정을 받는다.** 항공승객 데이터에서는 8개 중 3개만 정상이었던 것과 대조적이다. 이게 바로 §2의 "여러 후보가 다 정상이면 p-value만으로는 우열을 가릴 수 없다"는 원칙이 실전에서 그대로 필요해지는 순간이다.

1. **전부 원본과 같은 스케일**(로그를 안 썼으므로 단위가 전부 ℃로 통일되어 있다) → 이번엔 스케일 구분 없이 바로 표준편차만 비교하면 된다.
2. 표준편차를 비교하면: 원본 9.932 → 1차 차분 5.407 → 2차 차분 3.982 → 계절차분(12) **1.881** → 1차차분+계절차분 2.371. **최솟값은 "4. 계절차분(12)" 단독 조합**이다.
3. 즉 일반차분을 추가로 섞는 것(5번)보다 **계절차분 하나만 적용하는 것**이 오히려 표준편차가 더 작다 — 이건 "이 데이터가 가진 비정상성의 정체는 거의 전부 계절성이었지, 추세가 아니었다"는 걸 다시 한번 확인해주는 결과다.
4. **최종 결론**: 로그변환 불필요(애초에 불가능) + 일반차분 0회(d=0, 추세가 거의 없어서 필요 없음) + 계절차분 1회(D=1, s=12, 계절성만 제거하면 충분).

**항공승객과 정반대 결론이 나온 이유를 한 문장으로 요약하면**: 항공승객은 "추세 + 계절성 + 분산 확대"가 전부 섞여 있어서 로그+차분+계절차분이 다 필요했지만, 서울 기온은 애초에 추세가 거의 없고 분산도 안정적이라 오직 계절성만 제거하면 되는, **훨씬 단순한 구조**였다.

## 6. 두 가지 코드 작성 방식 — 이번 랩은 아직 "직접 코딩" 단계

지금까지 LAB-09/10에서는 `my_ols`, `my_logit`처럼 **모듈로 완성된 함수**(`fit_model`, `report_fitness` 등)를 불러와 쓰는 방식이 있었지만, **이번 LAB-11 실습에서는 아직 그런 전용 모듈이 없다.** `from helpers import *`로 여러 모듈을 불러오긴 하지만, 실제로 이번 두 노트북(실습·연습문제)에서 공통으로 쓰인 건 그래프를 그리는 `my_plot` 모듈뿐이고, ADF 검정을 감싸는 `adf_test()` 함수는 **매 노트북마다 똑같이 복붙해서 직접 정의한 로컬 함수**다.

이건 우연이 아니라 자연스러운 단계다. 지금까지 봐온 모듈 확장 패턴을 정리하면:

```
1단계 (지금 이 랩): 통계 함수(adfuller)를 직접 호출 → 결과가 튜플이라 다루기 불편
         → "매번 몇 번째 원소가 뭔지 외울 수 없다" → 감싸는 함수(adf_test)를 노트북 안에 정의
         → 실습 노트북과 연습문제 노트북 양쪽에서 완전히 동일한 함수를 두 번 복붙함
2단계 (다음 랩들에서 벌어질 일): 이 adf_test 같은 함수가 여러 노트북에서 반복되면
         → helpers 패키지 안에 my_ts.py(가칭) 같은 새 모듈을 만들어 이관
3단계: 모듈로 옮긴 뒤에는 직접 정의 대신 `from helpers import my_ts` 하고
         `my_ts.adf_test(...)` 형태로 호출 → 노트북이 짧아지고, 버그 수정도 모듈 한 곳만 고치면 전체에 반영됨
```

**정리하면**: "함수가 이 노트북에만 있고 반복될 조짐이 보이면 아직 직접 코딩 단계, 여러 랩(혹은 이번처럼 실습·연습문제)에서 똑같은 함수를 계속 복붙하고 있다면 그게 모듈로 옮길 신호"라고 판단하면 된다. 실제로 이번 두 노트북에서 `adf_test()`가 토씨 하나 안 틀리고 그대로 두 번 등장했다는 것 자체가 "지금이 딱 모듈로 승격시킬 타이밍"이라는 신호다. 지금까지 `my_ols`, `my_logit`이 만들어진 과정도 정확히 이 패턴이었다 — 처음엔 노트북 안에 직접 코딩하고, 검증하고 반복해서 쓰다가, 안정화되면 모듈 함수로 승격시켰다.

이 랩에서 **"직접 코드에 쓰는 것"과 "모듈을 불러와 쓰는 것"의 경계선**을 판단하는 기준은 다음과 같다:
- 이 노트북 안에서만 쓰이고 아직 검증 중인 로직 → 직접 코딩 (지금의 `adf_test`)
- 여러 노트북/여러 데이터셋에서 반복적으로 필요하고 안정된 로직 → 모듈 함수 (지금의 `my_plot.lineplot`, `my_plot.init`)

## 7. 자주 틀리는 함정 총정리

| 함정 | 왜 틀렸는가 | 올바른 판단 |
|---|---|---|
| p-value가 0.05를 못 넘으면 무조건 차분을 한번 더 한다 | 과대차분을 유발 — 표준편차가 오히려 커짐(노이즈 생성) | 표준편차가 최소가 되는 차수를 넘기지 않는다 |
| ADF가 "정상"이라 나오면 전처리 끝이다 | ADF는 단위근(추세)만 본다. 계절성은 못 잡는다(서울기온 원본이 그 실제 사례) | 그래프로 계절성 잔존 여부를 반드시 별도 확인 |
| 분산 문제(조건②)를 차분으로, 추세 문제(조건①)를 로그변환으로 처리 | 서로 다른 문제에 서로 다른 도구가 필요 | 분산→변환(로그), 추세→차분 매칭을 지킨다 |
| 로그변환은 데이터가 크면 아무데나 쓸 수 있다 | 로그는 0 이하 값에서 정의되지 않는다(서울기온에 영하 90개월 존재) | 적용 전 `(data <= 0).sum()`으로 반드시 확인 |
| 여러 조합을 비교할 때 표준편차가 제일 작은 걸 무조건 고른다 | 원본 스케일과 로그 스케일의 표준편차는 단위가 달라 직접 비교 불가 | 같은 스케일끼리 묶어서 비교한 뒤, 그중 정상성 조건을 다 만족하는 스케일을 고른다 |
| 코드 구조가 같으니 모든 데이터셋에 로그변환도 습관적으로 적용한다 | 데이터 진단(0 이하 값 존재 여부)에 따라 적용 가능 여부가 갈린다 | 진단 결과에 따라 combos에 넣을 조합 자체를 다르게 설계 |

### 9-3. ADF 검정 함수 — 그대로 복붙해서 계속 재사용

```python
def adf_test(data, name):
    x = Series(data).dropna()
    stat, pvalue, lag, _, crit, _ = adfuller(x)
    return {
        "대상": name, "관측치 수": len(x),
        "검정통계량(ADF)": round(stat, 3), "p-value": round(pvalue, 3),
        "사용 시차": lag,
        "1% 기각값": round(crit["1%"], 3), "5% 기각값": round(crit["5%"], 3),
        "10% 기각값": round(crit["10%"], 3),
        "판정": "정상" if pvalue < 0.05 else "비정상",
    }

r_origin = adf_test(df1["타겟컬럼"], "원본")
Series(r_origin)
```

```python
    r = adf_test(tmp, f"{i}차 차분" if i > 0 else "원본")
    r["표준편차"] = round(tmp.std(), 2)
    over_diff.append(r)
    tmp = tmp.diff().dropna()
DataFrame(over_diff)[["대상", "관측치 수", "검정통계량(ADF)", "p-value", "판정", "표준편차"]]
```
