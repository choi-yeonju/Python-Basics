## 0. 오늘 배운 것 한눈에 요약

- `lmplot`: 산점도 + 회귀선을 **figure 단위**로 그리는 함수. `hue`, `col`, `row`로 범주별/성별 분할 가능.
- `pairplot`: 여러 변수를 **행렬 형태**로 한 번에 다 조합해서 산점도 매트릭스를 그리는 함수. 대각선은 분포(hist/kde).
- 이 둘은 `scatterplot`, `boxplot` 같은 axes-level 함수랑 근본적으로 다르게 동작함 (아래 1-4 참고).
- 오늘 코드는 항상 **"raw seaborn으로 직접 코딩" → "my_plot 모듈 함수로 재현"** 두 버전이 세트로 나옴. 이 흐름 자체가 오늘 배운 핵심 작업 방식임.

## 1. 핵심 개념

### 1-1. lmplot이란

- `sb.lmplot(data, x, y, ...)` : 산점도(scatter) + 선형회귀선(regression line)을 같이 그려주는 함수.
- **figure-level 함수**다. 즉 `plt.subplots()`로 만든 `ax`에 그리는 게 아니라, 자기가 알아서 새 Figure를 만들어버림.
  → 그래서 사이즈 지정 방식이 `width`, `height`가 아니라 `height`(그래프 1개 높이) + `aspect`(가로/세로 비율)로 지정됨. 이게 오늘 계속 나온 "사이즈 지정 방식이 독특하다"는 부분.
- 결과로 `g`라는 **FacetGrid 객체**가 반환됨. 여기서 실제 그림 조작하려면:
  - `g.fig` → figure 객체 (dpi, suptitle 설정할 때 씀)
  - `g.axes.flatten()` → 내부의 ax들을 1차원 리스트로 꺼냄 (col/row로 나뉘면 ax가 여러 개라 이렇게 꺼내야 함)

### 1-2. pairplot이란

- `sb.pairplot(data, ...)` : 데이터의 **모든 수치형 변수 조합**을 자동으로 산점도 매트릭스로 그려줌.
- 대각선(자기 자신과의 조합)은 산점도 대신 분포 그래프(`diag_kind='hist'` 또는 `'kde'`)로 채워짐.
- 이것도 figure-level 함수라 `g.fig`, `g.axes.flatten()` 패턴 똑같이 적용됨.
- `x_vars`, `y_vars`를 지정하면 전체 조합이 아니라 **원하는 변수만 선택**해서 그릴 수 있음 (변수 많을 때 유용).

### 1-3. scatter_kws / line_kws 구조 (lmplot)

```python
sb.lmplot(..., 
    scatter_kws={"edgecolor": "...", "s": 50, "alpha": 0.8},
    line_kws={"color": "...", "linestyle": "--", "linewidth": 2}
)
```

- 점 스타일은 `scatter_kws`, 회귀선 스타일은 `line_kws`에 딕셔너리로 몰아넣는 구조.
- `hue`로 범주를 나누면 팔레트가 색을 자동 배정하니까 `scatter_kws`/`line_kws` 안에 **color를 따로 지정하면 안 됨** (충돌남 → 오늘 코드에서도 hue 쓸 때는 color 키를 뺐음).

### 1-4. pairplot에서 회귀선 켤 때 구조가 바뀌는 거 (중요, 헷갈리기 쉬움)

- 기본 pairplot(`kind='scatter'`, 기본값)일 때: `plot_kws={"s":30, "alpha":0.7}` 처럼 **평평하게** 씀.
- `kind='reg'`로 회귀선을 켜는 순간, seaborn 내부적으로 lmplot이랑 똑같은 로직을 타서 **`plot_kws` 안에 다시 `scatter_kws`, `line_kws`를 중첩**해야 함:

```python
plot_kws={
    'scatter_kws': {'s':15, 'alpha':0.5},
    'line_kws': {'linewidth':2, 'linestyle':'--'}
}
```

→ **"kind이 바뀌면 옵션을 넣는 계층 구조도 바뀐다"** 는 걸 기억하고 있어야 나중에 에러 안 남. (`my_plot.pairplot` 함수 안에서도 `reg=True`일 때만 이 중첩 구조로 분기시켜 놓은 게 그 이유임 — 아래 6장 참고)

## 2. 두 가지 코딩 버전: "직접 코딩" vs "모듈 호출"

오늘 노트북 구조를 보면 매 주제마다 항상 이 순서로 진행됨:

```
1) sb.lmplot(...) 직접 다 풀어서 코딩  →  작동 확인, 옵션 하나씩 실험
2) my_plot.lmplot(...) 모듈 함수 호출  →  같은 결과를 한 줄로 재현
```

### 왜 이렇게 두 버전을 다 하는가?

| 단계                    | 목적                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 직접 코딩 (raw seaborn) | seaborn 옵션이 실제로 어떻게 동작하는지, 각 파라미터가 뭘 바꾸는지**몸으로 이해**하기 위함. 여기서 에러 나면 seaborn 자체 문법 문제라서 디버깅이 쉬움. |
| 모듈 호출 (my_plot)     | 이해가 끝난 로직을**재사용 가능한 형태로 봉인**. 다음 프로젝트에서 이 옵션 조합을 또 짤 필요 없이 함수 호출 한 줄로 끝냄.                              |

즉 순서가 뒤집히면 안 됨. **직접 코딩으로 원리를 확인 → 모듈로 캡슐화**가 맞는 순서고, 원리를 모른 채 모듈부터 만들면 나중에 모듈이 안 될 때 왜 안 되는지 못 찾음.

### 코드 구조 비교

```python
# 버전 1: 직접 코딩 (raw seaborn) - 5단계를 매번 손으로 다 함
g = sb.lmplot(data=origin, x=..., y=..., height=height, aspect=width/height, ...)
g.fig.set_dpi(my_dpi)
g.fig.set_tight_layout(True)
g.fig.suptitle(...)
ax = g.axes.flatten()
ax[0].set_xlabel(...); ax[0].set_ylabel(...); ax[0].grid(True, alpha=0.5)
my_plot.show()

# 버전 2: 모듈 호출 - 위 5단계가 함수 안에 이미 다 들어있음
my_plot.lmplot(data=origin, x=..., y=..., title=..., xlabel=..., ylabel=...,
               markers="^", scatter_edgecolor="#000000", ...)
```

→ 모듈 함수 안에는 `g.fig.set_dpi()`, `suptitle`, `grid`, `show()` 호출까지 **다 이미 박혀 있음**. 그래서 호출부는 "무엇을 그릴지"만 신경 쓰면 됨 ("어떻게 화면에 띄울지"는 모듈이 책임짐).

## 3. my_plot 모듈, 왜 만들고 어떻게 사고해야 하나

### 3-1. 모듈화의 목적

- **반복 제거**: `init()` → 그리기 → `dpi/suptitle/grid 설정` → `show()` 이 5단계는 그래프 종류가 달라도 항상 똑같이 반복됨. 이걸 매번 손으로 치면 실수(오타, 빠뜨림)가 생김.
- **일관성**: 프로젝트 전체에서 폰트 크기, 그리드 스타일, 제목 위치가 항상 똑같이 나옴 (한 군데서 관리하니까).
- **재사용**: 나중에 Olist 프로젝트든 새 데이터셋이든, `my_plot.lmplot(data=새데이터, x=..., y=...)` 한 줄로 끝남.

### 3-2. 뼈대 구조: `init()` + `show()`

- `init(width, height, rows, cols, title, xlabel, ylabel, grid, twinx)` : figure/ax를 만들고 사이즈·dpi·제목·그리드를 세팅해서 반환.
- `show(save_path)` : `tight_layout()` → `plt.show()` → `plt.close()` 까지 마무리.
- **모든 그래프 함수(`lineplot`, `histplot`, `boxplot`, `barplot`, `scatterplot` 등)가 이 두 함수를 공통으로 씀.** 이게 모듈의 핵심 설계임.

### 3-3. 반복되는 함수 설계 패턴 (이거 이해하면 새 함수 추가할 때 그대로 따라 하면 됨)

```python
def 어떤plot(data, x, y, ..., ax=None):
    fig = None
    if ax is None:
        fig, ax = init(width=width, height=height, title=title, xlabel=xlabel, ylabel=ylabel)

    sb.어떤plot(data=data, x=x, y=y, ..., ax=ax)   # 실제 그리기는 seaborn에 위임

    if fig is not None:
        show(save_path=save_path)
```

왜 이렇게 짜는지가 중요함:

- `ax=None`이 기본값 → **혼자 단독으로 호출되면** 알아서 `init()`으로 새 figure를 만들고 끝나면 `show()`까지 해줌.
- 근데 **누가 `ax`를 넘겨주면** (예: 여러 그래프를 한 화면에 subplot으로 합칠 때) 새로 만들지 않고 **그 ax에 얹어서 그리기만** 함. `show()`도 호출 안 함 (바깥에서 한 번에 보여줄 거니까).
- → 이 패턴 덕분에 함수 하나로 "단독 사용"과 "여러 개 조합해서 서브플롯 구성"을 둘 다 지원함. **이게 재사용성 확장의 핵심 아이디어**임. 새 그래프 타입 추가할 때도 이 패턴 그대로 베끼면 됨.

### 3-4. lmplot / pairplot은 왜 이 패턴을 못 따르나 (예외)

- `init()`은 `plt.subplots()` 기반(axes-level)인데, `lmplot`/`pairplot`은 자기가 알아서 Figure를 새로 만드는 **figure-level** 함수라서 `ax`를 미리 받아서 꽂을 수가 없음.
- 그래서 `my_plot.lmplot()`, `my_plot.pairplot()`은 `ax=None` 분기 없이 **항상 자체적으로 그리고 항상 `show()`까지 호출**하는 구조로 따로 짜여 있음.
- **기억할 점**: 새 함수를 모듈에 추가할 때, 그게 axes-level 함수(scatterplot, boxplot 등)인지 figure-level 함수(lmplot, pairplot, catplot, jointplot 등)인지부터 먼저 확인해야 함. 이거에 따라 함수 설계 패턴이 달라짐.

### 3-5. 파라미터 설계 원칙

- seaborn 원래 파라미터명을 최대한 그대로 씀 (`hue`, `palette`, `markers` 등) → seaborn 문서 그대로 재사용 가능, 새로 외울 필요 없음.
- 다만 중첩된 `scatter_kws={"edgecolor":..., "s":...}` 같은 건 `scatter_edgecolor`, `scatter_size` 처럼 **평평하게(flatten) 풀어서** 노출시킴 → 호출할 때 딕셔너리 문법 안 써도 되게 편의성을 높인 것.
- 조건부 무효화 로직도 넣어둠: `if not hue and palette: palette=None` → hue 없이 palette만 준 무의미한 조합을 자동으로 정리해줌 (사용자 실수 방지).

## 4. 분석 순서 (Workflow) — "처음부터 끝까지 다 코딩"이 아니라 이렇게 진행

절대 한 번에 완성형 코드를 안 짬. 아래 순서로 **작게 쪼개서 매번 확인하면서** 감:

1. **데이터 로드 후 원본 그대로 확인** — `origin = load_data(...)`, `origin` 찍어서 컬럼/타입/결측 확인.
2. **raw seaborn으로 제일 기본 형태부터** — 옵션 없이 `sb.lmplot(data=origin, x=.., y=..)` 그냥 그려서 **일단 작동하는지**부터 확인. (이 단계에서 사이즈 지정 안 해도 됨 — 나중에 붙임)
3. **사이즈/해상도 세팅 추가** — `height`, `aspect`, `dpi` 붙여서 화면에 보기 좋게.
4. **스타일 옵션 하나씩 추가** — 마커 모양 → 색상 → `scatter_kws`/`line_kws` 순으로 하나 넣고 확인, 또 하나 넣고 확인. 한 번에 다 넣고 에러 나면 뭐가 문제인지 못 찾음.
5. **범주(hue) 추가** — 마커 개수를 범주 개수와 맞추는 것부터 체크 (`markers=["s","o","D"]` 개수 ≠ species 개수면 에러).
6. **분할(col/row) 추가** — `col='sex'` 등으로 패싯 나누기. 이때부터 `ax`가 여러 개가 되므로 `for a in ax:` 반복문으로 라벨/범례/그리드를 일괄 적용.
7. **여기까지 확인된 로직을 my_plot 모듈 함수로 옮기기** — 직접 짠 코드에서 어떤 파라미터가 필요했는지 정리해서 함수 시그니처(파라미터 목록) 설계.
8. **모듈 함수 호출로 똑같이 재현되는지 검증** — `my_plot.lmplot(...)` 호출했을 때 3~6 단계와 동일한 그림이 나오는지 눈으로 비교.
9. **다른 데이터셋(연습문제)에 적용해서 일반화 검증** — `city_districts`, `city_stats` 처럼 컬럼명만 다른 새 데이터에 그대로 함수를 돌려서, 함수가 특정 데이터에만 종속되지 않고 진짜 범용인지 확인.

> 이 9단계가 오늘 노트북 전체의 실제 흐름이었음. "완성 코드"를 처음부터 쓰는 게 아니라, **작게 확인 → 옵션 추가 → 또 확인**을 반복하다가 마지막에 모듈로 정리하는 구조.

## 5. lmplot 상세 문법 정리

```python
g = sb.lmplot(
    data=origin, x='bill_length_mm', y='bill_depth_mm',
    height=height,            # 그래프 1개의 세로 높이(inch)
    aspect=width/height,      # 가로세로 비율 (aspect * height = 가로 크기)
    hue='species',            # 범주별 색상 구분
    col='sex',                # 열 방향으로 패싯 분할 (row도 동일 원리)
    legend=False,             # 자동 범례 끄기 (겹치는 문제 있어서 수동으로 위치 지정 권장)
    markers=["s","o","D"],    # 마커 모양 리스트 — 개수는 hue 범주 수와 반드시 일치
    palette="Set2",           # 색상 팔레트
    scatter_kws={"edgecolor":"#000000","linewidths":1,"s":50,"alpha":0.8},
    line_kws={"linestyle":"--","linewidth":2}
)
g.fig.set_dpi(200)
g.fig.set_tight_layout(True)
g.fig.suptitle('제목', fontsize=24, fontweight=500, y=1)

ax = g.axes.flatten()          # col/row로 나뉘면 ax가 여러개 → 리스트로 순회
for a in ax:
    a.set_xlabel('...'); a.set_ylabel('...')
    a.legend(bbox_to_anchor=(1,1), loc='upper left')
    a.grid(True, alpha=0.5)

my_plot.show()
```

**주의할 점 정리**

- hue 쓸 때 `scatter_kws`/`line_kws`에 색상(color) 키를 넣으면 palette와 충돌 → 색상 관련 키는 빼야 함.
- `markers` 리스트 길이는 반드시 hue 범주 개수와 같아야 함 (안 그러면 ValueError).
- `col`/`row`로 나누면 `ax`가 배열이 되므로 `ax[0]` 하나만 만지지 말고 `for` 반복문으로 전체를 처리해야 함.

## 6. pairplot 상세 문법 정리

```python
g = sb.pairplot(
    origin,
    hue='species', markers=['o','s','^'], palette='cool',
    diag_kind='kde',           # 대각선: 'hist' 또는 'kde'
    kind='reg',                # 'scatter'(기본) 또는 'reg'(회귀선)
    plot_kws={                 # kind='reg'일 때만 이 중첩 구조 사용 (5-4 참고)
        'scatter_kws': {'s':15, 'alpha':0.5},
        'line_kws': {'linewidth':2, 'linestyle':'--'}
    },
    x_vars=["bill_length_mm","bill_depth_mm"],  # 선택적으로 일부 변수만
    y_vars=["bill_length_mm","bill_depth_mm"]
)
g.fig.set_dpi(200)
g.fig.set_figwidth(...); g.fig.set_figheight(...)
g.fig.suptitle('제목', fontsize=16, fontweight='bold')

for ax in g.axes.flatten():
    ax.set_axisbelow(True)
    ax.grid(True, alpha=0.5)
```

**주의할 점 정리**

- `kind='scatter'`(기본)일 땐 `plot_kws`가 평평한 딕셔너리, `kind='reg'`일 땐 `scatter_kws`/`line_kws`로 다시 중첩 — **kind 바뀌면 옵션 구조도 바뀐다**는 걸 꼭 기억.
- 변수가 너무 많으면 매트릭스가 커져서 느려짐 → `x_vars`/`y_vars`로 관심 있는 것만 추려서 그리는 습관 들이기.

## 7. my_plot.lmplot() / my_plot.pairplot() 사용법 요약

```python
# lmplot
my_plot.lmplot(
    data=origin, x='bill_length_mm', y='bill_depth_mm',
    title='...', xlabel='...', ylabel='...',
    hue='species', palette="Set2", col="sex",
    markers=["s","o","D"],
    scatter_edgecolor="#000000", scatter_linewidths=1, scatter_size=50,
    linestyle="--", linecolor="#0066ff", linewidth=2
)

# pairplot
my_plot.pairplot(
    data=origin, hue='species', reg=True, diag_kind='kde',
    title="...", width=1600, height=1200,
    markers=['o','s','^'], palette='Set2',
    scatter_size=5, scatter_alpha=0.7,
    linecolor='#0066ff', linewidth=1, linestyle='--'
)
```

- 호출부는 raw seaborn 버전보다 훨씬 짧고, "무엇을 그릴지"에만 집중하면 됨.
- 내부적으로 `dpi 설정 → suptitle → grid 반복 적용 → show()` 를 함수가 대신 다 해줌.

---

## 8. 알아둘 버그/이슈 노트

- `markers` 인자에 문자열 하나(`"^"`)를 줄 때와 리스트(`["s","o","D"]`)를 줄 때는 상황이 다름: hue 없을 땐 문자열 하나, hue 있을 땐 범주 수만큼 리스트로.
- `lmplot`/`pairplot`은 다른 함수들과 다르게 `ax=None` 파라미터가 없음 (3-4 참고) — 다른 함수 쓰듯 `ax`를 넘기려고 하면 안 됨.

---

## 9. 다른 데이터셋에 적용할 때 체크리스트

새 데이터셋(`city_districts`, `city_stats`, 혹은 나중에 Olist/무신사 데이터) 붙일 때 이 순서로 점검:

1. `x`, `y`로 쓸 컬럼이 **수치형**인지 확인 (`origin.dtypes`).
2. `hue`로 쓸 컬럼의 **범주 개수**를 먼저 세어봄 (`origin['컬럼'].nunique()`) → `markers` 리스트 길이를 여기에 맞춤.
3. 결측치가 있으면 seaborn이 알아서 빼고 그리긴 하지만, 회귀선(`reg=True`) 쓸 때는 결측 많으면 왜곡될 수 있으니 먼저 `isnull().sum()` 확인.
4. 컬럼 수가 많으면 `pairplot`은 무조건 `x_vars`/`y_vars`로 관심 변수만 골라서 그리기 (안 그러면 매트릭스 폭발).
5. 축 라벨(`xlabel`, `ylabel`)은 한글로 바꿔서 넘기기 — 컬럼명이 영어/코드성이면 그대로 쓰지 말고 사람이 읽을 이름으로.
6. 이 모든 걸 raw seaborn으로 먼저 1~2번 확인 후, 확실해지면 `my_plot` 함수 호출로 전환.

## 10. 앞으로 모듈을 확장할 때 사고 순서

새로운 그래프 타입(예: `jointplot`, `catplot`, `regplot`)을 `my_plot`에 추가하고 싶을 때, 이 순서로 생각하면 됨:

1. **이게 axes-level인지 figure-level인지 먼저 확인** (seaborn 공식 문서에 명시돼 있음). 이거에 따라 3-3 패턴을 쓸지, lmplot/pairplot처럼 예외 패턴을 쓸지 결정됨.
2. raw seaborn으로 원하는 결과가 나올 때까지 **직접 코딩으로 먼저 실험** (2장, 4장 순서 그대로).
3. 실험하면서 "이 옵션은 항상 이 값으로 고정해도 되겠다" 싶은 건 함수 내부 기본값으로, "매번 바뀔 것 같다" 싶은 건 파라미터로 노출.
4. 중첩 딕셔너리(`scatter_kws` 같은 것)가 있으면 3-3 원칙대로 **평평하게 풀어서** 파라미터명 짓기 (`scatter_size`, `scatter_alpha` 식).
5. `init()`/`show()`를 재사용할 수 있는 구조면 그대로 가져다 쓰고, 안 되면(figure-level) 왜 안 되는지 이유를 주석으로 남겨두기.
6. 함수 다 짜면 **최소 2개 이상의 다른 데이터셋**으로 테스트해서 특정 데이터에만 맞춰진 하드코딩이 없는지 확인.
7. docstring(Args 설명)까지 다 채워 넣기 — 나중에 본인이 봐도 바로 쓸 수 있게.
