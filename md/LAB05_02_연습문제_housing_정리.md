# 데이터 품질 검사(EDA Quality Check) 기본기 정리

> 실습: LAB-05 Housing Dataset
> 이 문서는 **"매번 새 데이터셋 받으면 이 순서대로 돌린다"** 는 체크리스트 겸 개념노트임.
> 나중에 Olist든 뭐든 새 프로젝트 시작할 때 그대로 재활용할 것.

---

## 0. 왜 이 순서가 중요한가

품질 검사는 **뒤 단계가 앞 단계 결과에 의존하는 구조**라서 순서를 바꾸면 안 됨.

```
자료형 점검 → 중복 제거 → 결측치 확인 → (정제본 저장) → 기술통계 → 인사이트 도출
```

- 자료형이 잘못된 채로 중복 검사하면 `"yes"`랑 `"Yes"`를 다른 값으로 취급하는 등 오탐 발생 가능
- 중복 제거 전에 통계 내면 평균/표준편차가 왜곡됨
- 결측치 확인 전에 통계 내면 결측 포함 여부에 따라 수치 자체가 달라짐

**즉, "정제 → 확정본 저장 → 그 확정본으로만 통계/분석" 이 원칙.**
확정본을 저장해두는 이유도 이거임 — 이후 통계·시각화·모델링 전부 이 파일 기준으로 재현 가능하게 하기 위함.

---

## 1. 자료형 점검 (`info()`, 타입 변환)

### 개념
- pandas가 자동으로 읽어들인 타입(`int64`, `object` 등)이 **의미상 맞는 타입인지** 확인하는 단계.
- 특히 `yes/no`, `male/female`처럼 **범주형인데 문자열(object)로 저장된 컬럼**을 찾아서 `category`로 변환.

### Why category로 바꾸나?
- `yes/no`는 숫자가 아니라 **이진 범주(binary categorical)**. 산술 연산 대상이 아님.
- `category` 타입으로 바꾸면:
  - 메모리 절약 (문자열 반복 저장 안 함)
  - `groupby`, `value_counts` 등에서 의미상 명확하게 처리됨
  - 이후 모델링 단계에서 `yes=1, no=0` 인코딩이나 더미변수 변환할 때 대상이 명확해짐

> 📌 재사용 포인트: 데이터 받으면 제일 먼저 `info()` 찍고, **"숫자처럼 보이지만 실제론 범주인 컬럼"** 부터 골라내는 습관 들이기. (0/1로 인코딩된 범주형 컬럼도 여기 해당될 수 있음 — 숫자 타입이라고 무조건 연속형 아님)

---

## 2. 중복 검사 (`duplicated()`)

### 개념
- 행 전체가 완전히 동일한 레코드가 있는지 확인.
- 중복이 있으면 특정 값의 비중이 부풀려져서 통계·모델 결과가 왜곡됨.

### Why 자료형 변환 다음에 하나?
- 타입이 안 맞으면 (예: 같은 값인데 `"1"`과 `1`) 실제로는 중복인데 다르게 인식될 수 있음.

> 📌 재사용 포인트: 중복 0건이어도 "확인했다"는 근거를 남겨야 함 (인사이트 문서에 "중복 0건 확인" 한 줄 남기는 습관).

---

## 3. 결측치 점검 (`check_missing_values`)

### 개념
- 컬럼별 결측치 개수/비율 확인.
- 이번 실습은 결측 0건이었지만, 있었다면 대응 전략이 갈림:
  - 결측 비율 낮음 → 행 삭제 or 대표값(평균/중앙값/최빈값) 대체
  - 결측 비율 높음 → 컬럼 자체를 버리거나, 결측 여부를 새로운 범주(`"결측"`)로 만드는 것도 방법
  - 결측 패턴이 랜덤이 아니라 특정 조건에서만 발생 → 그 자체가 인사이트일 수 있음 (예: 특정 지역만 배송 데이터 결측 등)

> 📌 재사용 포인트: "결측치 있음/없음"만 보지 말고, **결측이 왜 발생했는지 패턴을 의심**하는 습관. Olist 프로젝트처럼 관측기간(observation window) 이슈랑도 연결될 수 있음.

---

## 4. 품질 검사 결과 저장

### 개념
- 위 1~3단계를 거친 **정제된 데이터프레임을 별도 파일로 저장** (`housing_qtcheck.xlsx`).

### Why 저장하나?
- 원본(origin)은 절대 건드리지 않고 보존 → 재현성 확보
- 이후 통계/시각화/모델링은 전부 이 "정제본" 기준으로 진행 → 중간에 다시 품질 검사 반복 안 해도 됨
- 팀 프로젝트나 나중에 다시 열어볼 때, "이게 정제된 버전이다"라는 게 파일명으로 명확해짐

> 📌 재사용 포인트: 파일명 규칙을 `원본명_qtcheck.xlsx` 처럼 일관되게 가져가기. Olist처럼 테이블 여러 개일 땐 특히 중요.

## 5. 기술 통계량 (명목형 / 연속형 나눠서)

### 개념
- **명목형(범주형)**: `value_counts()` 기반 — 각 범주의 빈도, 비율
- **연속형(수치형)**: `describe()` 기반 — 평균, 중앙값, 표준편차, 최소/최대, 분위수 + **왜도(skewness)**

### Why 나눠서 봐야 하나?
- 평균/표준편차는 연속형에만 의미 있음. 범주형에 평균 내면 무의미한 숫자가 나옴.
- 반대로 범주형은 "각 값이 몇 번 나왔는지" 빈도가 핵심 정보.

### 📊 분포 판단 핵심 공식 — 평균 vs 중앙값 vs 왜도

| 상황 | 평균-중앙값 관계 | 왜도(skew) | 분포 형태 |
|---|---|---|---|
| 대칭 | 평균 ≈ 중앙값 | ≈ 0 | 정규분포에 가까움 |
| 우편향(right-skewed) | 평균 > 중앙값 | skew > 0 (보통 >1이면 강함) | 오른쪽 꼬리 김 (고가/이상치가 평균을 끌어올림) |
| 좌편향(left-skewed) | 평균 < 중앙값 | skew < 0 | 왼쪽 꼬리 김 |

- 이번 실습: `price`(왜도 1.212), `area`(왜도 1.321) 둘 다 우편향
- **우편향 + 왜도 > 1 → 로그 변환(`log1p`) 검토 대상**으로 판정하는 게 기준

> 📌 재사용 포인트: 새 연속형 변수 볼 때마다 "평균 vs 중앙값 비교 → 왜도 확인 → 로그변환 필요 여부 판단" 이 3단계를 세트로 돌리기. 회귀분석 앞두고 있으면 특히 중요 (Olist OLS 작업이랑 바로 연결됨).

## 6. 이상치 경계 — IQR(사분위범위) 방법

### 개념 & 공식
```
Q1 = 25% 지점, Q3 = 75% 지점
IQR = Q3 - Q1

하한 = Q1 - 1.5 × IQR
상한 = Q3 + 1.5 × IQR

하한보다 작거나 상한보다 크면 → 이상치(outlier)
```

### Why 1.5배인가?
- 통계적 관행(convention)임. 정규분포 가정 시 대략 상하위 약 0.7% 정도를 이상치로 잡는 효과.
- 강하게 잡고 싶으면 3×IQR, 느슨하게 잡고 싶으면 1.5×IQR — 상황에 따라 조절 가능.

### 이번 실습에서 나온 것 중 눈여겨볼 점
- `stories`: 상한 초과 **7.52%**로 다른 변수(2%대)보다 훨씬 높음
  → IQR 방법이 항상 정답은 아니고, **변수 특성(층수처럼 이산적/범위 좁은 변수)에 따라 과탐지 될 수 있음**을 보여주는 사례
- `bedrooms`, `bathrooms`, `parking`처럼 **정수 카운트형 변수**는 IQR 이상치 판단이 실제 "이상함"과 다를 수 있음 → 기계적으로 제거하지 말고 도메인 지식으로 재검토 필요

> 📌 재사용 포인트: IQR로 이상치 "탐지"까지는 자동화하되, "제거할지 말지"는 변수 성격 보고 판단. 특히 이산형(층수, 방 개수 등)은 주의.

## 7. 인사이트 도출 — 숫자를 "그래서 뭐?"로 연결하기

이번 실습에서 좋았던 흐름은 통계값 나열에서 끝내지 않고 **비교 → 해석 → 비즈니스 시사점**까지 간 것:

```
airconditioning=yes 집단 평균가격 vs no 집단 평균가격
→ yes가 43.45% 더 비쌈
→ "시설 보유 여부가 가격 프리미엄에 유의미한 영향" 이라는 결론
```

> 📌 재사용 포인트: 범주형 변수 나오면 **"이 범주에 따라 타깃(가격/구매여부 등) 평균이 갈리는가"** 를 습관적으로 체크. Olist 프로젝트에서 카테고리별(소모성/준소모성/내구재) 재구매율 차이 보는 것도 같은 논리임.

## 8. 다음 프로젝트 시작할 때 그대로 쓸 체크리스트

- [ ] `info()`로 타입 확인 → 범주형인데 object/int로 잘못 읽힌 컬럼 category 변환
- [ ] `duplicated()`로 중복 확인 및 제거
- [ ] 결측치 확인 → 있으면 발생 원인/패턴부터 의심
- [ ] 정제본 별도 저장 (`원본명_qtcheck.xlsx`), 원본은 보존
- [ ] 명목형/연속형 나눠서 기술통계
- [ ] 연속형 변수마다: 평균 vs 중앙값, 왜도 → 로그변환 필요 여부 판단
- [ ] IQR로 이상치 경계 계산 → 이산형 변수는 기계적 제거 금지, 도메인 판단
- [ ] 범주형 변수 있으면 타깃 변수와의 평균 차이 비교 → 비즈니스 해석까지 연결

## 한 줄 요약
**"정제 → 저장 → 그 저장본으로만 통계·분석"** 이라는 재현성 원칙과,
**"평균-중앙값-왜도 세트로 분포 판단, IQR로 이상치는 탐지만 하고 제거는 도메인 판단"** 이라는 통계 원칙,
이 두 개가 이번 LAB-05의 핵심 기본기임.
