## 0. 전체 파이프라인 한눈에 보기

```
[정제 단계 — Clean]                          [이해 단계 — Understand]
데이터 로드
  ↓
① 자료형 점검/변환 (set_type)
  ↓
② 중복 점검 (check_duplicates)
  ↓
③ 형식·표기·단위 점검 (value_counts, min/max)
  ↓
④ 결측치 점검 (check_missing_values)
  ↓
⑤ 품질검사 결과 저장 (to_excel)               ← 정제 끝, 여기서 스냅샷
─────────────────────────────────────────────
  ↓ (새 노트북에서 이어서 시작해도 됨)
⑥ 기술 통계량 (categorical_summary / numerical_summary)
  ↓
⑦ 중심 수준 파악 (평균 vs 중앙값 → rel_diff)
  ↓
⑧ 이상치 신호 감지 (IQR)
  ↓
⑨ 비대칭 신호 확인 (왜도/첨도 → 로그변환 판정)
  ↓
⑩ 인사이트 도출 (숫자 → "그래서 뭐?")
```

### 왜 이 순서를 지켜야 하는가 (원리)

**뒤 단계가 앞 단계의 전제조건에 의존하는 구조라서 순서를 바꾸면 결과 자체가 틀어짐.**

- ①을 안 하면(자료형 변환 전) → `numerical_summary`/`categorical_summary` 같은 함수가 컬럼을 엉뚱하게 분류함. 예: `cut`이 아직 object면 범주형 요약에서 통째로 빠짐.
- ②를 ①보다 먼저 하면 → `"1"`(문자열)과 `1`(숫자)이 같은 값인데 다른 것으로 인식돼서 중복 탐지 실패.
- ②를 안 하고 통계 내면 → 중복 행 때문에 평균·분산·`value_counts` 전부 특정 값 쪽으로 과대 반영 (왜곡).
- ④(결측치)를 확인 안 하고 넘어가면 → 이후 통계량이 결측 포함/미포함 여부에 따라 수치 자체가 달라짐.
- ⑤(저장)을 안 하면 → 원본을 계속 건드리게 되거나, 정제 과정을 매번 반복해야 함 (재현성 붕괴).

**즉 핵심 원칙 한 줄: "정제(①~④) → 확정본 저장(⑤) → 그 확정본으로만 통계·분석(⑥~⑩)"**

## 1. 원본 보존 원칙 (pandas 핵심 개념 재확인)

> 이미 알고 있는 내용이지만, 이 파이프라인 전체를 관통하는 원칙이라 다시 정리:

`astype`, `drop`, `rename`, `drop_duplicates` 등 대부분의 pandas 메서드는 **원본을 바꾸지 않고 새 객체를 반환**함. 그래서 이 파이프라인은 항상:

```python
df1 = origin.copy()          # 원본 절대 안 건드림
df1["X"] = df1["X"].astype("category")   # 반드시 재할당

df2 = df1.drop_duplicates()  # df1도 그대로 살아있음, df2가 새 결과
```

이렇게 **단계마다 새 변수(`df1`, `df2`, `df3`...)로 순차 저장**하는 이유:

- 원본(`origin`)은 언제든 다시 참조 가능
- 어느 단계에서 문제가 생겼는지 역추적 가능
- `inplace=True`를 쓰면 이 추적성이 사라지므로, 품질검사 단계에서는 지양하고 재할당 방식 권장

## 2. 단계별 상세

### ① 자료형 점검/변환

**개념:** pandas가 자동으로 잡은 dtype(`int64`, `object` 등)은 "추측"일 뿐, 의미상 맞는 타입인지는 사람이 판단해야 함. 특히 아래 두 경우를 놓치기 쉬움:

- `yes/no`, `male/female`처럼 문자열(object)로 저장된 범주형 → `category`로
- **숫자로 저장돼 있지만 실제론 범주인 컬럼** (예: Boston의 `CHAS` 0/1 = "강 경계 여부", insurance의 인코딩된 코드값 등) → 숫자 타입이라고 무조건 연속형은 아님, 이것도 `category`로

**왜 category로 바꾸나?**

- 메모리 절약 (문자열 반복 저장 안 함)
- `groupby`, `value_counts`, `describe(include='category')`에서 의미상 명확하게 처리됨
- 이후 인코딩/더미변수 변환 대상이 명확해짐

```python
origin.info()                          # 먼저 전체 타입 훑기

df1 = origin.copy()
df1["CHAS"] = df1["CHAS"].astype("category")
# 여러 개면 반복
for col in ["sex", "smoker", "region"]:
    df1[col] = df1[col].astype("category")

df1.info()                             # 변환 확인은 필수
```

**함수화 버전 (재사용):**

```python
df1 = my_qtcheck.set_type(origin, as_category=['cut', 'color', 'clarity'])
# 내부적으로 data.copy() 후 처리 → 원본 안전, 마지막에 info() 자동 출력
```

> 📌 습관: 새 데이터 받으면 `origin.info()` 찍고 "숫자처럼 보이지만 실제론 범주인 컬럼"부터 골라내기.

### ② 중복 점검

**개념:** 행 전체가 완전히 동일한 레코드 탐지. 중복이 남아있으면 값 비중이 부풀려져 통계·모델 결과 왜곡.

```python
dup = df1.duplicated()      # 첫 등장은 False, 반복분만 True
dup.sum()                    # 중복 개수

df2 = df1.drop_duplicates()  # 새 변수로 받기
df2.duplicated().sum()       # 반드시 0인지 재검증
```

**함수화 버전:**

```python
df2 = my_qtcheck.check_duplicates(df1)   # drop=True가 기본값
```

> 📌 insurance 실습에서 실제로 1건 발견됨(Boston/diamonds는 0건). **"이번엔 없겠지"라고 넘기지 말고 매번 검사**해야 하는 이유가 바로 이런 케이스. 중복 0건이어도 "확인했음" 기록은 남기기.

### ③ 형식·표기·단위 점검 ⭐ (housing/diamonds엔 없고 Boston/insurance부터 추가된 단계)

**개념:** ①②가 "타입이 맞나, 중복 있나"였다면, 여기는 **"값 자체가 말이 되는가"**를 보는 단계.

**명목형 → 값의 종류 확인**

fields = df2.select_dtypes(include="category").columns
for field in fields:

**연속형 → min/max 구간 확인**

fields = df2.select_dtypes(include="number").columns.to_list()

minmax = []
for field in fields:

> 📌 **위도/경도처럼 숫자형이어도 통계적으로 의미 없는 컬럼**(평균 내는 게 무의미)은 이후 기술통계·이상치 분석에서 제외 고려. "number 타입 = 연속형"이 아닐 수 있음.

### ⑥ 기술 통계량 — 명목형/연속형 나눠서

**연속형:**

### ⑦ 중심 수준 파악 — 평균 vs 중앙값 (rel_diff)

**개념:** 평균은 이상치에 민감, 중앙값은 둔감. 둘이 비슷하면 대칭적 분포, 차이 크면 이상치/비대칭 의심.

```python
desc_df['rel_diff'] = abs(desc_df['mean'] - desc_df['50%']) / desc_df['50%']

conditions = [desc_df['rel_diff'] < 0.1, desc_df['rel_diff'] < 0.5]
choices = ['similar', 'diff']
desc_df['rdiff_flag'] = np.select(conditions, choices, default='large_diff')
```

| rel_diff 구간 | 판정       | 의미                        |
| ------------- | ---------- | --------------------------- |
| < 0.1         | similar    | 평균≈중앙값, 대칭에 가까움 |
| 0.1 ~ 0.5     | diff       | 약간 차이, 주의             |
| ≥ 0.5        | large_diff | 큰 차이, 왜도·극단값 의심  |

**`np.select()` 사용법:** 조건 리스트를 위에서부터 순서대로 검사 → 가장 먼저 True인 조건의 결과 채택 → 전부 False면 `default`.

> 실전 사례: insurance `charges`의 rel_diff = 0.415 (diff 구간) → 왜도 의심 신호로 이어짐 → 실제로 왜도 1.515 확인됨 (아래 ⑨ 참고).

---

### ⑧ 이상치 신호 감지 — IQR(사분위범위) 방법

```python
Q1 = 25% 지점, Q3 = 75% 지점
IQR = Q3 - Q1
상한 = Q3 + 1.5 × IQR
하한 = Q1 - 1.5 × IQR
→ 하한보다 작거나 상한보다 크면 이상치
```

```python
desc_df['iqr'] = desc_df['75%'] - desc_df['25%']
desc_df['upper_bound'] = desc_df['75%'] + 1.5 * desc_df['iqr']
desc_df['lower_bound'] = desc_df['25%'] - 1.5 * desc_df['iqr']

# 명목형 제외 (이상치는 연속형 개념)
cate_fields = df3.select_dtypes(include='category').columns
df4 = df3.drop(columns=cate_fields)

desc_df['upper_outliers'] = (df4 > desc_df['upper_bound']).sum()
desc_df['upper_outliers_ratio'] = desc_df['upper_outliers'] / df4.shape[0]
desc_df['lower_outliers'] = (df4 < desc_df['lower_bound']).sum()
desc_df['lower_outliers_ratio'] = desc_df['lower_outliers'] / df4.shape[0]

desc_df['outliers'] = desc_df['upper_outliers'] + desc_df['lower_outliers']
desc_df['outliers_ratio'] = desc_df['outliers'] / df4.shape[0]
```

**동작 원리:** `df4 > desc_df['upper_bound']`는 컬럼명 기준 자동 매칭으로 True/False DataFrame을 만들고, `.sum()`으로 컬럼별 True 개수(=이상치 개수)를 집계.

**왜 1.5배인가?** 통계적 관행. 정규분포 가정 시 상하위 약 0.7%를 이상치로 잡는 효과. 강하게 잡고 싶으면 3×IQR, 느슨하면 1.5×IQR.

**주의할 함정 (housing 실습에서 확인된 것):**

- `stories`(층수) 같은 **이산형/범위 좁은 변수**는 상한 초과율이 7.52%로 다른 변수(2%대)보다 비정상적으로 높게 나옴 → IQR이 과탐지한 사례
- `bedrooms`, `bathrooms`, `children`(부양자녀 수)처럼 **정수 카운트형 변수**는 IQR상 이상치여도 실제로는 정상값일 수 있음
- → **IQR로 "탐지"까지는 자동화하되, "제거할지 말지"는 변수 성격 보고 도메인 지식으로 판단**. 특히 이산형은 기계적 제거 금지.

### ⑨ 비대칭 신호 확인 — 왜도(Skewness)/첨도(Kurtosis) → 로그변환 판정

**왜도:**

```python
desc_df['skew'] = df4.skew()
conditions_skew = [(desc_df['skew'] < -0.5), (desc_df['skew'] > 0.5)]
choices_skew = ['left tail', 'right tail']
desc_df['skew_interpret'] = np.select(conditions_skew, choices_skew, default='symmetric')
```

| 상황   | 평균-중앙값 관계 | 왜도             | 분포 형태                                     |
| ------ | ---------------- | ---------------- | --------------------------------------------- |
| 대칭   | 평균≈중앙값     | ≈0              | 정규분포에 가까움                             |
| 우편향 | 평균>중앙값      | >0 (>1이면 강함) | 오른쪽 꼬리 김, 고가/이상치가 평균을 끌어올림 |
| 좌편향 | 평균<중앙값      | <0               | 왼쪽 꼬리 김                                  |

**첨도:**

```python
desc_df['kurt'] = df4.kurt()
conditions_kurt = [(desc_df['kurt'] < 0), (desc_df['kurt'] > 0)]
choices_kurt = ['platykurtic', 'leptokurtic']
desc_df['kurt_interpret'] = np.select(conditions_kurt, choices_kurt, default='mesokurtic')
```

- `kurt<0` → platykurtic(납작함, 분산 넓게 퍼짐) / `kurt>0` → leptokurtic(뾰족함, 평균 근처 밀집+두꺼운 꼬리) / `kurt=0` → mesokurtic(정규분포 유사)
- pandas `kurt()`는 **초과 첨도** 기준 (정규분포=0)

**로그변환 필요성 자동 판정:**

```python
def judge_log_transform(skew, kurt):
    if skew >= 1:
        return "log1p"
    elif skew > 0.5 and kurt > 0:
        return "log1p"
    elif skew <= -1:
        return "reverse_log1p"
    elif skew < -0.5 and kurt > 0:
        return "reverse_log1p"
    else:
        return "none"

desc_df['log_need'] = desc_df.apply(
    lambda row: judge_log_transform(row['skew'], row['kurt']), axis=1
)
```

| skew 조건        | kurt 조건 | 결과          | 의미               |
| ---------------- | --------- | ------------- | ------------------ |
| skew ≥ 1        | 무관      | log1p         | 강한 우측 꼬리     |
| 0.5 < skew < 1   | kurt > 0  | log1p         | 우측 꼬리 + 뾰족함 |
| skew ≤ -1       | 무관      | reverse_log1p | 강한 좌측 꼬리     |
| -1 < skew < -0.5 | kurt > 0  | reverse_log1p | 좌측 꼬리 + 뾰족함 |
| 그 외            | -         | none          | 변환 불필요        |

`apply(axis=1)` = 행 단위 적용 (각 변수의 skew, kurt를 꺼내 함수에 넣음). `axis=0`(기본값)은 열 단위라서 헷갈리지 않게 주의.

**실전 사례 (insurance `charges`):**

| 지표        | 값                   | 해석             |
| ----------- | -------------------- | ---------------- |
| 평균        | 13,279               |                  |
| 중앙값      | 9,386                | 평균이 훨씬 큼   |
| rel_diff    | 0.415                | diff 구간        |
| 왜도        | 1.515                | 강한 우측 꼬리   |
| 상한 이상치 | 139개 (10.4%)        | 고액 청구가 다수 |
| 판정        | **log1p 필수** |                  |

→ 소수의 고액 건이 평균을 끌어올리는 전형적 패턴. 회귀분석/모델링 전에 이런 변수는 거의 필수로 로그 변환. (Olist OLS 작업과 직결되는 부분)

## 5. 추가로 넣으면 좋을 것 같은 것 (다음 단계 확장)

지금까지 4개 실습은 전부 "① 품질검사 → ② 기술통계"까지였는데, 이후 Olist 프로젝트처럼 **가설검정/회귀분석까지 갈 프로젝트**라면 이 뒤에 자연스럽게 이어지는 단계들이 있음. 지금 정리 문서에 없어서 짚어두는 게 좋을 것:

### ① 상관관계 점검 (⑥~⑨ 다음, 모델링 이전)

```python
corr = df4.corr(numeric_only=True)
```

- 연속형 변수끼리 상관 확인 → 다중공선성(multicollinearity) 미리 스크리닝
- Olist OLS 작업에서 이미 VIF 체크하고 계신데, VIF 계산 전에 상관행렬로 1차 스크리닝하면 "왜 이 변수가 VIF 높게 나왔는지" 직관적으로 확인 가능

### ② 시각화 검증 단계

- IQR/왜도로 "숫자상 이상치·비대칭"을 잡아도, boxplot/histogram으로 **눈으로 한 번 더 확인**하는 단계를 체크리스트에 명시적으로 넣는 게 좋음 (diamonds 문서 체크리스트엔 있는데 나머지엔 빠져있음)

```python
import seaborn as sns
sns.boxplot(x=df4['charges'])
sns.histplot(df4['charges'], kde=True)
```

### ③ 범주형 변수 간 관계 확인

- 지금까진 "범주형 vs 연속형 타깃"만 다뤘는데, **범주형 vs 범주형**(예: smoker vs region)도 필요하면 교차표 + Cramér's V로 확인 가능. 이미 Olist 작업에서 Cramér's V 쓰신 적 있으니 그 코드 재사용하면 됨.

```python
pd.crosstab(df3['smoker'], df3['region'])
```

### ④ "정제 단계"와 "이해 단계"에 이어 "검정 단계" 구획을 하나 더 만들기

현재 문서들은 ①~⑤(Clean) / ⑥~⑩(Understand) 2단계 구조인데, 실제 프로젝트(Olist, insurance charges 같은 케이스)는 보통 여기서 끝나지 않고:

```
Clean → Understand → Test(가설검정: t-test/ANOVA/chi-square) → Model(회귀/분류)
```

로 이어짐. 지금 이 가이드는 Clean+Understand 파트의 "완성형"이니, 이후 Test/Model 파트도 같은 톤으로 정리해서 이어붙이면 하나의 풀파이프라인 문서가 될 것 같음. (원하면 이 부분도 다음에 정리해줄 수 있음)

### ⑤ 함수 모듈에 로깅/버전 관리 습관

- `my_qtcheck.py`가 프로젝트마다 계속 재사용되는 핵심 자산이니, 함수 수정할 때마다 간단한 변경 로그(주석이라도)를 남겨두면 나중에 "이 버전에서 이 로직이 왜 바뀌었지"를 추적하기 편함. 지금은 실습 단계라 크게 중요하지 않지만, Olist처럼 본격 프로젝트에서 재사용할 땐 도움 될 것.
