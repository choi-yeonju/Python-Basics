## 1. 핵심 통계 개념 — 말로 풀어서

### 1-1. 모집단(population) vs 표본(sample)
- **모집단**: 내가 알고 싶은 전체 대상. 예) 이 빵집에서 만드는 **모든** 식빵의 무게.
- **표본**: 그 중 일부를 뽑아서 실제로 잰 것. 예) 25일 동안 산 식빵 25개.
- 모집단 전체를 다 재는 건 현실적으로 불가능하니까, 표본으로 모집단을 "추론"하는 게 추론통계.

### 1-2. 모평균(μ, mu)
- 모집단 전체의 진짜 평균값. **우리가 알고 싶지만 절대 직접 잴 수 없는 값**.
- 표본평균(예: 25개 식빵의 평균 무게)은 이 모평균의 **추정치**일 뿐.
- "표본평균이 480g이었다" ≠ "모평균이 480g이다". 표본평균과 모평균 사이엔 항상 오차(표준오차)가 낀다.

### 1-3. 귀무가설(H0)과 대립가설(H1) — 기호 말고 진짜 의미
- **귀무가설(H0, null hypothesis)**: "차이가 없다", "우연이다", "지금까지 알려진 게 맞다"는 보수적인 기본 가정.
  - 예) 빵의 평균 무게(μ)는 표시된 대로 500g이다. → **아무 문제도 없다는 전제**
- **대립가설(H1, alternative hypothesis)**: "차이가 있다", "우연이 아니다"는, 내가 통계적으로 증명하고 싶은 주장.
  - 예) 빵의 평균 무게(μ)는 500g이 아니다(또는 더 작다).
- 검정의 논리: **H0를 "일단 맞다고 가정"하고 시작해서, 표본 데이터가 그 가정 하에 나오기 너무 희박한 확률이면 H0를 기각**하고 H1을 채택한다.
- 절대 "H1이 맞다는 걸 증명"하는 게 아니라 "**H0를 기각할 근거가 충분한가**"를 보는 거라서, 기각 못 하면 "H0가 맞다"가 아니라 "**H0를 기각할 근거가 부족하다**"는 뜻 (H0 채택 ≠ H0 증명).

### 1-4. 양측검정 vs 단측검정 — 왜 3가지를 다 돌리나
검정 방향에 따라 H0/H1이 달라진다. 오늘 코드에서 `alternative` 파라미터로 조절한 부분.

| 구분 | H0 | H1 | 언제 쓰나 |
|---|---|---|---|
| 양측(two-sided) | μ = 기준값 | μ ≠ 기준값 | "다르기만 하면 됨" (크든 작든 관심 없음) |
| 좌측 단측(less) | μ ≥ 기준값 | μ < 기준값 | "기준보다 작은지"가 궁금할 때 (예: 빵이 표시보다 가벼운지) |
| 우측 단측(greater) | μ ≤ 기준값 | μ > 기준값 | "기준보다 큰지"가 궁금할 때 |

- `my_stats.test_1sample()`은 이 세 가지를 **한 번에 다 계산**해서 표로 보여줌 → 매번 3번 따로 실행할 필요 없음.
- 실전에서는 세 개 다 보고, **연구 질문에 맞는 방향 하나만 결론에 쓴다.** (빵 예제에서 "가벼운지 궁금했으니 less 결과가 핵심")

### 1-5. p-value (유의확률)
- "**H0가 참이라고 가정했을 때**, 지금 관찰된 (혹은 더 극단적인) 표본 결과가 나올 확률".
- p-value가 아주 작다 = "H0가 맞다면 이런 데이터가 나올 확률은 매우 낮다" = **H0를 믿기 어렵다** → 기각.
- 유의수준(α, alpha, 보통 0.05)과 비교: **p < α → 통계적으로 유의함(H0 기각)**, **p ≥ α → 유의하지 않음(H0 기각 못 함)**.
- 주의: p-value는 "효과가 얼마나 큰가"가 아니라 "**우연이 아닐 확률이 얼마나 되는가**"를 말해줌. (효과 크기는 별개 지표, Olist 프로젝트에서 Cramér's V 썼던 거랑 같은 맥락)

### 1-6. 검정통계량(statistic)과 자유도(degree of freedom, dof)
- **검정통계량**: 표본평균이 기준값(모평균 가설)에서 표준오차 몇 개만큼 떨어져 있는지를 하나의 숫자로 표현한 것. (t값, Wilcoxon 통계량 등)
- **자유도(dof)**: 표본크기 n에서 제약조건(평균을 이미 썼으니) 하나를 뺀 값, 보통 `n - 1`. t분포의 모양을 결정하는 파라미터.
- t값이 0에서 멀어질수록(양수든 음수든 절대값이 커질수록) 기준값과 실제 표본평균 차이가 "우연이라 보기엔 크다"는 뜻.

### 1-7. 신뢰구간(Confidence Interval, CI)
- "모평균이 있을 것으로 추정되는 범위"를 확률적으로 표현한 것. 95% 신뢰구간이면 "이 방식으로 100번 표본을 뽑아 구간을 구하면 그 중 95번은 진짜 모평균을 포함한다"는 뜻.
- `my_stats.ci()` 함수가 하는 일: 표본평균 ± (t분포 기준값 × 표준오차)로 구간을 계산.
- **표준오차(standard error)** = 표본표준편차 / √n → 표본이 클수록 표준오차는 작아지고, 신뢰구간은 좁아짐(더 정밀해짐).

### 1-8. 정규성 검정 (normaltest)
- t-검정은 "표본이 정규분포를 따른다"는 전제 위에서 작동하는 **모수검정(parametric test)**. 이 전제가 깨지면 t-검정 결과를 못 믿음.
- `normaltest()`: 데이터가 정규분포에서 얼마나 벗어나는지를 검정.
  - H0: "데이터가 정규분포를 따른다" / H1: "따르지 않는다"
  - p ≥ 0.05 → 정규성 충족(H0 유지) → t-검정 사용 가능
  - p < 0.05 → 정규성 위배 → **모수검정 못 씀, 비모수검정으로 전환**

### 1-9. 등분산성 검정 (Bartlett / Levene) — 오늘 코드엔 안 썼지만 my_stats에 포함된 이유
- 그룹이 **2개 이상**일 때 "그룹 간 분산이 같은가"를 보는 검정. (단일표본은 그룹이 1개라 자동으로 스킵됨 — 코드에서 `if len(columns) > 1` 조건으로 처리)
- **Bartlett**: 모든 그룹이 정규성을 충족할 때 사용 (정규성 가정에 민감함).
- **Levene**: 하나라도 정규성이 깨지면 사용 (더 안전한 대안, 중앙값 기반이라 이상치에 강함).
- 이건 나중에 **두 집단 비교(독립표본 t-검정)**나 ANOVA 갈 때 바로 쓰게 될 부분이라 미리 봐두면 좋음.

### 1-10. 모수검정 vs 비모수검정, 그리고 Wilcoxon 부호순위검정
- **모수검정(parametric)**: 데이터의 분포(정규분포 등)를 가정하고, 평균 같은 모수를 직접 검정. → t-test
- **비모수검정(non-parametric)**: 분포를 가정하지 않고, 데이터를 **순위(rank)**로 바꿔서 검정. 정규성이 깨졌을 때의 대안.
- **Wilcoxon 부호순위검정(signed-rank test)**: 단일표본에서 "기준값과의 차이"를 구하고, 그 차이의 **부호(+/-)와 순위**만 가지고 검정. 평균이 아니라 **중앙값(median) 개념**에 가까운 검정이라고 보면 됨.
  - 코드에서 `wilcoxon(data - popmean, alternative=...)` 형태로, 기준값을 미리 빼주는 걸 잊으면 안 됨 (안 빼면 "차이가 0과 다른가"가 아니라 "원본 값이 0과 다른가"를 검정하게 되는 실수 나옴).

## 2. 오늘 실습 흐름 — 분석 순서 (이 순서를 기본값으로 삼기)

```
1. 라이브러리 & 데이터 로드
   ↓
2. 데이터 분포 시각화 (kdeplot 등으로 눈으로 먼저 확인)
   ↓
3. 가설검정의 가정 확인 (정규성 검정 test_assumptions)
   ↓
4. 정규성 충족 여부에 따라 검정 방법 분기
   ├─ 충족(정규) → One-sample t-test (ttest_1samp)
   └─ 미충족    → Wilcoxon signed-rank test (wilcoxon)
   ↓
5. 양측 / 좌측단측 / 우측단측 세 방향 다 검정
   ↓
6. p-value를 유의수준(보통 0.05)과 비교해서 유의성 판단
   ↓
7. 연구 질문에 맞는 방향 선택해서 비즈니스/현실적 결론 문장으로 정리
```

**중요한 유의점**: 3번(정규성 확인)을 절대 건너뛰면 안 됨. 오늘 예제 두 개가 정확히 이걸 보여줌.
- 강아지 체온 데이터 → 정규성 충족(p=0.664) → t-검정 사용
- 보험 가입금액 데이터 → 정규성 위배(p=0.003) → Wilcoxon으로 전환

**만약 3번을 안 하고 무조건 t-검정만 썼다면?** → 보험 데이터처럼 정규성이 깨진 데이터에도 t-검정을 돌리는 실수를 하게 되고, 그 결과(p-value)를 신뢰할 수 없게 됨. 이게 오늘 배운 것의 핵심 이유.

## 3. 코드 두 버전 비교 — "직접 코딩" vs "내 모듈(my_stats) 호출"

오늘 노트북은 정확히 두 단계로 구성되어 있음. 이 차이를 이해하는 게 이 실습의 진짜 포인트.

### 버전 A — scipy 함수를 직접 하나씩 호출 (#02, #03 섹션)
```python
s, p = ttest_1samp(df1['체온'], popmean, alternative='two-sided')
s, p = ttest_1samp(df1['체온'], popmean, alternative='less')
s, p = ttest_1samp(df1['체온'], popmean, alternative='greater')
```
- 장점: 각 단계가 뭘 하는지 눈으로 다 보임 (학습 단계에서는 이게 맞음)
- 단점: 데이터셋이 바뀔 때마다 정규성 확인 → 분기 → 3방향 반복... 이 전체를 매번 손으로 다시 쳐야 함. 실수 나기 쉬움 (예: Wilcoxon에서 기준값 빼는 거 깜빡하기 등)

### 버전 B — 내가 만든 `my_stats.test_1sample()` 모듈 호출 (#04 섹션)
```python
my_stats.test_1sample(df1, column='체온', popmean=24.3)
```
- 이 한 줄 안에서 내부적으로 하는 일:
  1. `test_assumptions()`로 정규성 자동 검정
  2. 정규성 결과에 따라 t-test/Wilcoxon 자동 선택
  3. 양측/좌측/우측 3방향 자동 반복
  4. 결과를 보기 좋은 DataFrame(H0/H1 문장 포함)으로 정리
- **버전 A와 완전히 같은 로직**이고 실제로 숫자도 100% 동일함 (강아지 체온 예제: t=2.713, p=0.012로 둘 다 일치 확인됨). 다만 **재사용 가능한 형태로 캡슐화**한 것.

### 이 두 버전을 놓고 어떻게 사고해야 하나 (모듈 확장에 대한 사고방식)

1. **먼저 손으로 풀어서(버전 A) 검증한다.** 모듈이 신뢰할 수 있는지 확인하는 단계. 새로운 통계 기법을 처음 배울 땐 항상 이렇게 손으로 먼저 해보고, 모듈 결과와 대조(sanity check)하는 습관이 필요함. (오늘 노트북이 딱 이 구조: A로 검증 → B로 재사용성 확인)
2. **같은 패턴이 반복된다 싶으면 모듈에 함수로 박아넣는다.** "정규성 확인 → 분기 → 3방향 검정"이 데이터셋 바뀔 때마다 반복되는 패턴이라는 걸 깨달았으니까 `test_1sample()`로 만든 것. **패턴이 2~3번 이상 반복되면 함수화** — 이게 재사용 가능한 개인 라이브러리를 만드는 핵심 기준.
3. **모듈은 "이미 검증된 로직의 저장소"이지, "한 번에 다 짜는 것"이 아니다.** `my_stats.py`, `my_plot.py` 안의 함수 하나하나가 이미 과거에 검증 끝난 블록이라서, 새 데이터셋에서는 그 블록을 갖다 쓰기만 하면 됨. 앞으로 프로젝트 할 때마다 이 라이브러리가 점점 두꺼워지는 게 정상.
4. **확장은 "필요해질 때" 한다.** 예를 들어 다음에 "두 집단 비교"를 배우면 `test_2sample()` 같은 함수를 추가하게 될 텐데, 이때도 먼저 scipy로 손 풀이 → 검증 → 함수화 순서를 반복하면 됨. 처음부터 모든 케이스를 예측해서 거대한 함수를 만들려고 하지 않는 게 좋음 (오버엔지니어링 방지).
5. **모듈 함수를 믿고 쓰되, 내부 로직은 항상 설명할 수 있어야 함.** 면접이나 실무에서 "이 함수가 왜 이렇게 나왔어요?"라는 질문에 "모듈이 알아서 해줬어요"라고 답하면 안 되고, "정규성 검정을 먼저 하고, 정규성이 깨지면 비모수검정으로 자동 전환하도록 만들었다"고 설명할 수 있어야 함.

### `my_stats.py` 안에서 봐둘 것 (버그 리뷰할 때 참고)
- `test_assumptions()`가 단일 컬럼일 때는 등분산성 검정(Bartlett/Levene)을 자동으로 스킵하는 조건(`len(columns) > 1`)이 들어있음 → 단일표본 검정에서 안전하게 재사용 가능한 이유.
- `test_1sample()`은 `test_assumptions()`를 내부에서 호출해서 재사용함 → 함수끼리 조합(compose)해서 쓰는 구조. 이런 식으로 작은 함수들을 조립해서 큰 함수를 만드는 게 좋은 모듈 설계 방식.

## 5. 오늘 실습 결과 요약 (참고용 — 숫자 기억용)

| 예제 | 정규성(p) | 사용 검정 | 핵심 결과 | 결론 |
|---|---|---|---|---|
| 강아지 체온 (n=25, 기준 24.3) | 0.664 (충족) | One-sample t-test | 양측 p=0.012, 우측 p=0.006 | 체온이 24.3보다 유의하게 높음 |
| 보험 가입금액 (기준 1억) | 0.003 (위배) | Wilcoxon | 모든 방향 p>0.05 | 1억과 유의한 차이 없음 |
