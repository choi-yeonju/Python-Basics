## 0. 기본 원칙 — 두 부류를 구분해서 공부한다

| 구분                                              | 예시                                                                                                                                          | 목표 수준                                             | 이유                                                                                   |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **① 암기해야 하는 것 (판단 기준/원리)**    | scatter를 언제 쓰는지, hue 있으면 color가 왜 무시되는지, ConvexHull이 왜 3개 미만이면 에러나는지, ConvexHull이 scatter의 "확장 레이어"인 이유 | 코드/자료 안 보고**말로 설명 가능**해야 함      | 실무·면접에서 물어보는 건 "왜 이 차트를 골랐어요?"지 "함수 시그니처 외웠어요?"가 아님 |
| **② 찾아 쓰면 되는 것 (문법/옵션 디테일)** | `markers` vs `marker`, `edgecolor=`, `s=` 기본값, `plot_hull` 내부 코드 한 줄 한 줄                                                 | 레퍼런스 문서에서**빠르게 찾을 수 있으면 충분** | 외우고 있으면 시간 낭비. "필요할 때 정확히 찾아쓸 수 있다"가 진짜 실력                 |

> **체크**: 지금 헷갈리는 게 ①인지 ②인지부터 구분하기. ②를 못 외운다고 스트레스 받을 필요 없음.

## 1. ① 암기 체크리스트 — 자료 안 보고 설명해보기

아래 질문에 **말로(또는 글로) 막힘없이** 답할 수 있으면 체크.

### Scatter Plot

- [ ] 언제 scatter를 쓰는지 (연속형-연속형 관계, 이상치 확인, 군집별 관계 비교) 설명할 수 있다
- [ ] scatter가 barplot/boxplot과 뭐가 다른지 ("집계 없이 개별 관측치를 그대로 찍는다") 설명할 수 있다
- [ ] `hue`가 있을 때 `color` 파라미터가 왜 무시되는지 설명할 수 있다
- [ ] `data=df, x=컬럼명, y=컬럼명` 패턴을 왜 항상 쓰는지 (다른 함수들과 인터페이스 통일 = 재사용성) 설명할 수 있다

### Convex Hull

- [ ] Convex Hull이 뭘 계산해주는 알고리즘인지 (군집의 최외곽 점들을 이어 영역을 만듦) 설명할 수 있다
- [ ] 왜 최소 3개의 점이 필요한지 설명할 수 있다
- [ ] `hull.vertices`가 뭘 반환하는지, 왜 직접 좌표로 변환해서 plot/fill 해야 하는지 설명할 수 있다
- [ ] 다각형을 "닫는" 스텝(`np.append(vertices, vertices[0])`)이 왜 필요한지 설명할 수 있다
- [ ] Convex Hull이 왜 "독립적인 차트"가 아니라 "scatter 위의 레이어"인지 설명할 수 있다

### 새 데이터셋 적용 판단

- [ ] 새 데이터 받았을 때 scatter 그리기 전에 뭘 먼저 체크해야 하는지 (결측치 / x,y dtype / hue dtype / hue 범주 개수) 말할 수 있다
- [ ] hue를 연속형 컬럼에 그대로 쓰면 왜 안 되는지 설명할 수 있다
- [ ] hue 범주가 많아지면(6~8개 초과) 어떤 문제가 생기는지 설명할 수 있다

**→ 이 섹션은 며칠 지나서 다시 와서 체크하기. 한 번에 다 체크됐다고 끝난 게 아니라, 시간 지나도 유지되는지가 진짜 기준.**

## 2. ② 레퍼런스 체크리스트 — "어디 있는지 아는가"만 확인

암기할 필요 없고, **필요할 때 30초 안에 찾아낼 수 있으면 체크**.

- [ ] scatter 옵션 이름(`s`, `edgecolor`, `linewidth`, `alpha`) → 레퍼런스 문서 2장에서 찾을 수 있다
- [ ] `my_plot.scatterplot()` 전체 파라미터 목록 → 레퍼런스 문서 4장에서 찾을 수 있다
- [ ] `plot_hull` 함수 전체 코드 → 레퍼런스 문서 3-4장 / 8-3 템플릿에서 찾을 수 있다
- [ ] 새 데이터셋 적용 전 체크리스트 표 → 레퍼런스 문서 0-0장에서 찾을 수 있다

**→ 이건 "외웠나"가 아니라 "문서 구조를 기억하고 있나"를 확인하는 것. 문서 구조 자체를 못 찾겠으면 레퍼런스 문서를 다시 훑어볼 것.**

## 3. 연습문제 — 3단계로 나눠서 진행 (한 번에 3단계 목표 아님)

### 1단계 — 가이드 보면서 풀기 (지금 단계)

- [ ] study_scores 연습문제, 레퍼런스 보면서 완료
- [ ] byeolbit_city 연습문제, 레퍼런스 보면서 완료

### 2단계 — 가이드 없이 시작, 막힐 때만 찾아보기 (며칠 뒤 다시)

- [ ] study_scores를 가이드 안 보고 다시 풀어본다 → 막힌 지점 기록: ________________
- [ ] byeolbit_city를 가이드 안 보고 다시 풀어본다 → 막힌 지점 기록: ________________

> 막힌 지점이 ①(판단/원리)이면 → 1번 섹션 다시 복습
> 막힌 지점이 ②(문법/옵션)이면 → 정상. 레퍼런스에서 찾아보고 넘어가면 됨

### 3단계 — 완전히 새로운 데이터셋으로 판단력 테스트 (최종 목표)

- [ ] 처음 보는 데이터셋을 받았을 때, 코드 없이 "이건 scatter를 써야겠다 / hue로 뭘 나눠야겠다 / 전처리 뭐부터 체크해야겠다"를 말로 먼저 설계해본다
- [ ] 그다음에 코드로 옮긴다 (정확한 파라미터 스펠링은 찾아봐도 됨)

**최종 목표는 "안 보고 완벽히 코드 치기"가 아니라 "새 데이터 던져줬을 때 뭘 봐야 하는지 스스로 판단하기"다.**
이게 실무/코딩테스트에서 실제로 평가받는 지점.

## 4. 이 문서 사용법

- 오늘: 1단계 연습문제만 체크, 1번/2번 섹션은 지금 상태 그대로 훑어보기용
- 며칠 후 (LAB06 다음 파트 나가기 전): 1번 섹션 다시 체크 (유지되는지 확인) + 2단계 연습문제 시도
- 프로젝트 붙기 전: 3단계까지 도달했는지 최종 점검

이 문서는 계속 갱신하면서 쓰는 용도. 체크 안 된 항목이 남아있는 게 정상 — 그게 다음에 뭘 봐야 할지 알려주는 지표임.
