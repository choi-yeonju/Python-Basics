```
1. 준비작업 (라이브러리, 데이터 로드, 컬럼 의미 정리)
2. 데이터 품질 점검 (자료형, 중복, 결측치, 기술통계)
3. 변수 유형 분류 (연속형 / 명목형) ← 종속변수 스위치 하나로 전체 분기 결정
4. EDA — 단변량 → 이변량 → 다변량 (반드시 이 순서)
5. (다음 랩에서) 모델링 — 로지스틱 회귀 적합
```

**왜 순서가 중요한가**: 단변량을 안 보고 이변량부터 하면, 이상치 때문에 검정 결과가 왜곡됐는지 원본 분포가 이상한지 구분이 안 된다. 다변량(변수끼리의 상관)을 이변량보다 먼저 보면, "종속변수와 관련 있는 변수인데 서로 상관도 높은 애들"을 걸러내는 로직 자체가 성립하지 않는다. 즉 뒷 단계는 앞 단계의 결과를 재료로 쓰기 때문에 순서를 바꾸면 안 된다.

## 1. 종속변수 스위치 — 이 실습에서 제일 중요한 설계 아이디어

```python
target = "Quality"                  # 종속변수 이름
target_is_continuous = False        # 종속변수가 연속형이냐 아니냐 (bool 스위치)
```

이 값 하나(`True`/`False`)가 아래 4가지를 자동으로 결정한다.

| 스위치가 결정하는 것 | 연속형(True)일 때 | 명목형(False)일 때 — 지금 이 경우 |
|---|---|---|
| 이변량 분석 기법 | 상관분석(피어슨/스피어만) | T검정 / Mann-Whitney U |
| 점검할 가정 | 선형성, 정규성, 등분산성(잔차) | 정규성, 등분산성(두 집단) |
| 적합할 모형 | 선형회귀 | 로지스틱회귀 |
| 성능 지표 | R², RMSE | 정확도, AUC 등 |

**설계 의도**: 다른 데이터셋으로 똑같은 파이프라인을 돌릴 때, `target_is_continuous` 이 한 줄만 바꾸면 뒤쪽 코드는 손댈 필요가 없다. 코드를 매번 새로 짜는 게 아니라 "설정값만 갈아끼우는" 구조를 만든 것 — 이게 재사용 가능한 파이프라인의 핵심 사고방식이다.

```python
nominal_cols = my_qtcheck.get_categorical_column_names(df2)   # 명목형 변수 목록
continuous_cols = my_qtcheck.get_number_column_names(df2)     # 연속형 변수 목록

if target_is_continuous:
    continuous_cols.remove(target)   # 종속변수가 연속형이면 연속형 리스트에서 제거
else:
    nominal_cols.remove(target)      # 종속변수가 명목형이면 명목형 리스트에서 제거
```

여기서 `if/else`는 "종속변수가 원래 어느 타입 리스트에 섞여 있었는지"에 맞춰 **딱 그 리스트에서만** 종속변수 이름을 빼주는 역할이다. 그래야 `continuous_cols`, `nominal_cols`에는 순수하게 **독립변수만** 남는다.

## 2. 척도 조합표 — "어떤 검정을 써야 하나"를 결정하는 표

두 변수(독립변수 vs 종속변수)의 척도(연속형/명목형) 조합에 따라 쓸 수 있는 분석 기법이 정해져 있다. 이 실습에서 실제로 쓰인 건 아래 두 칸이다.

| | 종속변수: 연속형 | 종속변수: 명목형(2집단) |
|---|---|---|
| 독립변수: 연속형 | 상관분석 / 회귀 | **T검정 (Mann-Whitney U)** ← 이번 실습 |
| 독립변수: 명목형 | 분산분석(ANOVA) | **카이제곱 독립성 검정** ← 이번 실습 |

이 실습(Apple Quality)은 연속형 독립변수 7개, 명목형 독립변수 0개, 종속변수는 명목형 2집단(good/bad)이라서 **T검정(또는 비모수 대응인 Mann-Whitney U)** 만 실제로 수행됐다. (문제 8번 답)

## 3. 통계 개념 하나하나 풀어서 정리

### 3-1. 왜도(skewness)와 첨도(kurtosis)

- **왜도**: 분포가 좌우로 얼마나 치우쳐 있는지를 나타내는 값. 0이면 좌우 대칭, 양수면 오른쪽 꼬리가 길다(오른쪽으로 치우침), 음수면 왼쪽 꼬리가 길다.
- **첨도**: 분포가 얼마나 뾰족한지(극단값이 많은지)를 나타내는 값. 정규분포 기준으로 초과 첨도가 0이면 정규분포와 비슷한 뾰족함, 양수면 뾰족하고 꼬리가 두꺼움(leptokurtic), 음수면 완만함(platykurtic).
- 이번 실습에서는 왜도의 **절댓값**을 기준으로 "가장 비대칭이 심한 변수"를 찾았다 (문제 11번: Juiciness, 왜도 -0.113).

### 3-2. T검정 (독립표본)

**말로 풀면**: "두 개의 독립된 집단(여기선 bad 그룹과 good 그룹)의 평균이 통계적으로 다른가?"를 검정하는 방법.

- **귀무가설(H0)**: 두 집단의 모평균은 같다. (μ_bad = μ_good, 즉 "차이가 없다")
- **대립가설(H1)**: 두 집단의 모평균은 다르다. (μ_bad ≠ μ_good, 즉 "차이가 있다")

여기서 μ(뮤)는 **모집단의 평균**을 뜻하는 기호다. 우리가 가진 데이터는 표본(sample)이고, 그 표본의 평균으로 "원래 모집단의 평균이 같을 것이다/다를 것이다"를 추론하는 것.

**판정 방법**: p-value가 유의수준(보통 0.05)보다 작으면 귀무가설을 기각 → "두 집단 평균이 다르다(유의하다)"고 결론. p-value가 0.05보다 크면 귀무가설을 기각할 근거가 부족 → "차이가 없다고 봐도 무방하다"고 결론.

**T검정을 쓰기 전에 확인해야 하는 전제조건 2가지**:
1. **정규성**: 각 집단의 데이터가 정규분포를 따르는가
2. **등분산성**: 두 집단의 분산이 비슷한가

이 전제조건에 따라 실제로 쓰이는 검정 방법이 갈라진다:

| 정규성 | 등분산성 | 사용하는 검정 |
|---|---|---|
| 만족 | 만족 | Student's t-test (일반 t검정) |
| 만족 | 불만족 | **Welch's t-test** (분산이 다름을 보정) |
| 불만족 | 상관없음 | **Mann-Whitney U test** (순위 기반 비모수 검정) |

**Mann-Whitney U test란?**: 데이터 값 자체가 아니라 "순위(rank)"로 바꿔서 두 집단의 순위 분포가 다른지를 검정하는 방법. 정규분포를 가정하지 않기 때문에 "비모수(non-parametric)" 검정이라고 부른다. 원본 값 대신 순위를 쓰기 때문에 이상치의 영향을 덜 받는다는 장점도 있다.

이번 실습에서 7개 연속형 변수 중 **4개(Size, Sweetness, Acidity, Crunchiness)는 정규성을 만족 못 해서 Mann-Whitney U**, 나머지 3개(Weight, Juiciness, Ripeness)는 **정규성을 만족해서 Welch t-test**로 검정됐다 (문제 15번).

### 3-3. 카이제곱(χ²) 독립성 검정

**말로 풀면**: 두 명목형 변수(범주형 변수)가 서로 관련이 있는지(독립인지) 검정하는 방법. 교차표(cross-tabulation)를 만들어서, 실제 관측된 빈도와 "두 변수가 완전히 독립이라고 가정했을 때 기대되는 빈도"를 비교한다.

- **귀무가설(H0)**: 두 변수는 서로 독립이다 (관련이 없다)
- **대립가설(H1)**: 두 변수는 서로 독립이 아니다 (관련이 있다)

이번 데이터셋은 명목형 독립변수가 0개라서 카이제곱 검정 자체가 실행은 됐지만 대상이 없어 결과가 안 나왔다 (문제 7번).

### 3-4. 상관분석 (피어슨 / 스피어만)

**말로 풀면**: 두 연속형 변수가 함께 움직이는 정도를 -1~1 사이 숫자(상관계수 r)로 나타낸 것.
- r이 1에 가까우면: 한 변수가 커질 때 다른 변수도 커지는 양의 상관관계
- r이 -1에 가까우면: 한 변수가 커질 때 다른 변수는 작아지는 음의 상관관계
- r이 0에 가까우면: 선형적인 관계가 거의 없음

**주의할 점**: 상관분석은 두 변수가 **모두 연속형**일 때만 정의된다. 종속변수가 명목형이면 종속변수와의 관계는 상관분석이 아니라 T검정/카이제곱으로 봐야 하고, 상관분석은 **독립변수끼리**(다변량 분석 단계)의 관계를 볼 때만 쓴다.

**보통 절댓값 0.7 이상이면 "강한 상관"**으로 분류하고, 이 경우 다중공선성(multicollinearity) 문제를 의심해서 둘 중 하나를 제거하거나 처리한다. 이번 실습에서는 절댓값 0.7 이상인 조합이 없었다 (문제 16번, 17번: 가장 강한 조합도 Size-Sweetness -0.325로 약한 수준).

### STEP 3. 데이터 품질 점검 (5단계 고정 루틴)

**질문**: 이 데이터를 믿고 분석해도 되는가? (자료형이 맞는지 / 중복이 있는지 / 결측이 있는지)

```python
origin.info()   # ① 자료형 확인 - 숫자여야 할 게 문자열로 들어와 있진 않은지 등을 먼저 눈으로 스캔

# ② 분석 대상이 아닌 컬럼 제거 + 자료형 변환
df0 = origin.drop(columns=["A_id"])                        # A_id는 행마다 값이 다른 식별자 → 통계적 의미 없음, 제거
df1 = my_qtcheck.set_type(df0, as_category=["Quality"])     # Quality는 문자열(good/bad)이므로 category(명목형)로 명시 변환

# ③ 중복 행 점검
df2 = my_qtcheck.check_duplicates(df1)

# ④ 결측치 점검
my_qtcheck.check_missing_values(df2)

# ⑤ 기술통계 (명목형/연속형 따로)
cat_desc = my_qtcheck.categorical_summary(df2)
num_desc = my_qtcheck.numerical_summary(df2)
```

**생각의 흐름 (왜 이 순서인가)**:
1. `info()`를 제일 먼저 보는 이유 — 이후 모든 처리(제거/변환)의 **기준선**을 잡기 위해서다. 뭘 고칠지 알아야 고친다.
2. `A_id`를 제거하는 판단 근거 — "행마다 값이 모두 다르다 = 그룹을 나눌 수도, 관계를 볼 수도 없는 변수다"라는 논리. 식별자(ID)는 거의 항상 분석 대상에서 빼는 게 원칙이다.
3. `Quality`를 category로 바꾸는 이유 — pandas가 문자열을 그냥 object로 인식하면 `get_categorical_column_names()` 같은 함수가 "이게 명목형 변수구나"라고 자동으로 못 잡아낼 수 있다. **명시적으로 타입을 선언해줘야 이후 자동화 로직(변수 분류, 반복문)이 제대로 작동한다.**
4. 중복/결측 점검은 "이 단계에서는 점검만 하고 처리는 뒤로 미룬다"는 원칙이 있다 — 왜냐하면 처리 방법(제거? 대체?)은 이후 EDA에서 데이터 분포를 보고 판단하는 게 더 정확하기 때문. 점검과 처리를 분리하는 게 이 파이프라인의 설계 원칙이다.

**재사용 팁**: 이 5단계는 데이터셋이 바뀌어도 거의 그대로 쓸 수 있다. `drop`할 식별자 컬럼명과 `as_category`에 넣을 명목형 컬럼명, 이 두 개만 새 데이터셋에 맞게 바꾸면 된다.

### STEP 4. 종속변수 스위치 지정 & 변수 유형 분류

**질문**: 지금부터의 모든 분석 방향을 결정할 기준이 뭔가?

(코드는 위 1번 섹션 참고 — `target`, `target_is_continuous`, `nominal_cols`, `continuous_cols`)

**생각의 흐름**: 이 시점이 바로 "선형회귀 스타일로 갈 것인가, 로지스틱 스타일로 갈 것인가"가 갈리는 분기점이다. Quality가 good/bad 2개 범주라는 걸 STEP 3에서 이미 확인했으므로, `target_is_continuous = False`로 판단을 내린 것. **이 판단은 사람이 데이터를 보고 하는 것이지 코드가 자동으로 알아내는 게 아니다** — 그래서 이 값을 하드코딩해서 명시적으로 선언한다.

### STEP 5. 서열척도 지정 (필요할 때만)

**질문**: 명목형 변수 중에 "순서가 있는" 변수가 있는가? (예: 학점 F<D<C<B<A, 등급 저<중<고)

```python
ordinal_map = {}   # 이 데이터셋엔 순서가 있는 명목형 변수가 없어서 빈 딕셔너리
df = df2.copy()
for col, order in ordinal_map.items():
    if col in df.columns:
        df[col] = df[col].cat.reorder_categories(order, ordered=True)
```

**생각의 흐름**: 이건 통계 계산이 아니라 **사람의 도메인 지식이 필요한 판단**이다. Quality는 good/bad 2개뿐이고 "good이 bad보다 더 좋다"는 순서는 있지만, 2개짜리 범주라 순서를 지정하지 않아도 이변량 분석(T검정)에는 지장이 없다. 그래서 이번엔 빈 채로 뒀지만, **코드 구조 자체는 지우지 않고 남겨둔다** — 나중에 서열이 있는 데이터(예: 등급, 학년, 만족도 1~5점)를 만나면 `ordinal_map = {"컬럼명": ["낮은등급", "중간등급", "높은등급"]}`처럼 채워 넣기만 하면 되도록.

### STEP 6. 단변량 분석 (EDA 1단계)

**질문**: 변수 하나하나가 각각 어떤 모양(분포)을 하고 있는가? 이상한 값(이상치)은 없는가?

```python
# 종속변수(명목형) - 카운트플롯 + 빈도표
my_plot.countplot(data=df, x=target, hue=target, palette="Set2",
                  title=f"종속변수 {target}({column_mean[target]}) 분포")
freq = df[target].value_counts().rename("빈도").to_frame()
freq["비율"] = df[target].value_counts(normalize=True)

# 독립변수(연속형) 전체 반복 - 히스토그램+박스플롯
for f in continuous_cols:
    fig, ax = my_plot.init(rows=1, cols=2, width=960, height=640,
                           title=f"독립변수 {f}({column_mean[f]}) 분포")
    my_plot.histplot(data=df, x=f, kde=True, ax=ax[0])   # 분포 모양(히스토그램)
    my_plot.boxplot(data=df, x=f, ax=ax[1])                # 이상치(박스플롯)
    my_plot.show()

```

**생각의 흐름**: 종속변수가 연속형이면 왜도/이상치를 보지만, **명목형이면 관심사가 "분포 모양"이 아니라 "범주 비율의 균형"으로 바뀐다.** good/bad가 50:50에 가까운지, 아니면 한쪽으로 심하게 치우쳐 있는지(불균형 데이터)를 봐야 나중에 모델 성능 해석이 왜곡되지 않는다. 독립변수는 for문으로 7개를 한 번에 도는데, **히스토그램(분포 모양) + 박스플롯(이상치) 두 개를 나란히 보는 이유**는 "이 변수의 왜도가 큰 게 실제 분포 특성 때문인지, 극단적인 이상치 몇 개 때문인지"를 구분하기 위해서다.

### STEP 7. 이변량 분석 (EDA 2단계) — 이번 실습의 핵심 (문제 8~15번이 여기서 나옴)

**질문**: 각 독립변수 하나하나가 종속변수(Quality)와 관련이 있는가?

```python
# 연속형 독립변수 -> 명목형 종속변수 : T검정/Mann-Whitney U
for f in continuous_cols:
    print()
    display(Markdown(f"#### {f}({column_mean[f]}) -> {target}"))

    # long -> wide 변환: bad/good 두 집단을 각각 별도 컬럼으로 재배치
    wide_df = my_prep.long2wide(df, hue=target, values=f)
    display(my_stats.test_independent(wide_df,
             group1=wide_df.columns[0], group2=wide_df.columns[1], plot=False))

    my_plot.boxplot(data=df, x=target, y=f, hue=target, palette="Set2",
                    width=720, height=400)

# 명목형 독립변수 -> 명목형 종속변수 : 카이제곱 독립성 검정
for n in nominal_cols:
    print()
    display(Markdown(f"#### {n}({column_mean[n]}) -> {target}"))
    display(my_stats.chi2_independence(df, x=n, y=target, plot=False))
```

**생각의 흐름 (여기가 제일 중요)**:
1. **왜 `long2wide`가 먼저 필요한가**: 원본 데이터는 "행 하나 = 사과 한 개의 측정값" 형태(long)다. 그런데 T검정은 "bad 그룹의 값들"과 "good 그룹의 값들"을 각각 별도의 배열(컬럼)로 받아야 계산할 수 있다. 그래서 검정 함수를 호출하기 **직전에** 형태를 wide로 바꿔주는 전처리가 항상 들어간다. 이 순서를 안 지키면(먼저 검정 함수부터 부르면) 함수가 원하는 입력 모양이 아니라서 에러가 나거나 잘못된 결과가 나온다.
2. **`test_independent()` 내부에서 벌어지는 판단**: 이 함수 하나가 "정규성 검정 → 등분산성 검정 → 그 결과 조합에 따라 Student's t-test/Welch's t-test/Mann-Whitney U 중 알맞은 걸 자동 선택 → 결과표 리턴"까지 전부 캡슐화하고 있다. 즉 내가 매번 "이 변수는 정규성 만족하니까 Welch 써야지" 하고 손으로 판단하지 않아도 되는 것 — **판단 로직 자체를 함수 안에 넣어둔 것**이다.
3. **왜 반복문(for) 안에서 검정 + 시각화를 같이 하는가**: 숫자(p-value)만 보고 "유의하다"고 끝내면 안 된다. 박스플롯을 같이 봐야 "얼마나 다른지(효과 크기)", "어느 쪽 집단이 더 큰지(방향)"까지 눈으로 확인할 수 있다. 문제 14번(bad 평균이 더 큰 유일한 항목 찾기)이 바로 이 박스플롯을 봐야 풀리는 문제다.
4. **카이제곱은 왜 명목형 독립변수에만 도는가**: 카이제곱 독립성 검정은 "두 변수 모두 범주형"일 때 정의되는 지표라서, 연속형 변수에는 쓸 수 없다. `nominal_cols`가 빈 리스트라서(이번 데이터셋엔 명목형 독립변수가 0개) 이 for문은 사실상 아무것도 출력하지 않는다 — 이게 정상이고, "명목형 독립변수 개수 = 0"이라는 문제 7번의 답과 정확히 대응한다.

### STEP 8. 다변량 분석 (EDA 3단계) — 독립변수끼리 상관관계 (문제 16~20번이 여기서 나옴)

**질문**: 이변량에서 종속변수와 관련 있다고 나온 변수들이, 서로 겹치는 정보를 담고 있진 않은가?

```python
corr = my_stats.multi_correlation(df, columns=continuous_cols, plot=False)
my_stats.correlation_summary(corr)
```

**생각의 흐름**: 이변량 분석까지만 하고 끝내면, "종속변수와 관련 있다"고 나온 변수를 전부 모델에 넣으면 될 것 같지만 함정이 있다. 만약 A와 B 두 변수가 서로 상관이 0.9로 매우 높다면, 둘 다 모델에 넣는 게 사실상 같은 정보를 두 번 넣는 것과 비슷해서 **다중공선성(multicollinearity)** 문제가 생긴다. 그래서 "종속변수와의 관계(이변량)"뿐 아니라 "독립변수끼리의 관계(다변량)"까지 같이 봐야 최종적으로 모델에 넣을 변수 조합을 제대로 정할 수 있다. 이번 실습은 상관계수가 전부 절댓값 0.325 이하로 약해서, 다중공선성 문제로 제외해야 할 변수가 없었다 — 그래서 이변량에서 유의했던 변수는 전부 살아남고, 유의하지 않았던 변수도 "상관 문제가 없으니 굳이 지금 지울 필요는 없다"는 논리로 보류된 것 (문제 18~20번 로직).

## 5. 모듈(helpers) 어떻게 바라봐야 하나 — 사고방식

```python
from helpers import *
```
이 한 줄로 `my_qtcheck`, `my_prep`, `my_stats`, `my_plot` 같은 서브모듈이 한번에 들어온다. 처음엔 "그냥 남이 만든 도구를 갖다 쓰는 것"처럼 보이지만, 실제로는 **역할별로 책임이 딱 나눠져 있는 구조**라는 걸 이해하는 게 핵심이다.

| 모듈 | 책임 | 왜 이렇게 나눴나 |
|---|---|---|
| `my_qtcheck` | 데이터 품질 점검 (자료형, 결측, 중복, 기술통계, 변수유형 목록화) | "분석 시작 전 데이터가 믿을 만한가"를 확인하는 역할만 담당 |
| `my_prep` | 데이터 형태 변환/전처리 (long↔wide, 인코딩, 이상치 처리 등) | "분석 함수가 원하는 모양으로 데이터를 바꿔주는" 역할만 담당 |
| `my_stats` | 통계 검정 실행 (t검정, 카이제곱, 상관분석 등) | "가설검정 로직"만 담당 — 어떤 검정을 쓸지 판단하는 것도 여기 포함 |
| `my_plot` | 시각화 (히스토그램, 박스플롯, 카운트플롯 등) | "그림 그리는 것"만 담당, 통계 계산은 안 함 |

**왜 이렇게 나누는 게 중요한가**: 나중에 다른 데이터셋을 분석할 때, "이 값이 왜 이상하지?"라는 문제가 생기면 **어느 모듈을 의심해야 할지** 바로 좁혀진다. 그래프가 이상하면 `my_plot`, 검정 결과가 이상하면 `my_stats`, 데이터 자체가 이상하면 `my_qtcheck` — 이런 식으로 디버깅 범위를 줄일 수 있다.

**두 가지 코딩 버전이 공존하는 이유**: 이 실습에서는 "직접 statsmodels/scipy 코드를 쳐서 검정하는 버전"과 "`my_stats.test_independent()`처럼 모듈 함수 한 줄로 끝내는 버전"이 같이 있다. 처음 배울 때는 **직접 코딩 버전으로 원리를 이해**하고, 그게 맞게 동작하는 걸 확인한 다음에 **모듈로 감싸서 재사용 가능하게 만드는** 게 순서다. 처음부터 모듈만 쓰면 내부에서 뭘 하는지 몰라서 나중에 결과가 이상해도 원인을 못 찾는다. 반대로 매번 처음부터 다 직접 코딩하면 데이터셋 바뀔 때마다 똑같은 코드를 새로 짜야 해서 비효율적이다. → **"직접 코딩으로 검증 → 함수로 모듈화 → 다음부턴 함수 호출"**이 이 커리큘럼 전체를 관통하는 사고방식.

**앞으로 확장할 때 체크할 것**:
- 새 데이터셋을 붙일 때 제일 먼저 바꿔야 하는 건 `target`, `target_is_continuous`, `column_mean` 딱 3개.
- 모듈 함수가 예상과 다른 결과를 내면, 함수를 믿지 말고 **일단 작은 예제로 직접 계산해서 검증**하는 습관을 들일 것 (이전 랩들에서 실제로 `my_ols.py`, `my_plot.py`, `my_logit.py`에서 오타/버그를 여러 번 발견했었다).

## 6. 재사용 가능한 정형화 코드 템플릿 (다른 데이터셋에 그대로 적용)

```python
ordinal_map = {}   # {"컬럼명": [순서]}
df = df2.copy()
for col, order in ordinal_map.items():
    if col in df.columns:
        df[col] = df[col].cat.reorder_categories(order, ordered=True)

# ── STEP 5. 단변량 EDA ────────────────────────────
# (종속변수 타입에 따라 histplot/boxplot 또는 countplot 선택)

# ── STEP 6. 이변량 EDA ────────────────────────────
if target_is_continuous:
    # 연속형 x 연속형 -> 상관분석/산점도
    for f in continuous_cols:
        ...  # my_stats.correlation 계열
else:
    # 연속형 x 명목형(2집단) -> T검정
    for f in continuous_cols:
        wide_df = my_prep.long2wide(df, hue=target, values=f)
        display(my_stats.test_independent(wide_df,
                 group1=wide_df.columns[0], group2=wide_df.columns[1], plot=False))
    # 명목형 x 명목형 -> 카이제곱
    for n in nominal_cols:

# ── STEP 7. 다변량 EDA ────────────────────────────

my_stats.correlation_summary(corr)
```

**암기할 부분**: STEP 3의 if/else 구조와, STEP 6에서 종속변수 타입에 따라 어떤 함수를 쓸지 갈라지는 부분. 나머지는 데이터셋 이름/컬럼명만 바꾸면 되는 뼈대다.

## 7. 문제 20개 — 코드 + 해설 상세 정리

각 문제마다 "이 답을 얻으려면 어느 코드를 봐야 하는지"와 "왜 그 코드가 이 답을 알려주는지"를 같이 적었다. 시험/면접에서 "이거 어떻게 구했어요?"라고 물으면 이 흐름대로 대답하면 된다.

### 문제 1. 원본 관측치(행) 개수
```python
origin = load_data("apple_quality")
origin.info()   # RangeIndex: 4000 entries
```
**해설**: `info()`의 첫 줄 `RangeIndex: N entries`가 행 개수다. 어떤 처리도 하기 전, 원본 그대로의 개수를 묻는 것이므로 `origin`(가공 전 변수)에서 확인해야 한다. **답: 4000**

### 문제 2. 원본 컬럼 개수
```python
origin.info()   # Data columns (total 9 columns)
```
**해설**: 마찬가지로 `origin.info()` 출력의 "total N columns"를 그대로 읽으면 된다. A_id를 포함한 전체 원본 컬럼 수를 묻는 것. **답: 9**

### 문제 3. 분석대상 컬럼 개수 (식별자 제거 후)

### 문제 18~20. 채택/보류/최종 변수 개수
**해설 (코드가 아니라 종합 판단 로직)**:
- **18번(곧바로 채택)**: 이변량 분석(문제 13)에서 유의하다고 나온 변수 중, 다변량(문제 16)에서 다른 변수와 강한 상관도 없는 경우 → 바로 모델에 넣어도 되는 변수. 4개(Size, Sweetness, Juiciness, Ripeness) 전부 해당. **답: 4**
- **19번(보류)**: 이변량에서는 유의하지 않았지만(p≥0.05), 그렇다고 다른 변수와 상관이 높아서 "중복 정보"라고 볼 근거도 없는 경우 → 단독으로는 근거가 약해도 성급하게 제거하지 않고 모형 적합 단계(다변량 모델링)에서 다시 판단하기로 유보. Weight, Crunchiness, Acidity 3개. **답: 3**
- **20번(최종 투입)**: 18번(바로 채택) + 19번(보류, 아직 제거 안 함) = 이변량 분석만으로 확실히 제외할 근거가 있는 변수가 없으므로 7개 전부 모델에 일단 투입. **답: 7**

**이 세 문제의 핵심 논리**: 이변량 분석에서 "유의하지 않다"는 게 "무조건 제거해야 한다"는 뜻이 아니라는 점이 중요하다. 단독으로 볼 땐 관계가 안 보여도, 다른 변수와 결합했을 때(다변량 모델 안에서) 유의미해지는 경우가 있기 때문에, 이변량 단계에서는 "명백히 문제 있는 근거(강한 상관 등)가 없다면" 성급하게 지우지 않고 모델링 단계로 넘기는 게 일반적인 원칙이다.

## 8. 12번 vs 13번, 헷갈리지 않는 법

**12번**: "차이가 가장 없다" → p-value가 **가장 큰** 값 하나를 찾는 것 (7개 중 순위 비교)
**13번**: "유의수준 5% 기준 유의한 개수" → p-value가 **0.05보다 작은** 것들의 개수를 세는 것 (고정된 기준값과 비교)

둘 다 p-value를 보지만 하나는 "순위(가장 큰 게 뭐야)", 다른 하나는 "기준선 통과 여부(0.05보다 작아?)"를 묻는다는 방향 차이가 있다.
