## 0. 큰 그림: Pandas는 무엇이고, 왜 이 순서로 배우는가

- **Pandas** = 표(table) 형태의 데이터를 다루는 라이브러리. 엑셀을 코드로 다룬다고 생각하면 됨.
- Pandas의 자료구조는 크게 2개:
  - **Series** → 1차원 (엑셀의 "한 열")
  - **DataFrame** → 2차원 (엑셀의 "표 전체"). **DataFrame의 모든 행과 열은 사실 Series다.**
- Series를 먼저 이해해야 DataFrame(=Series가 여러 개 옆으로 모인 것)도 쉽게 이해됨.

```
        국어   영어    ← 컬럼(열) = 각각 하나의 Series
이름                    
철수     98    77      ← 각 행도 Series
영희     88    90      
```

데이터 분석은 항상 아래 3단계를 거칩니다.

```
① 데이터를 Series/DataFrame으로 "가져오기·만들기"
        ↓
② 그 데이터가 어떻게 생겼는지 "확인하고 다듬기"
        ↓
③ 완성된 결과를 파일로 "내보내기"
```

**② 확인 단계를 건너뛰고 바로 분석하면, 결측치·이상치·타입 오류가 있는 채로 잘못된 결론을 낼 위험이 크기 때문**에 이 순서를 지킵니다.

### list / ndarray와 Series의 결정적 차이

| 구분 | list / ndarray | Series |
|---|---|---|
| 인덱스 | 암묵적 (0,1,2... 안 보임) | **명시적** (직접 지정 가능, 문자열도 가능) |
| 라벨 | 없음 | 있음 (인덱스가 이름표 역할) |
| 연산 | 그냥 위치대로 연산 | **인덱스 이름 기준**으로 연산 (★중요) |

## 2. ① 객체 만들기

### 2-1. Series 생성 — 3가지 방법

**(1) list로 생성 → 인덱스가 자동으로 0,1,2...**
```python
s1 = Series([10, 30])
# 0    10
# 1    30
```

**(2) ndarray(numpy 배열)로 생성 → list와 결과 동일**
```python
s2 = Series(np.array([100, 200]))
```

**(3) dict로 생성 → dict의 key가 그대로 인덱스가 됨 (★제일 중요)**
```python
s3 = Series({"Hello":123, "world":456, "nice":789})
# Hello    123
# world    456
# nice     789
```

**(4) 생성과 동시에 인덱스 직접 지정 (list/ndarray + index 옵션)**
```python
my1 = Series([10, 20, 30], index=['hello', 'world', 'nice'])
```
→ dict로 만든 것과 결과적으로 똑같은 모양. 즉 "list + index 지정"과 "dict 생성"은 결과가 같음.

### 2-2. DataFrame 생성 — 3가지 방법

| 방법 | 코드 형태 | 특징 |
|---|---|---|
| 2차원 리스트 | `DataFrame(리스트, index=[], columns=[])` | 인덱스·컬럼 이름을 따로 지정해야 함 |
| 딕셔너리 | `DataFrame(딕셔너리)` | **key가 자동으로 컬럼 이름**이 됨 |
| 딕셔너리 리스트 | `DataFrame([{...}, {...}])` | 한 행 = 딕셔너리 하나, key는 역시 컬럼 이름 |

```python
# 방법 1: 2차원 리스트
grade_data = [
    [1, "남자", 98, 77, 88, 64],
    [2, "여자", 88, 90, 62, 72],
]
df = DataFrame(grade_data,
               index=['철수', '영희'],
               columns=['학년','성별','국어','영어','수학','과학'])

# 방법 2: 딕셔너리 (key → 컬럼명)
grade_dic = {'학년':[1,2], '성별':['남자','여자'], '국어':[98,88]}
df = DataFrame(grade_dic, index=['철수','영희'])
df.index.name = '이름'   # 인덱스 자체에도 이름을 붙일 수 있음

# 방법 3: 딕셔너리 리스트 (한 행씩 정의)
grade_list = [
    {"이름":"철수", "학년":1, "국어":98},
    {"이름":"영희", "학년":2, "국어":88},
]
df = DataFrame(grade_list)
```

> 💡 **어떤 걸 쓸지 감**: 엑셀표처럼 행 단위로 데이터가 있으면 "딕셔너리 리스트"가 직관적이고,
> 컬럼 단위로 이미 리스트가 있으면 "딕셔너리"가 편함. 실무에서는 대부분 `read_csv`/`read_excel`로
> 파일을 바로 불러오기 때문에, 이 3가지는 "구조 이해용"으로 알아두면 됨.

### 2-3. 외부 파일에서 DataFrame 만들기 (실무에서 제일 많이 씀)

```python
df = read_csv("경로 또는 URL", encoding="euc-kr", index_col='이름')
df = read_excel("경로 또는 URL", index_col='이름')
```

- `encoding`: 한글 CSV는 `euc-kr` 또는 `cp949`로 읽어야 깨지지 않는 경우가 많음 (원본 파일 인코딩에 따라 다름)
- `index_col='컬럼명'`: 불러오면서 바로 특정 컬럼을 인덱스로 지정 (`set_index`를 따로 안 해도 됨)
- CSV의 **첫 번째 행은 자동으로 컬럼 이름**이 됨
- 엑셀 파일을 다루려면 `openpyxl`, `xlrd` 패키지가 필요 (`!pip install --upgrade openpyxl xlrd`)

### 2-4. 인덱스 다루기 (핵심 개념: **리턴값**)

```python
df2 = df.set_index('이름')   # '이름' 컬럼을 인덱스로 이동한 "복사본"을 리턴
```

⚠️ **가장 중요한 함정**: pandas의 대부분 메서드는 **원본을 바꾸지 않고, 바뀐 결과를 새로 만들어서 "리턴"**합니다.

```python
df.set_index('이름')          # ❌ 리턴값을 안 받음 → 결과가 화면에 보이기만 하고 버려짐. df는 그대로.
df2 = df.set_index('이름')    # ✅ 리턴값을 변수에 담음 → df2가 진짜로 바뀐 상태
```

- Jupyter는 셀 마지막 줄의 리턴값을 **자동으로 화면에 출력**해줍니다. 그래서 `df.set_index('이름')`만 써도
  "바뀐 것처럼" 보이지만, **저장된 게 아니라 그냥 보여준 것뿐**입니다.
  (계산기로 3+4를 눌러서 7이 보이는 것과, 그 7을 어딘가에 적어두는 것의 차이와 같음.)
- 원본을 즉시 바꾸고 싶으면 `inplace=True` 사용 (단, 실수하기 쉬워서 **권장하지 않는 방식**):
  ```python
  df.set_index('이름', inplace=True)  # 리턴값 없음, df 자체가 바로 바뀜
  ```

**인덱스 되돌리기**: `reset_index()`
```python
df3 = df.reset_index()          # 인덱스였던 걸 다시 일반 컬럼으로. 새 일련번호 인덱스 생성됨
df3 = df.reset_index(drop=True) # 기존 인덱스를 컬럼으로 살리지 않고 그냥 삭제
```
⚠️ 이미 `reset_index()`를 한 결과(`df3`)에 또 `reset_index()`를 하면, 기존 일련번호 인덱스가
새 컬럼으로 추가되어버림 → **몇 번째로 하는 건지 항상 의식할 것.**

## 3. ② 데이터 확인하기 — 가장 자주 쓰는 파트

### 3-1. 구조부터 본다

```python
s.dtype          # (Series) 데이터 타입 하나만 확인 (예: int64)
s.info()         # (Series) 종합 정보: 타입, 개수, 결측치 유무, 메모리

origin.ndim      # (DataFrame) 차원 (DataFrame=2)
origin.shape     # (DataFrame) (행 개수, 열 개수)
origin.dtypes    # (DataFrame) 각 컬럼의 데이터 타입
origin.info()    # (DataFrame) 컬럼별 타입 + 결측치 유무를 한 번에 확인
```

`info()` 읽는 법 (Series 예시):
```
<class 'pandas.Series'>          → 이 객체의 종류
Index: 3 entries, hello to nice  → 인덱스 개수/범위
Series name: None                → 이름 없음 (Series(..., name="가격")로 지정 가능)
Non-Null Count  Dtype
3 non-null      int64             → 결측치(NaN) 없이 3개 다 값 있음
memory usage: 48.0+ bytes         → 메모리 사용량 (+는 문자열 인덱스라 추가 메모리 있다는 뜻)
```
- `9 non-null`처럼 나오면 → 9개 행 모두 값이 있다는 뜻. 전체 행 수보다 non-null 수가 적으면 **결측치가 있다는 신호**.

> ✅ **분석 순서 팁**: 새 데이터를 받으면 제일 먼저 `.info()`부터 찍어보는 습관을 들이자.
> "타입이 뭔지 / 빠진 값 있는지"를 제일 먼저 확인하는 게 분석의 시작.

origin.head(2)   # 상위 2건 (기본값 5)

### 3-3. 인덱싱 & 슬라이싱 (Series)

생성 방법에 따라 접근 방식이 달라짐.

**(1) list/ndarray로 만든 경우 → 숫자 인덱스**
```python
s = Series([10, 20, 30, 40, 50])
s[0]        # 10 (인덱싱)
s[1:3]      # 인덱스 1,2 (슬라이싱, 끝값 미포함 — 파이썬 슬라이싱 규칙과 동일)
```

**(2) dict로 만든 경우 → 이름(라벨) 인덱스**
```python
s = Series({"a":100, "b":200, "c":300, "d":400})
s["a"]        # 100
s["b":"d"]    # b,c,d 전부 (⚠️ 라벨 슬라이싱은 끝값 "포함"! 숫자 슬라이싱과 다름)
```

> ⚠️ **주의**: 숫자 인덱스 슬라이싱(`[1:3]`)은 끝을 **포함 안 함**, 라벨 인덱스 슬라이싱(`["b":"d"]`)은
> 끝을 **포함함**. 헷갈리기 쉬우니 꼭 기억.

### 3-4. 열 하나 vs 여러 개 뽑기 (DataFrame) — 대괄호 개수가 타입을 결정한다 (★핵심)

| 코드 | 결과 타입 | 의미 |
|---|---|---|
| `origin['국어']` | **Series** (1차원) | 문자열 하나 → "이 컬럼 하나만 줘" |
| `origin[['국어']]` | **DataFrame** (2차원, 컬럼 1개짜리 표) | 리스트(원소 1개) → "이 컬럼들 줘" |
| `origin[['국어','영어']]` | **DataFrame** | 여러 컬럼 |
| `origin['국어'].values` | numpy.ndarray | Series의 값만 순수 배열로 |

> 💡 **왜 중요한가**: 나중에 머신러닝에서 `X = df[['국어','영어']]` (2차원, 입력 피처들),
> `y = df['성적']` (1차원, 정답)처럼 **입력은 대괄호 두 겹, 라벨은 한 겹**을 구분해서 씁니다.

### 3-5. 행에 접근하기: `loc` vs `iloc` (DataFrame)

| | 기준 | 예시 |
|---|---|---|
| `loc` | **이름(label)** 기반 | `origin.loc['철수']` |
| `iloc` | **위치(번호, index-location)** 기반, 0부터 시작 | `origin.iloc[0]` |

```python
origin.loc['철수']     # '철수' 행 전체 (Series로 반환)
origin.iloc[0]         # 0번째 행 전체
origin.iloc[1:4]       # 1~3번째 행 (슬라이싱 가능, 4번째는 제외)
```

### 3-6. 단일 값(하나의 셀) 접근 (DataFrame)

```python
origin['국어']['철수']       # 열 → 행 순서
origin.loc['철수', '국어']   # loc: 행, 열 순서 (더 명확하고 권장되는 방식)
origin.iloc[1, 2]            # iloc: 행 번호, 열 번호
origin.iloc[:, 3]            # 모든 행에서 3번째 열만 (열 슬라이싱)
```
> 💡 값을 **변경**할 때는 `origin['국어']['철수'] = 100` 방식(체이닝)이 아니라
> 반드시 **`origin.loc['철수','국어'] = 100`** 처럼 `loc`로 접근해서 바꾸는 게 안전합니다.

### 3-7. 값/인덱스만 따로 꺼내기 (Series)

```python
s.values   # 값들만 → numpy ndarray 타입으로 반환
s.index    # 인덱스만 → pandas Index 타입으로 반환

list(s.values)   # 순수 파이썬 list로 변환하고 싶을 때
list(s.index)
```
→ Series는 사실 `[값들(ndarray)] + [인덱스(Index)]`가 합쳐진 구조라고 이해하면 됨.

### 3-8. 값 변경하기 (DataFrame)

```python
# 단일 값 변경
origin.loc['철수', '국어'] = 100

# 열 전체에서 특정 값을 일괄 치환
origin['영어'] = origin['영어'].replace(88, 92)

# 조건에 맞는 행만 골라서 특정 열 값 변경 (가장 실무적으로 많이 쓰는 패턴)
origin.loc[origin['수학'] < 50, '수학'] = 0
```
→ 마지막 패턴 `df.loc[조건, '열'] = 값`은 **"조건 필터링 + 값 수정"**의 표준 형태이니 꼭 기억.

### 3-9. Series 연산 — 인덱스 이름 기준 (★핵심 개념)

**(1) Series끼리 연산 → 인덱스 이름이 같은 것끼리 계산됨 (위치가 아니라 이름 기준!)**
```python
my1 = Series([10,20,30], index=['hello','world','nice'])
my2 = Series({"world":1, "test":2, "hello":3})

my1 + my2
# hello    13.0   (10+3)
# nice     NaN    (my2에 'nice' 없음 → 계산 불가 → NaN)
# test     NaN    (my1에 'test' 없음 → 계산 불가 → NaN)
# world    21.0   (20+1)
```
> 💡 **numpy 배열 연산과 결정적으로 다른 지점**. numpy는 순서대로(위치 기준) 더하지만,
> Series는 "이름표"가 같은 것끼리만 계산하고, 짝이 없으면 `NaN`(Not a Number, 결측값)을 만듦.

**(2) Series와 숫자(스칼라) 연산 → 모든 원소에 동일하게 적용 (numpy와 동일한 동작)**
```python
my1 + 1000   # 전체 원소에 +1000
my1 * 5      # 전체 원소에 *5
```

### 3-10. 조건 검색(필터링) — 실무에서 제일 많이 쓰는 부분

**(1) 기본 조건 검색 (numpy와 동일한 표현식)**
```python
col = Series(np.arange(0, 100, 10))
col[col > 30]     # 조건을 만족하는 값들만 추출
```

**(2) AND 검색 → 대괄호를 이어서(이중으로) 씀**
```python
col[col <= 70][col > 10]   # 10보다 크고 70 이하인 것만
```

**(3) OR 검색 → 괄호로 감싸고 파이프(|)로 연결**
```python
col[(col <= 10) | (col >= 70)]
```

> ⚠️ **주의 3가지 (초보자가 제일 많이 실수하는 부분)**
> 1. 조건마다 반드시 **괄호로 감싸기**: `(col <= 10) | (col >= 70)` — 괄호 안 하면 에러남.
> 2. and/or 대신 **`&`, `|`** 사용 (파이썬 기본 and/or는 Series에서 안 통함).
> 3. 조건에 맞는 게 하나도 없으면 에러가 아니라 **빈 Series**가 반환됨 (`Series([], dtype: int64)`).

### 3-11. 기술 통계량 (Series)

```python
s.sum()        # 합계
s.mean()       # 평균
s.max()        # 최댓값
s.min()        # 최솟값
s.var()        # 분산
s.std()        # 표준편차
s.median()     # 중앙값
s.quantile(0.25)  # 1사분위수
s.quantile(0.5)   # 2사분위수 (=중앙값)
s.quantile(0.75)  # 3사분위수
```
→ ndarray(numpy)가 갖고 있는 통계 기능을 Series도 그대로 갖고 있음.

### 3-12. 기술 통계량 (DataFrame) — 수치형 vs 명목형을 구분해서 본다

**수치형 컬럼** (국어, 영어처럼 계산 가능한 숫자):
```python
origin['국어'].sum()
origin['국어'].mean()
origin['국어'].max()
origin['국어'].min()
origin['국어'].var()
origin['국어'].std()
origin['국어'].median()
origin['국어'].quantile(0.25)
origin['국어'].describe()  # 위 통계량을 한 번에 요약
```

**DataFrame 전체 요약**:
```python
df2 = origin[['국어','영어','수학','과학']]  # 계산 가능한 열만 골라서
desc = df2.describe()
t = desc.T   # 전치(transpose): 가로세로를 바꿔서 보기 편하게
```

**명목형(카테고리) 컬럼** (성별, 학년처럼 종류를 세는 게 의미 있는 데이터):
```python
origin['성별'].value_counts()  # 값별 개수(빈도수)

origin['학년'] = origin['학년'].astype('category')  # 숫자여도 "범주"로 취급하고 싶으면 변환
origin.describe(include=['object', 'category']).T
# count: 총 개수 / unique: 종류 수 / top: 최빈값 / freq: 최빈값 개수
```
> 💡 `describe()`는 **기본적으로 숫자형만** 요약합니다. 성별처럼 문자(object)나 category 타입은
> `include='object'` 또는 `include=['object','category']`를 명시해야 나옵니다.

### 3-13. 타입 변환 (astype)

```python
origin.astype('float')   # 실수형으로 변환
origin.astype('str')     # 문자열로 변환
```
→ numpy와 사용법 동일. 변환 후 `.info()`로 타입이 잘 바뀌었는지 확인하는 습관 들이기.

### 3-14. 데이터 정렬

| 코드 | 기준 | 방향 |
|---|---|---|
| `s.sort_values()` | **값** | 오름차순 (기본) |
| `s.sort_values(ascending=False)` | 값 | 내림차순 |
| `s.sort_index()` | **인덱스(라벨)** | 오름차순 (기본) |
| `s.sort_index(ascending=False)` | 인덱스 | 내림차순 |

> 💡 정렬해도 원본은 안 바뀜 (새 변수에 담아서 써야 함, 예: `sort1 = origin.sort_values()`).

## 4. ③ 데이터 내보내기

### 4-1. 엑셀로 저장

```python
origin.to_excel("1.xlsx")   # 가장 단순한 형태 (인덱스 포함됨)

origin.to_excel("2.xlsx",

                index=False,                       # 인덱스 제외
                columns=["학년","성별","국어"],     # 저장할 컬럼만 선택
                header=['level','sex','kor']        # 컬럼명을 영문 등으로 바꿔서 저장
)
```

### 4-2. CSV로 내보내기 — **인코딩이 핵심**

```python
origin.to_csv("1.csv", encoding='utf-8')   # utf-8 → 엑셀에서 열면 한글 깨질 수 있음
origin.to_csv("1-1.csv", encoding='cp949') # cp949 → 한국 엑셀에서 한글 안 깨짐

origin.to_csv("2.csv", encoding="utf-8", index=True, index_label="Name")

origin.to_csv("3.csv",
              encoding="utf-8",
              index=False,
              columns=['학년','성별','국어'],
              header=['level','sex','kor'])
```

> 💡 **CSV 저장 시 인코딩 선택 기준**
> - 엑셀(윈도우 한국어판)에서 바로 열어볼 파일 → `encoding='cp949'` (또는 `euc-kr`)
> - 파이썬/웹/다른 시스템에서 다시 읽을 파일 → `encoding='utf-8'` (국제 표준, 호환성 좋음)

### 4-3. 엑셀 vs CSV 내보내기, 공통 파라미터 정리

| 파라미터 | 의미 |
|---|---|
| `index` | 인덱스 열을 파일에 포함할지 (True/False) |
| `index_label` | 인덱스를 포함할 때, 그 열의 제목 |
| `columns` | 저장할 컬럼을 리스트로 선택 (일부만 내보낼 때) |
| `header` | 저장될 컬럼명을 새로 지정 (원래 이름 대신) |
| `encoding` | (CSV 전용) 문자 인코딩 지정 |

## 5. 종합 연습으로 본 "실전 분석 흐름"

```python
scores = Series({"국어":85, "영어":92, "수학":78, "과학":95, "사회":88})
```

이 짧은 예제 안에 **분석의 기본 흐름 4단계**가 다 들어있음:

1. **전체 훑어보기** → `print(scores)` (데이터 구조/값 확인)
2. **특정 항목 콕 집어 보기** → `scores["수학"]` (개별 조회, 인덱싱)
3. **조건에 맞는 것만 걸러보기** → `scores[scores >= 90]` (조건 검색/필터링)
4. **전체를 하나의 숫자로 요약하기** → `scores.mean()` (통계 요약)

👉 **앞으로 어떤 데이터셋을 받든 이 순서(전체보기 → 개별조회 → 조건필터 → 통계요약)로 접근하면 얼개를 잃지 않음.**

### 참고: print 유무에 따른 출력 차이

- **주피터 노트북 셀의 "마지막 줄"**: print 없어도 자동으로 화면에 출력됨.
- **셀 중간 줄**: print 없으면 안 보임.
- **.py 파일 실행 시**: print 없으면 그 어떤 것도 안 보임 (주피터만의 특수 동작이므로 실무 스크립트에서는 항상 print 필요).

## 6. 🔑 새 데이터셋을 받았을 때 사고 순서 (통합 체크리스트)

Series 단계와 DataFrame 단계의 체크리스트를 하나로 합친, **처음부터 끝까지의 전체 흐름**입니다.

```
① 담기        : Series/DataFrame 생성 (list, dict, 파일 불러오기 등)
                 → read_csv() / read_excel() / Series(...) / DataFrame(...)
② 정체 파악    : .dtype, .ndim, .shape, .dtypes, .info() 로 타입/개수/결측치 확인
③ 미리보기     : .head(), .tail() — 실제 값이 어떻게 생겼는지 눈으로 확인
④ 값/인덱스    : .values / .index 로 따로 꺼내보기
⑤ 개별/구간 조회: 인덱싱, 슬라이싱, loc/iloc, df[[...]] vs df[...]
⑥ 계산         : 사칙연산 (Series는 인덱스 이름 기준 매칭 주의! 짝 없으면 NaN)
⑦ 조건 필터링  : 기본/AND/OR 조건 검색, 필요시 loc로 값 수정
⑧ 통계 요약    : sum/mean/max/min/var/std/median/quantile/describe/value_counts
                 (수치형/명목형 구분해서 보기)
⑨ 타입 변환    : astype() — 변환 후 .info()로 재확인
⑩ 정렬         : sort_values() / sort_index()
⑪ 저장         : to_csv() / to_excel() — 인코딩과 인덱스 포함 여부를 항상 의식
```

이 11단계가 이 문서 전체의 뼈대입니다.

## 7. 오늘 헷갈리기 쉬운 것 총정리

1. **dict로 만들면 key = 인덱스.** (Series, DataFrame 공통)
2. **숫자 슬라이싱은 끝 미포함 / 라벨 슬라이싱은 끝 포함.** (`s[1:3]` vs `s["b":"d"]`)
3. **Series끼리 연산은 "위치"가 아니라 "인덱스 이름"이 기준** → 짝 없으면 NaN.
4. **조건 검색은 `&`, `|` 사용 + 각 조건 괄호로 감싸기.** (and/or, 괄호 생략은 에러)
5. **조건에 맞는 게 없으면 에러가 아니라 빈 Series/DataFrame.**
6. **리턴값을 받아야 진짜로 바뀐다.** `df.set_index(...)`만 쓰면 화면엔 보이지만 저장 안 됨.
   `df2 = df.set_index(...)`처럼 변수에 담아야 함. (`inplace=True`는 원본을 직접 바꾸지만 지양)
7. **대괄호 한 겹 = Series(1차원), 두 겹 = DataFrame(2차원).**
   `df['국어']` vs `df[['국어']]` — ML에서 X(피처)/y(라벨) 구분과 직결됨.
8. **loc = 이름 기반, iloc = 번호(0부터) 기반.** 값 변경은 `loc`로 하는 게 안전.
9. **`describe()`는 기본이 숫자형만.** 문자/카테고리형은 `include='object'` 명시해야 함.
10. **CSV 저장 시 인코딩을 목적에 맞게 선택.** (엑셀용=cp949/euc-kr, 범용=utf-8)
11. **`reset_index()`를 두 번 하면 안 됨** — 이미 리셋된 것에 또 하면 불필요한 컬럼이 추가됨.
12. **정렬해도 원본은 안 바뀜** — sort 결과도 새 변수에 담아서 써야 함.
13. **주피터에서 셀 마지막 줄은 print 없어도 출력**되지만, `.py` 파일에서는 무조건 print 필요.
