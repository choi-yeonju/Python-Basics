# LAB-07. 독립표본 검정 (Independent Samples Test) — 개념부터 실전까지

> 지난번 "대응표본 검정" 정리 문서의 후속편이다. 오늘은 **서로 다른(독립적인) 두 집단**을 비교하는 방법을 배웠다.
> 지난 문서와 마찬가지로, 나중에 다시 봐도 "왜 이렇게 하는지" 기억할 수 있도록 정리한다.

---

## 1. 오늘 배운 것 한 줄 요약

**서로 관련 없는 두 집단**(예: 지혈제 그룹 vs 다른 지혈제 그룹, 정상 인공심장 그룹 vs 비정상 그룹)의 평균/분포에 차이가 있는지 검정하는 방법을 배웠다.

지난번 대응표본과 달리, 오늘은 **가정 확인 단계가 한 단계 더 많다.**

```
정규성 검정 (두 집단 각각) 
      │
      ├── 둘 다 정규성 O ──▶ 등분산성 검정
      │                         ├── 등분산 O ──▶ Student's T-Test
      │                         └── 등분산 X ──▶ Welch's T-Test
      │
      └── 하나라도 정규성 X ──▶ Mann-Whitney U test (비모수)
```

---

## 2. 독립표본과 대응표본, 무엇이 다른가 (지난 정리와 이어서)

| 구분                  | 대응표본 (paired)                                             | 독립표본 (independent)                                             |
| --------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| 비교 대상             | **같은 개체**의 전/후, 두 조건                          | **서로 다른 개체**로 이루어진 두 집단                        |
| 예시                  | 같은 사슴의 앞다리 vs 뒷다리, 같은 첨가제 실험의 전/후        | 지혈제 A를 쓴 환자들 vs 지혈제 B를 쓴 환자들 (다른 사람들)         |
| 정규성 검정 대상      | **차이값(diff)** 하나만 검정                            | **두 집단 각각** 따로 검정                                   |
| 등분산성 검정         | **하지 않음** (diff 하나로 환원되므로 개념 자체가 없음) | **한다** (두 집단의 퍼짐 정도가 같은지가 검정 방법을 가른다) |
| 정규성 만족 시 검정   | Paired T-test                                                 | Student's T-test (등분산) 또는 Welch's T-test (이분산)             |
| 정규성 미충족 시 검정 | Wilcoxon signed-rank test                                     | Mann-Whitney U test                                                |

**핵심 차이 한 문장**: 대응표본은 "짝을 지어서 차이 하나를 본다"는 개념이고, 독립표본은 "두 집단을 나란히 놓고 비교한다"는 개념이다. 그래서 독립표본에서는 등분산성이라는, 대응표본에는 없던 가정이 하나 더 필요해진다.

## 3. 통계 개념을 말로 풀어보기

### 3-1. 독립표본이란 (다시 한번)

- **서로 다른 대상**으로부터 얻은 두 그룹의 데이터. 한쪽 그룹에 어떤 사람이 있다고 해서 다른 쪽 그룹의 값에 영향을 주지 않는다.
- 예: 지혈제 실험에서 B그룹 환자들과 G그룹 환자들은 완전히 다른 사람들이다. "이 환자가 B그룹이면서 동시에 G그룹이다"라는 것 자체가 불가능하다 — 이게 대응표본과의 근본적 차이다.

### 3-2. 등분산성(equal variance)이란

- **두 집단의 "퍼짐 정도(분산)"가 서로 같은지**를 보는 가정.
- 예를 들어 A그룹은 값들이 3~5 사이에 몰려있고, B그룹은 1 ~10까지 넓게 퍼져있다면, 두 그룹은 평균이 같아도 "등분산"이 아니다.
- 등분산 검정에는 두 가지가 있다:
  - **Bartlett 검정**: 두 그룹이 **모두 정규분포를 따를 때** 사용. 정규성에 민감하지만 검정력이 좋다.
  - **Levene 검정**: 정규성을 만족하지 못할 때도 안정적으로 쓸 수 있는 대안. `my_stats.test_assumptions()`는 "모든 변수가 정규성을 충족하면 Bartlett, 하나라도 못 충족하면 Levene"으로 자동 분기한다.
- 등분산 검정의 귀무가설도 정규성 검정처럼 방향이 "반대"다: **귀무가설 = "두 분산이 같다"**. p ≥ 0.05면 귀무가설을 기각하지 못해서 "등분산이다"라고 본다.

### 3-3. Student's T-test vs Welch's T-test — 뭐가 다른가

- 두 검정 모두 **"두 집단의 평균이 같은지"**를 보는 t검정이다. 차이는 딱 하나: **분산이 같다고 가정하느냐 아니냐**.
- **Student's T-test**: 두 집단의 분산이 같다고 가정하고, 두 집단의 분산을 하나로 합쳐서(pooled variance) 계산한다. 등분산성 가정이 만족될 때 사용.
- **Welch's T-test**: 두 집단의 분산이 다를 수 있다고 보고, 각 집단의 분산을 따로 반영해서 계산한다. 등분산성이 깨졌을 때 쓰는 좀 더 안전한 대안.
- 실무에서는 등분산 여부가 애매할 때 그냥 항상 Welch를 쓰기도 하는데(Welch가 등분산일 때도 결과가 거의 비슷하기 때문), 이번 LAB에서는 **정확히 검정 순서를 지켜서 등분산이면 Student, 아니면 Welch**로 나누는 정석 절차를 밟았다.

### 3-4. Mann-Whitney U test란

- 두 집단 중 **하나라도 정규성을 만족하지 못하면** 쓰는 비모수 검정.
- t검정이 "평균"을 비교한다면, Mann-Whitney U는 **두 집단을 섞어서 전체 순위를 매긴 뒤, 각 집단의 순위 합을 비교**하는 방식이다. (지난번 배운 Wilcoxon signed-rank test와 원리가 비슷하지만, Wilcoxon은 "짝의 차이"에 순위를 매기고, Mann-Whitney는 "두 집단을 합친 것" 전체에 순위를 매긴다는 점이 다르다.)
- 정규분포를 가정하지 않기 때문에 이상치(outlier)에 덜 민감하다.

### 3-5. 가설 설정 (독립표본, 두 그룹 A vs B 예시)

- **귀무가설(H0)**: 두 그룹의 평균(또는 분포)이 같다. (A = B)
- **대립가설(H1, 양측)**: 두 그룹이 다르다. (A ≠ B)
- **좌측 단측**: A가 B보다 작다. (H0: A ≥ B, H1: A < B)
- **우측 단측**: A가 B보다 크다. (H0: A ≤ B, H1: A > B)
- 지난번에 정리했던 "`alternative`는 항상 첫 번째 인수 − 두 번째 인수를 기준으로 해석한다"는 규칙이 `ttest_ind`, `mannwhitneyu` 모두에 동일하게 적용된다.

## 4. 분석 프로세스 — 독립표본 검정의 표준 흐름

```
1. 데이터 불러오기 (load_data)
2. (선택) 시각화를 위해 wide → long 형태로 재배치 (melt)
3. 분포 시각화로 데이터 감 잡기 (kdeplot 등)
4. 가정 확인 (test_assumptions)
   - 각 그룹의 정규성 검정
   - 두 그룹 모두 정규성 만족 시에만 등분산성 검정까지 수행
5. 가정 결과에 따라 검정 방법 3가지로 분기
   - 둘 다 정규성 O, 등분산 O → Student's T-test
   - 둘 다 정규성 O, 등분산 X → Welch's T-test
   - 하나라도 정규성 X       → Mann-Whitney U test
6. 필요에 따라 양측/좌측/우측 검정 각각 수행
7. 결과 시각화 (boxplot + Annotator로 검정 결과 주석 달기)
```

이 흐름에서 5번(3방향 분기)이 지난번 대응표본(2방향 분기: t-test ↔ Wilcoxon)보다 한 단계 복잡해진 부분이다.

## 5. 이번 실습에서 나온 특이 케이스들

### 5-1. #02 지혈제 예제 — 표준 케이스

- `df1['B']`, `df1['G']` 두 그룹 모두 정규성 검정 통과 → 등분산성까지 검정 → Student's T-test(`equal_var=True`) 사용.
- 가장 기본적인 "정규성 O, 등분산 O" 케이스다.

### 5-2. #03 인공심장 예제 — Welch 케이스, 그리고 코드 오타 발견

```python
s, p = ttest_ind(df2['그룹2'], df2['그룹2'], equal_var=False)  # 양측검정
```

여기 **오타가 있다.** `그룹2`, `그룹2`로 같은 컬럼을 두 번 넣었다. 원래 의도는 `df2['그룹1'], df2['그룹2']`였을 것이다. 실제로 바로 다음 좌측/우측 단측검정 코드에서는 `그룹1, 그룹2`로 올바르게 쓰여 있어서, 양측검정 셀만 실수로 잘못 복붙된 걸 알 수 있다.

> **배울 점**: `ttest_ind(A, A, ...)`처럼 같은 데이터를 두 번 넣으면 statistic이 0, p-value가 1에 가깝게 나오는 등 결과가 이상하게 나온다. 검정 결과가 "너무 뻔하게" 나오면, 인수를 실수로 같은 걸 두 번 넣지 않았는지부터 의심하는 습관을 들이면 좋다.

이 예제는 등분산성이 깨져서(또는 처음부터 `equal_var=False`로 지정해서) **Welch's T-test**를 사용했다.

### 5-3. #03 진통제 예제 — long 데이터를 wide로 바꾸는 새로운 방법

지금까지는 `pivot_table`을 쓸 때 이미 "짝을 지을 수 있는 고유 식별자(code, id 등)"가 있는 경우만 다뤘다. 그런데 이번 데이터는 애초에 "짝지을 필요가 없는" 독립표본인데도 wide 형식으로 바꿔야 했다. 이때 쓴 방법:

```python
# 1. 그룹별로 순번을 매긴다 (그룹 내에서 0, 1, 2, ...)
df3_group = df3.copy()
df3_group['idx'] = df3_group.groupby("group").cumcount()

# 2. 그 순번을 임시 식별자로 삼아 pivot
df3_pivot = pivot_table(df3_group, index='idx', columns='group', values='value')
```

`groupby("group").cumcount()`는 **그룹 안에서 0부터 순서대로 번호를 매기는 함수**다. 예를 들어 "약물A"가 5명, "약물B"가 5명이면 각각 0~4번이 매겨진다.

> **중요한 주의점**: 이 `idx`는 **진짜 짝(pair)이 아니다.** 약물A의 0번째 사람과 약물B의 0번째 사람이 실제로 관련 있는 사람들이 아니라, 그냥 "표를 wide 형식으로 만들기 위한 임시 순번"일 뿐이다. `mannwhitneyu`나 `ttest_ind`는 애초에 두 컬럼의 "행 순서가 대응된다"는 걸 요구하지 않는 검정이기 때문에, 이렇게 순번으로 억지로 넣어도 통계적으로 문제는 없다. 지난 LAB(대응표본)에서 "짝을 명시적으로 보장해야 한다"고 강조했던 것과 헷갈리지 않아야 한다 — **그건 대응표본에서만 중요한 이야기**고, 독립표본 검정에서는 두 컬럼이 굳이 같은 행끼리 대응될 필요가 없다.

### 5-4. #03 진통제 예제 — Annotator 설정의 사소한 실수

```python
annotator.configure(test='t-test_welch')  # 주석에는 Mann-Whitney라고 써놓고 실제로는 t-test_welch를 씀
```

주석에는 "Mann-Whitney" 검정을 쓰겠다고 적혀 있는데, 실제 `configure()` 호출에는 `'t-test_welch'`가 들어가 있다. `test_assumptions` 결과를 보면 이 데이터는 정규성을 만족하지 못해 Mann-Whitney U test를 썼어야 하는 케이스였을 가능성이 높다.

> **배울 점**: 시각화 주석(Annotator)에 넣는 `test` 문자열은 **실제로 위에서 수행한 통계 검정과 반드시 일치시켜야 한다.** 그래프에 표시되는 유의성 표시(`*`, `**`, `ns` 등)가 실제 검정 결과와 다른 값을 기반으로 계산되기 때문이다. 코드를 복붙해서 쓸 때 이 부분을 특히 조심해야 한다.

## 6. 코드 두 가지 버전 — Raw 코드 vs 모듈화 코드 (`test_independent`)

### 버전 A — Raw 코드 (지혈제 예제)

```python
my_stats.test_assumptions(df1, columns=['B', 'G'])

s, p = ttest_ind(df1['B'], df1['G'], equal_var=True)
print(f"statistic: {s:.4f}, p-value: {p:.4f}")

s, p = ttest_ind(df1['B'], df1['G'], equal_var=True, alternative='less')
...
s, p = ttest_ind(df1['B'], df1['G'], equal_var=True, alternative='greater')
...

fig, ax = my_plot.init()
my_plot.boxplot(...)
annotator = Annotator(...)
annotator.configure(test='t-test_ind')
annotator.apply_and_annotate()
my_plot.show()
```

- 가정 확인 결과를 사람이 직접 눈으로 보고 `equal_var=True`를 손으로 지정했다. 이 과정에서 등분산성 결과를 잘못 읽거나(위 5-2 사례), 검정 이름을 잘못 적는(위 5-4 사례) 실수가 생길 여지가 있다.

### 버전 B — 모듈화 코드 (`my_stats.test_independent()`)

```python
my_stats.test_independent(df1, "B", "G")
my_stats.test_independent(df2, "그룹1", "그룹2")
my_stats.test_independent(df3_pivot, "약물A", "약물B")
```

- `my_stats.py`를 열어보면 이 함수 하나가 **가정 확인 → 정규성/등분산성 결과에 따라 3가지 검정 중 하나 자동 선택 → 양측/좌측/우측 3방향 검정 → 시각화까지** 전부 자동으로 처리한다.
- 특히 아래 로직이 핵심이다:
  ```python
  if not both_normal:
      test_name = "Mann-Whitney U test"
  elif equal_var:
      test_name = "Student t-test"
  else:
      test_name = "Welch t-test"
  ```

  이 부분이 정확히 "2절"에서 정리한 3방향 분기 흐름을 코드로 그대로 옮긴 것이다. **모듈을 쓰면 5-2, 5-4에서 발견한 것 같은 사람이 손으로 옮기다 생기는 실수(오타, 잘못된 검정 이름 지정)가 원천적으로 사라진다.** 이게 모듈화의 가장 큰 이점이다.

### 사고방식 정리

1. 처음에는 raw 코드로 각 단계(가정 확인 → 검정 선택 → 검정 수행 → 시각화)를 눈으로 직접 확인하며 이해한다.
2. 같은 패턴(가정 확인 → 3방향 분기 → 검정 → 시각화)이 반복된다는 걸 알게 되면, 그 패턴 전체를 함수로 캡슐화한다.
3. 캡슐화된 함수(`test_independent`)를 쓸 때도, "이 함수가 내부적으로 어떤 조건에서 어떤 검정을 자동으로 고르는지" 한 번은 `my_stats.py`를 열어서 확인해두면, 나중에 함수가 예상과 다른 검정을 골랐을 때 원인을 바로 찾을 수 있다. (예: "어? Student's t-test가 나올 줄 알았는데 왜 Welch가 나왔지?" → 등분산성 결과부터 확인)

## 7. `test_independent()` 함수 시그니처로 보는 설계 사고방식

```python
def test_independent(data, group1, group2, alpha=0.05, plot=True, palette=None,
                     title=None, xlabel=None, ylabel=None, width=1280, height=640, save_path=None):
```

- `data`: 하나의 DataFrame. `group1`, `group2`는 그 안의 **두 컬럼명(문자열)**이다.
- 지난 `test_paired(data, before, after, ...)`와 파라미터 구조가 거의 동일하다 — **일관된 인터페이스**를 유지하고 있다는 걸 알 수 있다. 이런 일관성 덕분에 "대응표본이든 독립표본이든 함수 호출 방식이 비슷하다"는 감각을 익힐 수 있고, 새로운 함수를 배울 때 학습 부담이 줄어든다.
- 내부적으로 `a = data[group1].dropna()`, `b = data[group2].dropna()`로 **각 컬럼을 독립적으로 결측 제거**한다. 대응표본의 `test_paired`가 `data[[before, after]].dropna()`로 **두 컬럼을 함께** 결측 제거하던 것과 다르다.
  - 왜 다른가? 대응표본은 짝이 있어야 하므로 한쪽이 없으면 그 짝 전체를 버려야 한다. 독립표본은 애초에 서로 관련 없는 데이터라서, 한쪽에 결측치가 있어도 다른 쪽 데이터는 그대로 살려서 쓸 수 있다.
  - 이 차이를 알고 있으면, 두 함수 중 어느 걸 써야 할지 헷갈릴 때 "이 두 컬럼이 결측 처리 방식에서 어떻게 달라야 하는가?"를 기준으로 다시 생각해볼 수 있다.

## 8. 새로운 데이터셋을 만났을 때 적용할 체크리스트 (독립표본 버전)

1. `load_data()` → `.head()`, `.isna().sum()`, 컬럼 확인으로 데이터 구조 파악.
2. **두 그룹이 서로 다른 대상인지(독립표본), 같은 대상의 전/후인지(대응표본)** 먼저 구분한다.
3. 독립표본이 확인되면 그룹별로 `test_assumptions()`를 돌려서 정규성 + 등분산성을 한 번에 확인한다.
4. 결과에 따라 Student's / Welch's / Mann-Whitney U 셋 중 하나를 선택한다 (또는 `test_independent()`를 그냥 호출).
5. 양측/좌측/우측 중 필요한 방향의 가설을 정하고 검정한다.
6. boxplot + Annotator로 시각화하되, **Annotator에 넣는 `test` 문자열이 실제로 수행한 검정과 일치하는지 반드시 재확인**한다 (5-4 실수 방지).
7. wide 형식이 필요한데 원래 짝지을 식별자가 없다면, `groupby(...).cumcount()`로 임시 순번을 만들어 pivot해도 무방하다 — **단, 이건 어디까지나 표 형태를 맞추기 위한 것이지 실제 짝짓기가 아니라는 것**을 잊지 않는다.
