## 0. 오늘 핵심 한 문장 요약

**서브플롯 = 하나의 도화지(fig) 안에 여러 개의 작은 그래프(ax)를 나눠서 그리는 것.**
그리고 `my_plot` 모듈의 모든 함수는 "이 ax 하나짜리 도화지 조각에 그림을 그려줘" 라는 요청을 받아서 처리할 수 있도록 설계돼 있음. 이게 오늘 배운 것의 전부라고 봐도 됨.

## 0-1. 진짜 기초 개념 — `plt`, `fig`, `ax`가 각각 뭔지

여기서부터 확실히 잡고 가면 뒤에 나오는 내용이 다 쉬워짐.

### (1) `plt`가 뭐야?

```python
from matplotlib import pyplot as plt
```

`matplotlib`이라는 그림 그리는 라이브러리가 있고, `pyplot`은 그 안에서 "그래프 그리는 도구 모음"임. `plt`는 줄여 부르는 이름.

> 비유: **`plt` = 미술 도구함 전체.** 여기 안에 캔버스도 있고, 붓도 있고, 액자도 있음.

### (2) `fig`가 뭐야?

`fig`는 **"도화지" 그 자체**. 그림이 그려질 종이 한 장.

```python
fig, ax = plt.subplots()
```

이 코드 한 줄이 하는 일: "도화지 한 장(`fig`) 줘. 그 위에 그림 그릴 영역(`ax`)도 하나 줘."

### (3) `ax`가 뭐야? (제일 헷갈리는 부분)

`ax`는 **`axes`의 줄임말**이고, 도화지 안에서 실제로 **그래프가 그려지는 네모난 영역** 하나를 말함.

```
┌─────────────────────┐
│  fig (도화지 전체)     │
│  ┌─────────────┐     │
│  │   ax        │     │  ← 여기 이 액자 안에 실제 선/막대/점이 그려짐
│  │  (그래프영역)  │     │
│  └─────────────┘     │
└─────────────────────┘
```

- `fig` = 벽에 걸 액자 틀 전체
- `ax` = 그 액자 틀 안의 "그림이 실제로 그려지는 캔버스"

축(x축, y축), 눈금, 제목, 그리드, 실제 선이나 막대 — 이 모든 게 `ax` 위에 그려짐. `fig`는 그냥 그 `ax`들을 담고 있는 큰 틀일 뿐이고, `fig` 자체에는 그림이 직접 그려지지 않음.

**그래서 그래프를 그릴 때 `sb.boxplot(..., ax=???)` 처럼 항상 "어느 ax에 그릴지"를 지정해주는 것.** ax가 곧 "이 그림이 들어갈 자리"이기 때문.

### (4) 왜 도화지(fig)랑 그림영역(ax)을 따로 나눴을까?

**한 도화지 안에 그림영역(ax)을 여러 개 넣을 수 있게 하려고.**

```python
fig, ax = plt.subplots(2, 3)
```

이러면 도화지 한 장(`fig`) 안에, 2행 3열로 배치된 **그림영역 6개**(`ax` 6개)가 생김. 이게 바로 "서브플롯".

```
┌───────────────────────────────────┐
│  fig (도화지 한 장)                    │
│  ┌───┐ ┌───┐ ┌───┐                 │
│  │ax0│ │ax1│ │ax2│   ← 1행           │
│  └───┘ └───┘ └───┘                 │
│  ┌───┐ ┌───┐ ┌───┐                 │
│  │ax3│ │ax4│ │ax5│   ← 2행           │
│  └───┘ └───┘ └───┘                 │
└───────────────────────────────────┘
```

도화지는 하나인데, 그 안에 작은 액자(ax)가 6개 걸려있는 그림. 이게 서브플롯의 정체.

### (5) `ax = ax.flatten()`은 왜 하는 거야?

위 그림처럼 `ax`가 6개 생기면, 파이썬은 이걸 **2차원 표(행,열) 형태**로 저장함.

```python
ax[0][0]  # 1행 1열
ax[0][1]  # 1행 2열
ax[1][0]  # 2행 1열
```

이렇게 `[행][열]`로 매번 접근하려면 번거로움. `flatten()`은 이 2차원 표를 **한 줄로 쭉 펴주는** 것.

```
펴기 전:        펴고 난 후:
[ax0 ax1 ax2]
[ax3 ax4 ax5]  →  [ax0, ax1, ax2, ax3, ax4, ax5]
```

그러면 `ax[0]`, `ax[1]`, `ax[2]`... 이렇게 **순서대로 하나씩** 꺼내 쓸 수 있어서, 반복문 돌리거나 하나씩 채워 넣을 때 훨씬 편해짐. (순서는 왼쪽→오른쪽, 위→아래로 감. row-major)

### (6) 지금까지 배운 걸 실제 그리기 흐름으로 연결

```python
fig, ax = plt.subplots(2, 3)   # ① 도화지 한 장 + 액자 6개 준비
ax = ax.flatten()               # ② 액자 6개를 순서대로 꺼내 쓸 수 있게 정리

sb.boxplot(data=df, ax=ax[0])   # ③ 1번째 액자에 boxplot 그리기
sb.histplot(data=df, ax=ax[1])  # ④ 2번째 액자에 histplot 그리기
...

plt.show()                      # ⑤ 도화지 전체를 화면에 보여주기
```

여기서 딱 봐야 할 것:
- **`fig`는 딱 한 번만 만들어지고, `show()`도 딱 한 번만** 호출됨 (도화지 전체를 한 번에 보여주는 거니까)
- **`ax`는 여러 개 만들어지고, 그리기 함수(`sb.boxplot` 등)를 호출할 때마다 "몇 번째 ax에 그릴지" 지정**해줌

### (7) `my_plot.init()`은 이걸 뭘 대신해주는 거야?

```python
fig, ax = my_plot.init(rows=2, cols=3, width=800, height=450, title='제목')
```

이게 하는 일은 위 ①②번 과정(`plt.subplots()` + `flatten()`)을 대신 해주고, 거기다 **그리드 표시, 제목 크기, 폰트, 여백** 같은 것까지 한 번에 세팅해주는 것. "도화지랑 액자들 미리 예쁘게 세팅해서 줄게" 하는 함수.

### (8) axes-level 함수 vs figure-level 함수

이제 위 그림으로 다시 보면 쉬움:

- **`sb.boxplot`, `sb.scatterplot` 같은 애들 = "액자(ax) 하나만 있으면 그 안에 그림 그릴 수 있는" 함수.** 그래서 `ax=ax[3]` 처럼 "몇 번째 액자에 그릴지" 지정 가능. → **axes-level 함수**
- **`sb.lmplot`, `sb.pairplot` 같은 애들 = "나는 액자 하나로는 안 되고, 아예 내 도화지(fig)를 새로 만들어야 해" 하는 함수.** 그래서 `ax=` 옵션 자체가 없음. 얘는 내가 만든 도화지에 들어갈 수 없고, **자기 도화지를 따로 만들어서 튀어나옴.** → **figure-level 함수**

즉, **"ax 하나로 충분한 애"랑 "지가 fig를 통째로 새로 만들어야 하는 애"**의 차이.

> ⚠️ 그래서 `lmplot`, `pairplot`은 서브플롯의 `ax[i]`에 절대 못 들어감. 서브플롯 계획 짤 때 이 둘은 처음부터 "따로 그릴 것"으로 빼고 칸 수를 계산해야 함. (8절 표에도 다시 정리되어 있음)

## 1. 서브플롯 개념부터

### 1-1. fig와 ax의 관계
- `fig` : 전체 캔버스(도화지) 자체
- `ax` : 그 캔버스 안에 그려지는 개별 그래프 영역

```python
fig, ax = plt.subplots(rows, cols, figsize=..., dpi=...)
```

- `rows=1, cols=1` 이면 `ax`는 단일 Axes 객체
- `rows>1` 또는 `cols>1` 이면 `ax`는 **2차원 배열**(예: 2행 3열이면 shape=(2,3))

### 1-2. `.flatten()`을 쓰는 이유
```python
ax = ax.flatten()
```
- 2차원 배열 상태로는 `ax[0][1]` 식으로 접근해야 해서 반복문 돌리기 불편함
- `flatten()`으로 1차원으로 펴주면 `ax[0]`, `ax[1]`, `ax[2]`... 순서대로 접근 가능
- **인덱스 순서는 행 우선(row-major)**: 2행 3열이면 `ax[0]~ax[2]`가 1행, `ax[3]~ax[5]`가 2행

> 오늘 코드에서 `rows=2, cols=3` → 총 6개의 ax, `len(ax)`로 확인하는 습관 들이면 좋음 (몇 개 만들어졌는지 항상 체크).

## 2. 두 가지 방식 비교: "raw matplotlib" vs "my_plot 모듈"

오늘 코드에 이 두 가지가 나란히 나왔음. 이 비교가 사실 제일 중요한 부분.

### 방식 A — 직접 구현 (raw)
```python
fig, ax = plt.subplots(rows, figsize=figsize, dpi=my_dpi)
ax = ax.flatten()
fig.suptitle('제목', fontsize=32, fontweight=500)
plt.tight_layout()
plt.show()
plt.close()
```
→ 매번 이 5~6줄을 반복해서 써야 함. 그래프마다 스타일(그리드, 폰트크기, dpi 등)을 손으로 맞춰야 함.

### 방식 B — my_plot 모듈화
```python
fig, ax = my_plot.init(width=600, height=400, rows=2, cols=3, title='...')
my_plot.show()
```
→ 같은 결과를 함수 호출 2줄로 끝냄. 스타일이 항상 일관됨(폰트, 그리드, 여백 등 `init()` 안에 이미 규칙이 박혀있음).

**핵심 포인트**: 모듈화의 이득은 "코드가 짧아진다"가 아니라 **"매번 같은 실수를 할 여지가 없어진다"**는 거. `fontsize=32`를 매번 손으로 치면 어떤 그래프는 30, 어떤 건 32로 미세하게 어긋날 수 있는데, 함수로 고정해두면 그럴 일이 없음.

## 3. my_plot 모듈의 설계 철학 (오늘의 진짜 핵심)

이 부분이 "모듈을 어떻게 사고해야 하는가"에 대한 답임.

### 3-1. 모든 plot 함수에 공통으로 들어있는 패턴

`lineplot`, `histplot`, `boxplot`, `scatterplot` ... 전부 다음 구조를 갖고 있음:

```python
def 어떤plot(data=None, x=None, y=None, ..., ax=None):
    fig = None
    if ax is None:
        fig, ax = init(width=width, height=height, title=title, ...)

    sb.어떤plot(data=data, x=x, y=y, ..., ax=ax)   # 실제 그리기

    if fig is not None:
        show(save_path=save_path)
```

이 패턴을 뜯어보면:

| 상황 | ax를 안 넘겨줌 (`ax=None`) | ax를 넘겨줌 (서브플롯의 한 칸) |
|---|---|---|
| 동작 | 함수가 **직접 fig/ax를 새로 만듦** | **넘겨받은 ax에 그냥 그림** |
| 결과 | 그래프 하나만 단독으로 화면에 출력 (`show()` 실행) | `show()`를 실행하지 않고 넘어감 (서브플롯 전체가 다 그려진 다음에 한 번만 `show()` 호출) |
| 예시 | `my_plot.lineplot(data=df, x='년도', y='발생건수')` | `my_plot.lineplot(data=df, x='년도', y='발생건수', ax=ax[0])` |

→ **하나의 함수가 "단독 그래프"와 "서브플롯의 한 조각" 두 가지 역할을 다 할 수 있게 설계된 것.**
`fig = None` 으로 시작해서, 함수 안에서 새로 fig를 만들었을 때만 `fig`가 값을 갖고, 그때만 `show()`를 호출하는 방식으로 이 분기를 처리함. **바깥에서 만든 그래프를 함수가 실수로 또 `plt.show()` 해버리는 걸 막는 안전장치**이기도 함.

### 3-2. 왜 이렇게 짜야 하는가 (사고 순서)

새로운 그래프 함수를 만들 때마다 스스로 물어볼 질문:

1. **이 함수, 서브플롯 안에서도 쓰일 수 있어야 하나?** → 그렇다면 반드시 `ax=None` 파라미터를 마지막에 추가하고 위 패턴을 그대로 적용
2. **ax가 넘어왔을 때 내부에서 새 fig를 만들면 안 됨** → `init()`을 호출하는 대신 넘겨받은 `ax`에 그리기만 해야 함
3. **`show()` 호출은 "내가 fig를 직접 만들었을 때만"** → 안 그러면 서브플롯 중간에 화면이 조각조각 튀어나옴

이 3가지가 my_plot 확장할 때(새 그래프 타입 추가할 때) 지켜야 할 규칙.

## 4. 오늘 코드 전체 진행 순서 (실전 흐름)

실제로 분석/시각화를 할 때는 아래 순서를 그대로 따라가면 됨. **처음부터 서브플롯 6~12개를 한 번에 다 그리려고 하지 말고**, 아래처럼 단계별로 검증하면서 진행하는 게 맞음.

```
[1] 데이터 불러오기 (load_data)
        ↓
[2] 전처리 — groupby, drop 등으로 분석 단위 맞추기
        ↓
[3] 그래프별로 필요한 데이터 "따로" 준비
    - 히트맵용: pivot_table로 재배치
    - 파이차트용: groupby + sum + reset_index로 집계
        ↓
[4] 서브플롯 틀(fig, ax) 초기화 — 몇 행 몇 열이 필요한지 먼저 결정
        ↓
[5] ax 하나하나에 그래프 얹기 (인덱스 순서대로)
        ↓
[6] show() 한 번으로 전체 출력
```

### 왜 [3]에서 데이터를 미리 다 따로 준비해두는가?
- `heatmap`은 pivot된(교차표) 형태가 필요하고, `pieplot`은 집계된 합계가 필요하고, `boxplot`/`scatterplot` 등은 원본(origin) 그대로 써도 됨.
- 그래프 종류마다 **요구하는 데이터 모양이 다름** → 이걸 서브플롯 그리는 도중에 즉석으로 처리하면 코드가 지저분해지고 에러 나기 쉬움
- 그래서 **"[2] 전처리 → [3] 그래프별 데이터 준비" 를 그리기 전에 전부 끝내놓고, [5]에서는 오직 "그리기"에만 집중**하는 게 좋은 습관

## 5. 점진적으로 확인하면서 만드는 법 (중요 — 질문하신 부분)

전체 코드를 한 번에 다 쓰고 실행하는 게 아니라, 아래 순서로 나눠서 검증하는 게 맞는 방식임.

### Step 1. 서브플롯 틀만 먼저 만들어서 개수 확인
```python
fig, ax = my_plot.init(rows=2, cols=3, width=800, height=450, title='제목')
print(f'총 {len(ax)}개의 ax객체가 생성되었습니다.')
my_plot.show()
```
→ 빈 틀만 찍어보고 "내가 원하는 행/열 개수가 맞게 나왔는가"부터 확인. 이 단계에서 rows*cols 계산 실수를 미리 잡아냄.

### Step 2. ax 하나에만 그래프 하나 넣어서 테스트
```python
fig, ax = my_plot.init(rows=2, cols=3, ...)
sb.boxplot(data=df, y='발생건수', ax=ax[0])
my_plot.show()
```
→ 나머지 ax는 비워둔 채로, **함수 하나가 서브플롯 안에서 제대로 작동하는지**만 확인. 여기서 파라미터 오타(`diag_kind="ked"` 같은 거)나 컬럼명 오류를 잡는 게 전체를 다 채운 다음 디버깅하는 것보다 훨씬 빠름.

### Step 3. 하나씩 늘려가며 채우기
`ax[0]` 확인 → `ax[1]` 추가 → `ax[2]` 추가 ... 순서로 하나씩 늘려나감.
- 특히 오늘처럼 `pairplot`, `lmplot`처럼 예전에 버그(marker 오타, linewidths 오타 등) 났던 함수들은 **단독으로 먼저 실행해서 정상 작동 확인한 뒤** 서브플롯에 넣는 게 안전함.

### Step 4. 전체를 한 번에 실행해서 최종 확인
모든 ax가 채워진 상태에서 전체 실행 → `my_plot.show()` 한 번으로 마무리.

> **왜 이렇게 하는가**: 서브플롯은 그래프 하나하나가 각각 데이터/파라미터가 다르기 때문에, 한 곳에서 에러가 나면 전체 셀이 다시 실행되면서 어디서 문제인지 찾기 어려워짐. 하나씩 검증하고 쌓아 올리면 에러 발생 시 "방금 추가한 것"만 의심하면 되므로 디버깅 범위가 좁아짐.

## 6. 다른 데이터셋에 적용할 때 체크리스트

새로운 데이터로 서브플롯 작업할 때 순서대로 확인:

- [ ] `origin.head()` 로 컬럼명/타입 먼저 확인했는가
- [ ] 그리려는 그래프 종류별로 **필요한 데이터 형태**를 파악했는가 (원본 그대로 되는지 / groupby 필요한지 / pivot 필요한지)
- [ ] 몇 개의 그래프를 그릴지 정하고 → `rows * cols >= 그래프 개수`로 배치를 먼저 계산했는가
- [ ] `my_plot.init()`으로 빈 틀만 먼저 만들어서 `len(ax)` 확인했는가
- [ ] 그래프 하나씩 넣어보면서 `ax=ax[i]` 인덱스가 순서대로 맞는지 확인했는가 (인덱스 꼬이면 그래프가 엉뚱한 칸에 들어감)
- [ ] hue/palette를 쓰는 함수는 범례가 서로 겹치지 않는지 확인했는가 (`bbox_to_anchor` 옵션으로 조정)
- [ ] 마지막에 전체 실행해서 `suptitle`, 여백(`tight_layout`)이 깨지지 않는지 확인했는가

## 7. 오늘 코드에 쓰인 그래프 함수 목록 (용도 빠른 참조)

| 함수 | 용도 | 필요한 데이터 형태 |
|---|---|---|
| `lineplot` | 시계열 추이 | 원본 그대로 (x=시간축) |
| `kdeplot` | 분포의 밀도 곡선 | 원본 그대로 (수치형 컬럼) |

| `boxplot` / `violinPlot` | 분포 + 이상치 확인 | 원본 그대로 |
| `heatmap` | 두 범주 교차 패턴 | **pivot_table로 재배치 필요** |
| `barplot` / `countplot` | 범주별 집계/개수 비교 | 원본 그대로 (estimator로 집계방식 지정) |

| `pairplot` | 여러 변수 조합 한 번에 | 원본 그대로 (역시 `ax` 미지원, figure-level) |

## 8. 오늘 정리하면서 기억해둘 문장

- **서브플롯을 짤 때는 "그리기 전에 데이터 준비 끝내기"가 먼저다.**
- **모듈 함수는 `ax=None` 패턴으로 "단독용/서브플롯용"을 겸하도록 설계한다.**
- **전체를 한 번에 실행하지 말고, 틀 → 그래프 1개 → 하나씩 추가 → 전체 확인 순서로 쌓는다.**
- **figure-level 함수(lmplot, pairplot)는 서브플롯에 못 들어간다는 것 기억.**
- **단위/스케일이 다른 두 변수를 한 그래프에 비교하고 싶으면 서브플롯이 아니라 이중 축(twinx)을 쓴다.**

# LAB-06-2 : 이중 축(Twin Axis) 그래프

## 9. 이중 축 그래프란 무엇인가

### 9-1. 왜 필요한가

지금까지는 "서로 다른 그래프를 나눠서" 그리는 걸 배웠음(서브플롯). 근데 이번엔 상황이 달라:

> **"발생건수"랑 "부상자수"를 같은 그래프 안에, 겹쳐서, 같이 보고 싶다.**

문제는 이 둘은 **값의 크기(스케일)가 완전히 다를 수 있음.** 예를 들어 발생건수는 수천 단위, 부상자수는 수백 단위면 같은 y축에 그려버리면 한쪽 선이 거의 0에 붙어서 안 보이게 됨.

**해결책: x축(년도)은 공유하되, y축을 왼쪽/오른쪽에 각각 따로 두는 것.** 이게 이중 축(twin axis, twinx) 그래프임.

```
        발생건수(왼쪽 축)              부상자수(오른쪽 축)
          10000 ┤                              ┤ 2000
                │  ＼                           │
           8000 ┤    ＼___                      │ 1500
                │         ＼___     ／‾‾‾＼      │
           6000 ┤              ＼＿／      ＼_   │ 1000
                └──────────────────────────────┘
                 2018  2019  2020  2021  2022     ← x축(년도)은 공유
```

**같은 x축을 공유하면서, y축만 왼쪽/오른쪽으로 나눠 각자 다른 스케일로 그리는 것** — 이게 핵심 아이디어.

### 9-2. 서브플롯이랑 뭐가 다른가? (헷갈리지 않게 구분)

| | 서브플롯 (Sub Plot) | 이중 축 (Twin Axis) |
|---|---|---|
| 그래프 개수 | 여러 개를 **나눠서** 따로따로 | **한 화면에 겹쳐서** 하나로 |
| 목적 | 서로 다른 그래프 종류를 한눈에 모아보기 | 스케일이 다른 두 변수를 **같은 시점끼리 비교** |
| x축 | 각 ax마다 따로 있음 | **공유함** (같은 x축 위에서 비교) |
| y축 | 각 ax마다 따로 있음 | **왼쪽/오른쪽으로 나눠서 각자** |

> 한 문장으로: 서브플롯은 "따로 보여주는 것", 이중 축은 "겹쳐서 비교하는 것".

---

## 10. `ax.twinx()` 뜯어보기

### 10-1. 기본 개념

```python
fig, ax = my_plot.init()          # ① 기본 도화지 + 왼쪽 축(ax) 하나 생성
ax_twinx = ax.twinx()             # ② ax와 x축을 공유하는 '오른쪽 축' 하나 더 생성
ax = (ax, ax_twinx)               # ③ 둘을 튜플로 묶어서 관리
```

`ax.twinx()`가 하는 일: **"이 ax(`ax`)랑 x축은 똑같이 쓰되, y축만 새로 하나 더 만들어서 오른쪽에 붙여줘"**

```
┌─────────────────────────────┐
│  ax (왼쪽 y축)      ax_twinx │  ← 같은 도화지, 같은 x축
│  │                       │  │
│  │      (겹쳐진 그래프 영역)  │
│  │                       │  │
└─────────────────────────────┘
   ↑ 왼쪽 y축 눈금            ↑ 오른쪽 y축 눈금
```

- `ax` → 왼쪽 y축을 가진 그래프 영역
- `ax_twinx` → 오른쪽 y축을 가진 그래프 영역 (근데 실제로는 **같은 자리에 겹쳐서** 그려짐)

### 10-2. 왜 튜플로 묶어서(`ax = (ax, ax_twinx)`) 관리하는가

이 부분이 "재사용 사고방식"에서 중요함. 앞서 배운 서브플롯에서 `ax[0]`, `ax[1]`처럼 **인덱스로 접근**하는 패턴을 그대로 이어가려는 거임.

```python
ax = (ax, ax_twinx)

my_plot.lineplot(..., ax=ax[0])   # 왼쪽 축에 그리기
my_plot.lineplot(..., ax=ax[1])   # 오른쪽 축에 그리기
```

즉, **서브플롯이든 이중 축이든 "여러 개의 ax를 인덱스로 꺼내 쓴다"는 사용법 자체는 똑같이 유지**되게끔 설계한 것. 새로운 문법을 또 익힐 필요 없이, 이미 아는 `ax[0]`, `ax[1]` 패턴을 그대로 씀.

---

## 11. `my_plot.init(twinx=True)` — 모듈이 이걸 대신 해주는 것

앞 섹션에서 본 3줄(`init()` → `twinx()` → 튜플 묶기)을 직접 안 해도 되게, `my_plot.init()`에 옵션 하나가 추가돼 있음:

```python
fig, ax = my_plot.init(title='멀티 축을 갖는 그래프', twinx=True)
```

이 한 줄이 앞의 3줄(`ax.twinx()` 만들고, 튜플로 묶는 것)을 **전부 내부에서 처리**해주는 것. 결과적으로 `ax`는 바로 `(왼쪽축, 오른쪽축)` 튜플로 나옴.

> 이게 바로 "모듈을 어떻게 확장하는가"의 좋은 예시임: **자주 반복되는 3줄짜리 패턴을 함수 파라미터 하나(`twinx=True`)로 흡수시킨 것.** 나중에 my_plot을 직접 확장할 때도 "이 패턴, 매번 반복되네?" 싶으면 옵션 파라미터로 빼는 식으로 사고하면 됨.

### 11-1. `my_plot.init()` 내부에서 실제로 일어나는 일 (개념적으로)

```python
def init(..., twinx=False):
    fig, ax = plt.subplots(...)   # 기본 축 생성
    ...
    if twinx:
        ax_right = ax.twinx()      # 오른쪽 축 추가 생성
        ax = (ax, ax_right)        # 튜플로 묶어서 반환
    return fig, ax
```

`twinx=True`를 넘기면 함수 안에서 자동으로 오른쪽 축까지 만들어서 튜플로 돌려주는 것. 우리가 직접 `ax.twinx()`를 호출할 필요가 없어짐.

## 12. 실전 코드 흐름 정리

```python
# 1) 데이터 준비 (지금까지와 동일한 흐름)
origin = load_data('traffic_acc')
df = origin.drop('월', axis=1).groupby('년도').mean()

# 2) 이중 축 캔버스 초기화 — 이 한 줄이 왼쪽/오른쪽 축을 다 만들어줌
fig, ax = my_plot.init(title='교통사고 발생건수, 부상자수 추이', twinx=True)

# 3) 왼쪽 축(ax[0])에 발생건수 그리기
my_plot.lineplot(data=df, x=df.index, y='발생건수', ylabel='발생건수',
                 color='tab:blue', ax=ax[0])

# 4) 오른쪽 축(ax[1])에 부상자수 그리기 — 같은 x축(년도) 위에 겹쳐짐
my_plot.lineplot(data=df, x=df.index, y='부상자수', ylabel='부상자수',
                 color='tab:orange', ax=ax[1])

# 5) 출력
my_plot.show()
```

**진행 순서 요약**
```
[1] 데이터 로드 & 전처리 (년도별 평균)
        ↓
[2] my_plot.init(twinx=True) 로 왼쪽/오른쪽 축 한 번에 준비
        ↓
[3] ax[0](왼쪽)에 첫 번째 변수 그리기 — color를 지정해서 어느 축인지 시각적으로 구분
        ↓
[4] ax[1](오른쪽)에 두 번째 변수 그리기 — 다른 color로 구분
        ↓
[5] show() 한 번으로 출력 (겹쳐진 하나의 그래프로 보임)
```

> 여기서 `color='tab:blue'` / `color='tab:orange'`를 서로 다르게 지정한 게 우연이 아님. **두 선이 어느 y축(왼쪽/오른쪽)에 속하는지 색으로 구분**해줘야, 보는 사람이 헷갈리지 않음. 이중 축 그래프를 그릴 때는 **색상 구분이 사실상 필수**라고 기억해두면 좋음.

## 13. 이중 축 그래프 쓸 때 주의할 점 (실수하기 쉬운 부분)

- **서로 다른 스케일일 때만 쓰는 게 맞음.** 두 변수의 값 범위가 비슷하면 굳이 이중 축 안 쓰고 그냥 같은 y축에 같이 그리는 게 더 직관적임. (오히려 이중 축은 두 선의 "실제 교차점"이 착시를 일으킬 수 있어서 남용하면 안 됨 — 왼쪽 축과 오른쪽 축 스케일이 다르므로 "두 선이 만나는 지점"이 실제로 의미 있는 교차가 아닐 수 있음)
- **범례(legend)가 자동으로 합쳐지지 않음.** `ax[0]`과 `ax[1]`은 서로 다른 축 객체라서, 각자 `legend()`를 호출하면 범례가 따로따로 뜨거나 겹칠 수 있음. 필요하면 두 축의 handle을 합쳐서 하나의 범례로 만드는 처리가 별도로 필요함 (지금 코드에는 이 처리가 없어서, 나중에 legend가 필요하면 추가 작업이 필요하다는 것만 기억).
- **색상으로 반드시 축을 구분할 것.** 왼쪽 축 선/오른쪽 축 선이 같은 색이면 어떤 게 어느 축 값인지 알 수 없음.
- **twinx는 "x축 공유 + y축 분리"임.** 반대로 y축을 공유하고 x축을 분리하고 싶으면 `twiny()`를 쓰는데, 오늘 코드에는 안 나왔지만 개념은 twinx와 대칭이라는 것만 알아두면 됨.

## 14. 서브플롯 vs 이중 축 — 언제 뭘 써야 하는가 (선택 기준)

새로운 데이터셋 다룰 때, 아래 질문으로 판단하면 됨:

1. **"여러 변수/그래프를 각각 독립적으로 보고 싶다"** → 서브플롯 (`my_plot.init(rows=, cols=)`)
2. **"딱 두 변수를 같은 시점(x축) 기준으로 겹쳐서, 추세를 비교하고 싶다. 근데 스케일이 다르다"** → 이중 축 (`my_plot.init(twinx=True)`)
3. **"스케일도 비슷하고 그냥 겹쳐 보기만 하면 된다"** → 이중 축도 필요 없이 그냥 하나의 ax에 `lineplot`을 두 번 그리면 됨 (같은 y축 공유)

## 16. 모듈 원본 코드를 직접 보고 찾은 진짜 중요한 함정

지금까지는 "모듈을 어떻게 쓰는지" 위주로 봤는데, `my_plot.py` 원본 코드를 뜯어보면 **실제로 동작에 영향을 주는 함정 2가지**가 있음. 이건 지금 당장 에러가 안 나더라도 나중에 "왜 안 나오지?" 하면서 헤맬 수 있는 부분이라 꼭 짚고 넘어가야 함.

### 16-1. `ax=`를 넘기면 `title`, `xlabel`, `ylabel`, `width`, `height`가 조용히 무시됨

`lineplot` 원본 코드를 보면:

```python
def lineplot(data=None, x=None, y=None, hue=None,
             title=None, xlabel=None, ylabel=None,
             ..., width=1280, height=540, save_path=None, ax=None):

    fig = None
    if ax is None:
        fig, ax = init(width=width, height=height, title=title,
                       xlabel=xlabel, ylabel=ylabel)     # ← title/xlabel/ylabel이 여기서만 적용됨

    sb.lineplot(data=data, x=x, y=y, hue=hue, ..., ax=ax)  # ← 여기선 title/xlabel/ylabel을 아예 안 씀

    if fig is not None:
        show(save_path=save_path)
```

**핵심: `title`, `xlabel`, `ylabel`, `width`, `height`는 오직 `init()`을 새로 호출할 때만 적용됨.** 근데 `init()`은 `ax is None`일 때만 호출됨. 즉:

| 상황 | title/xlabel/ylabel 파라미터를 줬을 때 |
|---|---|
| `ax=None` (함수가 직접 fig/ax 생성) | 정상 적용됨 (init()에게 전달되어 축에 반영) |
| `ax=ax[0]` 처럼 **넘겨받은 ax 사용** | **완전히 무시됨.** `sb.lineplot()` 호출 시 이 값들을 아예 쓰지 않음 |

### 16-2. 실제로 오늘 twinx 코드에서 이미 이 문제가 숨어있었음

```python
my_plot.lineplot(data=df, x=df.index, y='발생건수', ylabel='발생건수',
                 color='tab:blue', ax=ax[0])
```

여기서 `ylabel='발생건수'`를 분명히 줬는데, `ax=ax[0]`도 같이 줬기 때문에 **이 ylabel은 실제로 왼쪽 축에 절대 안 나타남.** `ax`가 이미 존재하니 `init()`이 호출 안 되고, `ylabel` 값은 함수 안에서 만들어지고 버려짐.

> 이게 왜 위험하냐면 — 에러가 안 남. 코드가 그냥 조용히 실행되고, 그래프도 정상적으로 그려지긴 함. 근데 y축 레이블만 안 붙는 거라서, **한참 뒤에 그래프 보다가 "어? 왜 라벨이 없지?"하고 나서야 알아차리게 됨.** 이런 종류의 버그(조용히 무시되는 파라미터)가 제일 잡기 어려움.

### 16-3. 그럼 어떻게 해야 하나 (지금 구조에서 실전 대응법)

`ax=`를 직접 넘기는 상황(서브플롯/twinx)에서 축 제목이 필요하면, **함수 호출 후에 직접 `ax` 객체에 설정**해줘야 함:

```python
my_plot.lineplot(data=df, x=df.index, y='발생건수', color='tab:blue', ax=ax[0])
ax[0].set_ylabel('발생건수')   # ← 이렇게 직접 지정해야 실제로 반영됨

my_plot.lineplot(data=df, x=df.index, y='부상자수', color='tab:orange', ax=ax[1])
ax[1].set_ylabel('부상자수')   # ← 마찬가지
```

또는 나중에 모듈을 직접 고칠 수 있는 상황이 되면, `ax=None`이든 아니든 상관없이 라벨을 적용하도록 함수 내부를 아래처럼 바꾸는 게 근본적인 해결책:

```python
# 개선 방향 (참고용 - 지금 당장 고치라는 게 아니라 "이런 식으로 생각해야 한다"는 예시)
sb.lineplot(..., ax=ax)
if ylabel:
    ax.set_ylabel(ylabel)   # ax가 새로 만들어졌든 넘겨받았든 항상 적용
if xlabel:
    ax.set_xlabel(xlabel)
if title:
    ax.set_title(title)
```

> **여기서 배울 사고방식**: "이 파라미터가 **모든 경로(ax 있을 때/없을 때)**에서 다 적용되는가?"를 함수 볼 때마다 체크하는 습관을 들이면 좋음. `my_plot`의 다른 함수들(`histplot`, `boxplot`, `barplot` 등)도 전부 똑같은 구조라서, **`ax=`를 직접 넘기는 모든 상황에서 title/xlabel/ylabel은 항상 무시된다는 걸 기본값으로 기억**해두면 됨.

### 16-4. `twinx=True`는 `rows=1, cols=1`일 때만 작동함 (구조적 제약)

`init()` 원본을 순서대로 읽어보면:

```python
def init(width=1280, height=640, rows=1, cols=1, ..., twinx=False):
    fig, ax = plt.subplots(rows, cols, figsize=my_figsize, dpi=200)

    if rows > 1 or cols > 1:
        ax = ax.flatten()          # ← 이 경우 ax는 배열(array)이 됨
        ...
    else:
        ...                        # ← 이 경우에만 ax가 단일 Axes 객체

    if twinx:
        ax_right = ax.twinx()      # ← array는 .twinx() 메서드가 없음!
        ax = (ax, ax_right)

    return fig, ax
```

**`.twinx()`는 단일 Axes 객체에만 있는 메서드지, 배열(array)에는 없음.** 그래서:

- `rows=1, cols=1` (기본값) + `twinx=True` → 정상 작동 (오늘 배운 방식)
- `rows=2, cols=3` + `twinx=True` 처럼 **서브플롯 + 이중 축을 동시에 시도하면 → 에러남** (`AttributeError: 'numpy.ndarray' object has no attribute 'twinx'`)

> 즉, **지금 구조로는 "여러 칸짜리 서브플롯 각각에 이중 축을 넣는 것"은 지원 안 됨.** 만약 나중에 "3개 서브플롯 각각에 다 이중 축을 넣고 싶다"는 상황이 오면, 지금 `init()` 함수로는 안 되고 직접 `plt.subplots()`로 만든 뒤 각 ax마다 개별적으로 `.twinx()`를 호출하는 방식으로 짜야 함. 이건 지금 모듈의 한계로 기억해두기.

## 15. 최종 요약 문장 (전체 문서 통틀어)

- **fig = 도화지, ax = 그 안의 그림 영역.** 여러 ax를 나누면 서브플롯, x축만 공유하고 y축을 나누면 이중 축.
- **서브플롯은 "따로 보기", 이중 축은 "겹쳐서 비교하기".** 목적이 다르면 그리는 방식도 다르다.
- **모듈(my_plot)은 반복되는 matplotlib 패턴(축 초기화, twinx 생성, 스타일 세팅)을 함수 옵션 하나로 흡수한 것.** 새로운 상황이 반복되면 "이거 옵션으로 뺄 수 있지 않을까?"라고 사고하는 게 모듈 확장의 핵심.
- **axes-level 함수(ax= 받는 것)만 서브플롯/이중 축 둘 다에 넣을 수 있고, figure-level 함수(lmplot, pairplot)는 둘 다 못 들어간다.**
- **색상 구분, 스케일 차이 여부를 먼저 확인하고 이중 축을 쓸지 판단할 것.**
- **`ax=`를 직접 넘길 때는 title/xlabel/ylabel/width/height가 조용히 무시된다는 것 — 항상 의심할 것.** 필요하면 함수 호출 뒤에 `ax.set_ylabel()` 등으로 직접 지정.
- **`twinx=True`는 단일 Axes(`rows=1, cols=1`)에서만 작동하고, 서브플롯 각 칸에 이중 축을 넣는 건 지금 구조에서 지원 안 됨.**
