## 0. 오늘 실습의 큰 그림 — 두 가지 버전이 왜 같이 나오는가

오늘 코드에는 계속 두 가지 버전이 번갈아 나온다. 이 둘을 헷갈리지 않는 게 제일 중요함.

1. **직접 코딩 버전 (풀어쓴 버전)**: `statsmodels`의 `OLS`, `add_constant` 같은 원재료를 직접 불러와서, 적합도 문장·계수 표를 `template.format()`으로 그 자리에서 다 짜는 방식. LAB-09 1번째 문서(3-1 실습코드)가 이 버전이다.
2. **모듈화 버전**: 위에서 짠 로직을 `my_ols.py`라는 파일 안에 함수(`fit_model`, `report_fitness`, `report_variables`, `report_variables_text`, `test_linear`, `test_normal`, `test_equalvar`, `test_independent`)로 옮겨놓고, 실습 노트북에서는 `from helpers import *` 한 줄로 불러와 `my_ols.fit_model(...)` 처럼 함수 호출만 하는 방식. LAB-09 2번째 문서(3-2 연습문제)와 3번째 문서(salary 전체 워크플로우)가 이 버전.

**왜 이렇게 두 단계로 가는가?**
- 1번(직접 코딩)은 "이 로직이 원래 뭘 계산하는지" 눈으로 확인하고 검증하는 단계다. 여기서 통계량이 맞게 나오는지, 템플릿 문장이 제대로 채워지는지 하나하나 확인한다.
- 검증이 끝나면 그 로직을 함수로 감싸서(`def report_fitness(fit, ...): ... return report`) `helpers` 패키지에 넣는다. 이게 2번(모듈화)이다.
- 이후로는 새 데이터셋이 들어와도 `fit_model` → `report_fitness` → `report_variables` 세 줄이면 끝난다. **매번 처음부터 다시 코딩하지 않는 게 핵심.**

즉 오늘 배운 사고방식은: **"직접 짜서 검증 → 함수로 추상화 → 재사용"**. 이건 회귀분석뿐 아니라 앞으로 어떤 통계 기법을 배우든 똑같이 적용되는 흐름이다 (LAB-07 ANOVA 때도 같은 패턴이었음).

## 1. `helpers` 패키지 / 모듈을 다루는 사고방식

### 1-1. 지금 구조가 뭘 의미하는가

```
helpers/
├── __init__.py      # 패키지 진입점. 여기서 하위 모듈들을 모아서 노출시킴
├── my_stats.py       # 상관분석, VIF 계산 등 통계 유틸
├── my_plot.py         # 그래프 그리는 유틸 (init, show, lineplot, lmplot 등)
├── my_qtcheck.py       # 결측치/이상치/왜도 체크 (데이터 품질)
└── my_ols.py           # 오늘 새로 확장한 모듈 — 회귀분석 전용
```

`my_ols.py` 안에서 `from . import my_plot`, `from . import my_stats` 처럼 **상대 임포트**로 다른 모듈을 갖다 쓰고 있다. 이게 패키지를 "확장"한다는 의미다 — 새 기능(회귀분석)을 만들 때 이미 있는 유틸(그래프, VIF 계산)을 새로 안 짜고 재사용한다.

노트북에서는 `from helpers import *` 한 줄로 `my_ols`, `my_stats`, `my_plot`, `my_qtcheck`가 전부 딸려 들어온다 (이건 `__init__.py`에서 `from . import my_ols` 식으로 미리 등록해놨기 때문 — 지금 파일엔 안 보이지만 구조상 그렇게 돼있어야 `my_ols.fit_model(...)`이 바로 호출된다).

### 1-2. 앞으로 이 패키지를 "확장"할 때 사고 순서

새로운 분석 기법(예: 로지스틱 회귀, 시계열)을 추가하고 싶다면:

1. **직접 코딩으로 먼저 검증한다.** 노트북에서 `statsmodels`든 뭐든 raw하게 짜서 결과가 맞는지 확인.
2. **공통으로 반복되는 부분을 함수로 뽑는다.** "매번 다시 타이핑하게 되는 코드"가 함수화 대상. 오늘로 치면 "적합도 문장 만들기", "계수표 만들기"가 매 데이터셋마다 반복됐으므로 함수가 됨.
3. **함수 시그니처를 일반화한다.** `fit_model(data, y, summary=False)`처럼 "어떤 데이터든, 어떤 종속변수든" 받을 수 있게 매개변수화. 오늘 `report_fitness`에 `log_y`, `log_x` 같은 옵션 매개변수가 붙은 것도 이런 확장 — "로그변환 쓸 수도, 안 쓸 수도 있으니 옵션으로 열어둔다"는 설계.
4. **docstring을 꼭 쓴다.** 오늘 `my_ols.py`의 모든 함수에 Args/Returns가 상세히 달려있는 이유 — 나중에 내가 다시 보거나 팀원이 봤을 때 "이 함수 뭐 받고 뭐 뱉는지" 바로 알아야 재사용이 됨.
5. **기존 모듈을 참조(import)하되, 서로 순환 참조되지 않게 조심한다.** `my_ols.py`가 `my_stats`, `my_plot`을 가져다 쓰는 건 되지만, 반대로 `my_stats`가 `my_ols`를 가져다 쓰면 안 됨(순환 임포트 에러).
6. **Jupyter에서 수정 중이면 `importlib.reload()`로 반영 확인.** (이건 이전 LAB에서부터 쓰던 습관 — 오늘도 `my_ols.py` 수정하면서 이 워크플로우를 계속 썼을 것.)

### 1-3. "지금 소스에 직접 코딩" vs "모듈 불러와서 코딩" — 언제 뭘 쓰나

| 상황 | 어느 버전? |
|---|---|
| 새로운 통계기법을 처음 배우는 중, 원리를 이해해야 함 | 직접 코딩 (raw statsmodels) |
| 이미 검증된 로직, 데이터셋만 바뀜 (실전 분석) | 모듈 호출 (`my_ols.fit_model` 등) |
| 함수 안에 버그가 있는지 의심될 때 | 직접 코딩으로 내부 로직을 한 줄씩 재현해서 대조 |
| 면접/포트폴리오에서 "왜 이 결과가 나왔는지" 설명해야 할 때 | 직접 코딩 버전의 수식/로직을 기준으로 설명 (모듈은 그걸 감싼 것뿐이므로) |

## 2. 전체 분석 순서 (앞으로 어떤 데이터셋이든 이 순서로)

salary 실습(문제2)이 사실상 **회귀분석 표준 워크플로우**다. 이 순서를 그대로 기억해두면 됨.

```
1. 데이터 로드 & 확인          load_data(), .head()
2. 결측치 점검                 my_qtcheck.check_missing_values(df)
3. 기술통계 + 이상치 + 왜도    my_qtcheck.numerical_summary(df).T
   → 로그변환 필요 여부 판단 (|왜도| >= 1 이면 로그변환 고려)
4. 상관분석                    my_stats.correlation(df, x=..., y=...)
   → 정규성 만족하면 Pearson, 아니면 Spearman이 자동 선택됨
5. 회귀모형 적합                fit = my_ols.fit_model(df, 'Y컬럼', summary=True)
6. 모형 적합도 보고             my_ols.report_fitness(fit)
7. 회귀계수 표 + 해석 문장     my_ols.report_variables(fit, df)
                               my_ols.report_variables_text(fit)
8. (필요시) 예측                my_ols.predict(fit, new_data)
9. 회귀분석 4대 가정 검정       test_linear → test_normal → test_equalvar → test_independent
```

**포인트**: 4번(상관분석)과 9번(가정검정)은 순서가 다르다는 것에 유의.
- 상관분석은 **회귀모형을 적합하기 전에** "두 변수가 관계가 있긴 한지"를 먼저 보는 탐색 단계.
- 가정검정 4가지는 **모형을 적합한 후에** "이 모형을 통계적으로 신뢰해도 되는지" 사후 점검하는 단계.

이 순서를 안 지키고 가정검정부터 하면 안 됨 — 애초에 `fit` 객체(적합된 모형)가 있어야 잔차(`fit.resid`)를 뽑아서 검정할 수 있기 때문.

## 3. 핵심 통계 개념 — 말로 풀어서 정리 (면접 대비)

### 3-1. 회귀분석이 뭔지부터

회귀분석은 "독립변수(X)가 변할 때 종속변수(Y)가 얼마나, 어느 방향으로 변하는가"를 직선(또는 평면) 하나로 요약하는 방법이다. `Y = B0 + B1*X1 + B2*X2 + ... + e` 형태의 식을 데이터에 가장 잘 맞도록 추정하는 것.

- **단순선형회귀**: 독립변수가 1개일 때 (예: 연봉 ~ 근속년수)
- **다중선형회귀**: 독립변수가 2개 이상일 때

### 3-2. 최소자승법(OLS, Ordinary Least Squares)

"가장 잘 맞는 직선"이 뭘 기준으로 잘 맞는다고 하는지가 OLS다. 실제 관측값과 회귀직선이 예측한 값의 차이(잔차, residual)를 각각 제곱해서 다 더한 값(잔차제곱합)이 **가장 작아지는** 절편(B0)과 기울기(B1, B2...)를 찾는 방법. 제곱을 하는 이유는 양수/음수 잔차가 서로 상쇄되지 않게 하기 위함.

### 3-3. 회귀계수 B (비표준화 계수)

- **의미**: 다른 변수는 고정한 채로 해당 독립변수가 1 증가할 때, 종속변수가 평균적으로 얼마나 증가/감소하는지를 나타내는 값.
- salary 예시: B ≈ 9,449.96 → "근속년수가 1년 늘어날 때마다 연봉이 평균 9,450원가량 오른다"는 뜻.
- 부호(+/-)가 방향을 말해주고, 절댓값이 크기를 말해준다.

### 3-4. 절편 B0 (const)

독립변수가 0일 때 종속변수의 기대값. 항상 의미가 있는 건 아니다 (예: 근속년수 0년이 실제로 존재 가능한 값이면 의미가 있지만, 그렇지 않은 경우도 많음). 해석할 때 "현실적으로 말이 되는 값인지"를 같이 봐야 함.

### 3-5. 표준오차 (Standard Error, SE)

회귀계수 추정치가 얼마나 불안정한지를 나타내는 값. 같은 모집단에서 표본을 여러 번 뽑아 회귀분석을 반복했을 때, B값이 평균적으로 얼마나 흩어지는지를 뜻한다. 표준오차가 작을수록 그 계수 추정이 더 안정적이라는 뜻.

### 3-6. 베타(표준화 회귀계수)

B는 변수마다 단위가 달라서(예: "년"과 "원") 여러 독립변수의 영향력 크기를 서로 비교하기 어렵다. 그래서 B에 (독립변수 표준편차 / 종속변수 표준편차)를 곱해서 **단위를 없앤** 값이 베타다. 여러 독립변수가 있을 때 "어떤 변수가 종속변수에 상대적으로 더 큰 영향을 주는가"를 비교할 때 쓴다.

### 3-7. t-통계량과 계수의 유의확률(p-value)

- **귀무가설(H0)**: "이 독립변수의 실제 회귀계수는 0이다" — 즉 "이 변수는 종속변수에 영향이 없다"는 가정.
- **대립가설(H1)**: "이 독립변수의 실제 회귀계수는 0이 아니다" — 즉 "이 변수는 종속변수에 영향을 준다".
- t-통계량은 "추정된 B값이 표준오차 대비 얼마나 0에서 멀리 떨어져 있는가"를 나타내는 값 (t = B / 표준오차).
- p-value가 0.05보다 작으면 귀무가설을 기각 → "이 변수는 통계적으로 유의한 영향을 준다"고 해석. 0.05 이상이면 귀무가설을 기각할 근거가 부족 → "유의하지 않다"(영향이 없다고 단정하는 게 아니라, 있다고 볼 근거가 부족하다는 뜻).

### 3-8. 결정계수 R² (R-squared)

모형이 종속변수의 전체 분산(흩어진 정도) 중 **몇 %를 설명하는지**를 나타내는 값. 0~1 사이 값이며, 1에 가까울수록 모형이 데이터를 잘 설명한다는 뜻. salary 예시에서 R² ≈ 0.957이면 "연봉의 분산 중 95.7%가 근속년수로 설명된다"는 뜻. 나머지 4.3%는 근속년수로 설명 안 되는 다른 요인(운, 직급, 성과 등) 몫.

### 3-9. 수정된 결정계수 Adj.R² (Adjusted R-squared)

R²는 독립변수를 늘리면 늘릴수록 (그 변수가 쓸모없어도) 항상 커지거나 최소 그대로인 특성이 있다. 그래서 다중회귀에서는 "쓸모없는 변수를 넣었는데도 R²가 커 보이는" 착시를 방지하려고, 독립변수 개수에 대한 페널티를 준 게 Adj.R²다. 독립변수가 늘어도 설명력이 실제로 안 늘면 Adj.R²는 오히려 떨어진다. 다중회귀에서는 R²보다 Adj.R²를 더 신뢰해서 본다.

### 3-10. F-통계량과 모형 전체의 유의확률

- 계수 하나하나의 유의성(t-test)과 별개로, **모형 전체**가 통계적으로 의미가 있는지를 검정하는 게 F-test다.
- **귀무가설(H0)**: "모든 독립변수의 회귀계수가 다 0이다" (즉 이 모형 자체가 아무 설명력이 없다).
- **대립가설(H1)**: "적어도 하나의 독립변수는 계수가 0이 아니다".
- F(자유도1, 자유도2) = F값, p < 0.05면 "이 모형은 통계적으로 유의하다"고 결론. salary 예시: F(1,28)=622.51, p<.001 → 모형 자체가 유의미.

### 3-11. VIF (분산팽창계수, Variance Inflation Factor)와 다중공선성

- 다중회귀에서 독립변수들끼리 서로 너무 강하게 상관돼 있으면(다중공선성), 각 계수의 추정이 불안정해진다 (계수 부호가 이상하게 뒤집히거나, 표준오차가 커짐).
- VIF는 "이 독립변수가 다른 독립변수들로 얼마나 잘 설명되는가"를 수치화한 것. 일반적으로 VIF가 10(또는 보수적으로 5) 이상이면 다중공선성 문제를 의심.
- **공차(Tolerance)** = 1/VIF. VIF와 반대 방향으로, 값이 작을수록(0에 가까울수록) 문제가 심각하다는 뜻.

### 3-12. 회귀분석의 4대 가정 (오늘 salary에서 검정한 것들)

회귀분석 결과(계수, p-value, R² 등)를 믿을 수 있으려면 아래 4가지 전제가 성립해야 한다. 하나라도 심하게 위배되면 결과 해석에 주의가 필요함.

1. **선형성 (Linearity)**: X와 Y의 관계가 실제로 직선 형태여야 함. 곡선 관계인데 직선으로 억지로 맞추면 잔차에 패턴이 남는다.
   - 검정: **Ramsey RESET test**. 회귀식에 고차항(X²)을 추가로 넣어봤을 때, 그 고차항이 유의하게 나오면 "직선만으로는 부족하고 곡선 성분이 남아있다"는 뜻 → 선형성 위배.
   - 귀무가설: "고차항의 계수는 0이다(=선형성 위배 없음)". p ≥ 0.05면 귀무가설 채택(선형성 만족).

2. **정규성 (Normality of residuals)**: 잔차(실제값-예측값)들이 정규분포를 따라야 함. (Y 자체가 아니라 잔차가 정규분포여야 한다는 점 주의)
   - 검정: 표본수(n) 30 미만이면 **Shapiro-Wilk**, 30 이상이면 **Kolmogorov-Smirnov(K-S)**. 표본이 작을 때 Shapiro-Wilk가 더 검정력이 좋고, K-S는 표본이 커도 안정적이라 관례적으로 이렇게 나눠 씀.
   - 귀무가설: "잔차는 정규분포를 따른다". p ≥ 0.05면 정규성 만족.
   - 보조 확인: **Q-Q plot**(잔차의 분위수를 이론적 정규분포 분위수와 비교해서 직선에 가까우면 정규성 만족), **68-95-99.7 규칙**(정규분포라면 ±1·2·3 표준편차(여기선 루트MSE) 구간 안에 각각 약 68%, 95%, 99.7%의 데이터가 들어와야 한다는 경험칙으로 실제 비율과 비교).

3. **등분산성 (Homoscedasticity)**: 예측값 수준과 무관하게 잔차의 흩어진 정도(분산)가 일정해야 함. 예측값이 커질수록 잔차가 커지는 "나팔 모양" 패턴이 있으면 위배(이분산성, heteroscedasticity).
   - 검정: **Breusch-Pagan test**. 잔차의 제곱을 독립변수들로 다시 회귀시켜서, 그 설명력이 유의한지 봄 (설명력이 있다는 건 = 독립변수 수준에 따라 잔차 크기가 달라진다는 뜻 = 등분산 위배).
   - 귀무가설: "잔차의 분산은 독립변수 수준과 무관하게 일정하다(등분산)". p ≥ 0.05면 등분산성 만족.

4. **독립성 (Independence of residuals)**: 잔차들끼리 서로 상관(자기상관)이 없어야 함. 원래는 시계열 데이터(시간 순서가 있는 데이터)에서 중요한 가정 — 어제 잔차가 크면 오늘 잔차도 크다 식의 패턴이 있으면 위배.
   - 검정: **Durbin-Watson**. 통계량이 대략 1.5~2.5 사이면 자기상관이 없다고 판단 (2에 가까울수록 이상적). 1.5보다 작으면 양(+)의 자기상관, 2.5보다 크면 음(-)의 자기상관 의심.
   - 코드 주석에도 나와 있듯, 횡단면 데이터(시간 순서가 없는 일반 데이터)라면 이 가정이 다소 위배돼도 크게 문제 삼지 않는 경우가 많다 — 원래 시계열 전용 검정이기 때문.

### 3-13. 로그변환과 % 해석 (report_variables_text의 log_x, log1p_y 등)

- 원래 척도(B, X 그대로): "X가 1 증가하면 Y가 평균 B만큼 증가"
- Y만 로그변환(log_y): "X가 1 증가하면 Y가 평균 약 (e^B - 1)×100 % 변화" — 계수가 %변화율에 가까워짐
- X만 로그변환(log_x): "X가 1% 증가하면 Y가 평균 약 B×ln(1.01)만큼 변화"
- X, Y 모두 로그변환: 둘 다 %단위로 해석 (탄력성 개념에 가까움)
- **log1p**(=ln(1+x))는 0이나 작은 값이 있어서 log(0)이 안 되는 데이터에 쓰는 변환. 다만 % 해석이 "x"가 아니라 "(1+x)" 기준이라, 값이 작을 때는 근사가 부정확해서 부호·유의성 위주로 보거나 예측값을 원래 척도로 되돌려서(expm1) 비교하라는 주의사항이 붙어있음.

## 4. 오늘 코드에서 재사용되는 핵심 패턴 (복습 시 여기 집중)

### 4-1. `fit` 객체에서 "완전 정밀도" 값을 직접 꺼내는 습관

```python
fit.params[x]       # 회귀계수 B (반올림 안 된 실제값)
fit.bse[x]           # 표준오차
fit.tvalues[x]       # t값
fit.pvalues[x]       # 계수 p-value
fit.fvalue           # F통계량
fit.f_pvalue         # 모형 전체 p-value
fit.rsquared         # R²
fit.rsquared_adj     # Adj.R²
fit.nobs             # 표본수
fit.df_model         # 모형 자유도
fit.df_resid         # 잔차 자유도
fit.resid            # 잔차 배열
fit.fittedvalues     # 예측값(적합값) 배열
fit.model.exog_names # 독립변수 이름(상수항 포함)
fit.model.endog_names # 종속변수 이름
```

**왜 summary() 표를 파싱 안 하고 이렇게 직접 꺼내나?** summary()가 화면에 보여주는 숫자는 반올림된 "표시용" 값이다. 문자열을 파싱해서 쓰면 반올림 오차가 누적되거나, summary 포맷이 버전마다 달라지면 깨질 위험이 있다. `fit` 객체 속성에서 직접 꺼내면 항상 정확한 원본 값을 얻고, 반올림은 보고 문장 만들 때 `round()`로 내가 직접 통제할 수 있다.

### 4-2. 상수항(const) 걸러내는 패턴

```python
xnames = [name for name in fit.model.exog_names if name != 'const']
```
`exog_names`에는 절편(const)까지 포함돼 있어서, "진짜 독립변수 이름만" 필요할 땐 항상 이 필터링을 거친다. 오늘 코드 전체에서 반복적으로 나오는 패턴이니 외워둘 것.

### 4-3. p-value → 유의수준 구간 표기(APA 스타일) 패턴

```python
if p < 0.001:   alpha = "< 0.001"
elif p < 0.01:  alpha = "< 0.01"
elif p < 0.05:  alpha = "< 0.05"
else:           alpha = ">= 0.05"
```
논문/보고서에서 p-value는 정확한 숫자(p=0.0003 같은)보다 이렇게 구간으로 표기하는 관례가 있음(APA 스타일). 이것도 매번 반복되는 로직이라 함수 안에 박아둠.

### 4-4. `template.format()`으로 보고 문장 생성

미리 자리표시자(`{n}`, `{r_squared}` 등)가 있는 문자열을 만들어두고, `.format(n=..., r_squared=...)`로 한 번에 채워 넣는 패턴. `display(Markdown(...))`으로 감싸면 Jupyter에서 굵은 글씨, 인용구 등 마크다운 서식이 그대로 렌더링된다.

### 4-5. `add_constant` — 절편을 자동으로 안 넣어주는 statsmodels 특성

```python
x_input = add_constant(x)
model = OLS(y_series, x_input)
```
statsmodels의 `OLS`는 절편(상수항)을 자동으로 추가하지 않는다(다른 라이브러리, 예를 들어 sklearn의 LinearRegression과 다른 점). 그래서 `add_constant()`로 상수항 컬럼(전부 1인 컬럼)을 X에 직접 추가해줘야 절편이 있는 모형이 적합된다. 이걸 빼먹으면 원점을 지나는 회귀선(절편=0)이 강제로 적합돼서 결과가 완전히 달라지니 항상 체크.

### 4-6. `my_ols.py` 안에서 그래프 그릴 때 `sb`(seaborn) 쓰는 부분

`sb.regplot(..., lowess=True, ...)`처럼 lowess(국소회귀) 추세선을 얹어서, 잔차가 곡선 패턴을 그리는지 눈으로도 확인하는 방식. 통계 검정(RESET test) + 시각화를 같이 보는 습관을 들이는 게 좋음 — 수치 하나만 보고 판단하지 않기.
