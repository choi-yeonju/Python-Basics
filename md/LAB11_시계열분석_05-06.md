## 0. 전체 그림 — 지금 내가 어느 단계에 있는가

```
[01] 정상성 확보        → d, D, s 확정              (adf_test, transform)
[02] 평활/EDA           → 추세·잡음 감 잡기          (plot_rolling, compare_smoothing)
[03] 분해               → 가법/승법 판정, 계절조정   (decompose, report_seasonal)

[05] ARIMA 모델링        → 상한 안에서 최적 차수 "확정"  (fit_model)  ← 오늘
```

이 순서를 거꾸로 하면 안 된다 — 진단은 반드시 **모형을 확정한 뒤에** 그 모형의 잔차를 대상으로 한다.

## 1. 5단원: ARIMA/SARIMA 모델링

### 1-1. 표기법부터 말로 풀기

**ARIMA(p, d, q)** — 비계절 성분만 있는 모형
- **p (AR 차수)**: "몇 시점 전까지의 **값**을 참고하는가." AR(1)이면 바로 전 시점 값 하나로 현재를 설명.
- **d (차분 횟수)**: 정상성을 얻기 위해 몇 번 차분했는가.
- **q (MA 차수)**: "몇 시점 전까지의 **예측 오차(잔차)**를 참고하는가." MA(3)이면 최근 3개 시점의
  오차가 현재 값에 영향을 준다고 보는 것.

**SARIMA(p,d,q)(P,D,Q,s)** — 계절 성분까지 포함
- **P, D, Q**: 위와 같은 개념을 "**계절 주기만큼 떨어진 시점**"에 적용한 것. 월별 데이터(s=12)라면
  P=1은 "작년 같은 달의 값"을, Q=1은 "작년 같은 달의 오차"를 참고한다는 뜻.
- **s (계절 주기)**: 한 계절 사이클의 길이. 월별 데이터면 12.

> **말로 외우기**: AR = "예전 **값**의 기억", MA = "예전 **실수**의 기억", 대문자(P,D,Q)는 그 기억을
> "몇 시점 전"이 아니라 "몇 **시즌** 전"에서 가져온다는 뜻.

### 1-2. 차수 탐색은 왜 "상한"만 정해두고 그리드서치를 하는가

04단원(ACF·PACF)에서 이미 각 차수의 **상한**을 좁혀 놓았다. 그런데 ACF·PACF는 "대략 이 근처"까지만
알려줄 뿐 정확한 최종값을 보장하지 않는다. 그래서 5단원은 **0부터 상한까지 모든 조합**을 실제로
적합시켜 보고, 그중 가장 좋은 조합을 통계적 기준(AIC/BIC)으로 고른다.

**조합 개수 계산 (연습문제 1번 핵심)**
- 상한이 있는 차수 하나가 가질 수 있는 값은 $0, 1, \dots, k$ 로 **k+1가지**.
- d, D는 이미 확정된 값이라 탐색 대상이 아니고(고정), p, q, P, Q 네 개만 곱해서 조합 수를 구한다.
- 예: p 상한 1, q 상한 3, P 상한 3, Q 상한 2 → $(1+1)\times(3+1)\times(3+1)\times(2+1) = 2\times4\times4\times3 = 96$가지.
- **함의**: ACF·PACF로 상한을 미리 좁혀두지 않으면(예: 모두 0~5로 탐색) $6^4=1296$가지를 적합해야
  한다. 03~04단원이 하는 일이 바로 이 탐색 공간을 줄이는 것 — **전 단원이 다음 단원의 비용을 줄인다.**

### 1-3. 모형 선택 기준 — AIC vs BIC (귀무가설이 아니라 "정보기준")

AIC, BIC는 가설검정이 아니라 **모형끼리 상대 비교**하는 정보기준이다. 둘 다 다음 형태를 따른다.

$$\text{기준값} = -2\ln(L) + \text{벌점}$$

- $-2\ln(L)$: 모형이 데이터를 얼마나 잘 설명하는가(적합도). L은 우도(likelihood). 값이 작을수록
  잘 맞는다는 뜻이 되도록 부호가 잡혀 있다.
- **벌점**: 계수(파라미터)를 늘릴수록 적합도는 항상 좋아지는 경향이 있으므로("계수를 늘리면 무조건
  더 잘 맞춰버린다"), 계수 개수에 비례한 벌점을 더해서 **너무 복잡한 모형을 억제**한다.

| 기준 | 벌점 공식 | 특징 | 언제 쓰나 |
|---|---|---|---|
| **AIC** | $2k$ (k = 계수 개수) | 벌점이 상대적으로 약함 → **복잡한 모형**을 고르는 경향 | **예측**이 목적일 때 |
| **BIC** | $k\ln(n)$ (n = 관측치 수) | 표본이 클수록 벌점이 커짐 → **단순한 모형**을 고르는 경향 | **설명·해석**이 목적일 때 |

- 관측치 n=602개면 $\ln(602)=6.40$. 즉 BIC는 계수 하나당 6.40점을 깎아먹는데, AIC는 2점만 깎는다.
  **BIC의 벌점이 AIC보다 3배 이상 세다.** 그래서 표본이 클수록 두 기준이 서로 다른 모형을 고르기
  쉬워진다 — 이게 갈리는 게 오히려 정상이다.
- `fit_model()`은 **항상 AIC 기준으로 최적 모형을 반환**한다(뒤에 코드 설명 참고). 목적이 예측이면
  이게 맞는 선택이고, 목적이 "이 시계열이 어떤 구조로 움직이는가"를 보고서로 설명하는 것이라면
  BIC가 고른(더 단순한) 모형이 나을 수 있다. **→ 지표가 모형을 정하는 게 아니라, 목적이 지표를 정한다.**

### 1-4. `fit_model()` 코드 뜯어보기 — 무슨 일을 하는 함수인가

```python
best_fit = my_ts.fit_model(
    source, "평균기온(℃)",
    p=p, d=d, q=q, P=P, D=D, Q=Q, s=s,   # d,D,s는 앞단원이 확정한 "고정값"
    log=False                             # 기온처럼 음수가 있으면 로그변환 불가
)
```

내부 로직(중요한 것만 요약):
1. **대상 추출**: 데이터프레임이면 지정한 컬럼만 뽑고 결측치 제거. `log=True`면 여기서 **한 번만**
   로그를 씌운다(차분은 SARIMAX가 d, D로 알아서 처리하므로 직접 diff() 하지 않는다).
2. **탐색 조합 생성**: `d, D`는 기본적으로 고정값 하나만 시도한다(이미 확정된 값이므로). 이유는
   **차분 횟수가 다르면 "설명하는 대상 자체"가 달라져서 AIC를 나란히 비교할 수 없기 때문**이다
   (원 계열과 1차 차분 계열은 서로 다른 확률변수를 모델링하는 것과 같다).
3. **조합마다 SARIMAX 적합 → AIC/BIC 기록**: 적합 실패한 조합(수렴 실패 등)은 조용히 건너뛴다.
4. **AIC가 가장 낮은 모형을 `best`로 갱신**하며 반복 — 별도로 다시 적합할 필요 없이 그 자리에서 교체.
5. **결과표(`grid`)는 AIC 오름차순 정렬** 후 결과 객체에 `best.grid`, `best.log` 속성으로 붙여서 반환.
   → `predict()`가 나중에 이 `log` 속성을 보고 로그 역변환 여부를 자동으로 판단한다.

**반환값(`best_fit`)이 들고 있는 것**: 채택된 SARIMAX 결과 객체 + `.grid`(전체 탐색표) + `.log`(로그
여부). 이후 `predict()`, `report_residual()`, `report_score()`가 전부 이 객체 하나만 받아서 동작한다.
즉 **한 번 적합한 모형 객체를 계속 재활용**하는 구조 — 절대 매번 다시 적합하지 않는다.

### 1-5. `predict()` 코드 뜯어보기 — 예측값과 예측구간

```python
my_ts.predict(best_fit, steps=s, history=48, xlabel="월", ylabel="평균기온(℃)")
```

- `steps`: 관측이 끝난 다음 시점부터 몇 개를 내다볼지. 계절 주기(s=12)를 넣으면 **딱 한 시즌**을
  예측한다는 뜻이 된다.
- 내부적으로 `fit.get_forecast(steps=steps)` → `conf_int(alpha=alpha)`로 **점 예측(pred)**과
  **예측구간(lower, upper)**을 함께 얻는다. `alpha=0.05`가 기본이므로 **95% 예측구간**.
- `log` 적합이었다면 예측값·예측구간을 **원래 단위로 되돌리기 위해 `np.exp()`**를 씌운다(로그를
  씌운 채로 두면 "명 단위 오차"를 말할 수 없다).
- `plot=False`로 호출하면 그래프 없이 표(`DataFrame`: pred, lower, upper)만 반환 — 표만 다시 뽑고
  싶을 때 재적합 없이 이렇게 쓴다.

> **예측구간을 꼭 함께 말해야 하는 이유**: 점 예측 하나만 던지면 반드시 틀린다. "**얼마나 틀릴 수
> 있는가**"까지 폭으로 답하는 것이 예측의 완결이다. `pred_df["upper"] - pred_df["lower"]`가 그 폭이다.

### 1-6. 05단원 연습문제(서울 기온) 정리

**세팅**: `d=0, D=1, s=12` (고정) / 상한 `p≤1, q≤3, P≤3, Q≤2` (04단원이 넘긴 값). 기온은 음수가
있어 `log=False`.

| # | 질문 요지 | 정답 | 핵심 개념 |
|---|---|---|---|
| 1 | 시도하는 차수 조합 수 | **96가지** | $(p{+}1)(q{+}1)(P{+}1)(Q{+}1) = 2\times4\times4\times3$. d,D,s는 고정이라 탐색 안 함 |
| 2 | BIC 1위 모형의 계수 개수 | **4개** | BIC 최적 (1,0,1)(0,1,1,12) — 벌점이 세서 더 단순한 모형 선택 |

- AIC 1위와 BIC 1위가 다를 때 "어느 게 맞다"가 아니라 **목적(예측 vs 설명)에 따라 다른 게 맞다**.

## 2. 6단원: ARIMA 진단 및 평가

> 05단원에서 모형을 하나로 확정했다. 6단원은 이 모형을 "그대로 믿고 써도 되는가"를 두 갈래로 검증한다.
> **(A) 가정 점검(잔차 진단)**: 모형이 세운 통계적 전제를 지키고 있는가.
> **(B) 적합도 평가**: 그 모형이 실제로 얼마나 잘 맞는가(성능 숫자).

### 2-1. burn-in 개념 — 왜 잔차 앞부분을 잘라내야 하는가

차분은 "이전 값과의 차"를 계산하는 연산이라, **뺄 대상이 없는 맨 앞 시점들은 값이 만들어지지 않는다.**
계절차분(주기 s)까지 겹치면 소모되는 시점 수는:

$$\text{BURN} = d + D \times s$$

- 항공승객 예제: $d{=}1, D{=}1, s{=}12$ → $1+1\times12=13$개를 잘라낸다.
- 서울기온 예제: $d{=}0, D{=}1, s{=}12$ → $0+1\times12=12$개를 잘라낸다.
- **잘라낼 개수는 데이터마다 고정된 숫자가 아니라 "그 모형의 차분 횟수"에서 나온다.** 다른 데이터셋을
  분석할 때는 반드시 그 모형의 (d, D, s)로 다시 계산해야 한다 — 이전 랩 숫자를 그대로 재사용하면 안 됨.

```python
BURN = d + D * s
resid = fit.resid[BURN:]      # 이 구간부터가 "정상적으로 자리 잡은" 잔차
```

이 구간을 자르지 않으면 모형이 아직 자리를 못 잡은 초반의 비정상적으로 큰 잔차가 이후의 모든 진단
검정(정규성, 등분산성, 자기상관)을 왜곡한다.

### 2-2. 잔차가 만족해야 할 세 가지 가정 — 하나하나 말로 풀기

ARIMA 계열 모형은 "**잔차(모형이 설명하지 못하고 남긴 오차)**가 사실상 백색잡음(white noise)처럼
보여야 한다"는 전제 위에 서 있다. 이 전제를 세 가지 검정으로 나눠서 확인한다.

#### ① 무상관(독립성) — Ljung-Box 검정

- **왜 확인하나**: 잔차에 시간적 패턴(자기상관)이 남아 있다면, 모형이 뽑아낼 수 있었던 정보를 아직
  덜 뽑아낸 것이다 — 즉 차수를 더 조정할 여지가 있다는 신호. **세 가정 중 가장 중요한 가정**이다.
- **가설을 말로 풀면**:
  - 귀무가설 $H_0$: "여러 시차에 걸쳐 잔차들 사이에 자기상관이 **없다**(잔차는 백색잡음이다)."
  - 대립가설 $H_1$: "적어도 한 시차에서 잔차들 사이에 자기상관이 **존재한다**."
- **검정 방식**: 개별 시차를 하나씩 보는 게 아니라, **여러 시차를 한 묶음으로 모아** 한 번에 검정한다
  (포트맨토 검정). 계절 데이터면 **한 시즌(s), 두 시즌(2s)** 떨어진 자리를 본다 — 계절 패턴이 남았는지
  보려는 것.
- **자유도 보정이 필요한 이유**: 잔차는 원자료가 아니라 "모형이 계수를 추정하고 남긴 결과물"이다.
  그래서 검정 시 자유도에서 **모형이 추정한 계수 개수만큼 빼야 한다.**
  $$\text{자유도} = \text{시차} - (p+q+P+Q)$$
  이걸 빼지 않으면 p-value가 실제보다 **크게** 나와서 "문제 없음" 쪽으로 부당하게 관대해진다.
- **판정**: p-value ≥ 0.05 → 귀무가설 기각 못 함 → **통과(자기상관 없음)**. p-value < 0.05 → **실패**.

```python
from statsmodels.stats.diagnostic import acorr_ljungbox

model_df = p + q + P + Q                 # 추정한 계수 수만큼 자유도 차감
lb = acorr_ljungbox(resid, lags=[12, 24], model_df=model_df, return_df=True)
lb["판정"] = np.where(lb["lb_pvalue"] >= 0.05, "통과", "실패")
```

#### ② 정규성 — Jarque-Bera 검정

- **왜 확인하나**: 예측구간(신뢰구간)은 잔차가 정규분포를 따른다는 전제로 계산된다. 정규성이 깨지면
  **점 예측값 자체는 여전히 쓸 수 있지만, "구간"의 폭을 그대로 믿기는 어렵다.**
- **가설을 말로 풀면**:
  - 귀무가설 $H_0$: "잔차의 분포는 정규분포와 **같다**(왜도=0, 첨도=3에 해당)."
  - 대립가설 $H_1$: "잔차의 분포는 정규분포와 **다르다**."
- **왜도(skewness)**: 분포가 좌우로 얼마나 치우쳐 있는가. 0에 가까울수록 좌우 대칭.
- **첨도(kurtosis)**: 분포가 얼마나 뾰족한가(꼬리가 얼마나 두꺼운가). 정규분포의 첨도는 3이며,
  3보다 크면 평소보다 극단값(아주 크거나 작은 잔차)이 잦다는 뜻.
- Jarque-Bera는 왜도와 첨도를 하나의 통계량으로 묶어서 "정규분포에서 기대되는 값(왜도0, 첨도3)과
  얼마나 다른가"를 검정한다.
- **판정**: p-value ≥ 0.05 → **통과(정규성 만족)**.
- **실전에서 흔한 패턴**: 왜도는 거의 0(좌우 대칭)인데 첨도만 3보다 커서 실패하는 경우 — 이는
  "좌우로 치우쳐서"가 아니라 "**평소보다 유난히 튀는 값(극단적인 달)이 몇 번 있어서**"라는 뜻이다.
  표본이 클수록(수백 개 이상) 이런 작은 차이도 검정이 예민하게 잡아낸다.

```python
jb_stat, jb_p, skew, kurtosis = fit.test_normality("jarquebera")[0]
```

#### ③ 등분산성 — 이분산(H, breakvar) 검정

- **왜 확인하나**: 잔차의 흔들림(분산)이 시간이 지나도 일정해야("등분산") 예측구간의 폭이 전 구간에
  걸쳐 공정하게 계산된다. 분산이 커지거나 작아지는 추세가 있으면 구간 폭이 어느 시점에서는 실제보다
  좁게(위험), 어느 시점에서는 넓게(보수적으로) 잡힌다.
- **가설을 말로 풀면**:
  - 귀무가설 $H_0$: "잔차의 분산은 관측 구간 앞부분과 뒷부분에서 **동일**하다(등분산)."
  - 대립가설 $H_1$: "앞부분과 뒷부분의 분산이 **다르다**(이분산)."
- **통계량 H의 의미**: 뒤 구간의 분산 ÷ 앞 구간의 분산.
  - $H > 1$: 뒤로 갈수록 흔들림이 **커진다** → 원계열이 로그변환 없이 그대로면 자주 나타나는 방향.
  - $H < 1$: 뒤로 갈수록 흔들림이 **작아진다** → 로그변환을 한 뒤에 자주 나타나는 방향(로그는 큰 값을
    더 세게 눌러 압축하므로).
  - 1에 가까울수록 등분산.
- **판정**: p-value ≥ 0.05 → **통과(등분산)**.
- **실무 함의**: H<1(넓게 잡힘, 즉 보수적)은 위험한 방향이 아니지만, H>1(좁게 잡힘)은 예측구간이
  실제보다 좁아 위험할 수 있으니 주의가 필요하다.

```python
h_stat, h_p = fit.test_heteroskedasticity("breakvar")[0]
```

### 2-3. `report_residual()` — 세 가정을 한 번에 점검하는 모듈 함수

```python
my_ts.report_residual(fit, xlabel="연도")
```

이 함수가 내부에서 자동으로 하는 일:
1. `fit.model`에서 `(p,d,q)`와 `(P,D,Q,s)`를 **직접 읽어와** BURN을 스스로 계산한다 → 호출자가
   BURN을 따로 넘길 필요가 없다(재사용성).
2. Ljung-Box의 시차(lags)를 **계절 주기가 있으면 [s, 2s], 없으면 [10]**으로 자동 결정하고, 자유도
   보정(`model_df = p+q+P+Q`)까지 반영한다. 또한 시차가 표본 대비 너무 크면(관측치의 1/5 초과) 걸러
   내는 안전장치도 있다.
3. 정규성(Jarque-Bera), 등분산성(breakvar) 검정을 이어서 수행.
4. 세 검정 결과를 **하나의 DataFrame**(검정명 인덱스, 통계량/p-value/통과여부/판정/비고 컬럼)으로
   묶어 반환하고, 옵션에 따라 잔차의 시계열 그래프 + 분포 히스토그램도 함께 그린다.
5. `report=True`면 "실패한 검정: OO" 형태로 한 줄 요약을 출력 — **어느 가정이 깨졌는지 즉시 알 수 있다.**

> **직접 코딩 버전 vs 모듈 버전 차이**: 실습코드(air_passengers)에서는 BURN 계산, Ljung-Box 호출,
> Jarque-Bera, breakvar를 **하나씩 따로** 작성했다. `report_residual()`은 이 네 단계를 한 함수로
> 캡슐화한 것 — 다른 데이터셋을 분석할 때는 이 모듈 함수 한 줄이면 충분하다.

### 2-4. 적합도 평가 지표 — MAE, RMSE, MAPE

세 지표 모두 "**오차 = 관측값 − 예측값(적합값)**"을 요약하는 방식이 다르다.

| 지표 | 계산식 | 특징 |
|---|---|---|
| **MAE** (평균절대오차) | $\frac{1}{n}\sum \lvert y_i - \hat y_i \rvert$ | 오차를 그대로 절댓값 평균. **데이터와 같은 단위**로 말할 수 있어 해석이 직관적("평균 몇 도/몇 명 틀린다") |
| **RMSE** (평균제곱근오차) | $\sqrt{\frac{1}{n}\sum (y_i-\hat y_i)^2}$ | 오차를 제곱하므로 **큰 오차에 더 민감**. RMSE와 MAE의 차이가 크면 "가끔 크게 틀리는 달"이 있다는 신호 |
| **MAPE** (평균절대백분율오차, %) | $\frac{1}{n}\sum \left\lvert \frac{y_i-\hat y_i}{y_i} \right\rvert \times 100$ | 단위 없는 **비율**이라 서로 다른 데이터셋끼리도 비교 가능. 단, **관측값이 0에 가까우면 분모가 0에 가까워져 비율이 폭발** — 영하/영상을 오가는 데이터(기온 등)에는 쓰면 안 됨 |

**성능은 반드시 기준선(baseline)과 함께 봐야 의미가 있다.** 그래서 항상 "**계절 나이브**"를 같이
계산한다 — "작년 같은 달 값을 그대로 이번 달 예측값으로 쓴다"는, 모형 없이도 가능한 가장 단순한
예측 방식. ARIMA가 이 기준선보다 얼마나 나은지가 곧 "모형이 실제로 학습한 것"의 크기다.

```python
naive = df["Passengers"].shift(12)[BURN:]     # 계절 나이브: 12개월 전 값 그대로
arima_error = actual.values - fitted.values
naive_error = actual.values - naive.values

MAE  = np.mean(np.abs(error))
RMSE = np.sqrt(np.mean(error ** 2))
MAPE = np.mean(np.abs(error / actual.values)) * 100
```

> **주의**: 이 지표들은 모형이 **이미 학습에 쓴 데이터**(적합값, in-sample)에 대한 값이다. 그래서
> "모형이 데이터를 얼마나 잘 설명하는가"는 말할 수 있어도, "미래를 얼마나 정확히 맞히는가"를 그대로
> 보장하지는 않는다(진짜 예측 성능을 보려면 별도의 out-of-sample 검증이 필요 — 이 랩의 범위 밖).

### 2-5. `report_score()` — 적합도 평가를 자동화한 모듈 함수

```python
my_ts.report_score(fit, name="SARIMA 적합값")
```

내부 로직 요약:
1. `fit.model`에서 (p,d,q), (P,D,Q,s), 로그 여부(`fit.log_`)를 읽어온다.
2. 로그 적합이었다면 관측값·적합값을 `np.exp()`로 **원래 단위로 되돌린 뒤** 지표를 계산한다
   (그래야 "몇 명/몇 도 틀리는가"를 말할 수 있다).
3. 계절 주기가 있으면 "계절 나이브(시차 s)", 없으면 "나이브(직전값)"를 자동으로 기준선으로 잡는다.
4. BURN(=d+D×s)만큼 앞부분을 제외하고, 모형·기준선 두 컬럼이 **모두 존재하는 공통 구간**만 남긴 뒤
   MAE/RMSE/MAPE를 계산해 표로 반환한다.
5. MAPE 계산 시 **관측값이 정확히 0인 시점은 자동으로 제외**한다(분모 0 방지) — 다만 0에 "가까운"
   값들은 걸러지지 않으므로, 기온처럼 0 근처를 오가는 데이터는 MAPE 결과를 신뢰하지 말아야 한다
   (연습문제 6번 참고).
6. `report=True`면 "MAPE OO% → OO% (기준선 대비 개선폭)"을 한 줄로 출력.

7. 적합도: 로그 스케일 적합값 `fit.model.data.orig_endog`, `fit.fittedvalues`를 `np.exp()`로 환원 →

   **매년 증가 추세**라서, 작년 값을 그대로 쓰면 증가분만큼 항상 모자라기 때문.
8. `my_ts.report_residual(fit)`, `my_ts.report_score(fit, name="ARIMA 적합값")`로 위 전체를 모듈 함수
   한 줄씩으로 재현 — **직접 코딩으로 원리를 확인한 뒤, 모듈로 압축**하는 이 랩 전체의 학습 패턴.

## 3. `my_ts` 모듈 확장 사고방식 — 지금까지의 전체 함수 지도

이 랩은 "**직접 코딩으로 원리를 확인 → 검증되면 모듈 함수로 승격**"하는 패턴을 반복해왔다
(my_ols, my_logit도 같은 패턴). 05~06단원까지의 `my_ts.py` 함수:

| 함수 | 단원 | 역할 |
|---|---|---|
| `set_index` | 02~ | 날짜 컬럼을 인덱스로, freq 지정 |
| `transform` | 01~ | 로그/차분/계절차분 적용 |
| `adf_test`, `adf_diff`, `adf_transform` | 01 | ADF 검정으로 정상성 확보 경로 탐색 |

| `decompose`, `report_seasonal`, `adjust_seasonal` | 03 | 분해, 계절지수, 계절조정 |
| `auto_correlation` | 04 | ACF·PACF로 p,q,P,Q 상한 도출 |
| **`fit_model`** | **05** | **차수 그리드서치 → AIC 최적 모형 확정** |
| **`predict`** | **05** | **예측값 + 예측구간 계산·시각화** |

**앞으로 확장할 때 사고 순서**(다른 데이터셋에 적용할 때도 동일):
1. 01~04단원 함수로 `d, D, s`와 `p,q,P,Q` **상한**을 먼저 확정한다 — 05단원 전에 반드시 끝나 있어야 함.
2. `fit_model()`에 **d, D, s는 고정값**으로, **p,q,P,Q는 상한**으로 넘긴다. 데이터에 음수가 있으면
   `log=False`를 명시(기온·수익률 등). 양수만 있고 분산이 값 크기에 비례해 커지면 `log=True` 고려.
3. `predict()`로 원하는 시점 수만큼 예측 + 예측구간 확보. `steps=s`면 딱 한 시즌.
4. **모형을 확정했으면 반드시** `report_residual()`로 세 가정을 점검 — 특히 무상관(가장 중요)이
   실패하면 차수를 다시 잡아야 한다(4단원으로 되돌아감을 의미).
5. `report_score()`로 나이브 기준선 대비 성능을 확인. 데이터가 0을 지나는 값이면 **MAPE는 참고만
   하고 MAE/RMSE 위주로 판단**.

## 4. 재사용 코드 템플릿

### 템플릿 A — 05단원: 모델링 + 예측

```python
from jussam import load_data
from helpers import *

origin = load_data("데이터셋명")
df = my_ts.set_index(origin, "날짜컬럼", freq="MS")   # freq는 데이터 주기에 맞게

# 01~04단원에서 확정한 값
d, D, s = 0, 1, 12          # 일반차분, 계절차분, 계절주기 (고정)
p, q = 1, 3                 # AR, MA 상한 (탐색)
P, Q = 3, 2                 # 계절 AR, 계절 MA 상한 (탐색)

best_fit = my_ts.fit_model(
    df, "대상컬럼",
    p=p, d=d, q=q, P=P, D=D, Q=Q, s=s,
    log=False,      # 음수 가능하면 False, 값 커질수록 변동폭도 커지면 True 검토
)

pred_df = my_ts.predict(best_fit, steps=s, history=48,
                        xlabel="시점", ylabel="대상단위")
pred_df["구간 폭"] = (pred_df["upper"] - pred_df["lower"]).round(3)
```

## 5. 함정 · 자주 헷갈리는 지점 총정리

- **BURN 값은 매번 다시 계산**: `d + D*s` 공식만 기억하고, 이전 랩(항공승객 13개)의 숫자를 그대로
  다른 데이터셋에 재사용하지 않는다.
- **Ljung-Box 자유도**: 시차 − (p+q+P+Q). **차분 횟수(d, D)는 계수가 아니므로 빼지 않는다** — 여기서
  혼동해 자유도를 더 깎는 실수가 흔하다.
- **AIC ≠ BIC 최적 모형**: 갈리는 게 정상. `fit_model()`은 **항상 AIC 기준**으로 반환하므로, "설명"이
  목적인 보고서를 쓸 때는 `grid`에서 BIC 기준으로 직접 다시 골라야 한다.
- **d, D는 `fit_model()`에서 탐색하지 않고 고정**: 차분 횟수가 다르면 서로 다른 대상을 모델링하는
  것이라 AIC 비교 자체가 성립하지 않는다.
- **로그 적합이면 예측값·적합값·관측값을 모두 `np.exp()`로 환원 후 지표 계산**: 로그 스케일 그대로
  MAE를 구하면 "몇 명/몇 도 틀리는가"라는 실질적인 단위 해석이 불가능해진다.
- **MAPE는 관측값이 0을 지나거나 0에 가까운 데이터에는 쓰지 않는다**: 기온·순이익률처럼 부호가
  바뀌는 데이터가 대표적 위험군. MAE/RMSE로 대체 해석.
- **정규성 위반 ≠ 모형 폐기**: 점 예측은 그대로 쓰되, 예측구간의 폭을 "그대로 믿지 말고 여유를 두고
  해석한다"는 식으로 보고서에 명시하는 게 정석 대응.
- **등분산 통계량 H의 방향 해석**: H>1(뒤로 갈수록 커짐, 구간이 실제보다 좁아져 위험할 수 있음) vs
  H<1(뒤로 갈수록 작아짐, 구간이 보수적으로 넓어짐 — 상대적으로 덜 위험). 로그변환을 했다면 H<1
  방향이 나오기 쉽다는 것도 함께 기억.
- **적합도 지표는 in-sample(이미 학습한 데이터)에 대한 값**: "얼마나 잘 설명하는가"이지 "미래를
  얼마나 맞히는가"의 보장이 아님을 보고서에서 구분해서 말해야 한다.
