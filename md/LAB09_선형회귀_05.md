## 0. 이 문서를 보는 법 (복습할 때 뭘 봐야 하나)

복습할 때 코드를 다시 치는 것보다 아래 3가지를 스스로 말로 설명할 수 있는지 확인하는 게 우선이다.

1. **왜 이 순서인가?** — 라벨링 → 더미 → 로그변환 → 이상치 → VIF → 정규화. 순서를 바꾸면 결과가 달라진다는 것(연습문제 문제6이 실제로 보여줌).
2. **각 단계에서 "무엇을 판단 기준으로" 처리 대상을 고르는가?** — 왜도로 로그변환 대상을 고르고, IQR로 이상치를 고르고, VIF로 공선성 변수를 고르는 식. 값을 외우는 게 아니라 "판단 기준 → 처리 방법"의 연결을 기억해야 면접에서 설명할 수 있다.
3. **내 모듈(my_prep, my_qtcheck)이 내부적으로 뭘 하고 있는가?** — 함수를 블랙박스로 쓰지 말고, 함수 하나 열어서 "이 안에서 pandas/numpy/statsmodels 코드가 어떻게 짜여 있는지" 최소 한 번은 눈으로 확인해야 한다. 그게 "직접 코딩 버전"과 "모듈 호출 버전"을 연결하는 다리다.

## 1. 전체 파이프라인 (이번 LAB의 뼈대)

```
[이전 EDA 산출물: df, desc, cat_desc, target, nominal_cols, continuous_cols]
        │
        ▼
1. 명목형 라벨링        my_prep.labeling()
        ▼
2. 더미변수 인코딩      my_prep.dummies()
        ▼
3. 로그변환 대상 선정   desc['log_need'] 컬럼 참조 (직접 코딩)
        ▼
4. 로그 변환            my_prep.log_transform()
        ▼
5. 이상치 대체          my_prep.replace_outlier()
        ▼
6. 다중공선성 제거      my_prep.reduce_vif()
        ▼
7. 정규화(표준화)       my_prep.scaling()
        ▼
[모델 투입 가능한 데이터]
```

**이 순서가 왜 중요한가**
- 로그변환이 이상치 대체보다 먼저 와야 한다 — 로그를 씌우면 분포 자체가 바뀌므로, 이상치 판단 범위(IQR 경계)도 로그 스케일 기준으로 계산돼야 한다. (연습문제 6번: `children`의 정상범위가 음수로 나온 이유가 바로 "log(1+x) 변환 후" 값으로 IQR을 계산했기 때문)
- VIF(다중공선성 제거)는 로그변환·이상치 대체가 끝난 뒤, 정규화 전에 한다 — 스케일링 자체는 상관관계(VIF)에 영향을 주지 않지만, 관례상 "분포를 다 정리한 최종 변수들" 사이의 공선성을 보는 것이 맞다.
- 정규화(표준화)는 **항상 마지막**, 그리고 **독립변수에만** 적용한다. 종속변수(target)를 표준화하면 나중에 예측값을 원래 단위(달러, 가격 등)로 되돌리기가 번거로워지기 때문에 대상에서 제외한다.

## 2. 두 가지 실행 버전 — "직접 코딩"과 "모듈 호출"

이 LAB에서 헷갈리기 쉬운 부분: 노트북 안에 실제로 보이는 코드는 짧지만(`my_prep.labeling(df, columns=...)` 한 줄), 그 뒤에는 훨씬 긴 pandas/numpy/statsmodels 코드가 함수 안에 숨어 있다.

| | 실습코드(boston) 노트북 | 연습문제(insurance) 노트북 |
|---|---|---|
| 이전 단계 산출물 확보 방법 | `%run "...EDA 노트북.ipynb"` 으로 **직전 EDA 노트북을 통째로 재실행**해서 그 안의 변수(df, desc, target 등)를 그대로 가져옴 | `load_data()` 로 **미리 저장된 결과 데이터셋**(origin, desc, cat_desc)을 바로 불러옴 |
| 전처리 실행 방법 | `my_prep.함수명()` 모듈 호출 | 동일하게 `my_prep.함수명()` 모듈 호출 |
| 의미 | "직접 이어 붙이기" 버전 — 매번 EDA 전체를 재실행해야 하므로 무겁지만, 앞 단계와의 연결이 눈에 보임 | "모듈+데이터 캐시" 버전 — 이미 완성된 중간 결과를 바로 로드해서, 전처리 로직 자체에만 집중 |

**정리하면 두 버전의 차이는 "이전 단계 데이터를 어떻게 확보하냐"의 차이일 뿐, 전처리 로직(`my_prep`, `my_qtcheck` 모듈 호출)은 완전히 동일하다.** 즉 "직접 코딩 vs 모듈 코딩"의 진짜 축은:

- **모듈 안쪽(my_prep.py, my_qtcheck.py 내부)** = 원본 pandas/numpy/statsmodels/sklearn 코드를 직접 짠 부분
- **노트북 바깥쪽(이 실습 노트북)** = 그 모듈을 불러와서 한 줄로 호출하는 부분

으로 나뉜다. 노트북에서는 항상 후자만 보이지만, 실력을 늘리려면 전자(모듈 내부 코드)를 열어서 "이 한 줄이 실제로 몇 단계를 압축한 것인지" 확인하는 습관이 필요하다.

## 3. 모듈(helpers 패키지) 사고방식 — 어떻게 확장해 나가야 하나

### 3-1. 지금 쓰는 4개 모듈의 역할 분담

| 모듈 | 역할 | 이번 LAB에서 쓴 함수 |
|---|---|---|
| `__init__.py` | 패키지 진입점. `from helpers import *` 했을 때 어떤 이름들을 노출시킬지 정의 | (직접 호출 X, 다른 모듈들을 내부적으로 import해서 연결) |
| `my_qtcheck.py` | **데이터 품질 점검 + 타입/변수유형 분류** 담당 | `set_type()`, `get_categorical_column_names()`, `get_number_column_names()` |
| `my_prep.py` | **모델 투입 전 전처리(preprocessing)** 담당 | `labeling()`, `dummies()`, `log_transform()`, `replace_outlier()`, `reduce_vif()`, `scaling()` |
| `my_stats.py` / `my_plot.py` | 추론통계 검정, 시각화 (이번 LAB에서는 직접 안 씀, 이전 LAB에서 만든 모듈) | - |

### 3-2. 앞으로 확장할 때의 원칙

1. **"이 함수가 하는 일이 한 문장으로 설명되는가?"** — `my_prep.py`에 새 함수를 추가할 때, 함수 하나가 여러 책임을 갖지 않도록 한다. (예: `log_transform`은 "로그 변환만" 하고, "어떤 컬럼에 로그를 씌울지 판단"하는 로직은 `desc['log_need']`를 만드는 EDA 단계 몫으로 분리되어 있음 — 실제로 이번 노트북에서도 대상 컬럼 선정은 모듈 호출이 아니라 노트북에서 직접 `desc.loc[...]` 코드로 처리했다.)
2. **새 데이터셋에 적용하기 전에 반드시 "작은 단위로 실행 확인"** — 처음부터 파이프라인 전체를 한 번에 돌리지 말고, `df1 = my_prep.labeling(...)` 한 줄 실행 → `df1.head()`로 확인 → 다음 단계, 순서로 검증한다. 이번 두 노트북 모두 매 단계마다 `.head()` 또는 `.describe()`로 눈으로 확인하는 패턴을 유지한 것이 그 이유다.
3. **모듈 함수는 원본을 바꾸지 않고 새 데이터프레임을 반환한다** — `df1, df2, df3 ... df6`처럼 단계별로 변수명을 다르게 쌓아가는 이유는, 중간 단계로 언제든 되돌아가 디버깅할 수 있게 하기 위함이다. (pandas의 "원본 비파괴 반환" 원칙과 같은 맥락)
4. **체크포인트 저장(`to_excel`) 습관** — boston 실습에서는 `df2.to_excel("boston_checkpoint_0.xlsx")`처럼 단계마다 저장했다. 새 데이터셋으로 확장할 때도 최소한 "라벨링/더미 후", "로그·이상치·VIF·정규화 후" 이 두 지점은 저장해두면, 커널이 죽거나 실수했을 때 처음부터 다시 안 해도 된다.
5. **함수 시그니처(파라미터)를 먼저 읽는다** — 예를 들어 `reduce_vif(df, columns, threshold=10.0)`처럼 기본값이 있는 파라미터는, 다른 데이터셋에서 그 기본값이 적절한지 먼저 따져야 한다(VIF 임계값 10은 관례값이지만 데이터 크기·분야에 따라 5를 쓰기도 함).

## 4. 단계별 개념 + 수식 + 코드

### 4-1. 사전 준비 — 변수 유형 확정 (`my_qtcheck`)

```python
df = my_qtcheck.set_type(origin, as_category=cat_desc.columns)
nominal_cols = my_qtcheck.get_categorical_column_names(df)
continuous_cols = my_qtcheck.get_number_column_names(df)
continuous_cols.remove(target)   # 종속변수는 독립변수 목록에서 반드시 제외
```

**개념**: 전처리를 시작하기 전에 "이 컬럼은 명목형(범주형)이다 / 이 컬럼은 연속형(수치형)이다"를 코드가 아니라 **데이터 타입 자체**로 확정해야 한다. pandas는 기본적으로 정수/문자를 구분할 뿐, "이게 통계적으로 범주형인지 연속형인지"는 모른다. `set_type`으로 `category` dtype을 명시적으로 부여하면, 이후 함수들이 "이 컬럼은 라벨링/더미 대상"이라고 자동으로 인식할 수 있게 된다.

**주의**: EDA에서 제외하기로 한 변수(`sex`, `region`)는 데이터프레임에서 `drop`할 때, **명목형 목록(`nominal_cols`, `cat_desc.columns`)에서도 함께 제거**해야 한다. 목록만 남겨두면 다음 단계에서 "이미 없는 컬럼을 라벨링하라"는 오류가 난다 — 실무에서 가장 자주 하는 실수.

---

### 4-2. 명목형 라벨링 (Label Encoding) — `my_prep.labeling()`

**개념**: 문자로 된 범주(`no`, `yes` 등)를 정수로 바꾸는 가장 단순한 인코딩. 순서를 직접 지정하지 않으면 **알파벳(사전) 순서로 0부터** 번호를 매긴다.

- `smoker`: `no` → 0, `yes` → 1 (n이 y보다 알파벳 순서상 앞이므로)

**왜 중요한가**: 이 매핑을 확인하지 않으면 나중에 회귀계수의 부호를 반대로 해석하게 된다. `smoker` 계수가 양수(+)라면 "1(흡연자)일수록 청구비용이 높다"로 읽어야 하는데, 매핑을 착각하면 정반대 결론을 내리게 된다.

```python
df1 = my_prep.labeling(df, columns=nominal_cols)
```

---

### 4-3. 더미변수 인코딩 (One-Hot / Dummy Encoding) — `my_prep.dummies()`

**개념**: 범주가 3개 이상인 명목형 변수는 라벨 인코딩만으로 부족하다. 정수로 바꾸면 `0, 1, 2`처럼 **크기·순서 관계가 있는 것처럼** 모델이 잘못 해석할 수 있기 때문에(예: "지역 2가 지역 0보다 크다"는 의미 없는 관계), 각 범주를 독립된 0/1 컬럼으로 쪼갠다.

**규칙 (k-1 규칙, `drop_first=True`)**: 범주가 k개면 더미 컬럼은 보통 k-1개만 만든다. 마지막 하나는 "나머지 컬럼이 모두 0이면 이 범주"라는 뜻으로 자동으로 표현되기 때문(기준 범주, reference category). 이걸 지키지 않으면 **더미변수 함정(dummy variable trap)** — 더미 컬럼들의 합이 항상 1이 되어 완전한 다중공선성이 생긴다.

**예외 — 이진 변수는 더미를 만들지 않는다**: `smoker`처럼 범주가 2개뿐인 변수는 라벨링 결과 자체가 이미 0/1이므로, 더미 인코딩을 또 적용하면 `smoker_1`이라는 이름만 바뀐 동일한 컬럼이 생길 뿐이다. 그래서 `my_prep.dummies()`는 범주 2개짜리는 자동으로 건너뛴다(원래 컬럼 유지).

> 인코딩 전후 컬럼 수 변화가 "늘었나 그대로인가"를 보면, 몇 개짜리 범주형이 있었는지 역으로 확인할 수 있다 (insurance 예제: `smoker`만 남았고 2범주라 컬럼 수는 5개 → 5개로 그대로).

```python
df2 = my_prep.dummies(df1, columns=nominal_cols, drop_first=True)
```

### 4-4. 로그변환 대상 선정 — 직접 코딩 (desc 테이블 참조)

```python
log_cols = desc.loc[desc['log_need'] == 'log'].index.tolist()
log1p_cols = desc.loc[desc['log_need'] == 'log1p'].index.tolist()
reflect_cols = desc.loc[desc['log_need'] == 'reverse_log1p'].index.tolist()
```

여기가 "모듈로 자동화되지 않고, 노트북에서 직접 판단 로직을 짜는" 대표적인 지점이다. EDA 단계에서 이미 계산해 둔 `desc` 표의 `log_need` 컬럼(왜도·첨도·최솟값을 근거로 사전 판정된 값)을 조건 필터링(`desc.loc[...]`)해서 세 가지 컬럼 목록으로 나눈다.

#### 개념 1 — 왜도(Skewness, 3차 표준화 모멘트)

$$\text{Skewness} = \frac{E[(X-\mu)^3]}{\sigma^3}$$

**말로 풀면**: 분포가 평균을 중심으로 얼마나 비대칭인지를 나타내는 값이다.
- 왜도 > 0: **오른쪽(양의) 꼬리**가 길다 — 대부분 값은 작은 쪽에 몰려 있고, 소수의 매우 큰 값들이 오른쪽으로 늘어져 있다. (보험 청구비용처럼 "대부분 저렴하지만 극소수가 매우 비싼" 분포)
- 왜도 < 0: **왼쪽(음의) 꼬리**가 길다.
- 왜도 ≈ 0: 좌우 대칭(정규분포에 가까움).
- 실무 기준: **|왜도| < 0.5**면 "충분히 대칭"이라고 보고 변환하지 않는다. (insurance 예제에서 `age`(0.055), `bmi`(0.284)는 이미 대칭이라 로그변환 대상에서 빠짐 — "모든 변수에 로그를 씌우는 게 아니라 치우친 변수만 골라 씌운다"가 핵심)

#### 개념 2 — 로그 변환의 세 갈래 (`log`, `log1p`, `reverse_log1p`)

로그변환은 오른쪽으로 긴 꼬리를 가진 분포를 압축해서 대칭에 가깝게 만드는 가장 기본적인 방법이다. 다만 로그함수는 정의역이 양수(x>0)이므로, **최솟값이 어디인지에 따라 방법이 갈린다**:

| 상황 | 방법 | 이유 |
|---|---|---|
| 오른쪽 꼬리 + 최솟값 > 0 | `log(x)` (순수 로그) | 정의역 문제 없음 |
| 오른쪽 꼬리 + 최솟값 = 0 포함 | `log(1+x)` (`log1p`) | `log(0)`은 -∞로 계산이 깨지므로, 1을 더해 0을 1로 만든 뒤 로그를 취해 우회 |
| 왼쪽(음의) 꼬리 | `reverse_log1p` (반사 후 로그) | 왼쪽 꼬리 데이터를 최댓값 기준으로 좌우 반전(reflect)시켜 오른쪽 꼬리 형태로 바꾼 다음 로그를 취하고, 다시 되돌리는 방식 |

> **판단 기준은 분포 모양이 아니라 "최솟값"이다.** insurance 예제: `charges`는 왜도 1.515로 크고 최솟값이 1,121.874(0보다 큼) → 순수 `log`. `children`은 왜도 0.937이고 자녀 없는 가입자가 573명이라 최솟값이 0 → `log1p`.

---

### 4-5. 로그 변환 적용 — `my_prep.log_transform()`

```python
df3 = my_prep.log_transform(df2, log_columns=log_cols,
                             log1p_columns=log1p_cols,
                             reflect_columns=reflect_cols)
```

변환 효과 확인 예시(insurance): `charges` 왜도 1.51 → **-0.09**, `children` 왜도 0.94 → 0.26. 둘 다 |왜도| < 0.5로 들어와 "대칭에 가까워졌다"고 판단.

**해석 시 주의 — 로그 스케일로 바뀐 종속변수**: `charges`를 로그변환한 채로 모델을 학습시키면, 모델이 예측하는 값도 로그 스케일이다. 나중에 실제 달러 금액으로 해석하려면 **지수(exp)를 취해 되돌려야 한다.** 이걸 잊으면 예측값을 그대로 "예상 청구비용"이라고 잘못 보고하게 된다.

---

### 4-6. 이상치 대체 (Outlier Treatment) — `my_prep.replace_outlier()`

**개념 — IQR(사분위범위) 기준 이상치 판정**

$$IQR = Q_3 - Q_1$$
$$\text{정상범위} = [\,Q_1 - 1.5 \times IQR,\;\; Q_3 + 1.5 \times IQR\,]$$

- $Q_1$: 하위 25% 지점(1사분위수), $Q_3$: 상위 25% 지점(3사분위수)
- 이 범위를 벗어나는 값을 이상치(outlier)로 판정한다. 1.5라는 배수는 통계학에서 관례적으로 쓰는 값(박스플롯의 "whisker" 길이와 동일한 기준).

**"대체(replace)"라는 표현이 핵심**: 이상치를 발견하면 **그 행을 삭제하지 않고**, 정상범위의 경계값으로 눌러 담는다(winsorizing, 경계값 대체). 예를 들어 정상범위 상한이 47.32인데 값이 55라면 47.32로 바꿔치기한다. 이렇게 하면 **표본 수(행 개수)가 그대로 유지**되면서도 극단값의 영향력만 줄일 수 있다 — 데이터가 적을 때 행을 함부로 지우면 안 되는 상황에서 특히 유용.

```python
df4 = my_prep.replace_outlier(df3, columns=continuous_cols)
```

**순서가 결과를 바꾸는 실제 사례**: insurance 예제에서 `children`의 "정상범위"가 -1.65 ~ 2.75라는, 자녀 수로는 말이 안 되는 음수로 나온다. 이유는 바로 전 단계에서 `children`을 이미 `log(1+x)`로 변환했기 때문에, IQR 계산이 로그 스케일 값을 기준으로 이루어진 것. 즉 **전처리 파이프라인의 순서(로그변환 → 이상치 대체)가 그대로 계산 결과에 반영된다**는 것을 보여주는 대표적 예시.

### 4-7. 다중공선성 제거 (Multicollinearity Reduction) — `my_prep.reduce_vif()`

**개념 — VIF(Variance Inflation Factor, 분산팽창인자)**

$$VIF_i = \frac{1}{1 - R_i^2}$$

**말로 풀면**: 독립변수 $X_i$ 하나를 종속변수처럼 놓고, **나머지 독립변수들로 그 변수를 회귀했을 때 나오는 결정계수($R_i^2$)** 를 구한다. 이 $R_i^2$가 크다는 것은 "이 변수가 다른 독립변수들로 상당 부분 설명(예측)된다"는 뜻이고, 이는 곧 이 변수가 다른 변수들과 강하게 겹쳐 있다(다중공선성이 크다)는 뜻이다. VIF는 이 $R_i^2$를 "분산이 몇 배로 부풀려지는가"의 형태로 변환한 지표다.

- $R_i^2 = 0$ (다른 변수들과 전혀 무관) → $VIF = 1$ (부풀림 없음)
- $R_i^2 \to 1$ (다른 변수들로 거의 완벽히 설명됨) → $VIF \to \infty$

**왜 문제가 되는가**: 다중공선성이 크면 회귀계수의 추정이 불안정해져서(표준오차가 커짐), "이 변수가 종속변수에 미치는 영향이 얼마인지"를 신뢰 있게 해석할 수 없게 된다.

**임계값(threshold) 관례**: 보통 VIF > 10이면 심각한 다중공선성으로 보고 해당 변수를 제거 대상으로 삼는다(분야·데이터에 따라 5를 쓰는 경우도 있음). insurance 예제에서는 로그변환·이상치 대체까지 마친 뒤 VIF를 계산했을 때 **최대 VIF가 1.01**로 임계값 10에 한참 못 미쳐 **제거된 변수가 없었다** — "이 단계를 거쳤지만 실제로 아무것도 안 바뀔 수도 있다"는 것도 정상적인 결과임을 기억.

```python
df5 = my_prep.reduce_vif(df4, columns=continuous_cols, threshold=10.0)
```

### 4-8. 정규화 / 표준화 (Standardization) — `my_prep.scaling()`

**개념 — Z-점수 표준화 (StandardScaler)**

$$z = \frac{x - \mu}{\sigma}$$

**말로 풀면**: 각 값에서 평균을 빼고 표준편차로 나눠서, 변환된 변수가 **평균 0, 표준편차 1**이 되도록 척도를 통일하는 작업이다. 서로 다른 단위(나이는 세로, 체질량지수는 kg/m², 자녀 수는 명)를 가진 변수들을 같은 스케일로 맞춰야, 회귀계수의 크기를 서로 비교하거나 정규화(regularization)가 제대로 작동한다.

**정규화 대상에서 종속변수(target)는 제외**: `age`, `bmi`, `children`(독립변수)만 표준화하고, `charges`(종속변수)는 표준화하지 않는다. 이유는 종속변수를 표준화하면 예측값을 원래 단위(달러 등)로 되돌리는 과정이 한 번 더 필요해져 번거롭기 때문 — 표준화는 "독립변수들의 척도를 맞추는" 목적에 한정한다.

**이진 변수(`smoker`)도 대상에서 제외**: 이미 0/1이라 표준화할 스케일 문제가 없다.

```python
df6 = my_prep.scaling(df5, columns=continuous_cols, method='standard')
df6.describe().T[['mean', 'std', 'min', 'max']]
```

**계수 해석이 달라진다는 것 기억하기**: 표준화된 변수로 회귀를 하면, 계수를 "1살 늘어날 때"가 아니라 "**1 표준편차만큼 늘어날 때**"로 읽어야 한다. 이건 면접에서 자주 물어보는 포인트 — "표준화 이후 회귀계수를 어떻게 해석하시겠습니까?"

## 5. 통계 개념 총정리 (말로 설명하는 버전)

| 개념 | 수식/정의 | 한 줄 해석 | 이번 LAB에서의 역할 |
|---|---|---|---|
| 왜도(Skewness) | $E[(X-\mu)^3]/\sigma^3$ | 분포가 좌우로 얼마나 기울어져 있는가 | 로그변환 대상을 고르는 기준 (\|왜도\|<0.5면 변환 불필요) |
| IQR (사분위범위) | $Q_3 - Q_1$ | 데이터의 중간 50%가 퍼진 범위 | 이상치 판정 기준 ($Q_1-1.5IQR \sim Q_3+1.5IQR$ 벗어나면 이상치) |
| 이상치 대체(Winsorizing) | 경계값으로 clip | 극단값의 영향은 줄이되 표본 수는 유지 | `replace_outlier` |
| VIF (분산팽창인자) | $1/(1-R_i^2)$ | 한 변수가 다른 변수들로 얼마나 잘 설명(중복)되는가 | 다중공선성이 큰 변수를 골라내는 기준 (관례상 VIF>10) |
| 표준화(Z-score) | $(x-\mu)/\sigma$ | 서로 다른 단위를 평균0·표준편차1 스케일로 통일 | 독립변수 스케일을 맞춰 계수 비교·정규화가 가능하게 함 |
| 라벨 인코딩 | 범주 → 정수(알파벳 순 0,1,2...) | 문자를 모델이 먹을 수 있는 숫자로 | 명목형 변수를 숫자로 바꾸는 1차 처리 |
| 더미(원-핫) 인코딩 | 범주 k개 → k-1개의 0/1 컬럼 | 범주 간에 크기 관계가 없다는 것을 명시 | 3개 이상 범주형 변수의 표준 처리, 이진변수는 예외 |

> 이번 LAB-09 전처리 노트북에는 $\mu$(모평균) 가설검정, ANOVA 같은 **추론통계(가설검정) 개념은 등장하지 않는다.** 이 노트북은 순수하게 "회귀모델에 넣기 전 변수 형태를 다듬는" 기술통계·전처리 단계이고, 귀무가설/대립가설 기반의 검정은 이전 LAB(예: LAB-07 ANOVA, LAB-09의 가정검정 단계 — Ramsey RESET, Shapiro-Wilk, Breusch-Pagan, Durbin-Watson)에서 다뤄진 부분이니 헷갈리지 않게 구분해서 기억해두자.

## 6. 다른 데이터셋에 적용할 때 체크리스트

새 데이터셋을 받았을 때 이 파이프라인을 재활용하려면 아래 순서로 점검한다.

- [ ] **변수 유형 확정**: `my_qtcheck.set_type` 으로 범주형 지정 → `get_categorical_column_names` / `get_number_column_names` 로 명목형·연속형 목록 뽑기
- [ ] **목표변수(target) 제외**: 연속형 목록에서 target을 `remove()` 했는지 확인
- [ ] **EDA 결과 반영**: 관련 없다고 결론난 변수를 데이터프레임과 명목형 목록 양쪽에서 함께 `drop`
- [ ] **라벨링 대상**: 남은 명목형 변수 확인, 라벨링 후 매핑(어떤 범주가 몇 번인지) 반드시 눈으로 확인
- [ ] **더미 대상**: 범주 3개 이상인 변수만 실질적으로 컬럼이 늘어남 — 이진 변수는 자동 스킵되는지 결과로 확인
- [ ] **로그변환 대상 선정**: `desc`(또는 직접 계산한 왜도표)에서 \|왜도\| ≥ 0.5인 변수만 후보로, 최솟값이 0 이상인지/음수인지로 `log`/`log1p`/`reverse_log1p` 분류
- [ ] **변환 효과 확인**: 변환 후 왜도가 실제로 줄었는지 재확인 (변환은 "적용하는 것" 자체가 목적이 아니라 "효과가 있는지 확인"까지가 목적)
- [ ] **이상치 대체는 로그변환 이후**: 순서를 바꾸지 않기
- [ ] **VIF는 임계값(보통 10)과 비교, 제거 대상이 "없을 수도 있다"는 것을 정상 결과로 받아들이기**
- [ ] **정규화는 연속형 독립변수에만, target·이진변수 제외**
- [ ] **각 단계 후 `.head()` / `.describe()` 로 눈으로 확인** — 파이프라인 전체를 한 번에 실행하지 않기
- [ ] **중간 체크포인트 저장(`to_excel` 등)** — 최소 "인코딩 후", "전체 전처리 후" 두 지점

## 8. 재사용 템플릿 코드 (새 데이터셋에 그대로 적용)

체크리스트(6번)를 실제 코드로 옮긴 버전. 데이터셋이 바뀌어도 `origin`, `target`, `drop_cols` 정도만 바꾸면 그대로 돌릴 수 있게 짰다. `desc['log_need']` 컬럼이 아직 없는 데이터셋(=EDA에서 미리 판정해두지 않은 경우)에도 쓸 수 있도록, 왜도·최솟값을 직접 계산해서 로그변환 대상을 나누는 범용 함수(`classify_log_need`)를 포함시켰다.

```python
import pandas as pd
from scipy.stats import skew
from helpers import my_qtcheck, my_prep

# ── 0. 변수 유형 확정 ────────────────────────────────────────
df = my_qtcheck.set_type(origin, as_category=cat_desc.columns)   # 명목형 dtype 지정
target = "종속변수명"                                              # 예: "charges"

nominal_cols = my_qtcheck.get_categorical_column_names(df)
continuous_cols = my_qtcheck.get_number_column_names(df)
continuous_cols.remove(target)                                    # target은 독립변수 목록에서 제외

# EDA에서 관련 없다고 결론난 변수 — 데이터·목록 양쪽에서 함께 제거
drop_cols = []          # 예: ['sex', 'region']
df = df.drop(columns=drop_cols)
nominal_cols = [c for c in nominal_cols if c not in drop_cols]

# ── 1. 명목형 라벨링 ─────────────────────────────────────────
df1 = my_prep.labeling(df, columns=nominal_cols)

# ── 2. 더미변수 인코딩 (이진 변수는 자동 스킵됨) ────────────────
df2 = my_prep.dummies(df1, columns=nominal_cols, drop_first=True)

# ── 3. 로그변환 대상 선정 — desc['log_need'] 없이 직접 계산하는 범용 버전 ─
def classify_log_need(frame, columns, skew_threshold=0.5):
    """왜도·최솟값을 근거로 log / log1p / reverse_log1p 대상을 나눈다."""
    log_cols, log1p_cols, reflect_cols = [], [], []
    for col in columns:
        s = skew(frame[col].dropna())
        mn = frame[col].min()
        if abs(s) < skew_threshold:          # 이미 충분히 대칭
            continue
        if s > 0:                             # 오른쪽 꼬리
            (log_cols if mn > 0 else log1p_cols).append(col)
        else:                                  # 왼쪽 꼬리
            reflect_cols.append(col)
    return log_cols, log1p_cols, reflect_cols

log_cols, log1p_cols, reflect_cols = classify_log_need(df2, continuous_cols)

# ── 4. 로그 변환 ─────────────────────────────────────────────
df3 = my_prep.log_transform(df2, log_columns=log_cols,
                             log1p_columns=log1p_cols,
                             reflect_columns=reflect_cols)

# ── 5. 이상치 대체 — 반드시 로그변환 다음 순서 ───────────────────
df4 = my_prep.replace_outlier(df3, columns=continuous_cols)

# ── 6. 다중공선성 제거 ───────────────────────────────────────
df5 = my_prep.reduce_vif(df4, columns=continuous_cols, threshold=10.0)

# ── 7. 정규화 — continuous_cols(=target·이진변수 제외된 목록)에만 적용 ─
df6 = my_prep.scaling(df5, columns=continuous_cols, method='standard')

# ── 체크포인트 저장 (최소 두 지점) ───────────────────────────────
df2.to_excel("checkpoint_encoded.xlsx", index=False)   # 인코딩 후
df6.to_excel("checkpoint_final.xlsx", index=False)     # 전처리 완료 후
```

**단계별 실행 확인 습관 (전체 실행 X)**: 위 블록을 한 번에 다 돌리지 말고, 단계마다 끊어서 `dfN.head()` 또는 `dfN.describe()`로 눈으로 찍어보고 다음 단계로 넘어간다. 특히 `classify_log_need` 결과(`log_cols`, `log1p_cols`, `reflect_cols`)는 실행 직후 꼭 `print`해서, 원하는 변수가 올바른 그룹으로 분류됐는지 확인한다.

- "로그변환 대상을 어떻게 고르셨나요? log와 log1p는 어떻게 구분하나요?"
- "이상치를 왜 삭제하지 않고 대체하셨나요?"
- "VIF가 뭔가요? 수식으로 설명해 주세요. 임계값을 왜 10으로 잡나요?"
- "표준화한 변수의 회귀계수는 어떻게 해석해야 하나요?"
- "종속변수는 왜 표준화하지 않나요? 로그변환한 종속변수의 예측값은 어떻게 원래 단위로 되돌리나요?"
- "전처리 순서를 바꾸면 결과가 어떻게 달라지나요? (실제 사례로 설명 가능한가?)"
